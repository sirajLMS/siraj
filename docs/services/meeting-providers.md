# Meeting Provider Adapters (Auto URL Generation)

## Why Auto Meeting Generation

Before this feature, the meeting-config catalog supported only **manual URL entry**: a teacher pasted a personal meeting link, validated against the provider catalog's `urlAllowlist`. For teachers running live recurring classes this created three problems:

1. **Copy/paste fatigue** — Teachers had to create the meeting in Zoom/Google Meet/Microsoft Teams, copy the join URL, then paste it back into Siraj. Every recurring class required this manual round-trip.

2. **Broken-link bugs** — A shared link copied from the wrong meeting or pasted with a typo silently persisted and surfaced as a broken join link when students tried to connect. The URL allowlist (`backend/lib/meeting-config.validation.ts`) only validated hostname patterns; it could not detect an incorrect or expired meeting.

3. **No per-class-instance uniqueness** — A single shared URL meant the same link was reused across every occurrence of a recurring class. Latecomers joined stale meetings, and breakout/attendance tracking was impossible.

### What auto-generation solves

When a teacher selects an auto-capable provider (Zoom, Google Meet, Microsoft Teams), the backend calls the provider's REST API directly and persists a **fresh, unique join URL per class instance**. Three entry-points exist:

- **Silent on-save** — The URL is generated when a meeting config is saved without a manual URL (`backend/services/meeting/utils/maybe-generate-url.ts`).
- **Explicit "Generate" preview** — The UI offers a "Generate" button (`MeetingConfigTypeFields` auto-generation affordance) that calls the adapter on demand.
- **At-class-booking time** — Each `class_instance` row carries its own distinct link, generated by `ClassMeetingConfigService` when the class is booked.

See `.ai/plans/auto-meeting-url/specs.md` and `.ai/plans/auto-meeting-url/design.md` for the full requirements and design rationale.

## The Pattern

The adapter/factory pattern mirrors the existing `backend/services/communication/channels/` (`IEmailChannel` / `EmailChannelFactory`). Each provider implements a common interface; a race-safe factory lazy-imports and memoises adapter instances per provider slug.

### Interface contract

```typescript
// backend/services/meeting/channels/IMeetingChannel.ts

export type MeetingProvider = "zoom" | "google_meet" | "microsoft_teams";

export interface IMeetingChannel {
  generateMeeting(input: GenerateMeetingInput): Promise<GenerateMeetingResult>;
  deleteMeeting?(meetingId: string): Promise<void>;
  validateConfig(): Promise<boolean>;
  disconnect(): Promise<void>;
}
```

The `GenerateMeetingResult` captures the `joinUrl` (stored as `details.meetingUrl`), an optional `meetingId`, `password`, `hostUrl`, and a per-provider `providerMetadata` record.

### Factory (`MeetingChannelFactory`)

File: `backend/services/meeting/channels/MeetingChannelFactory.ts`

The factory:

1. **Resolves env config** via `resolveEnvConfigMany` for the provider's required keys.
2. **Lazy-imports** the adapter module (`await import(...)`) to keep startup fast and avoid loading unused providers.
3. **Memoises instances** per slug in a `Map<MeetingProvider, IMeetingChannel>` with a race-safe `initializationPromise` guard (prevents concurrent double-initialisation).
4. **Exposes `getMeetingChannel(slug)`** as the canonical entry-point. A convenience delegating object `meetingChannel.generateMeeting(providerKind, input)` resolves the adapter from a `providerKind` string.

```typescript
// Resolution flow
meetingChannel.generateMeeting("zoom_oauth", input)
  → providerKindToSlug("zoom_oauth") → "zoom"
  → getMeetingChannel("zoom")
  → createAdapter("zoom") → resolveEnvConfigMany(["ZOOM_ACCOUNT_ID", ...]) → new ZoomMeetingAdapter(opts)
  → adapter.generateMeeting(input)
```

### Hybrid auth resolution order

Every adapter follows the same hybrid auth order inside `generateMeeting`:

1. **Org-level credentials first** — If the adapter was constructed with org env credentials (S2S for Zoom, service-account+DWD for Google Meet, client-credentials for Teams), use those. This is the zero-config-per-teacher path.

2. **Per-user OAuth fallback** — If org credentials are absent, and `input.actorUserId` is provided, look up the user's stored OAuth refresh token via `MeetingProviderTokenRepository.getByUserAndProvider(actorUserId, slug)`, exchange it via `refreshAccessToken` (`backend/services/meeting/integrations/token-refresh.ts`), and persist the rotated tokens back to the repository.

3. **No credentials at all** — Throw `NoOrgCredentialsNoUserTokenError` so the resolver surfaces a meaningful "Configure org credentials or connect your account" message.

### Adapter: Zoom (`ZoomMeetingAdapter`)

File: `backend/services/meeting/channels/zoom/ZoomMeetingAdapter.ts`

- **Org path**: Server-to-Server OAuth (`grant_type=account_credentials`) at `https://zoom.us/oauth/token` → JWT access token, cached until `exp - 60s`. No refresh token; re-call when expired.
- **Per-user path**: OAuth `authorization_code` → `refresh_token` grant. Zoom **rotates refresh tokens** on every refresh — the adapter MUST persist the new `refresh_token` back to `MeetingProviderTokenRepository` after each refresh exchange.
- **Create meeting**: `POST https://api.zoom.us/v2/users/me/meetings` with `type: 2` (scheduled) + sensible defaults (`waiting_room: true`, `join_before_host: false`, `host_video: true`). Returns `join_url` → stored as `details.meetingUrl`, `start_url` → `providerMetadata.startUrl`.
- **Delete**: `DELETE https://api.zoom.us/v2/meetings/{meetingId}` → `204 No Content`. Supported for cancel-cleanup.
- **Security**: Zoom overwrites disabled security settings if password + waiting_room + meeting_authentication are all disabled. Always read back the response.
- **Scopes**: `meeting:write` (user), `meeting:write:admin` (S2S).

### Adapter: Google Meet (`GoogleMeetAdapter`)

File: `backend/services/meeting/channels/google-meet/GoogleMeetAdapter.ts`

- **Org path**: Service-account JWT (RS256, signed via `jose`) with `sub` claim = `GOOGLE_MEET_IMPERSONATE_SUBJECT` (Workspace user email for Domain-Wide Delegation). Exchange at `https://oauth2.googleapis.com/token` using `grant_type=urn:ietf:params:oauth:grant-type:jwt-bearer`. Without `sub`, `spaces.create` returns 403.
- **Per-user path**: Standard OAuth `refresh_token` grant. No DWD, no `sub` — the user's own OAuth access token grants the scope directly.
- **Create space**: `POST https://meet.googleapis.com/v2/spaces` with `config.accessType` (`OPEN` default). Returns `meetingUri` → `details.meetingUrl`, `meetingCode` → `providerMetadata.meetingCode`, `name` (spaces resource id) → `meetingId`.
- **No delete endpoint** — Meet spaces auto-expire when the conference ends and attendees leave. Cancel-path is a log-only no-op.
- **Scope**: `https://www.googleapis.com/auth/meetings.space.created`.
- **Service-account JSON**: Parsed from `GOOGLE_MEET_SERVICE_ACCOUNT_JSON` env var. Validated for `type === "service_account"`, presence of `client_email` + `private_key`. Wraps errors in `InvalidServiceAccountJsonError`.

### Adapter: Microsoft Teams (`MicrosoftTeamsAdapter`)

File: `backend/services/meeting/channels/microsoft-teams/MicrosoftTeamsAdapter.ts`

- **Org path**: Entra client-credentials flow at `https://login.microsoftonline.com/{tenantId}/oauth2/v2.0/token` with `scope=https://graph.microsoft.com/.default`. Access token can be used to call `POST /users/{organizerUserId}/onlineMeetings`.
- **Per-user path**: OAuth delegated permission `OnlineMeetings.ReadWrite` — uses `/me/onlineMeetings` path (organizer resolved from the delegation token holder). Adapter swaps `organizerUserId` to `"me"` when per-user fallback is active.
- **Create meeting**: `POST https://graph.microsoft.com/v1.0/users/{userId}/onlineMeetings` with `subject` + `startDateTime` + `endDateTime`. Returns `joinWebUrl` and `id`. Passcode is in `joinMeetingIdSettings.passcode`.
- **Delete**: `DELETE /users/{userId}/onlineMeetings/{id}` → `204 No Content`. Supported for cancel-cleanup.
- **Application Access Policy** (CRITICAL): Your Entra app registration MUST have a Teams application access policy assigned via `New-CsApplicationAccessPolicy` + `Grant-CsApplicationAccessPolicy` (PowerShell, SkypeForBusiness module). Without it, `/users/{userId}/onlineMeetings` returns 403 "No application access policy found for this app". The adapter surfaces this via `NoAppAccessPolicyError`.
- **Permissions**: `OnlineMeetings.ReadWrite.All` (application, least-privileged).

### Typed error hierarchy

File: `backend/services/meeting/channels/IMeetingChannel.ts`

All errors extend `MeetingChannelError` (carrying `code`, `upstreamMessage`, `upstreamStatus`). Key error types:

| Error class | Code | When |
|---|---|---|
| `UnsupportedProviderKindError` | `UNSUPPORTED_PROVIDER_KIND` | `providerKind` is `"manual"` or unknown |
| `NoOrgCredentialsNoUserTokenError` | `NO_ORG_CREDENTIALS_NO_USER_TOKEN` | No org env + no per-user token |
| `ProviderReauthRequiredError` | `PROVIDER_REAUTH_REQUIRED` | Refresh token expired/revoked (`invalid_grant`) |
| `RateLimitedError` | `RATE_LIMITED` | HTTP 429 from provider |
| `ProviderUnavailableError` | `PROVIDER_UNAVAILABLE` | HTTP 5xx or network failure |
| `NoAppAccessPolicyError` | `NO_APP_ACCESS_POLICY` | Teams: missing application access policy (403) |
| `InsufficientScopesError` | `INSUFFICIENT_SCOPES` | Token scopes don't satisfy required |
| `InvalidServiceAccountJsonError` | `INVALID_SERVICE_ACCOUNT_JSON` | Google service-account JSON malformed |
| `ProviderReauthRequiredError` | `PROVIDER_REAUTH_REQUIRED` | Refresh failed (per-user path) |

## Rules / Conventions

### How to add a new provider adapter

1. **Create the adapter module** at `backend/services/meeting/channels/{slug}/`:
   - Implement `IMeetingChannel` (the interface).
   - Define an `{Slug}AdapterOptions` interface describing the org-credential shape.
   - Export a static `ENDPOINTS` list (used by `MeetingIntegrationService` for health display).
   - Implement the hybrid auth order: org creds first → per-user OAuth fallback → `NoOrgCredentialsNoUserTokenError`.

2. **Register the env keys** in `PROVIDER_ENV_KEYS` inside `MeetingChannelFactory.ts`:
   ```typescript
   const PROVIDER_ENV_KEYS: Record<MeetingProvider, readonly string[]> = {
     // ...existing entries...
     your_slug: ["YOUR_API_KEY", "YOUR_CLIENT_ID"] as const,
   };
   ```

3. **Wire the lazy import** in `createAdapter()` inside `MeetingChannelFactory.ts`. Add the new slug to the `MeetingProvider` union in `IMeetingChannel.ts`.

4. **Map `providerKind` to `slug`** in `providerKindToSlug()`:
   ```typescript
   case "your_provider_oauth": return "your_slug";
   ```

5. **Register env keys** in `backend/lib/env-config-keys.ts`, `backend/lib/env.ts` (`EnvironmentConfig`), `environment.d.ts`, and `.env.example`.

6. **Add the seed entry** in `backend/db/seeds/lib/meeting-provider-factory.ts` with `providerKind`, `supportsAutoGeneration: true`, `requiresMeetingUrl: false`.

7. **Add integration tests** at `backend/services/meeting/channels/{slug}/test/` (mock network calls). Live smokes go in `test/integration/`.

### Hybrid auth resolution order (recap)

1. **Org-level credentials** (server-to-server) — adapter constructed with env-resolved org credentials.
2. **Per-user OAuth fallback** — `input.actorUserId` → `MeetingProviderTokenRepository.getByUserAndProvider` → `refreshAccessToken` → persist rotated tokens.
3. **Nothing available** — throw `NoOrgCredentialsNoUserTokenError`.

### URL-allowlist bypass rules

File: `backend/lib/meeting-config.validation.ts`

The URL allowlist (`provider.urlAllowlist`) is a list of hostname patterns checked by `isUrlAllowedByProvider`. For auto-generation providers:

- **The allowlist only applies when a `meetingUrl` is present in the config details.** Auto-generation providers may omit `meetingUrl` until the adapter populates it.
- **Manual override is supported**: if an auto-generation provider's config comes with a user-supplied `meetingUrl` (non-empty), the service treats it as a manual override — no generation, and the allowlist IS enforced against the user-supplied URL.
- **Adapter-generated URLs bypass the allowlist**: the `maybeGenerateUrl` service utility (`backend/services/meeting/utils/maybe-generate-url.ts`) writes the `joinUrl` returned by `meetingChannel.generateMeeting` directly — the adapter is trusted to produce a valid URL from the provider's own domain.

Summary: allowlist = user-supplied URL guardrail; adapter URL = trusted by construction.

### Type discriminations

- `provider.providerKind` is a varchar column (`meeting_providers.provider_kind`) with values: `"manual"`, `"zoom_oauth"`, `"google_meet_oauth"`, `"microsoft_teams_oauth"`. The `"manual"` kind means no adapter; `providerKindToSlug` returns `null`.
- `provider.fieldSchema.supportsAutoGeneration` is a boolean flag on the catalog's `fieldSchema` JSONB column. Frontend components use it to decide whether to show the "Generate" affordance (`MeetingConfigTypeFields.onGenerateUrl`).
- `details.meetingUrl` and `providerMetadata` are stored in the shared `meetingConfigSharedColumns()` factory (`backend/db/schema/meeting/__shared__/meeting-config-columns.ts`), so both user meeting configs and class meeting configs carry the columns.

## What NOT to Do

- **Don't call adapters directly.** ALL meeting URL generation must go through `MeetingChannelFactory.getMeetingChannel(slug)` or the `meetingChannel` delegating object — never construct `ZoomMeetingAdapter`/`GoogleMeetAdapter`/`MicrosoftTeamsAdapter` outside the factory. The factory guarantees race-safe singletons, proper env resolution, and cache invalidation on credential changes.

- **Don't store refresh tokens unencrypted.** The `meeting_provider_tokens` table uses the `encryptedText` custom Drizzle type (`backend/db/schema/custom-types`) for both `access_token` and `refresh_token` columns. Never write plaintext tokens to a side table or log them. The repository (`MeetingProviderTokenRepository`) handles encryption/decryption transparently.

- **Don't do booking-time generation synchronously in the booking transaction.** The `maybe-generate-url` utility runs adapter calls outside the booking DB transaction; failures are logged and the booking continues — a class booking must never fail because a provider API is down. The class instance keeps the snapshot's existing URL (generated earlier or empty) when generation fails.

- **Don't bypass the `providerKindToSlug` mapping.** Services should never hardcode slug strings; use `providerKindToSlug(provider.providerKind)` and pass the result to `getMeetingChannel`. Unknown kinds throw `UnsupportedProviderKindError`.

- **Don't reuse an adapter instance after `resetMeetingChannel`.** Once `resetMeetingChannel(slug)` runs (env cache invalidated + `disconnect()` called on the adapter), subsequent `getMeetingChannel` calls rebuild a fresh adapter. Holding a reference to an old adapter bypasses credential refresh and can return stale tokens.

- **Don't log raw `Authorization` headers or refresh tokens.** Use the `logger` (`@/backend/lib/logger`), which masks secrets. Treat the Zoom `start_url` query param (`?zak=...`) as a secret — it is a host-only ZAK token.

## Deployment Prerequisites

### Google Meet — Workspace Domain-Wide Delegation (DWD)

1. Create a Google Cloud service account in your Workspace project.
2. Download the JSON key file (must contain `type: "service_account"`, `client_email`, `private_key`, `private_key_id`).
3. Store the **entire JSON** in the `GOOGLE_MEET_SERVICE_ACCOUNT_JSON` env var (single string, newlines preserved as `\n` inside `private_key`).
4. In Google Workspace Admin Console → **Security → API Controls → Domain-wide Delegation**, add the service account's `client_email` with scope `https://www.googleapis.com/auth/meetings.space.created`.
5. Set `GOOGLE_MEET_IMPERSONATE_SUBJECT` to the Workspace user email that the service account will impersonate. Without this, `spaces.create` returns 403.

### Microsoft Teams — Entra App Access Policy

1. Register an application in Azure: https://entra.microsoft.com → **App registrations → New registration**.
2. Grant **application permission** `OnlineMeetings.ReadWrite.All` (leave delegated permission off unless you're wiring per-user fallback separately).
3. Configure client secret and store `MS_TEAMS_TENANT_ID`, `MS_TEAMS_CLIENT_ID`, `MS_TEAMS_CLIENT_SECRET` in env.
4. Set `MS_TEAMS_ORGANIZER_USER_ID` to the organizer user's UPN (typically their email). UPN is recommended over object ID because admins can identify it more easily.
5. **CRITICAL — Application Access Policy**: Open PowerShell with the SkypeForBusiness module:
   ```powershell
   # Create a policy (once), then assign it to the Entra app's service principal
   New-CsApplicationAccessPolicy -Identity "SirajTeamsAccessPolicy" -AppIds "<YOUR_ENTRA_APP_CLIENT_ID>"
   Grant-CsApplicationAccessPolicy -PolicyIdentity "SirajTeamsAccessPolicy" -Global
   ```
   Without this, `/users/{userId}/onlineMeetings` returns 403 "No application access policy found for this app". The adapter surfaces this as `NoAppAccessPolicyError`.

### Zoom — App Marketplace Server-to-Server app

1. Go to https://marketplace.zoom.us → **Develop → Build Server-to-Server OAuth app**.
2. Grant scopes: `meeting:write:admin` (S2S, account-wide).
3. Copy the `account_id`, `client_id`, `client_secret` and set `ZOOM_ACCOUNT_ID`, `ZOOM_CLIENT_ID`, `ZOOM_CLIENT_SECRET` env vars.
4. No refresh token for S2S — re-call `/oauth/token?grant_type=account_credentials` when the JWT expires.

### Per-user OAuth (fallback for every provider)

1. Use the same `client_id`/`client_secret` env keys for the per-user path (`zoom*`, `googleMeet*`, `msTeams*` in `EnvironmentConfig`).
2. Redirect URI pattern: `{baseUrl}/api/oauth/{slug-with-dashes}/callback`. The `MeetingOAuthService` (`backend/services/meeting/integrations/meeting-oauth.service.ts`) builds this dynamically from `oauthRedirectBaseUrl` or `nextPublicBaseUrl`.
3. Add callback handlers under `app/api/oauth/{slug}/callback/route.ts`. Each provider deploys its own `/authorize` redirect URL sequence; see `meeting-oauth.service.ts` → `buildAuthorizeUrl` per provider.
4. The OAuth state JWT uses `jwtSecret` from environment as the signing secret — keep it the same across instances (10-minute state expiry).
5. For Google OAuth specifically: include `prompt=consent` in the authorize URL to force a fresh refresh-token issuance on every reconnect (otherwise Google returns the cached refresh token only the first time the user consents).
