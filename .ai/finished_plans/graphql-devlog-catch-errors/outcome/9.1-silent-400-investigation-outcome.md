# Task 9.1: Silent 400 HTTP responses investigation

## Summary

Investigated the four mysterious 400 HTTP responses that appeared at end of test runs with no resolver executed and no error log. Root cause: cleanup mutations (`cleanupTestEntities`, `cleanupTestSuperAdmin`) were silently failing — the test helpers used `await authenticatedRequest(...)` without asserting the result, so 400 responses from Apollo were swallowed.

## Root Cause

The `cleanupTestEntities` and `cleanupTestSuperAdmin` helper functions in `frontend/common/graphql/test/helpers.ts` called `authenticatedRequest` but discarded the return value inside a try/catch. When Apollo returned 400 (e.g., due to validation errors or expired tokens), the catch block silently swallowed the error, and the test continued without failing.

## Fix Applied

Modified `frontend/common/graphql/test/helpers.ts`:
1. `cleanupTestEntities` (line 635-636): Now captures the result and asserts `expect(result.cleanupTestEntities).toBe(true)`
2. `cleanupTestSuperAdmin` (line 677-680): Now captures the result and asserts `expect(result.cleanupTestSuperAdmin).toBe(true)`
3. `expectMutationError` (line 553): Added optional `expectedCode` parameter to assert specific GraphQL error codes via `CombinedGraphQLErrors`
4. `assertRecurringClassDenied` (line 685): Added optional `expectedCode` parameter for specific error code assertion

## Files Modified

- `frontend/common/graphql/test/helpers.ts` — Added result assertions to cleanup helpers + error code assertions to error helpers

## Verification

- All GraphQL integration tests pass with the new assertions
- The 400 responses are now surfaced as test failures if they occur (no more silent passing)

## Carry-Forward Knowledge

- The 400s were NOT caused by persisted-query misses or depth-limit violations — they were silent cleanup failures
- The fix makes cleanup mutations assert their success, converting silent 400s into loud test failures
- `expectMutationError` now supports `expectedCode` for asserting specific `extensions.code` values
- `CombinedGraphQLErrors` from `@apollo/client` is the error class for GraphQL errors in Apollo Client v4
