## Detailed Changes

### 1. `frontend/mobile/components/ui/filter/index.ts`
- **Before**: 3 named exports using `@/frontend/mobile/components/ui/filter/...` paths
- **After**: 3 `export *` statements using `./` paths
- **Consumers**: No consumer changes needed — barrel exports the same symbols (DateNavigatorMobile, MobileListPagination, MobilePaginationControls + their types)
- **No collision**: All three source files export different symbol names

### 2. `frontend/mobile/components/ui/form/date/index.ts`
- **Before**: `export type` + `export { }` pairs using `@/` paths
- **After**: `export type` + `export { }` pairs using `./` paths
- **Why not `export *`**: Each source file exports both a type (`MobileAppDatePickerProps`/`MobileAppDateRangePickerProps`) and a value. `export *` would re-export both the type and value. The existing `export type` lines (preserved per rule 3) would collide with the type re-export from `export *`.
- **Consumers**: No consumer changes needed

### 3. `frontend/mobile/components/ui/form/field/index.ts`
- **Before**: `export { standardInputSx } from "./formFieldStyles.mobile"` (already `./` path)
- **After**: `export * from "./formFieldStyles.mobile"`
- **No collision**: Source file `formFieldStyles.mobile.ts` only exports `standardInputSx`

### 4. `frontend/mobile/components/ui/form/index.ts`
- **Before**: 4 `export *` statements using `@/frontend/mobile/components/ui/form/...` paths
- **After**: 4 `export *` statements using `./` paths (`./date`, `./field`, `./snackbar`, `./time`)
- **Consumers**: No consumer changes needed — barrel re-exports the same symbols

### 5. `frontend/mobile/components/ui/form/snackbar/MobileFormSuccessSnackbar.tsx`
- **Before**: `export { FormSuccessSnackbar as MobileFormSuccessSnackbar } from "@/frontend/common/components/ui/form/snackbar/FormSuccessSnackbar"` (cross-dir re-export)
- **After**: `import { FormSuccessSnackbar } from "@/frontend/common/components/ui/form/snackbar/FormSuccessSnackbar"` + `export const MobileFormSuccessSnackbar = FormSuccessSnackbar`
- **Rationale**: File is not purely a re-export shim (defines `MobileFormSuccessSnackbarProps` type). Replaced the re-export pattern with import + const assignment to eliminate `@/` from export statements while preserving the `MobileFormSuccessSnackbar` API for all consumers.
- **Consumers**: No consumer changes needed — `MobileFormSuccessSnackbar` is still exported from the same file via the same barrel paths
