# Batch 032 Outcome — Re-export Elimination

## Files Modified

### 1. `frontend/common/graphql/test/testClient.ts` (non-index .ts with re-exports)
- **Issue:** Had cross-dir re-export: `export { getTestApiUrl, getTestBaseUrl, getTestGraphqlUrl, getTestPort } from "@/frontend/common/graphql/test/testPort"`

### 3. `frontend/common/hooks/userAutocomplete/index.ts` (index.ts with @/ paths to same-dir files)

- No collision risk — each hook file exports uniquely named functions/interfaces

### 4. `frontend/common/lib/country/index.ts` (deprecated cross-dir re-export shim)
- **Issue:** Re-exported from `@/frontend/common/lib/locale` (cross-directory). Marked `@deprecated` with no consumers.

- **Side effect:** `frontend/common/lib/index.ts` had `export * from "./country"` which broke after deletion — removed that line (no consumers of the barrel either)

### 5. `frontend/common/lib/locale/country/index.ts` (index.ts with @/ paths to same-dir files)
- **Issue:** Used `@/frontend/common/lib/locale/country/xxx` paths (absolute `@/` to same directory)
- **Fix:** Converted exports to `./` relative paths:
  - `export * from "./countries"` (for `countries`)
  - `export { countries as countryList } from "./countries"` (alias — `export *` cannot create aliases)
  - `export * from "./display"`, `export * from "./emoji"`, `export * from "./lookup"`, `export * from "./preferred"`
  - `export type { CountryDetectionResult, CountryType } from "./types"` (kept as-is per rule 3)
