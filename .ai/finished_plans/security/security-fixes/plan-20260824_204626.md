### H1 — Escape LIKE wildcards in student name filters

- **File:** `backend/utils/student.filterUtils.ts`
- **Lines:** 26, 35, 38
- **Layer:** Repository utility (query builder)
- **Problem:** `nameNotContains`, `nameStartsWith`, and `nameEndsWith` are interpolated directly into `notLike()` / `like()` patterns. `escapeLikeWildcards` is imported nowhere in this file, while `backend/utils/db.utils.ts:12` provides it and it's applied in `teacher.repository.ts`, `staff-profile.repository.ts`, `user.repository.ts`, `quota.repository.ts`, etc. A user supplying `%`, `_`, or `\` characters can inject wildcard semantics, turning an equality-ish search into a full-table or pattern-match scan and enabling data enumeration via prefix probing.
- **Fix:** Import `escapeLikeWildcards` and wrap every user-derived pattern fragment before concatenating the surrounding `%`.

```typescript
// backend/utils/student.filterUtils.ts
import { asc, desc, eq, gt, gte, isNull, like, lt, lte, not, notLike } from "drizzle-orm";
import type { PgSelect } from "drizzle-orm/pg-core";
import { fullTextSearch } from "@/backend/db/query.extensions";
import { students } from "@/backend/db/schema";
import { escapeLikeWildcards } from "@/backend/utils";          // ADD
import { OrderSortDirection } from "@/backend/enum";
import { StudentsOrderByColumn } from "@/backend/enum/students";
import type * as Types from "@/backend/types";

function applyNameFilters<T extends PgSelect>(qb: T, args: Types.StudentFilterArgs): T {
  const ftsLang = "simple";
  if (args.name) {
    const ftsCondition = fullTextSearch(students.name, args.name, ftsLang);
    if (ftsCondition) {
      qb = qb.where(ftsCondition);
    }
  }
  if (args.nameNotContains) {
    qb = qb.where(notLike(students.name, `%${escapeLikeWildcards(args.nameNotContains)}%`));
  }
  if (args.nameEquals) {
    qb = qb.where(eq(students.name, args.nameEquals));
  }
  if (args.nameNotEquals) {
    qb = qb.where(not(eq(students.name, args.nameNotEquals)));
  }
  if (args.nameStartsWith) {
    qb = qb.where(like(students.name, `${escapeLikeWildcards(args.nameStartsWith)}%`));
  }
  if (args.nameEndsWith) {
    qb = qb.where(like(students.name, `%${escapeLikeWildcards(args.nameEndsWith)}`));
  }
  if (args.nameIsEmpty) {
    qb = qb.where(eq(students.name, ""));
  }
  if (args.nameIsNotEmpty) {
    qb = qb.where(not(eq(students.name, "")));
  }
  return qb;
}
```

### H2 — Harden `fullTextSearch` against tsquery syntax errors

- **File:** `backend/db/query.extensions.ts`
- **Lines:** 9–37 (function `fullTextSearch`)
- **Layer:** Repository query extension
- **Problem:** Words are cleansed of `[&|!():]` and then re-assembled with `:*` / `&` into a `to_tsquery()` string. Characters such as `'` (apostrophe), `"`, `*`, `<`, `-`, `@`, and stray parentheses introduced by partial sanitization produce a PostgreSQL `syntax error in tsquery` and abort the transaction — trivially repeatable DoS against any resolver that reaches it (student directory search).
- **Fix:** Prefer `plainto_tsquery`, which treats the entire input as plain text (no operator semantics, never throws). If prefix search is required, sanitize more aggressively and quote each term.

```typescript
// backend/db/query.extensions.ts
export function fullTextSearch(
  column: SQL | SQL.Aliased | Column,
  searchText: string,
  config: string = "simple"
): SQL | null {
  if (!searchText || searchText.trim() === "") {
    return null;
  }
  // Defense-in-depth: clamp length before touching the DB engine.
  const clamped = searchText.trim().slice(0, 256);
  // plainto_tsquery never raises on user input — operators are treated as text.
  // Prefix matching is preserved via the trailing :* applied to each sanitized token.
  const tokens = clamped
    .split(/\s+/)
    .map(word => word.replace(/[^\p{L}\p{N}_-]/gu, "")) // keep alphanumerics only
    .filter(Boolean);
  if (tokens.length === 0) {
    return null;
  }
  const safeQuery = tokens.map(t => `${t}:*`).join(" & ");
  return sql`to_tsvector(${config}, ${column}) @@ to_tsquery(${sql.raw("'" + config + "'")}, ${safeQuery})`;
}
```

> Note: keep `config` coming from a code-level constant (`"simple"`, `'english'`, etc.) — never from request args, since it is interpolated via `sql.raw`.

### H3 — Fail closed on login rate-limit/lockout lookups

- **File:** `backend/graphql/mutation/auth/auth.mutation.ts`
- **Lines:** 43–53 (failOpen helper usage), 191–248 (login resolver), 271–316 (demoLogin resolver)
- **Layer:** GraphQL auth mutations
- **Problem:** The custom `failOpen()` wrapper catches transient errors and returns the "allow" fallback: `isLocked` falls back to `false`, `recordAttempt` falls back to a synthetic non-locked result. Any DB/Redis transient disables brute-force protection on `login` and `demoLogin`. Additionally, `checkRateLimit(...)` errors are swallowed the same way.
- **Fix:** Remove the wrappers for auth-critical paths. Let errors propagate — the global error handler already maps unexpected failures to a 500. Optionally catch and convert to a 503 `SERVICE_UNAVAILABLE` (never "allow").


### H5 — Deny-by-default for files without registered usages

- **File:** `backend/services/storage/storage.service.ts`
- **Lines:** ~140–160 (`checkFileAccess`)
- **Layer:** Service
- **Problem:** The current implementation returns `null` (allow) when `usages.length === 0`. Any authenticated user who guesses or learns a non-public storage path (e.g., `private/billing/x.pdf`) can stream it via `/api/storage/files/[[...path]]` as long as no junction row exists — the most common case for "uploaded but never linked" artifacts (orphaned payment proofs, drafts, etc.). Authentication is required, but authorization effectively fails open.
- **Fix:** Return deny for zero-usage files unless the user is a super admin or holds `STORAGE_MANAGE`.

```typescript
// backend/services/storage/storage.service.ts
export async function checkFileAccess(
  userId: string,
  filePath: string,
  locale?: string
): Promise<{ error: string; status: number } | null> {
  const tErrors = getServerTranslations(locale ?? "en").errorsTranslations.file;
  const userContext = await PermissionsService.getUserContext(userId);
  if (userContext.isSuperAdmin) return null;
  if (userContext.permissions.includes(AppPermission.STORAGE_MANAGE)) return null;

  const usages = await StorageDbRepository.getFileUsages(filePath);
  if (usages.length === 0) {
    // Deny-by-default: an unlinked protected file must NOT be readable merely
    // because the caller is authenticated (IDOR guard, R-21).
    return { error: tErrors.forbidden, status: 403 };
  }
  if (usages.some(u => u.referenceTable === "users" && u.referenceId === userId)) {
    return null;
  }
  const entityUsages = usages.filter(
    (u): u is typeof u & { referenceTable: "teachers" | "parents" } =>
      u.referenceTable === "teachers" || u.referenceTable === "parents"
  );
  const entityChecks = entityUsages.map(u => checkUserAccessThroughEntity(userId, u.referenceTable, u.referenceId));
  const hasEntityAccess = (await Promise.all(entityChecks)).some(Boolean);
  if (hasEntityAccess) return null;
  return { error: tErrors.forbidden, status: 403 };
}
```

### M1 — Encrypt env-config secrets at rest

- **File:** `backend/services/system/environment-config.service.ts`
- **Lines:** 379–405 (`upsertEnvConfigOverride`) and the read path in `resolveEnvConfig` (lines ~183–203) plus `commitDbResolvedValue`.
- **Layer:** Service / system settings persistence
- **Problem:** `upsertEnvConfigOverride` writes `input.value` verbatim into `system_settings.value`. The `ENV_CONFIG_KEYS` registry marks dozens of keys `isSecret: true` (e.g., `RESEND_API_KEY`, `TWILIO_AUTH_TOKEN`, `FIXER_API_KEY`, meeting OAuth client secrets). Masking only happens on the GraphQL read path — the plaintext sits in the database, visible to anyone with DB access, backups, or log dumps.
- **Fix:** Encrypt with `encryptField()` (AES-256-GCM via `DATABASE_ENCRYPTION_KEY`) on upsert; decrypt on read. Mark the value with a prefix so legacy plaintext rows still function and can be rotationally migrated.

```typescript
// backend/services/system/environment-config.service.ts
import { decryptField, encryptField } from "@/backend/lib/field-encryption"; // ADD

const ENCRYPTED_PREFIX = "enc:v1:";

function encryptIfSecret(key: string, value: string): string {
  const descriptor = getDescriptorIndex().get(key);
  if (descriptor?.isSecret !== true) return value;
  return `${ENCRYPTED_PREFIX}${encryptField(value)}`;
}

function decryptIfSecret(value: string): string {
  if (!value.startsWith(ENCRYPTED_PREFIX)) return value; // legacy plaintext passthrough
  const decrypted = decryptField(value.slice(ENCRYPTED_PREFIX.length));
  return decrypted ?? "";
}

export async function upsertEnvConfigOverride(input: EnvConfigUpsertInput): Promise<EnvConfigUpsertReturnType> {
  const descriptor = getSettingsExposedDescriptor(input.key);
  if (descriptor === undefined) {
    throw new EnvConfigServiceError("ENOT_IN_REGISTRY", `Environment config key "${input.key}" is not in the registry.`);
  }
  const dbKey = toDbKey(input.key);
  const row = await SystemSettingsRepository.upsertSetting({
    key: dbKey,
    value: encryptIfSecret(input.key, input.value),                            // CHANGED
    dataType: SystemSettingDataType.String,
    description: descriptor.description.en,
    category: SystemSettingCategory.System,
    updatedByUserId: null,
  });
  invalidateEnvConfigCache(input.key);
  maybeInvalidateAppearanceCache(input.key);
  return { key: input.key, source: "db", hasDbOverride: true, updatedAt: row.updatedAt ?? new Date() };
}

async function resolveDbEligibleKey(key: string): Promise<ResolvedEntry> {
  const dbKey = toDbKey(key);
  let dbValue: string | undefined;
  try {
    const setting = await SystemSettingsRepository.getByKey(dbKey);
    if (setting?.value != null && setting.value !== "") {
      dbValue = setting.value;
    }
  } catch (error) {
    logger.warn(`env-config-service: DB lookup failed for key "${key}", falling back to process.env.`);
  }
  if (dbValue !== undefined) {
    const descriptor = getDescriptorIndex().get(key);
    const plaintextValue = descriptor?.isSecret === true ? decryptIfSecret(dbValue) : dbValue;  // CHANGED
    return { value: plaintextValue, source: "db", hasDbOverride: true };
  }
  const envValue = readFromProcessEnv(key);
  return { value: envValue, source: envValue ? "env" : "unset", hasDbOverride: false };
}
```

### M2 — Bound and rate-limit the client log ingestion endpoint

- **File:** `app/api/logs/route.ts`
- **Lines:** 124–156 (`POST` handler), plus top-of-file constants
- **Layer:** API route
- **Problem:** Once authenticated, a client can POST arbitrarily large `body.logs` arrays of unbounded-length messages, which the handler writes line-by-line into `logs/` on disk — a disk-exhaustion vector. No batch cap, no message-size cap, no rate limit.
- **Fix:**

```typescript
const MAX_BATCH_ENTRIES = 200;
const MAX_MESSAGE_LENGTH = 4000;

export async function POST(request: NextRequest) {
  const locale = request.headers.get("accept-language")?.split(",")[0]?.split("-")[0] ?? "ar";
  const tErrors = getServerTranslations(locale).errorsTranslations;

    return NextResponse.json({ error: tErrors.file.authenticationRequired }, { status: 401 });

    return NextResponse.json({ error: tErrors.rateLimitExceeded }, { status: 429 });
  }

  try {

    if (!isBatchLogRequest(rawBody)) {
      return NextResponse.json({ error: tErrors.invalidRequestFormat }, { status: 400 });

      }
      log.message = log.message.slice(0, MAX_MESSAGE_LENGTH);                     // ADD
      if (log.caller) log.caller = log.caller.slice(0, 512);                      // ADD
```

### M9 — Escape prefixes in cache repository LIKE queries

- **File:** `backend/db/repo/shared/cache.repository.ts`
- **Lines:** 92–152 (`updateExpiryByPrefix`, `deleteByPrefixAndScore`, `countByKeyPrefix`)
- **Layer:** Repository (cache persistence)
- **Problem:** Prefixes are interpolated into `LIKE '<prefix>%'` patterns inside `sql` template tags and are sometimes built from dynamic values (`ratelimit:` + identifier, email-derived auth keys). A value containing `%` or `_` escapes the intended prefix boundary; combined with delete-by-prefix this could cross-delete unrelated keys.

```typescript
// backend/db/repo/shared/cache.repository.ts
import { escapeLikeWildcards } from "@/backend/utils"; // ADD

const ESCAPE_SUFFIX = "e"; // drizzle template uses default escaping — we only need literal escaping done here

export const updateExpiryByPrefix = async (prefix: string, seconds: number): Promise<number> => {
  try {
    const table = getTable(prefix);
    const newExpiresAt = new Date(Date.now() + seconds * 1000);
    const safePrefix = escapeLikeWildcards(prefix);                                    // ADD
    const result = await db
      .update(table)
      .set({ expiresAt: newExpiresAt })
      .where(sql`${table.key} LIKE ${safePrefix + "%"}`)
      .returning({ key: table.key });
    return result.length;
  } catch (error) {
    logger.error(`Failed to update expiry for prefix ${prefix}:`, error);
    throw error;
  }
};

export const deleteByPrefixAndScore = async (prefix: string, maxScore: number): Promise<number> => {
  try {
    const table = getTable(prefix);
    const now = new Date();
    const safePrefix = escapeLikeWildcards(prefix);                                    // ADD
    const result = await db
      .delete(table)
      .where(
        and(
          sql`${table.key} LIKE ${safePrefix + "%"}`,
          sql`${table.value}::bigint <= ${BigInt(maxScore)}`,
          gte(table.expiresAt, now)
        )
      )
      .returning();
    return result.length;
  } catch (error) {
    logger.error(`Failed to delete cache entries for prefix ${prefix}:`, error);
    throw error;
  }
};

export const countByKeyPrefix = async (prefix: string): Promise<number> => {
  try {
    const table = getTable(prefix);

    const q = queryDb();
    const safePrefix = escapeLikeWildcards(prefix);                                    // ADD

      .select({ count: sql<number>`count(*)`.mapWith(Number) })
      .from(table)
      .where(sql`${table.key} LIKE ${safePrefix + "%"} AND ${table.expiresAt} > ${now}`);
```

### L8 — Sign pagination cursors

- **File:** `backend/db/repo/students/student.repository.ts`
- **Lines:** `decodeCursor` (~22–39) plus cursor emission in `processStudentQuery` (~97–103)
- **Problem:** Pagination cursors are unsigned base64 JSON — anyone can forge arbitrary offsets/windows. Low impact behind existing permission scoping, but trivially fixable.
- **Fix:**

```typescript
import { createHmac } from "node:crypto";

function signCursorPayload(payload: { createdAt: string; id: string }): string {
  const body = Buffer.from(JSON.stringify(payload)).toString("base64url");
  const sig = createHmac("sha256", process.env.JWT_SECRET ?? "").update(body).digest("base64url").slice(0, 32);
  return `${body}.${sig}`;
}

function decodeCursor(after: string): { createdAt: string; id: string } | null {
  const dot = after.lastIndexOf(".");
  if (dot <= 0) return null;
  const body = after.slice(0, dot);
  const sig = after.slice(dot + 1);
  const expected = createHmac("sha256", process.env.JWT_SECRET ?? "").update(body).digest("base64url").slice(0, 32);
  if (sig !== expected) return null;
  try {
    const parsed: unknown = JSON.parse(Buffer.from(body, "base64url").toString("utf8"));
    if (
      typeof parsed === "object" && parsed !== null &&
      "createdAt" in parsed && "id" in parsed &&
      typeof parsed.createdAt === "string" && typeof parsed.id === "string"
    ) {
      return { createdAt: parsed.createdAt, id: parsed.id };
    }
  } catch { /* fall through to null */ }
  return null;
}
```

## Risks & Refinements

- **R1 — GraphQL schema churn.** H4 (`STORAGE_MANAGE` on storage reads) and M6 (`notImpersonating`/`notSimulatingGroup` on demoLogin) change `authScopes` on public fields — any existing teacher/parent integration tests hitting `listFiles` will now 403. Land behind a feature flag or coordinate with affected frontend consumers before merge.

- **R2 — RLS cascade risk (V2).** If `app.current_user_id` is not being set, enabling more restrictive RLS later could silently break parent/teacher dashboards. Fix V2 before layering additional RLS policies.

- **R3 — Encrypted env values (M1).** The `enc:v1:` prefix requires `DATABASE_ENCRYPTION_KEY` to be stable across environments. A key rotation without decrypting existing rows bricks every DB-managed secret (Twilio, Resend, meeting OAuth). Add a key-rotation script alongside.

- **R4 — Transaction envelope (M7).** Wrapping profile updates in `db.transaction` requires threading `tx` through several services (`StaffProfileService`, `TeacherPortalService`, `ParentProfileService`, `UserRepository`) — some currently open their own transactions when `tx` is absent, so the threading must be exhaustive or the atomicity goal silently regresses.

- **R5 — Circular imports.** H4's service-side guard should import from `@/backend/services` barrel carefully — `storage.service.ts` appears in `services/index.ts`; adding new cross-service references can re-trigger existing circular-import warnings (see `backend/services/billing/quota.service.ts` ↔ `credit.service.ts` pattern for the failure mode).

- **R6 — Cursor signature format change (L8).** Existing client-stored cursors become invalid — this is acceptable (they're transient) but should be called out in release notes so frontend clears stale Apollo cache pages.

## Testing Strategy

- **H1 — LIKE escaping:** unit test `StudentFilterUtils.applyFilters` with inputs containing `%`, `_`, `\`. Assert Drizzle-generated SQL binds the pattern parameter and contains escaped wildcards.
- **H2 — FTS guard:** fuzz `fullTextSearch` with tsquery metacharacters (`'`, `"`, `:*`, `<->`, `!`, `@`, nested parentheses) — expect `null` or safe query, never a thrown DB error.
- **H3 — Auth fail-closed:** integration test with rate-limit store artificially failing (mock `RateLimitService.isLocked` to reject) — assert login returns an error, not success.
- **H4 — Storage reads:** GraphQL integration — teacher token calling `listFiles` must return FORBIDDEN; super admin must pass.
- **H5 — Unlinked files:** create a protected file with zero junction rows; assert a non-manager logged-in user receives 403 from `/api/storage/files/...`.
- **M1 — Secret round-trip:** upsert `RESEND_API_KEY`, assert DB row begins with `enc:v1:`, assert `resolveEnvConfig("RESEND_API_KEY")` returns the plaintext.
- **M2 — Log batching:** POST 10,000-entry batch → 400; POST with 1MB message → 400 / truncated; rapid-fire 50 bursts → 429.
- **M3 — APQ:** 10k unique query hashes → table growth bounded by TTL sweep; batched requests `[q1,q2]` are rejected with 400.
- **M5 — Status tracking:** seed 1000 rows for one day; assert query returns ≤ 500 and search executes in SQL (inspect query plan or row count).
- **M7 — Profile atomicity:** force `updateStatus` to throw mid-sequence (mock); assert no `staff`/`parent`/`core` changes persisted.
- **Regression sweeps:** full GraphQL smoke suite (`withPageAuth`-protected routes), invoice download flow (H5 affects `/api/storage/files`), impersonation + group simulation E2E (M10 touches audit paths).

New security tests to add: LIKE wildcard fuzz test, forged-cursor test, env-secret at-rest ciphertext test, APQ TTL eviction test.
