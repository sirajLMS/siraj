# 3. Backend Security Fixes — Implementation Plan

## HIGH Severity

### H1 — Remove hardcoded super-admin credentials from production migrations

- **File**: `backend/db/migration/4e-default_super_admin_seed.sql`
- **Line**: 1–13 (INSERT of `default_admin@example.com` with fixed bcrypt hash)
- **Layer**: Migration
- **Problem**: A production-applied migration creates a super-admin account with a publicly known password ("Seed_Pass1!" hash). Any environment running this migration exposes full system compromise.
- **Fix**: Gate the seed behind an explicit environment guard executed in the migrator; never run it in production. Instead, require `ADMIN_EMAIL`/`ADMIN_PASSWORD` env vars at first boot and create the admin there.

```ts
// backend/db/scripts/ensureMigrationsBeforeSeed.ts
import { getEnvironmentConfig } from "@/backend/lib/env";
import { logger } from "@/backend/lib/logger";

export async function ensureMigrationsBeforeSeed(): Promise<void> {
  const env = getEnvironmentConfig();
  const isDemoOrTest = env.isDemo === true || process.env.TEST_SERVER === "1";
  if (!isDemoOrTest && process.env.NODE_ENV === "production") {
    logger.warn("[seed] Skipping default super-admin seed in production.");
    return;
  }
  // ... existing bootstrap
}
```

And in the SQL file, comment the header:

```sql
-- ⚠️ DEV/TEST ONLY. This migration MUST NOT be applied to production databases.
-- Production admin bootstrap is handled by env-driven bootstrap (ADMIN_EMAIL/ADMIN_PASSWORD)
-- in backend/db/scripts/ensureMigrationsBeforeSeed.ts.
```

- **Validation**: CI test asserting the migration folder is excluded from the migration set when `NODE_ENV=production`.

### H2 — Fail-closed production env validation

- **File**: `backend/lib/env.ts`
- **Line**: `validateRequiredAppSecret`, `validateNoPlaceholderSecrets`, `validateEnvironment`
- **Layer**: Config
- **Problem**: Required app secrets (`JWT_SECRET`, `DATABASE_ENCRYPTION_KEY`, `ADMIN_PASSWORD`) must throw in production when missing or placeholder-like. Warn-and-continue paths must not exist in prod.
- **Fix**:

```ts
// backend/lib/env.ts
function validateRequiredAppSecret(name: string): string {
  const value = process.env[name];
  const isProd = process.env.NODE_ENV === "production";
  const isPlaceholder = !value || value.length < 16 || /<|>/.test(value);
  if (isProd && isPlaceholder) {
    throw new Error(`[env] Missing or invalid required secret: ${name}`);
  }
  if (isPlaceholder) {
    logger.warn(`[env] ${name} is not set; using development fallback.`);
    return "";
  }
  return value;
}
```

Also extend `validateDatabaseUrlForVercel` to fail build-time on missing `JWT_SECRET`/`DATABASE_ENCRYPTION_KEY` when `VERCEL_ENV === "production"`.

### H3 — Harden `getIpAddress` for INET columns + IPv6

- **File**: `backend/graphql/gqlContextFactory.ts` AND `backend/lib/ip-utils.ts`
- **Layer**: GraphQL context / utils
- **Problem**: Fingerprint fallback strings must never reach the INET-typed `auth_rate_limits.ip_address` column; IPv6 must not be mangled by naive colon-splitting.
- **Fix**:

```ts
// backend/lib/ip-utils.ts
import { isIP } from "node:net";

export function sanitizeIpAddress(ip: string | null | undefined): string | null {
  if (!ip) return null;
  const v = isIP(ip);
  if (v === 0) return null;
  return ip; // already a valid IPv4 or IPv6 literal
}

export function ipForInetColumn(ip: string | null | undefined): string {
  const clean = sanitizeIpAddress(ip);
  return clean ?? "127.0.0.1"; // safe INET-typed fallback
}
```

And in `gqlContextFactory.getIpAddress`:

```ts
// Prefer platform-trusted headers only on those platforms;
// strip ":port" ONLY for IPv4; keep IPv6 intact.
const raw = headersList.get("x-forwarded-for")?.split(",")[0]?.trim()
  ?? headersList.get("x-real-ip")
  ?? undefined;
const ip = sanitizeIpAddress(raw);
if (ip) return ip;
// fingerprint fallback — NEVER store into INET columns; prefix for clarity
const fingerprint = createHash("sha256")
  .update(`${headersList.get("user-agent")}|${headersList.get("accept-language")}`)
  .digest("hex")
  .slice(0, 32);
return `fp:${fingerprint}`;
```

Then ensure rate-limit writes call `ipForInetColumn(...)` only for the DB `auth_rate_limits` insert, and keep the fingerprint variant only in the cache key.

### H4 — Harden storage file-serving against path traversal

- **File**: `app/api/storage/files/[[...path]]/route.ts`
- **Layer**: API route
- **Problem**: `relativePath` must be normalized and constrained to the storage root before any auth/access checks.
- **Fix**:

```ts
import path from "node:path";

const STORAGE_ROOT = path.resolve(getLocalStorageBasePath());

function resolveSafePath(relativePath: string): string | null {
  const decoded = decodeURIComponent(relativePath);
  const normalized = path.normalize(decoded).replace(/^([/\\])+/, "");
  const abs = path.resolve(STORAGE_ROOT, normalized);
  if (!abs.startsWith(STORAGE_ROOT + path.sep)) return null;
  return abs;
}

// in GET handler:
const absPath = resolveSafePath(relativePath);
if (!absPath) return NextResponse.json({ error: "Invalid path" }, { status: 400 });
const isPublic = normalized.startsWith("public/");
```

## Risks & Refinements

- **R1**: Removing the seeded super-admin may break local dev onboarding — provide an explicit `bun run bootstrap:admin` script gated on non-prod.
- **R2**: H3's fingerprint prefix (`fp:`) will break the `auth_rate_limits` INET insert if accidentally passed; keep `ipForInetColumn` as the single choke point.
- **R3**: H4 normalization may break existing stored paths containing special characters — add a one-time validation scan of `storage_files.path` before deploying.
- **R4**: M1 session-binding may break legitimate flows where OAuth is initiated on one device and completed on another; accept this tradeoff (log a warning).
