## API Design

The extended `createTabbedPanePanels` factory now supports both permission-gated panels (via `permissions`) and inline permission callbacks (via `canRender`):

```typescript
export const BillingTabPanels = createTabbedPanePanels<BillingTabId>({
  useVisitedTabs: () => useBillingTabsStore(state => state.visitedTabs),
  ariaIdPrefix: "billing",
  panels: [
    { id: "overview", permissions: PAGE_PERMISSIONS.billingOverview, Component: LazyOverviewTab },
    { id: "invoices", permissions: PAGE_PERMISSIONS.billingInvoices, Component: LazyInvoicesTab },
    // ...
  ],
});
```

- `permissions?: PagePermission` — wraps content in `<RequirePermission>` with `fallback={null}`
- `canRender?: () => boolean` — inline gate (pre-existing; backward compatible)
- `ariaIdPrefix: string` — generates `{prefix}-tabpanel-{id}` / `{prefix}-tab-{id}` aria ids

## Behavioral Equivalence

The refactored components preserve all behavioral characteristics:

1. **Visited tabs stay mounted** — inactive panels use `visibility:hidden + height:0 + position:absolute` (not `display:none`) so DataGrid widths persist
2. **Lazy loading** — each tab component is lazy-loaded via `next/dynamic` at module scope
3. **Suspense boundary** — shared `TabPanelFallback` (CircularProgress) while tab chunks load
4. **Permission gating** — `RequirePermission` with `fallback={null}` suppresses unauthorized panels
5. **Aria attributes** — `role="tabpanel"`, `id`, `aria-labelledby`, `aria-hidden` all preserved with matching prefix patterns
6. **Zustand store subscription** — `visitedTabs` record read via per-domain store hook
