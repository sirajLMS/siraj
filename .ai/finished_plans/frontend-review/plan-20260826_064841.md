## 3.2 — Security: Snapshot Cache Function-Eval Removal

### Task 3.3 — Eliminate `Function` Constructor from Translation Snapshot Reviver

**File:** `shared/locale/client/snapshot-cache.ts` (lines 34–49, and read path at line 77)

Diff (target):

```diff
-export function reviver(_key: string, val: unknown): unknown {
-  if (val && typeof val === "object" && FN_PROP in val) {
-    const fnValue = val[FN_PROP as keyof typeof val];
-    if (typeof fnValue === "string") {
-      try {
-        const fnObj: unknown = Reflect.construct(globalThis.Function, [`return (${fnValue})`]);
-        if (typeof fnObj === "function") { return fnObj(); }
-      } catch { return val; }
-    }
-  }
-  return val;
-}
+export function reviver(_key: string, val: unknown): unknown {
+  // forbid poisoned function payloads: labels with functions must be
+  // re-derived from the compile-time namespace loader, never from cache.
+  if (val && typeof val === "object" && FN_PROP in val) {
+    return undefined;
+  }
+  return val;
+}
```

Also: in `readSnapshot`, if any parsed top-level subtree returns `undefined` from the reviver, discard the whole snapshot and fall through to `config.load[locale]()` (fail-closed).

Mock IndexedDB via fake-indexeddb if already a repo devDependency — otherwise guard behind capability check as the current code does
- [ ] 3.3.SEC **Security & Tenancy Audit**: Threat-model note — IndexedDB tampering can no longer yield code execution; verify no other code path depends on function-materializing revive (search for `FN_PROP` consumers; `writeSnapshot` never serializes functions — confirm by test)
