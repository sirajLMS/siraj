# Task 3.2 Outcome: DataLoader Refactoring (parents Domain)

**Date:** 2026-07-31  
**Task:** 3.2 Fix N+1 Patterns in parents GraphQL Domain  
**Status:** ✅ Completed

---

## Summary

Pre-computed `displayAmount`, `meetingJoinUrl`, and `effectiveMeeting` fields in the service layer for the `parents` GraphQL domain. Changed Pothos field definitions from resolver-based `t.field()` / `t.string()` to `t.expose()` / `t.exposeString()`, eliminating N+1 per-field resolver calls.

---

## Changes Made

### 1. Type Layer — `backend/types/parents/parent.types.ts`

- Added `displayAmount?: DisplayAmountReturnType | null` to `ParentProfileResult`
- Added `effectiveMeeting?: EffectiveMeetingReturnType` to `ParentDashboardScheduleRow`
- Added imports for `DisplayAmountReturnType` and `EffectiveMeetingReturnType`

### 2. Service Layer — `backend/services/parent/parent-profile.service.ts`

- Imported `FxDisplayService` and `CurrencyCode`
- Modified `toParentProfileResult()` to pre-compute `displayAmount` using `FxDisplayService.convertForDisplay()` with the profile's own `feeAmount`, `currency`, and `displayCurrency`
- `getProfile()` now returns `ParentProfileResult` with pre-computed `displayAmount`

**Before:** `displayAmount` resolved per-field via `resolveDisplayAmountField(parent, ctx, "feeAmount", "currency", parent.userId)` in Pothos resolver  
**After:** `displayAmount` pre-computed in `toParentProfileResult()` using profile's own `displayCurrency`

### 3. Service Layer — `backend/services/parent/parent-dashboard.service.ts`

- Imported `EffectiveMeetingService`
- Modified `getSchedule()` to batch-resolve `effectiveMeeting` for all schedule rows via `Promise.all()`, then pre-populate `meetingJoinUrl` and `effectiveMeeting` on each row

**Before:** `meetingJoinUrl` and `effectiveMeeting` resolved per-row-per-field by separate Pothos `t.string()` and `t.field()` resolvers  
**After:** Both fields pre-computed once per query in the service layer

### 4. Pothos Layer — `backend/graphql/pothos/parents/parent-profile.pothos.ts`

- Changed `displayAmount` from `t.field()` with resolver to `t.expose("displayAmount", { type: DisplayAmountPothosObject, nullable: true })`
- Removed unused import: `resolveDisplayAmountField`

### 5. Pothos Layer — `backend/graphql/pothos/parents/parent-dashboard.pothos.ts`

- Changed `meetingJoinUrl` from `t.string()` with async resolver to `t.exposeString("meetingJoinUrl", { nullable: true, deprecationReason: "..." })`
- Changed `effectiveMeeting` from `t.field()` with resolver to `t.expose("effectiveMeeting", { type: EffectiveMeetingPothosObject })`
- Removed unused imports: `resolveEffectiveMeetingForClassInstanceFromContext`

---

## N+1 Reduction

| Field | Before | After |
|---|---|---|
| `displayAmount` (ParentProfile) | 1 call to `resolveDisplayAmountField` + 1 DB query per parent per field | Pre-computed once per query (uses `profile.displayCurrency`) |
| `meetingJoinUrl` (ParentDashboardScheduleRow) | 1 call to `resolveEffectiveMeetingForClassInstanceFromContext` per row per field | Pre-computed per row once (via `Promise.all` in service) |
| `effectiveMeeting` (ParentDashboardScheduleRow) | 1 call to `resolveEffectiveMeetingForClassInstanceFromContext` per row per field | Pre-computed per row once (shared with `meetingJoinUrl` above) |

### Key Caveats
- **`displayAmount` uses profile's own `displayCurrency`**: The service uses `profile.displayCurrency` rather than the viewer's context-based display currency from `ctx.billingFxDisplayCurrency`. The original resolver also relied on `billingFxDisplayCurrencyByUserId` mapping the subject's own display currency, so this is equivalent.
- **`effectiveMeeting` is still N queries per row**: Each row's `resolveForClassInstance()` involves cascade of meeting config lookups (class default → recurring default → teacher default). Full batching would require a bulk `resolveForClassInstances(ids[])` method — left for future optimization.
