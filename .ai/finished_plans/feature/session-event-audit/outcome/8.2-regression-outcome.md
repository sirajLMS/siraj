## Fixes applied (plan-caused workflow failures)

Both failures in the first `test:workflows` run were in this plan's own journey test files
(`test/workflows/accounting/session-audit-*.test.ts`) — they had drifted out of sync with
intentional fix-wave changes, not with other plans' in-flight work.

1. **`test/workflows/accounting/session-audit-access-isolation.test.ts` — step 4** failed with
   - Expected: logged `filters` equal the caller's raw object `{ teacherId, studentId }`.
   - Received: logged object additionally carried `dateFrom`/`dateTo`.
   - Root cause: fix wave 3 (review MEDIUM #5) added the spec-mandated (AC-4.6) default
     last-30-days window in `SessionAuditService.getReport` (`withDefaultDateRange`, added by
     `fix-r-backend-outcome.md`); the service now logs the **resolved** filters. The journey
     still asserted the raw caller object.
   - Fix: step 4 now pins the fixture window explicitly (`dateFrom: DAY_ONE, dateTo: DAY_TWO`),
     so resolved filters equal caller filters and the identity assertion holds.
   - Hardening in the same file: steps 1, 2 (both reads), and 3 previously relied on the default
     window covering the hardcoded fixture days `DAY_ONE = 2026-08-10` / `DAY_TWO = 2026-08-11`;
     that assumption silently breaks once the window slides past the fixtures (≈2026-09-10).
     All fixture-read steps now pass the explicit bounds; step 5's export-shaped read also pins
     the window so its `totalCount ≥ cast size` invariant survives window drift.

2. **`test/workflows/accounting/session-audit-payroll-visibility.test.ts` — step 5** failed with
   `CSV export does not contain instance <id>`.
   - Root cause: the serializer's canonical column layout (AC-8.3) puts the join-back id columns
     (`teacherId`, `studentId`, `instanceId`) **last**; the journey's `csvLineFor` helper still
     assumed `instanceId` is the leading cell (`startsWith(`${instanceId},`)`).
   - Fix: `csvLineFor` now matches the trailing cell (`endsWith(`,${instanceId}`)`).

Verification after fixes: `bun run test:workflows` → `98 pass, 0 fail` (exit 0), and
`scripts/health/sub-loop.ts --lifecycle lint` on both edited journey files → both exit 0.
