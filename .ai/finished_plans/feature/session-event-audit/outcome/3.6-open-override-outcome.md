# Task 3.6 — Audit drawer `?openOverride` deep link

**Date:** 2026-09-04 · Files touched: `frontend/common/views/dashboard/classes/audit/ClassAuditContainer.tsx` (edited), `frontend/common/views/dashboard/classes/audit/ClassAuditContainer.test.tsx` (new).

## What landed

`ClassAuditContainer` now honors the `?openOverride=…` deep link produced by
the reports grid's "Open audit page" row action:

- A new `useOpenOverrideDeepLink()` hook (module-local to the container, in
  `frontend/common/views/dashboard/classes/audit/ClassAuditContainer.tsx`)
  reads `useSearchParams().get("openOverride")`. Truthiness is the contract
  per trackable-tasks 3.6 (the producer emits `?openOverride=1`).
- **Gating:** the open fires only when `useUserStore(state => state.hasPermission)(
  AppPermission.AccountingPayrollManage)` is true — i.e. the
  `ACCOUNTING_PAYROLL_MANAGE` permission (Plan 3), a UX-level gate per
  `docs/auth/permission-architecture.md` (the `applyPayrollOverride` mutation
  re-checks the same permission server-side via `authScopes`).
- **Store method used:** `useClassDetailsStore.getState().openOverrideDialog`
  via `useClassDetailsStore(state => state.openOverrideDialog)` — the exact
  reuse target verified in `outcome/0.3-plan3-prereqs-outcome.md` §4
  (`frontend/common/stores/classDetailsStore.ts:46`, consumed by
  `frontend/common/views/dashboard/classes/details/hooks/useClassDetailsViewModel.ts:319`).
  Called as `openOverrideDialog("", null)`: opening the dialog re-seeds the
  form from its arguments, and the instance snapshot is still query-loading at
  mount, so the form starts blank rather than with a stale leaked edit.
- **URL cleanup:** after consuming the param, `stripOpenOverrideParam()`
  removes it with `window.history.replaceState` (no client navigation),
  mirroring the established precedent in
  `frontend/common/views/dashboard/profile/shared/meeting-configs/OAuthCallbackHandler.tsx:33-43`.
  Other query params are preserved; if none remain the `?` is dropped
  entirely. The param is stripped when present regardless of permission, so
  the deep link is single-shot (a refresh or copied URL never re-fires it).
- The hook runs in a `useEffect` keyed on
  `[isDeepLinkRequested, canManagePayroll, openOverrideDialog]`, so it fires
  once on mount and never re-opens after the user closes the dialog.

Resolves deferred item **D3** in `deferred-items.md` (container previously had
zero searchParams handling; the `useClassDetailsStore.openOverrideDialog`
reuse target is now wired). The ledger row itself is left for the orchestrator.

Four cases cover the task bullets plus URL hygiene:

1. `?openOverride=1` + `AccountingPayrollManage` →
   `useClassDetailsStore.getState().overrideDialogOpen === true`.
2. `?openOverride=1&other=kept` + manage → `window.location.search` becomes
   `"?other=kept"` (param stripped, no navigation, other params preserved).
3. No param + manage → dialog stays closed.
4. `?openOverride=1` without the permission → dialog stays closed and the
   param is still stripped (single-shot consumption).

`useUserStore` permissions, and restores the URL so cases stay isolated.
