## Endpoint contract (for the frontend CSV button + E2E agent)

**URL:** `GET /api/accounting/reports/export`

### Query parameters (all optional)

| Param | Type | Validation | Behaviour |
|---|---|---|---|
| `teacherId` | string | trimmed, blank → unset | equality filter on the teacher |
| `studentId` | string | trimmed, blank → unset | equality filter on the student |
| `dateFrom` / `dateTo` | `YYYY-MM-DD` | strict calendar-date check (rejects `2026-02-30`); `dateFrom > dateTo` rejected by the service (`INVALID_DATE_RANGE`) | inclusive scheduled-start bounds |
| `currentStatuses` | repeatable and/or comma-separated (`?currentStatuses=open&currentStatuses=end,Absent`) | each value must be one of `open`, `end`, `Absent`, `absent_student` | status multi-filter |
| `search` | string | max 200 chars | case-insensitive substring on teacher/student names |
| `includeDeleted` | `"true"` / `"false"` (absent → false) | other values → 400 | `true` passes through **only** when the caller holds `ACCOUNTING_REPORTS_MANAGE`; otherwise silently cleared to `false` |
| `sortField` + `sortDirection` | paired; fields: `scheduledStartAt`, `scheduledEndAt`, `actualStartAt`, `actualEndAt`, `durationMinutes`, `calculatedDuration`, `teacherPaidAmount`, `calculationStatus`, `teacherName`, `studentName`; direction `asc` \| `desc` | partial pair or unknown value → 400 | pair absent → `sort: null` (service default `scheduledStartAt desc`) |

### Response — success (200)

- `Content-Type: text/csv; charset=utf-8`
- `Content-Disposition: attachment; filename="session-audit-report.csv"` (fixed name, per implementation.md §4.3 — **no date suffix**, unlike the payroll export)
- `X-Export-Truncated: "true"` when `totalCount > 10_000`, otherwise `"false"` (header always present)
- Body: 22-column CSV (CRLF lines, trailing CRLF) — exact column order + header labels from outcome `1.5-csv-serializer-outcome.md` (grid visual order, ids last, per the post-review fix). Header line:

```
scheduledStartAt,scheduledEndAt,teacherName,studentName,subjectName,subjectId,actualStartAt,actualEndAt,bookingTimezone,durationMinutes,currentStatus,calculatedDuration,teacherPaidAmount,teacherPaidCurrency,calculationStatus,isPartialPercentage,payrollNote,payrollCalculatedAt,teacherDuePaymentDate,teacherId,studentId,instanceId
```

### Error-status mapping

| Condition | Status | Body | Source |
|---|---|---|---|
| No authenticated session | `401` | `{ error: tErrors.unauthorized }` | `getServerUserContext()` returns no `userId` |
| Missing `ACCOUNTING_REPORTS_VIEW` | `403` | `{ error: tErrors.insufficientPermissions }` | `requirePermission` throws `ForbiddenError` |
| Malformed params (bad date / unknown status / over-long search / half sort pair / unknown sort field / non-boolean `includeDeleted`) | `400` | `{ error: tErrors.invalidInput }` | route-local validation throws `ValidationError` |
| `dateFrom > dateTo` (or a malformed date that slips past route validation) | `400` | `{ error: tErrors.invalidInput }` | `SessionAuditService` throws `ValidationError("INVALID_DATE_RANGE", …)` |
| Unexpected failure | `500` | `{ error: tErrors.internalServerError }` | logged via `logger.error` |

Locale for error messages comes from the `accept-language` header (first tag, primary subtag; falls back to `ar`), resolved via `getServerTranslations(locale).errorsTranslations` from `@/shared/locale/server-graphql` (per root AGENTS.md i18n rule for API routes).

### Service call

```ts
SessionAuditService.getReport(userId, filters, sort, { limit: 10_000, offset: 0 }, tErrors);
serializeSessionAuditCsv(report.rows);
```

The route also emits `logger.info("Session audit CSV export", { actorUserId, filters, sort, rowCount, truncated })` on every successful export (NFR-11), complementing the service's own query log.

Post-review (see `fix-r-backend-outcome.md`): an export with no `dateFrom`/`dateTo` params now runs against the service's default 30-day window (UTC calendar days ending today) — the route passes absent dates as `null` and the service resolves the bounds, so the exact window appears in the service log, not the route's.

## Deviations / decisions

1. **`hasPermission` gating of `includeDeleted`**: the route (not the service) clears `includeDeleted` for view-only callers, because the `SessionAuditReportFilters` type documents this as a caller-facing rule and the service signature exposes no second permission check. Uses `PermissionsService.hasPermission(userId, AppPermission.ACCOUNTING_REPORTS_MANAGE)`; skipped entirely when `includeDeleted` isn't requested.
2. **`sortField`/`sortDirection` are both required together** — a half pair is a client bug, so it rejects with 400 instead of silently ignoring (documented above).
3. **Fixed filename** `session-audit-report.csv` per implementation.md §4.3 (payroll's date-stamped filename was not copied).
4. Initial oxlint run flagged two `no-unsafe-type-assertion` warnings; fixed with `isSessionAuditStatus` / `isSortField` type guards (no assertions remain).
