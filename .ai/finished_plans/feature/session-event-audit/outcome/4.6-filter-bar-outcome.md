## Composition notes (what the container agent passes)

- **Person pickers**: the existing `TeacherAutocomplete` / `StudentAutocomplete` from
  `@/frontend/common/components/ui/input/userSelect`, plus `AppDateRangePicker` from
  `@/frontend/common/components/ui/form/date`. Because the store carries only ids, the
  bar keeps the freshly picked option in local state and falls back to a display option
  built from the loaded report `rows` when the stored id is a URL-hydration remnant
  (the `findRowPersonOption` bridge — same contract as the payroll filter bar).
- **Status multi-select**: MUI `Select multiple` over the codegen `SessionAuditStatus`
  enum (`Object.values` order), labels from `labels.status` (wire values are the label
  keys verbatim, including `Absent` and `absent_student`); collapsed preview = up to 2
  status chips then a `+N` chip; empty selection shows `filters.all`.
- **Search**: plain `TextField` wired to the raw `search`/`setSearch` pair with a
  `SearchOutlined` start adornment and 200-char cap; debouncing (300 ms) stays in the
  view model, so the input never lags keystrokes.
- **Date range**: `AppDateRangePicker` (`fromDate`/`toDate` empty-string ↔ `null`
  conversion at the boundary). An inverted range (`dateFrom > dateTo`) renders
  `FormHelperText` with `error.dateRangeInvalid` under the picker — the store
  deliberately never drops inverted ranges on hydration, so this is where the copy
  surfaces.
- **Clear filters**: `Tooltip` + `IconButton` (`ClearOutlined`, `aria-label` =
  `filters.clear`) rendered only when `hasActiveFilters` is true.
- **Responsiveness**: single `Stack` with `direction: { xs: "column", md: "row" }`,
  wrap, and full-width controls on `xs` — the same collapse pattern as the payroll
  and settings filter bars (controls stack vertically with `xs: "100%"` widths).
- **Labeling (Task 7.2)**: every control is labeled — MUI `label`/`InputLabel` +
  `labelId` on the pickers and select, `htmlInput aria-label` on the search box,
  `aria-label` on the clear button.
- Prototype `01-full-reports-session-audit-grid-en.png` reviewed once (toolbar row:
  teacher, student, date range, status, search, clear button). The prototype's red
  "Clear Filters" text button was intentionally not copied: theme rules forbid
  hardcoded color emphasis, so the icon-button + tooltip affordance from the
  established payroll filter bar is used instead. All prototype row data ignored.
