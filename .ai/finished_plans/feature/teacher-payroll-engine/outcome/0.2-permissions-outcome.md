# Task 0.2 Outcome — `ACCOUNTING_PAYROLL_VIEW` + `ACCOUNTING_PAYROLL_MANAGE` permissions

## Summary

Added the two payroll permissions end-to-end: TypeScript enum values
(`accounting.payroll_view` / `accounting.payroll_manage`), an idempotent custom SQL
migration (enum values + `permissions` rows + group grants), the auto-bundled drizzle
migration folder + sidecar update, and enum test coverage asserting both new values
define, parse (`isAppPermission`), and resolve (`parseAppPermission`) correctly — plus a
payroll-typo rejection assertion.

Grants follow the repo precedent for every `accounting.*` manage permission
(`33-accounting-permissions-and-enums.sql`, `35-accounting-credits-permission.sql`):
**`super_admin` + `academy_admin` only**. There is no dedicated "Accounting" /
"Finance Manager" permission group in this system (full slug set: `super_admin`,
`academy_admin`, `teacher_default`, `parent_default`, `staff_default`, `system_automated`,
`supervisor_default`, `student_default`) — the admin groups are the ones that own all
`accounting.*` / `billing.*` manage permissions. `payroll_view` is intentionally NOT
granted to `staff_default` (unlike `payments_view` in migration 33) because teacher
payroll data is salary-sensitive; read-only auditors get view-only access via per-user
overrides, per the implementation spec's separation rationale.
