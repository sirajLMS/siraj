## Container contract

- `ExpensesViewProps = ExpensesViewModel & ExpensesDialogCallbacks & { onOpenDrawer }` — exported from the container; both tier views consume it (carryover `CarryoverViewProps` convention).
- Overlay state is a single discriminated union (`form` / `delete` / `drawer`), so exactly one overlay is open at a time and row snapshots survive until close.
- `onDone` after every successful delete (single or bulk) → `clearSelection()`; the form dialog is excluded because its own cache eviction refetches and a saved row stays valid (carryover convention).
- Row `onOpenDelete` ⇒ single row → `DeleteExpenseDialog`; toolbar Bulk Delete (2+ rows) ⇒ `BulkDeleteExpensesDialog`. The grid resolves the selected rows from the current page itself (`selectedVisibleRows`), so the container needs no `selectedRows` resolution (unlike carryover, whose bulk-to-expense modal needed it).
- `onOpenDrawer` guards against a null row id. The desktop grid has no drawer affordance (row menu is Edit / Delete / View Source by design, 4.6); the mobile tier opens the drawer on card tap, and both tiers deep-link via `/accounting/expenses/[id]`.
- No separate `actionsMenuLabel` injection: the expenses namespace already carries `column.actions`, which the grid uses for its row-menu aria-label and the mobile view reuses for its card-menu aria-label (carryover needed it only because its `CarryoverLabels` lacked the key).

## ExpenseSourceChip wiring (task item 4)

Per outcomes 4.5 / 5.4, `onViewSource(sourceEntityId)` = `router.push("/accounting/carryover/<id>")` — the carryover `[id]` deep-link route that opens `CarryoverDetailDrawer`. One shared handler shape in the container serves the grid's View Source menu item and the chip column; `ExpenseDetailDrawer` carries the same push internally, so grid, drawer, and mobile never diverge. The `ExpenseSourceChip` itself only fires for `sourceEntity = carryover_balances` with a non-null id (4.5 leaf rule); mobile cards render the chip presentational-only (no click) to avoid nested interactive elements inside the card tap target.
