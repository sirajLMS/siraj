## Spec contents (5 tests)

1. **Locale snapshots** — `dashboard.accounting.expenses.json` exists under
   `public/static/locale-snapshots/{en,ar}/`.
2. **Operator with permission** (`DEMO_USERS.academyAdmin`, VIEW+MANAGE) —
   `/accounting/expenses` renders; toolbar ids `expenses-add-new`,
   `expenses-bulk-delete`, `expenses-export-csv`; sidebar nav item
   (`coreNav.accountingExpenses`) present. **RTL assertion**: the page renders
   under the default Arabic locale, so `<html dir="rtl">` is asserted.
3. **VIEW-only pass** — builds a genuine view-only actor: a run-scoped custom
   permission group with exactly `accounting.expenses_view` is created via the
   real GraphQL management mutations (`createPermissionGroup`,
   `assignPermissionGroupToUser` — academy admin holds
   `permission_groups.manage`/`assign`) and assigned to the demo teacher (whose
   seeded roles carry no accounting permissions); `demoLogin` resolves the
   teacher as the group's sole member (`loginDemoUser` /
   `loginAsDemoUserAtRoute` both accept arbitrary group slugs). Asserts: page +
   nav item render, Export CSV visible, Add New / Bulk Delete / row checkboxes
   all absent, and the CSV export itself succeeds. Cleanup revokes the
   membership and deletes the group in `finally` (report.test.ts convention).
   Necessary because migration `44-accounting-expenses-permissions.sql` grants
   the expense permissions to `super_admin`/`academy_admin` only — no seeded
   demo group is view-only, and every sibling E2E ("user without permission")
   covers only the fully-denied side.
4. **Denied-role pass** (`DEMO_USERS.teacher`) — redirected away from
   `/accounting/expenses`, sidebar item absent, plus the CSV route gates:
   403 for the teacher session (via `context.request`, cookie-sharing
   Playwright API context) and 401 for an anonymous `fetch`.
5. **Operator flow** (single big serial test, `finally`-guarded cleanup):
   - **Carryover settlement leg** (board `/accounting/carryover`): create one
     carryover via the Add New form (teacher option 0 — name read back from
     the autocomplete input; currency option 0; today as from/to; per-run
     `studentsText` token `E2EEX-<run>-C`; payable `450 + now%200`), then Bulk
     To Expense (payment date today) → Paid chip. Record id captured from the
     grid row's `data-id` (the grid's `getRowId = row.id`).
   - **Ledger leg** (`/accounting/expenses`):
     - **Create 2 expenses via the UI form** — Marketing (`E2EEX-<run>-A`,
       note token) and Logistics (`-B`): title, type combobox (the Salaries
       option is asserted `aria-disabled` before picking), numeric value,
       currency autocomplete, masked payment-date + masked year-month helpers,
       `success.created` toast each.
     - **Edit 1** — row menu Edit on `-A` → `titleEdit` dialog → retitle to
       `-AE` + new value → `success.updated`.
     - **Protected Salaries row rejection (single delete)** — row menu Delete
       on the carryover-backed row (located by teacher-name + Salaries chip):
       `EXPENSE_DELETE_VIA_UNPAY` keeps the dialog open with the in-dialog
       `role="alert"` banner (`errors.expenses.deleteViaUnpay`) and the
       confirm disabled; cancelled.
     - **Protected Salaries row rejection (bulk delete)** — select salaries +
       `-B` → Bulk Delete dialog (`modal.bulkDelete.title(2)`) → confirm → the
       atomic batch rejects with the server-localized
       `errors.expenses.deleteViaUnpay` toast, dialog stays open; cancelled.
       Both rows remain.
     - **Unpay-via-carryover surface** — salaries row menu View Source →
       `/accounting/carryover/<id>` deep link; the CarryoverDetailDrawer opens
       pre-expanded (RTL assertion: the `.MuiDrawer-paper` bounding box anchors
       left of the half-viewport), footer Unpay → confirm dialog →
       `success.unpaid` toast → drawer refetches and the paid-only Unpay
       footer disappears.
     - **Soft-deleted row surfaces** — back on the ledger, the salaries row is
       absent under the default filter (polled), then `filters.includeDeleted`
       toggle → row visible again with the `deletedBadge` chip.
     - **CSV download assertions** — filename `expenses-<YYYY-MM-DD>.csv`; the
       fixed 19-column header contract asserted verbatim; row `-AE` (Marketing,
       `<editedValue>.00`, note token, empty sourceEntity/deletedAt, today's
       paymentDate, current `YYYY-MM` expenseDate); row `-B` (Logistics, value,
       empty provenance/deletedAt); salaries row found by
       `sourceEntityId = <carryoverId>` (type `Salaries`,
       `sourceEntity = carryover_balances`, teacher snapshot name, payment
       date, **non-empty `deletedAt`**). Enum labels come from the shared
       `ExpenseType` enum, the provenance marker from
       `EXPENSE_SOURCE_CARRYOVER_BALANCES` — no hardcoded data strings.
   - **Cleanup** — bulk-delete the two manual expenses through the toolbar
     dialog (single-row fallback uses the single-delete dialog contract), then
     on the carryover board: Unpay if still Paid, then Delete the carryover
     row. Failures log via `testLogger` and never mask the flow result.

## DESIGN DECISION: no demo preconditions for the flow

The spec seeds everything it asserts through UI flows only (carryover Add New
+ Bulk To Expense on the carryover board), because the demo dataset holds no
expense rows at all (`backend/db/seeds` has no expenses fixtures) — the
carryover 8.1 spec made the same call for its manual records. The only demo
preconditions are the teacher/currency autocompletes needing ≥ 1 option each.
