## Deliverable

`frontend/common/stores/expenseFilterStore.ts` (new, 126 lines) — flat
non-persisted Zustand store mirroring `carryoverFilterStore.ts` /
`payrollReportsFilterStore.ts` conventions, per implementation.md §5.5/§5.7.

- **State**: `title` (raw text; consumers debounce 300 ms before querying),
  `types` (`readonly ExpenseType[]`, codegen enum from
  `@/frontend/common/graphql/generated/gql/graphql`), `expenseDate`
  (`YYYY-MM`, null = all months), `paymentDateFrom` / `paymentDateTo`
  (ISO `YYYY-MM-DD`, inclusive bounds), `includeDeleted` (boolean, default
  off per §5.5), `page` (0-based), `pageSize` (default 50 =
  resolver convention, exported as `EXPENSE_DEFAULT_PAGE_SIZE`),
  `selectedIds` (`readonly string[]`).
- **Actions**: `setTitle`, `setTypes`, `setExpenseDate`,
  `setPaymentDateFrom`, `setPaymentDateTo`, `setIncludeDeleted`, `setPage`,
  `setPageSize`, `toggleSelected(id)`, `clearSelection()`, `clearFilters()`,
  `reset()`.
- **Semantics** (mirroring carryover precedent): every filter setter resets
  `page` to 0; `setPage` clamps to a non-negative integer; `setPageSize`
  clamps to ≥1 and resets the page; `clearFilters()` restores default filters
  + page 0 and **clears the selection** (selected rows may leave the filtered
  set) while keeping the chosen `pageSize`; `reset()` restores the pristine
  state including default `pageSize`.
- Also exports `EXPENSE_PAGE_SIZE_OPTIONS` (`[25, 50, 100]`) for the pager.

## Design decisions

- **Filter fields match the GraphQL `ExpenseFilter` input one-to-one**
  (`title`, `types`, `expenseDate`, `paymentDateFrom`, `paymentDateTo`,
  `includeDeleted`), so the future page task can spread store state into
  query variables with no mapping layer (stores AGENTS.md NO-MAPPING rule).
  Field name is `title` (not `search`) per §5.7; §5.5's "title search"
  confirms the title is the searched field.
- **No `PersonOption` / selected-entity persistence**: the carryover M2
  `teacherOption` pattern exists only because the carryover filter bar owns
  a teacher autocomplete filter. The expense filter bar (§5.5) has no
  teacher filter and the `ExpenseFilter` GraphQL input has no `teacherId`,
  so there is no entity-selection field to keep alive across a viewport
  tier switch; the teacher appears only as a display column. Nothing was
  persisted.
- **`types` uses the codegen `ExpenseType` enum** rather than a local union —
  the schema declares `types: Array<ExpenseType>` (generated
  `graphql.ts:1117-1132`), so codegen supplies the type and no local
  redefinition was needed (unlike carryover's `CarryoverPaidStatusFilter`,
  whose GraphQL field is a plain `String`).
- **Selection shape**: `readonly string[]` array, matching the repo
  precedent (`teacherDuesStore.ts`, `carryoverFilterStore.ts`).
- **No URL sync / hydration, no Storybook mock store** — same rationale as
  carryover 4.3 (plain filter+selection store; filter-store precedents ship
  no mock).
