### Guards & idempotency

- **Empty selection guard (carryover precedent):** `bulkDeleteExpenses` rejects an empty
  `ids` list in the resolver with `ValidationError(tErrors.invalidInput)` before touching
  the service. The `ExpenseErrors` locale leaf deliberately has no dedicated empty-selection
  key, so the generic `invalidInput` message is used (same keyed error the carryover
  resolver used for its required-field narrowing).
- **Oversized selection:** enforced by `maxItems: 500`, which is already baked into
  `BulkDeleteExpensesInputPothos.ids` (Task 2.1) and enforced at runtime by the Apollo
  `@constraint` validation plugin on the route — nothing further needed in the resolver.
- **Idempotency:** `createExpense` passes `clientRequestId` straight through to
  `ExpenseService.create`, whose replay window returns the original row for duplicate
  submissions.
- `deleteExpense`'s service `ExpenseRow` return is mapped to
  `{ id: row.id, deleted: true }` (the `DeleteExpenseResult` backing shape from 2.1);
  `bulkDeleteExpenses` returns the service's `BulkDeleteExpensesResult` as-is.
- No public mutation for `createInternal` (internal TS-only settlement seam).
