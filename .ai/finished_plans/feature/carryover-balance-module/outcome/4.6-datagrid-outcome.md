## Key decisions

- **Selection**: controlled `rowSelectionModel={{ type: "include", ids: new Set(selectedIds) }}`;
  `onRowSelectionModelChange` diffs the model against `selectedIds` and calls
  `toggleSelected` per added/removed id (the store has no bulk-set action).
  `checkboxSelection` only when `canManageCarryover`; `disableRowSelectionOnClick`.
- **Page-turn clears selection** (`handlePageChange`/`handlePageSizeChange` call
  `clearSelection()` first): bulk semantics are verifiable only for visible rows
  (the container sees only the current page); keeping selection page-local avoids
  stale ids surviving into bulk payloads across pages.
- **Bulk To Expense gating**: enabled only when every selected visible row is
  unpaid (`isPaid !== true`), per §5.3.
- **Columns** (per §5.3 + task text): teacher, studentsCount, studentsText,
  totalDuration, payable+currency, paid chip, paymentDate, fromDate→toDate
  period, createdAt, actions (manage-only).
- **Prototype**: inspected `carryover-list-default-desktop.png` (single image).
  Structure matched (toolbar split, columns, footer). Prototype row data treated
  as placeholder — none copied. Omitted the prototype's "N selected" chip: the
  namespace has no selected-count key; disabled-state gating carries the info.
- **Auxiliary namespaces in-component** (precedent: `SessionAuditDataGrid`
  importing `DashboardBillingPayroll`; folder precedent: chips/FilterBar call
  `useAppTranslation` in-component): `DashboardAccountingPayments` for generic
  `columns.actions` / `columns.createdAt` headers, `DashboardBillingPayroll` for
  `exportTruncated` / `exportFailed` toast copy (see cross-file note).
- Error path: `error !== null` → `ErrorState` with `onRetry={refetch}`, footer
  still rendered (aggregates hold last good values via cache).
