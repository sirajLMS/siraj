## What was implemented

### `backend/db/repo/teachers/carryover-balance.repository.ts` (NEW)

`export namespace CarryoverBalanceRepository` with the 10 assigned methods, using
types from `@/backend/types` and tables from `@/backend/db/schema`:

- **`findFiltered(filters: CarryoverFilters, pagination: { limit; offset }, tx?)`** →
  `{ rows: CarryoverBalanceListRow[]; totalCount: number }`. Joins `teachers → users`
  for `teacherName`/`teacherAvatarUrl` (inner joins). Filter semantics per specs.md
  US-5: exact `teacherId`; `paidStatus` `Paid`/`Unpaid` map to `isPaid`, `Both`/null
  disable the filter; `dateFrom`/`dateTo` are inclusive text-column bounds
  (`fromDate >= filter`, `toDate <= filter` — ISO date text compares lexicographically);
  `includeDisabledTeachers` off/absent → `isDisabledTeacher = false`; `search` is a
  trimmed, wildcard-escaped (`escapeLikeWildcards`) dialect-aware ILIKE
  (`caseInsensitiveLike`) over `users.name` OR `students_text`. Order:
  `createdAt DESC, id ASC` (deterministic pagination). `totalCount` comes from a
  parallel count query sharing joins and WHERE but no limit/offset. Read aggregates
  are NOT computed here — implementation.md §3.6 derives them in the service from the
  page rows; the test proves the data supports correct aggregation.
- **`getByIdsForUpdate(ids, tx)`** — locking batch lookup (`withForUpdate` from
  `@/backend/db`: `FOR UPDATE` on PG, no-op on SQLite), `order by id` so concurrent
  bulk operations lock in the same order (deadlock avoidance). `tx` is REQUIRED —
  the lock is only meaningful inside the caller's transaction. Empty ids → `[]`.
- **`getById(id, tx?)`** / **`findByTeacherId(teacherId, tx?)`** — bare reads via
  `queryDb(tx)` per repo AGENTS (Neon-HTTP-eligible).
- **`findLinkedSessions(carryoverId, tx?)`** — resolves `class_instances` through the
  `carryover_balance_items` snapshot rows (not the `carryover_balance_id`
  back-reference), ordered by `scheduledStartAt` then item id, so the result survives
  if sessions are later unlinked.
- **`create(input, tx?)`** — insert + returning; DB defaults apply (`paid="0"`,
  `isPaid=false`, `isDisabledTeacher=false`). Throws an invariant `Error` if the
  insert returns no row (package-plan repo precedent — no carryover error namespace
  exists yet; the i18n task owns adding one if ever needed).
- **`update(id, patch, tx?)`** — `CarryoverBalanceUpdatePatch =
  Partial<Omit<CarryoverBalanceInsertType, "id">>`; auto-bumps `updatedAt`; returns
  null on unknown id (mutations return null, service maps to NotFoundError).
- **`deleteById(id, tx?)` / `bulkDelete(ids, tx)`** — hard deletes (items cascade via
  `ON DELETE CASCADE`); return deleted row(s); unknown ids silently skipped. Named
  `deleteById` because `delete` is a reserved word (existing repo convention:
  `site-content.repository.ts`).

Local exported types `CarryoverBalanceListRow` and `CarryoverBalancePageResult`
live in the repo file (payroll-1.2 precedent: repo-level projection types like
`GetClassInstanceOptions`/`PayrollCalculationPatch` live with the repo).

### `backend/db/test/repo/teachers/carryover.repository.test.ts` (NEW)

31 tests / 128 expects, `bun:test`, all wrapped in `runInRollback` with `tx` passed
to every repo call (one deliberate exception: the lock test, below). No
`expect().rejects`, no seed-data queries, no `console.*`, no `any`; fixtures via
`setupTeacher` / `setupStudent` / `createMockClassInstance` after verifying helper
signatures in `entity-setup.ts`.

Coverage of the 4 tiers:

- **Tier 1 (branches)**: every `buildConditions` branch (teacherId, Paid, Unpaid,
  Both/null, dateFrom, dateTo, disabled default/on/off, search present/blank) plus
  empty-input short-circuits for `getByIdsForUpdate` / `insertItems` / `bulkDelete`;
  unknown-id null paths for `getById` / `update` / `deleteById`; item leak isolation
  between carryovers; cascade removal of items on delete; non-transactional read
  fallbacks (`getById` / `findByTeacherId` without `tx`).
- **Tier 2 (boundaries)**: inclusive date edges (`dateFrom == fromDate` matches,
  `+1 day` excludes; same for `toDate`); NULL date columns excluded when a date
  filter is active; pagination offset exactly at the end → 0 rows with correct
  `totalCount`; empty/unmatched pages.
- **Tier 3 (chaos)**: LIKE-wildcard injection — search `"<name>%"` must NOT match
  (wildcards escaped), while `"<name>"` matches; mixed-case search on teacher name
  and `studentsText` both match.
- **Tier 4 (concurrency)**: real lock-contention test — committed fixture (outside
  rollback, second connection can't see uncommitted rows), blocker tx calls
  `getByIdsForUpdate` and holds the rows, contender tx with
  `SET LOCAL statement_timeout = '500'` fails with a lock timeout, proving the
  `FOR UPDATE` shape. Skipped on SQLite via `test.skipIf(isSqlite())` (no FOR UPDATE
  there). Fixture cleaned up in `finally`.
- **Aggregate totals**: teacher-scoped page with one paid + one unpaid row yields
  `totalPayable "300.25"` / `totalPaid "200.25"` / paid-split 1+1 / single dominant
  currency — the exact reduction the §3.6 service will perform.

## Carry-forward knowledge

- **Import path**: `import { CarryoverBalanceRepository } from "@/backend/db/repo/teachers";`
  (or the top-level `@/backend/db/repo` barrel).
- **Signatures** (exact):
  ```ts
  findFiltered(filters: CarryoverFilters, pagination: { limit: number; offset: number }, tx?: DBTransaction)
    // → { rows: CarryoverBalanceListRow[]; totalCount: number }
  getByIdsForUpdate(ids: readonly string[], tx: DBTransaction) // tx REQUIRED
  getById(id: string, tx?: DBTransaction)
  findByTeacherId(teacherId: string, tx?: DBTransaction)
  findLinkedSessions(carryoverId: string, tx?: DBTransaction) // ClassInstanceSelectType[]
  create(input: CarryoverBalanceInsertType, tx?: DBTransaction)
  update(id: string, patch: CarryoverBalanceUpdatePatch, tx?: DBTransaction) // null on miss
  deleteById(id: string, tx?: DBTransaction) // null on miss; items cascade
  bulkDelete(ids: readonly string[], tx?: DBTransaction) // db-side filter, unknown ids skipped
  insertItems(items: CarryoverBalanceItemInsertType[], tx?: DBTransaction)
  ```
- **`CarryoverBalanceListRow` keeps `Date` timestamps** — the service's
  `mapToCarryoverRow` must serialize `createdAt`/`paidAt` to ISO strings to satisfy
  `CarryoverRow`.
- The delete service flow can read `originalStatus` straight from
  `carryover_balance_items` (via `insertItems`' return or a direct query) and revert
  sessions through `ClassInstanceRepository.findByCarryoverId`; `findLinkedSessions`
  is the repo-side session viewer and works even if `class_instances.carryover_balance_id`
  was cleared.
- `CarryoverBalanceUpdatePatch` allows patching payment columns; the service must
  enforce its own invariants (§3.5 teacher immutability, paid-rows protected on
  delete) — the repo intentionally enforces none of them.
