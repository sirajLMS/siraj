## Idempotency / double-submit

- `clientRequestIdRef` is regenerated with `crypto.randomUUID()` on every dialog open
  (`open` effect) and passed into `CreateCarryoverInput.clientRequestId`.
- `submittedTokenRef` guard makes a double-click produce exactly ONE mutation in both
  modes (the token doubles as the update-mode guard since `UpdateCarryoverInput` carries
  no `clientRequestId`); the guard re-arms on failure so the same token backstops
  server-side retry idempotency.

## Mutations / cache / error mapping

- `useMutation(createCarryoverBalanceMutationDocument | updateCarryoverBalanceMutationDocument)`
  with `errorPolicy: "none"` (per sibling: domain errors reject as `CombinedGraphQLErrors`
  with `extensions.code`).
- Success: `cache.evict({ fieldName: "carryoverBalances" })` + `cache.gc()` (aggregates live
  on the list query, so the whole root field is dropped rather than patched), toast
  `success.created` / `success.updated` via `useNotifications`, then `onSaved?.()` + `onClose()`.
- `CARRYOVER_TEACHER_IMMUTABLE` → inline `form.setError("teacher", { message:
  errors.carryover.teacherImmutable })` (server `errors.carryover.*` namespace copy, per
  outcome 1.7). All other rejections toast the server-localized message
  (`getGraphQLErrorMessage`) with `common.operationFailed` fallback.
