## MEDIUM

1. **[MEDIUM] `frontend/common/views/dashboard/accounting/carryover/CarryoverDataGrid.tsx:308-328` + `frontend/mobile/views/dashboard/accounting/carryover/carryover.mobile.tsx:176-179` — VIEW-only operators have no way to open the linked-sessions detail drawer.** The per-row actions column (which holds "View Sessions") is pushed into `columns` only under `canManageCarryover`, and there is no row-click fallback on desktop; on mobile the whole `CarryoverRowMenu` (including the read-only "View Sessions" entry) renders only under `canManage`. The drawer is a read surface — `carryoverBalance(id)` + `carryoverBalanceLinkedSessions` are VIEW-gated (spec §3 "read behind ACCOUNTING_CARRYOVER_VIEW", US-8/AC-8.2), and `app/(dashboard)/accounting/carryover/[id]/page.tsx` is VIEW-gated — so the backend deliberately exposes drill-down to viewers, but no UI affordance reaches it. Only the invisible deep-link URL works. — **Fix**: give VIEW users a drawer entry point (e.g. a row-click / single "View" item rendered for VIEW holders, keeping Edit/Unpay/Delete manage-gated).
2. **[MEDIUM] `frontend/common/views/dashboard/accounting/carryover/CarryoverFilterBar.tsx:76-87` (`useTeacherFilterSelection`) — selected teacher option does not survive a viewport tier switch.** `picked` is `useState` inside the FilterBar, but the FilterBar mounts inside the tier views (`carryover.desktop.tsx:22`, `carryover.mobile.tsx:239-241`), which the switcher unmounts on tier change. After desktop→mobile, the store's `teacherId` still filters but the `TeacherAutocomplete` renders empty (option resolution is by `picked.id === teacherId`), so the active filter is invisible and even the store "Clear" round-trip then silently re-queries. This violates `frontend/views/AGENTS.md` ("All mutable state… lives in Zustand stores so it survives viewport tier switching") and the store-layer convention that page/domain stores hold the selected `PersonOption`. — **Fix**: store `{ id, name, avatarUrl }` (serializable) in `carryoverFilterStore` alongside `teacherId`, or have the autocomplete resolve the selected id against `userAutocompleteStore`.
