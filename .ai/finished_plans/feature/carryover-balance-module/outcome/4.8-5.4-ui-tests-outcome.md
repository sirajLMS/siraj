## Placement decision

Tests are **co-located** with the components (per trackable-tasks 4.8/5.4 paths), following
the same-domain sibling precedent (`accounting/payroll/PayrollReportsContainer.test.tsx`,
`OverrideDialog.test.tsx`) rather than `test/ui/components/`. Consequences baked into the
harness: `GlobalRegistrator.register()` before dynamic `@testing-library` imports, jest-dom
matchers destructured off the interop default, namespaces warmed via a `warmNamespace` helper
instead of the shared preload, manual `next/dynamic` re-implementation for the container's
`createLazyView` tier imports, and `mockNextNavigation("/accounting/carryover", { includeI18nMocks: false })`
for the desktop page-header breadcrumbs. Toolpad `useNotifications` and `crypto.randomUUID`
(pinned token) are mocked; the carryover filter store and user-autocomplete store reset in
`afterEach`.

## Written-but-unexecuted — what a first run must verify

These suites have never been executed (the wave policy forbids running UI tests). First-run risks, in rough likelihood order:

1. **MUI X date-picker typing** (`fireEvent.change` on the picker textbox with `"09/01/2026"`, `MM/dd/yyyy`): no repo precedent sets `AppDatePicker` values from tests. If the field does not commit on change, blur may be needed and the exact-input/double-click/immutable cases that depend on the picker dates will need adjusting (`CarryoverFormDialog` tests 3–7, `BulkToExpenseModal` tests 2–5).
2. **Option accessible names**: the currency option regex `/EGP/` and teacher option `RegExp(name)` assume the autocomplete option's accessible name contains those strings (source reads support this, unverified at runtime).
3. **Autocomplete mount query**: `teachersMock("")` is provided unconditionally on the assumption `useAudienceAutocomplete` queries on mount even with a value preset; an extra `maxUsageCount` mock is harmless if unused.
4. **Debounce timing**: the container's search test allows two 300 ms debounces (filter bar → store, VM → query) under the 5 s RTL timeout — generous, but timing-dependent by nature.
5. **CSV export path in Happy DOM**: depends on `Response.blob()` + `URL.createObjectURL` behaving (the payroll sibling test makes the same assumption and asserts no failure toast).
6. **Axe**: `color-contrast` is disabled (Happy DOM has no styles); the container test also disables `heading-order` (owned by shared page layout primitives) — same exclusions as the payroll sibling.

First-run command (when the policy allows): `bun run test/scripts/run-test.ts frontend/common/views/dashboard/accounting/carryover/<file>` — the suites run through the single-file runner, not `test:ui:components` (co-located suites self-register Happy DOM).
