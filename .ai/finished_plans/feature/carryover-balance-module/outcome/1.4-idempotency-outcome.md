# Task 1.4 Outcome — Carryover Idempotency Helpers

- **Date**: 2026-09-05
- **Status**: ✅ Complete

## What was implemented

Three deterministic sha256 idempotency-key derivers, per implementation.md §3.7:

- `deriveBulkCreateIdempotencyKey(input: BulkCreateCarryoverInput)` — hashes
  (scope prefix, actorUserId, **sorted** instanceIds). Stable across
  instance-id reordering; note/clientRequestId excluded per plan.
- `deriveBulkToExpenseIdempotencyKey(input: BulkToExpenseInput)` — hashes
  (scope prefix, actorUserId, paymentDate, expenseDate ?? "", note ?? "",
  **sorted** carryoverIds). A payment-date change produces a different key.
- `deriveCrudIdempotencyKey(input: CreateCarryoverInput)` — hashes
  (scope prefix, actorUserId, teacherId, fromDate, toDate, payable,
  teacherCurrency, clientRequestId). Not listed in implementation.md §3.7 but
  required by the task; designed for the single-record create double-submit
  guard (specs E1, `clientRequestId` + 60s window semantics).

Shared `hashCarryoverParts(scope, parts)` helper joins segments with `:` and
sha256-hex digests (mirrors `backend/services/billing/credit-adjustment.idempotency.ts`
precedent: verbatim hashing, null/undefined → empty segment normalization, no
date/whitespace normalization). List fields sorted with
`toSorted((a, b) => a.localeCompare(b))` (ESLint `no-array-sort` +
sonarjs `no-alphabetical-sort` compliant).

## Carry-forward knowledge

- **Scope prefixes matter**: each deriver prefixes its operation name
  (`carryover-bulk-create` / `carryover-bulk-to-expense` / `carryover-crud-create`)
  so keys from different operations can never collide even with overlapping payloads.
- The service (Task 1.x `carryover-balance.service.ts`) consumes these as
  `audit_logs.metadata.idempotencyKey` via `AuditLogRepository.findRecentByActorAndHash`
  (60s window) — key stability across input reordering is load-bearing for the
  replay short-circuit.
- `toSorted` mutates nothing, so `readonly string[]` inputs can be passed
  directly (plan types use `readonly string[]` for ids).
- Distinct fixture constants must actually be distinct strings — same-literal
  constants silently invalidate "changing X changes the key" assertions.
