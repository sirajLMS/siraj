## Key decisions

- **Router**: `useRouter` from `@/shared/i18n/navigation` (locale-aware), same
  as `StudentCreditsList`. Cancel also pushes `/accounting/credits`.
- **Toasts**: Toolpad `useNotifications()` — the app-wide host survives the
  navigation to the list page (a local `FormSuccessSnackbar` would unmount
  before anyone reads it). Tests mock `@toolpad/core/useNotifications` per the
  established pattern in `AppearanceCustomizer.test.tsx`.
- **Cache eviction**: `client.cache.evict({ fieldName: "studentsDirectory" })`
  on success (no `refetchQueries`; the list's `cache-and-network` policy + the
  evicted root field guarantee a refetch on return; the mutation result carries
  no recalculated balances, per 4.2-4.3).
- **Enum mapping**: shared `CreditAdjustmentType` (ADD/SUBTRACT/SUBTRACT_WITH_CARRYOVER)
  → generated `CreditAdjustmentType` (`Add/Subtract/SubtractWithCarryover` — note:
  the generated **input** enum carries those names; the `CreditAdjustmentAdd|…`
  members live on the unrelated `CreditReason` enum) via a `Record` map.
  `clientRequestId` is **not** sent (server-derived idempotency).
- **Double-submit guard**: `submittedTokenRef` compared against the store's
  `clientRequestId` (rotated on mount via `regenerateClientRequestId()` and on
  `reset()`), plus `loading`-driven button disable. After a rejected submit the
  ref is cleared so retry works (E9).
- **Client validation mirrors the server**: hours integer ≥ 1, non-empty reason
  (AC-5.3), carryover requires teacher + 3 dates, `fromDate > toDate` blocked
  (AC-4.3 — ISO strings compare lexicographically), `paymentDate > today+1d`
  blocked (AC-4.4). Carryover inline errors are **re-derived from the live
  store each render** (`validateCarryoverDraft`), so fixed fields clear
  immediately without waiting for the next submit.
- **Error mapping**: `errorPolicy: "none"` is set explicitly on the mutation
  (TestWrapper defaults mutations to `"all"`, which would resolve instead of
  throwing). Errors are inspected via `CombinedGraphQLErrors.is` (cron
  viewmodel convention). `INSUFFICIENT_CLASSES` → inline hours error, no
  navigation, no toast. Everything else → error toast with the server's
  already-localized message, falling back to `common.operationFailed`.
- **Teacher display name for the carryover toast**: the store keeps only the
  teacher id (serializability, 5.1) and `CarryoverBanner` exposes no callback,
  so the form resolves the name from the person-picker result cache
  (`useUserAutocompleteStore`, audience `teacher`) — every selectable option
  has passed through a fetched options page, so the lookup is reliable in
  practice. If somehow unresolved, the toast degrades to `success.subtracted`
  instead of inventing a string. See CROSS-FILE DEPENDENCY for the cleaner fix.
- **Preselection (AC-1.5)**: mount effect seeds the store from the
  `studentId` prop; `studentByIdQueryDocument` resolves the display record.
  Verified empirically (probe test) that these shared pickers' controlled
  `inputValue` ignores MUI's `reset` sync, so a programmatically-set `value`
  does **not** render the name inside the input — hence the form renders a
  read-only **preselection summary row** (avatar + name + `remaining / total`
  chip, mirroring the list's balance presentation and the prototype's
  "Current balance" line) whenever the fetched row matches the store id.
  A manual re-pick replaces it.
- **Unmount**: effect cleanup calls `reset()`, so list → form navigation never
  inherits a previous session's draft; successful submit also resets (fresh
  guard token) before navigating.
- Styling: `SectionPanel` shell matching `StudentCreditsList`; palette-only
  colors via existing primitives (`FilterButton`, `PrimaryPageAction` with
  `loading`); RTL inherited. No prototype data hardcoded anywhere.

### Mock-data gotchas worth copying (pair with 4.2-4.3's `__typename` note)

- **Apollo v4 `MockLink.MockedResponse` dropped `newData`** — use
  `result: () => ({...})` (a *function* result also runs per invocation, making
  it a natural call counter for "exactly one mutation" assertions).
- Mocks without `result`/`error` hang the operation forever (promise never
  settles), which first manifests as waitFor timeouts, not a mock error.
- Picking an autocomplete option fires **another** directory/teacher query with
  the selected label as the search term (reason `selectOption`) — mock
  `{ search: "<label>" }` too, or the post-selection query goes unmatched.
- Mocks for `AssociationStudent` rows need `__typename: "AssociatedStudent"`;
  teacher options `__typename: "TeacherSimple"`.

## CROSS-FILE DEPENDENCY

1. **Teacher name for the carryover toast** (non-blocking, quality window):
   `CarryoverBanner` owns the selected `PersonOption` locally and only writes
   the id to the store; the form currently resolves the display name by
   scanning `useUserAutocompleteStore`. Cleaner fix: add an optional
   `onTeacherChange?: (option: PersonOption | null) => void` prop to
   `CarryoverBanner` (or persist `{ id, name }` in the form store), letting the
   form capture the name directly. Flagged for the orchestrator — the current
   fallback is functional and covered by tests (test 4 exercises the real
   picker + toast), so this is an improvement, not a blocker.
2. Informational only: the shared `AudienceAutocomplete` ignores MUI's
   `reset` input sync, so programmatic `value` sets never appear inside the
   input text (verified empirically in a throwaway probe test, since removed).
   The form works around this with the preselection summary row; if the shared
   picker's display behavior is ever revisited, that workaround can be
   re-evaluated.
