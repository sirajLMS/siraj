## Journey steps (8 tests, sequential)

1. **Sync from Meta** — admin (academy_admin + run-scoped `whatsapp.config_manage` grant, the
   sibling suite's cast) runs `WhatsappAccountService.syncFromMeta` against a stubbed Graph edge:
   `GET /{waba}/phone_numbers` lists one number whose detail (`verified_name: "Test Number"`,
   `code_verification_status: "NOT_VERIFIED"`, display digits starting `1555`,
   `status: "CONNECTED"`) makes `isMetaTestNumber` true. Asserts the created row has
   `isTestNumber = true` (service result + DB row + recorded detail fetch).
2. **addRecipient** — PENDING row persisted; append-only audit row with
   `action = CREATE` / `description = "whatsapp-test-recipient registered"` on the
   `WHATSAPP_ACCOUNT` entity asserted from `audit_logs`.
3. **verifyRecipient** — stub accepts the `hello_world` send; row flips to ALLOWED with
   `lastErrorCode: null`, `lastCheckedAt` stamped; the stubbed wire body is asserted to carry
   `template.name = hello_world` + `language.code = en_US`.
4. **sendMessage TEMPLATE** — persists `whatsapp_messages` with `direction = API_OUTBOUND`,
   `type = template`, `status = sent`; conversation rolled forward
   (`lastMessageAt` set, preview `[template] hello_world`, `lastInboundMessageAt` still null).
5. **TEXT window gating** — free-text refused first with `WHATSAPP_OUTSIDE_SERVICE_WINDOW`
   (asserted via `expectJourneyError` against the translated label); a real inbound webhook
   (`persistWebhookChanges` + `WhatsappWebhookHandler.processPendingWebhookEvents`) stamps
   `lastInboundMessageAt`; the TEXT send then succeeds and persists an API_OUTBOUND text row.
6. **Recipient cap** — second recipient added, registry filled to 5 (parallel adds serialize on
   the account-scoped advisory lock), the sixth add throws
   `DomainError` with `whatsappRecipientLimitReached`.
7. **Honest denial** — a `staff_default` actor (view-only) calling `sendMessage` gets
   `ForbiddenError` (`insufficientPermissions`) and no Graph call is recorded.
8. **View surface** — the staff actor lists the thread via
   `WhatsappConversationsService.listConversations`/`listConversationMessages`, seeing the
   template, text, and inbound rows.

## Interception & env strategy

- Only `globalThis.fetch` is stubbed (restored in `afterAll`); the stub is keyed on the
  run-unique phone-number id and path suffixes, never on env values, so env-config cache state
  from sibling suites cannot leak in. `WHATSAPP_WABA_ID`/`WHATSAPP_ACCESS_TOKEN` come from
  `.env.test`; a run-scoped fallback + `invalidateEnvConfigCache()` covers envs where they are
  absent, with full restore in `afterAll`.
- Phone-shaped fixtures are built from fragment joins / UUID digit extraction (the
  `[PHONE_REDACTED]` PII filter garbles literal phone-like strings).

## Cleanup

`afterAll`: audit rows for the synced account id + the sync's WABA-keyed UPSERT row are swept
with the immutability trigger lifted (sibling-suite precedent); the account row is hard-deleted
(cascades recipients, conversations, messages, sync requests); `cleanupWhatsappCast(cast,
webhookHashes)` purges webhook events and the actor cast in FK-safe order.
