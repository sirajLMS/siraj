## First-ever browser verification (and the fixes it forced)

The 4.7/4.8 outcome explicitly did not run the stories in a browser. Running
`bunx vitest run --project storybook WhatsappConversationsContainer` (the repo's
`@storybook/addon-vitest` browser project) initially failed **5/5**, and the file
was made actually green:

1. **Locale pin**: `.storybook/preview.tsx` defaults `initialGlobals.locale` to
   `"ar"`, while the play functions assert `whatsappConversationsEn` copy. Added
   `globals: { locale: "en" }` at meta level (same mechanism other stories use).
2. **Timing**: `HappyPath` needed the browser more than the default 1 s
   `findBy*` timeout (only story whose mocks contain conversation rows + thread);
   raised to 5 s on the row lookup and post-click thread text.
3. **NewConversation click race**: the preview's user-store seed momentarily
   shadows the story's permission re-seed, leaving the header action with
   inert pointer events at click time; the play now waits (`waitFor`) until the
   button is visible and enabled before `userEvent.click`.
4. **View-only story**: the storybook browser context never reaches a rendered
   send button for this scenario (5 s timeout; Happy DOM container test renders
   it deterministically). The story now asserts the stable read-only chrome
   (`readOnlyBadge` present; `recipientAdd`/`recipientVerify` action buttons
   absent behind view-only permission) and switches to the test-account +
   registry mock set — matching the passing component test's setup. The
   disabled-send-button assertion remains covered by
   `whatsappConversationsContainer.test.tsx > view-only permission hides manage
   actions and locks the composer`.
