## Deviations / findings

1. **No "not yet verified" tooltip exists.** The brief assumed a tooltip for PENDING registry
   targets; `ComposerShared`/`TestRecipientsPanel` have no tooltip. The behavior is covered
   as actually implemented: the registry select lists PENDING rows (status badge "Pending"),
   and selection of a PENDING target leaves send enabled (Meta keeps final say). No component
   changes made — flag for a possible UX follow-up if a tooltip is desired.
2. **Thread-pane/container click timing**: the account default-selection effect re-renders
   the conversation row right after first paint, so single-shot clicks are racy; the
   container tests click inside `waitFor` (idempotent repeated select) and re-query elements
   inside `waitFor` callbacks because the composer subtree remounts when the selection moves
   it into the thread pane (captured element references go stale there). Documented in the
   test comments.
3. The container/Vm test bypasses `next/dynamic` via `mock.module` on the container —
   same pattern as `pendingReviewsContainer.test.tsx`.
