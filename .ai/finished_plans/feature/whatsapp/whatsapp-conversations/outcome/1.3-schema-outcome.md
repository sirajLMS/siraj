# 1.3 — DB schema changes (whatsapp conversations)

Date: 2026-09-10.

## What was done

### Schema edits

- `backend/db/schema/whatsapp/whatsapp-accounts.ts` — added
  `isTestNumber: booleanColumn("is_test_number").notNull().default(false)` (next to `isActive`).
- `backend/db/schema/whatsapp/whatsapp-conversations.ts` — added
  `lastInboundMessageAt: timestampColumn("last_inbound_message_at")` (nullable tz timestamp).
- `backend/db/schema/whatsapp/whatsapp-test-recipients.ts` (NEW) — `whatsapp_test_recipients`
  table per design-02, built with the dialect-aware helpers (`createTable`, `uuidColumn`,
  `uuidDefaultColumn`, `varcharColumn`, `timestampColumn`):
  - `id` uuid pk `gen_random_uuid()`; `account_id` uuid notNull → `whatsapp_accounts.id`
    ON DELETE CASCADE; `phone_number` varchar(32) notNull; `status` varchar(16) notNull
    default `'PENDING'`; `last_checked_at` tz ts nullable; `last_error_code` varchar(24)
    nullable; `note` varchar(200) nullable; `created_by_user_id` uuid notNull → `users.id`
    (no onDelete — audit FK); standard `created_at`/`updated_at`.
  - `uniqueIndex whatsapp_test_recipients_account_phone_unique (account_id, phone_number)`
    + `index whatsapp_test_recipients_account_id_idx (account_id)`.
- `backend/db/schema/whatsapp/index.ts` — `export * from "./whatsapp-test-recipients"` added
  (alphabetical slot; top-level barrel already re-exports `./whatsapp`, no config change needed).

### Generated migrations (no `db push` / `db migrate` run, per task bounds)

- PG: `backend/drizzle/20260910130512_wooden_swordsman/` — table + 2 column adds only.
  NOTE: `drizzle-kit generate` initially also emitted two `ALTER TYPE app_permission ADD VALUE`
  lines — those come from the in-flight task-1.1 edit to
  `backend/enum/permissions/permission.enum.ts` (uncommitted at generate time) and are owned by
  task 1.2's custom `backend/db/migration/46a-whatsapp-conversations-permissions-enum.sql`.
  The two lines were removed from this folder's `migration.sql` to keep it scoped; the enum
  values remain in the folder's `snapshot.json` (drizzle diff baseline) and are applied by 46a
  (idempotent `IF NOT EXISTS`), so re-runs and ordering are safe. The file was also rewritten to
  idempotent form by the repo's `ensureIdempotentMigrations` step (another process ran migrate
  while this task was in flight) — content verified after the rewrite.
- SQLite: `backend/drizzle-sqlite/20260910131250_shiny_pixie/` — mirror generated via
  `bun db generate --env-file .env.sqlite`. WARNING: sqlite snapshots lagged multiple
  already-committed features (expense ledger, credit-hours package plans, student credit
  columns, whatsapp coexistence columns), so this folder is primarily a catch-up sync of that
  backlog plus this task's three changes. The sqlite diff for this task is exactly:
  `whatsapp_test_recipients` CREATE TABLE + `whatsapp_accounts.is_test_number` +
  `whatsapp_conversations.last_inbound_message_at` + the two indexes. Keeping the folder is
  also protective: with its snapshot in place, concurrent agents running sqlite generate see
  "no schema changes" instead of duplicating the backlog diff.
