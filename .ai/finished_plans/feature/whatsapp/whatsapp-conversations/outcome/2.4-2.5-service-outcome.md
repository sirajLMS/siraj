## Error codes thrown (GraphQL `extensions.code` via DomainError)

| Code | Error class | Trigger |
|---|---|---|
| `WHATSAPP_RECIPIENT_LIMIT_REACHED` | DomainError | addRecipient: test number already at 5 registry rows |
| `WHATSAPP_RECIPIENT_CONFLICT` | DomainError | addRecipient: `(accountId, phoneNumber)` unique violation (SQLSTATE 23505, cause-chained) |
| `WHATSAPP_RECIPIENT_NOT_ALLOWED` | DomainError | sendMessage: test number + recipient missing/not ALLOWED; or Meta 131030 mid-send (message differs: `whatsappRecipientNotAllowed` vs `whatsappRecipientNotAllowedFromMeta`) |
| `WHATSAPP_OUTSIDE_SERVICE_WINDOW` | DomainError | sendMessage TEXT: no conversation or `lastInboundMessageAt` older than 24h |
| `WHATSAPP_CONVERSATION_SEND_FAILED` | DomainError | sendMessage: any non-131030 GraphApiError |
| `WHATSAPP_CONFIG` | DomainError | account row has no decrypted access token |
| `NotFoundError("WHATSAPP_ACCOUNT" | "WHATSAPP_TEST_RECIPIENT" | "WHATSAPP_CONVERSATION")` | unknown ids / cross-account conversation |
| `ValidationError` | empty `to`, TEXT without body (`whatsappMessageRequired`), TEMPLATE without name (`whatsappTemplateRequired`) |

## Credential resolution

Per-account: `WhatsappAccountRepository.findCredentialsById(accountId, tx)` returns the
`WhatsappAccountSelectType`; the `encryptedText` column driver decrypts at read time, so
`encryptedAccessToken` IS the plaintext Bearer token. Graph context =
`{ accessToken, apiVersion: resolveGraphApiVersion() }` (env-config
`WHATSAPP_GRAPH_API_VERSION` → legacy `WHATSAPP_API_VERSION` → `DEFAULT_GRAPH_API_VERSION`).
No env-global token fallback inside this service.

## sendMessage flow (as implemented)

1. manage gate → account → digits-only `to` → mode payload validation.
2. Test-number hard block: registry row must exist with `status === ALLOWED`.
3. Conversation resolution: `conversationId` given → `findById` + account-ownership check
   (else NotFound); absent → `findByIdentity(accountId, { waId: to })`.
4. TEXT requires the 24h window (`Date.now() - lastInboundMessageAt <= 24h`); TEMPLATE skips.
5. Dispatch via `buildSendTextMessageRequest` / `buildSendTemplateMessageRequest`
   (default template language `en_US`), single `fetch` with `FETCH_TIMEOUT_MS`; non-2xx →
   `GraphApiError`; only `GraphApiError` is translated (other errors propagate).
6. Persist: `WhatsappMessageRepository.upsertByWamid` with
   `conversationId`, `accountId`, `wamid` (Meta id), `direction: API_OUTBOUND`,
   `type: "text" | "template"`, `content: { text: { body } } | { template: { name, languageCode } }`,
   `status: "sent"`, `mediaPlaceholder: false`, `mediaId/mediaMime/mediaSha256/phase/chunkOrder/editedAt/revokedAt: null`,
   `sentAt: new Date()`. Thread: existing conversation or `upsertByIdentity({ accountId, waId })`;
   `touchLastMessage` with preview truncated to 140 chars (`[template] <name>` for templates).
7. Audit: `CREATE` on entity type `WHATSAPP_ACCOUNT`, description
   "whatsapp-conversation message sent", metadata `{ messageId, wamid, conversationId }`.
   Returns `{ message }`.

Registry audits use the same `WHATSAPP_ACCOUNT` entity with
`metadata: { registry: "whatsapp_test_recipients", recipientId }` and descriptions
"whatsapp-test-recipient registered" / "whatsapp-test-recipient removed" /
"whatsapp-test-recipient verify allowed|rejected".

## verifyRecipient

`hello_world`/`en_US` test template send with the owning account's credentials; the outcome is
recorded via `recordVerify(id, { allowed, errorCode, checkedAt })` — success → ALLOWED with
`lastErrorCode: null`; `GraphApiError` → PENDING with the extracted Meta code string. Only
`GraphApiError` is swallowed into the verdict; unexpected errors propagate.

## Test-authoring gotcha (environment note)

Phone-number-shaped digit literals written by the agent get PII-redacted to
`[PHONE_REDACTED]` in transit; build the fixtures by joining short fragments
(`["1", "555", "010", "0123"].join("")`) so the file lands with real digits — verified by
rerunning the suite after the fix.
