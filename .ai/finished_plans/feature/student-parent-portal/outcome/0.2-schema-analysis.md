## 1. Payments ↔ invoices ↔ credit_transactions ↔ quotas linkage (F5)

**Files inspected**: `backend/enum/billing/billing.enum.ts`, `backend/db/schema/billing/billing.ts`, `backend/db/schema/billing/credit-transactions.ts`, `backend/db/schema/billing/quotas.ts`, `backend/enum/billing/credit.enum.ts`.

### `InvoiceType` members (`backend/enum/billing/billing.enum.ts`)

```ts
export enum InvoiceType {
  PER_CLASSES = "PER_CLASSES",
  MONTHLY = "MONTHLY",
  MANUAL = "MANUAL",
}
```

Three members. `InvoiceStatus` members: `UNPAID`, `PAYMENT_PENDING`, `PAID`, `CANCELLED`.

### `payments` ↔ `invoices` linkage (`backend/db/schema/billing/billing.ts`)

- `payments.invoiceId` (NOT NULL, FK → `invoices.id`, `onDelete: "restrict"`).
- `invoices` carries: `parentId` (NOT NULL, FK → `parents.id`), `studentId` (NULLABLE, FK → `students.id`), `issueDate`, `dueDate`, `paidDate`, `amount` (text, precision-preserving), `currency`, `status` (invoiceStatusEnum), `invoiceType` (invoiceTypeEnum — the **only** package-kind signal), `idempotencyKey`, `exchangeRateSnapshot`, `exchangeRateSource`, `createdByUserId`, `emailSentAt`, timestamps, `deletedAt`.
- **`payments` has NO package/quota-kind column.** `paymentMethodType` + `paymentMethodSnapshot` (jsonb) are the only payment-level signals — gateway/method display, not package.

### `credit_transactions` (credits purchased) — `backend/db/schema/billing/credit-transactions.ts`

```ts
creditTransactions:
  id, studentId (NOT NULL FK students), changeAmount (integer),
  reason (creditReasonEnum — CreditReason.PURCHASE / DEDUCTION / REFUND / ADJUSTMENT),
  sourcePaymentId (NULLABLE FK payments.id, onDelete: set null),
  classInstanceId (NULLABLE FK class_instances.id),
  notes, creditedByUserId (NOT NULL FK users),
  idempotencyKey, timestamps.
```

- **Credits purchased** are recoverable: `WHERE reason = 'PURCHASE' AND sourcePaymentId = <payment.id>`, `changeAmount` is the number of credits purchased.
- **No line-items table** for invoice rows — only `invoiceCoverageMonths` (composite PK `invoiceId + year + month`) exists. Confirmed.

### `quotas` table (current balance) — `backend/db/schema/billing/quotas.ts`

- `quotas.studentId` (NOT NULL FK students), `kind` (quotaKindEnum — PACKAGE / PERIODIC), `name`, `totalClasses`, `remaining` (default 0), `reservedClasses`, `usedThisPeriod`, `status` (default ACTIVE), `priority`, `periodType`, `periodDays`, `periodAnchor`, `validFrom`, `validUntil`, `idempotencyKey` (sha256).
- **Per-student balance** for the ledger UI = `SUM(quotas.remaining)` for the parent's students, with `status = 'ACTIVE' AND deletedAt IS NULL`.

### Derivation decision (feeds Task 9)

| Ledger column | Source |
|---|---|
| student | `invoices.studentId` (NULLABLE — display "—" if null) |
| credits purchased | `credit_transactions.changeAmount` WHERE `sourcePaymentId = payments.id AND reason = 'PURCHASE'` |
| amount | `payments.amount` |
| currency | `payments.currency` |
| package name | `invoices.invoiceType` mapped to a localized label (`PER_CLASSES` → "Per Classes", `MONTHLY` → "Monthly", `MANUAL` → "—" placeholder). **No DB-level package column on `payments`.** |
| payment gateway | `payments.paymentMethodType` + `payments.paymentMethodSnapshot` jsonb (gateway-specific snapshot) |
| payment date | `payments.paymentDate` |
| balance (per student) | `SUM(quotas.remaining)` over `quotas WHERE studentId IN (caller's students) AND status='ACTIVE' AND deletedAt IS NULL` |

→ **Deferred-items "Package name as snapshot column" stays deferred**: derive-from-invoice (`invoiceType`) is sufficient for v1. If a parent needs the human package name (e.g. "Grade 7 — 12 classes"), that requires linking through `quotas.name` for the student's PACKAGE-kind quotas — added as Task 9 design note.

## 4. leave_quota_usage trigger interplay (F2) — verified

### Trigger definition (`backend/db/migration/leave_quota_limits_trigger.sql`)

```sql
CREATE OR REPLACE FUNCTION enforce_leave_quota_limits() RETURNS TRIGGER AS $$
DECLARE v_max_leaves INTEGER; v_setting_key TEXT;
BEGIN
  IF NEW.teacher_id IS NOT NULL THEN v_setting_key := 'teacher_max_leaves';
  ELSE v_setting_key := 'student_max_leaves'; END IF;
  SELECT COALESCE(value::INTEGER, 2) INTO v_max_leaves FROM system_settings WHERE key = v_setting_key;
  IF v_max_leaves IS NULL THEN v_max_leaves := 2; END IF;
  IF NEW.used_count > v_max_leaves THEN
    RAISE EXCEPTION 'Leave quota exceeded. Maximum allowed leaves is %', v_max_leaves;
  END IF;
  RETURN NEW;
END; $$ LANGUAGE plpgsql;

CREATE TRIGGER trg_enforce_leave_quota_limits
BEFORE INSERT OR UPDATE ON leave_quota_usage
FOR EACH ROW EXECUTE FUNCTION enforce_leave_quota_limits();
```

- Trigger fires **only on INSERT/UPDATE to `leave_quota_usage`**. If self-service cancel/delay paths DO NOT write to `leave_quota_usage`, the trigger is dormant for those flows.
- `leave_quota_usage` schema has `teacherId XOR studentId` CHECK constraint — `teacherId` and `studentId` are mutually exclusive (one must be set, the other null).
- Setting keys: `teacher_max_leaves` and `student_max_leaves` (default 2 if not in `system_settings`).

### Teacher-leave path uses the trigger (`backend/services/session/class-session.service.ts`)

`updateStatusLeave` (line 523):
1. `assertPermission(userId, SESSION_UPDATE_STATUS_LEAVE)`
2. `getOrThrow(classInstanceId)`
3. `assertSessionActivated(instance)`
4. **`SystemRulesService.assertLeaveQuotaAvailable(instance.teacherId)`** — pre-checks teacher quota BEFORE writing
5. `db.transaction(tx => { EffectiveMeetingService.resolveForNewBooking + SchedulingRepository.processClassLeave(... join_url) })` — `processClassLeave` writes to `leave_quota_usage` (teacher_id set, student_id null).

### DECISION confirmed (design F2): self-service cancels are EXEMPT from student leave quota

- The new `leave-request.service.ts` approve-cancel path MUST NOT call `SystemRulesService.assertLeaveQuotaAvailable(studentId)` and MUST NOT write to `leave_quota_usage` (it should reuse `refundCreditIfDeducted` / `releaseQuotaIfDeducted` only — line 232+ in class-session.service.ts).
- The trigger risk is eliminated by policy (simply not writing the row), per the R3 design decision.
-approve-delay path calls `reschedule()` (line 625 of class-session.service.ts) — `reschedule` already asserts `SESSION_RESCHEDULE` (the supervisor approval gate) and writes the meeting URL regen; no quota involvement.
