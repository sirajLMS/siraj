## Phase 3.5: Environment-Config Cold-Start Resilience

### File Modified
- `backend/services/system/environment-config.service.ts`

### 3.5.1: Fix cache `source` tag when DB lookup fails
- `commitDbResolvedValue()` now accepts a `source: "db" | "env"` parameter
- When DB lookup succeeds (hit or miss): `source: "db"` (authoritative)
- When DB lookup fails (error): `source: "env"` (non-authoritative — next call re-queries DB)
- Both single-key (`resolveEnvConfig`) and batch (`recordResolvedKey`) paths updated

### 3.5.2: Short-TTL retry for transient DB failures
- Added `SHORT_CACHE_TTL_MS = 30_000` (30 seconds) constant
- Added `isTransientError` import from `@/backend/lib`
- Transient DB error: 30s TTL with `source: "env"` — DB re-queried sooner
- Non-transient DB error: full 5min TTL with `source: "env"`
- Extracted `performDbLookup()` and `resolveTtl()` helpers to keep cognitive complexity under limit
- Applied to both single-key and batch (`lookupDbValueFor`) paths

### 3.5.3: Verification
- `CACHE_PROVIDER` resolution chain verified:
  1. DB lookup fails (transient) → catch → `process.env.CACHE_PROVIDER` checked → cached `source: "env"`, 30s TTL
  2. After 30s, cache expires → DB re-queried → override picked up
