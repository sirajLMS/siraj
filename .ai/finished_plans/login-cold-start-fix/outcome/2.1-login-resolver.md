# Tasks 2.1-2.6: Login Resolver Error Handling

## File Modified
- `backend/graphql/mutation/auth/auth.mutation.ts` — Login resolver cold-start resilience

## Changes Applied

### 2.1: checkRateLimit fail-open (REQ-1)
- Wrapped `checkRateLimit(ipAddress, authRateLimiter)` in try/catch
- Default `rateLimitResult = { success: true }` — on error, proceeds with login
- On catch: `logger.warn("Rate limit check failed (cold-start), failing open")`

### 2.2: isLocked fail-open (REQ-1)
- Wrapped `RateLimitService.isLocked(ipAddress, email.value)` in try/catch
- Default `isLocked = false` — on error, proceeds with credential verification
- On catch: `logger.warn("isLocked check failed (cold-start), failing open")`

### 2.3: findByEmail retry (REQ-1, REQ-2)
- Wrapped `UserService.findByEmail(email.value)` with `retryTransient()`
- Existing try/catch retained — throws SERVICE_UNAVAILABLE if retries exhausted
- `retryTransient` import added from `@/backend/lib` barrel

### 2.4: recordAttempt fail-open (REQ-1)
- Both `recordAttempt` calls (user-not-found + invalid-password paths) wrapped in try/catch
- On catch: `logger.warn("recordAttempt failed (cold-start), continuing")`
- Invalid-password path: default `result = { isLocked: false }` — doesn't block login with false lock

### 2.5: resetAttempts fail-open (REQ-1)
- Wrapped `RateLimitService.resetAttempts(ipAddress, email.value)` in try/catch
- On catch: `logger.warn("resetAttempts failed (cold-start), continuing")`
- Does NOT block successful login

### 2.5.5: createAuthSession retry (REQ-4.5)
- Wrapped `createAuthSession(user.id, user.email)` with `retryTransient()`
- Critical: credentials already verified when this runs — without retry, cold-start failure forces a second Vercel invocation
- 3 retries (~1.7s) should allow DB pool to warm within the same invocation

### 2.6: Quality verification
- All checks pass: tsgo ✅, oxlint ✅, biome ✅, lint:type-aware ✅, duplicates ✅, codescene ✅

## Import Change
- Added `retryTransient` to existing `@/backend/lib` import (already had `extractTokenFromHeader`, `generateAccessToken`, etc.)

## Carry-Forward Knowledge
- The `login` resolver now has a **backend-first** cold-start resolution strategy:
  - Fail-open: `checkRateLimit`, `isLocked`, `recordAttempt`, `resetAttempts`
  - Retry 3x: `findByEmail`, `createAuthSession`
- User NEVER sees "invalid credentials" during cold start — only genuine credential failures
- The `demoLogin` resolver was NOT modified (it uses different code paths)
