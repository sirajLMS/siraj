# Task 2.17: Consolidate Parallel Test Runners - Outcome

## Summary

Consolidated three near-identical parallel test runner scripts into a single configurable shared runner. All common logic (ANSI parsing, file discovery, worker pool, result aggregation, failure reporting) was extracted into `scripts/test/run-parallel-tests.ts`. The three existing scripts now act as thin configuration wrappers that pass a `RunParallelTestsConfig` to the shared `runParallelTests()` function.

## Changes Made

### New File: `scripts/test/run-parallel-tests.ts`

Shared parallel test runner exporting:
- `RunParallelTestsConfig` — config interface (pattern, cwd, maxWorkers, label, timeoutMs)
- `TestRunResult` — result interface (passed, failed, duration, errors)
- `runParallelTests(config)` — main entry point

Internal structure:
- ANSI/parsing helpers: `stripAnsi`, `extractSummaryStats`, `shouldSkipLine`, `formatTestLine`, `parseTestOutput`
- `runSingleTestFile(file, timeoutMs, acc)` — single file execution, writes to accumulator
- `processQueue(queue, timeoutMs, acc)` — recursive worker that drains the queue
- `printFailureSummary(details)` — prints failure logs at the bottom
- `printFinalSummary(...)` — prints Bun-style summary stats
- `runParallelTests(config)` — orchestration: discover → spawn workers → aggregate → print → exit

## Behavioral Preservation

All original behaviors are preserved:
- File discovery uses `Glob` scan with the same patterns and cwd directories
- Worker count capped at `Math.min(availableParallelism(), fileCount, maxWorkers)`
- `DATABASE_URL` dropped in local mode (non-CI) so `--env-file=.env.test` is authoritative
- `TEST_CI=true` preserves workflow `DATABASE_URL` (Postgres service)
- `FORCE_COLOR=1` and `NODE_ENV=test` set on each worker env
- `--env-file=${TEST_ENV_FILE}` and `--timeout=${timeoutMs}` passed to each `bun test` child
- ANSI-styled output (✓ green, ✗ red, gray headers) identical to originals
- Failure summary with STDOUT/STDERR sections printed at bottom
- Final summary with pass/fail/expect counts and "Ran N tests across M files" line
- Exit code 1 on any failure, 0 on all pass with "All tests passed!" message

## Lint Fixes Applied

During sub-loop verification, two ESLint issues were found and fixed in the shared runner:
1. **Cognitive complexity** (18, limit 15) — resolved by extracting nested `runSingleTestFile` and `worker` into module-scoped functions, reducing `runParallelTests` nesting level
2. **Unused collection** (`errors: Error[]`) — removed entirely; the array was populated but never consumed (callers rely on `process.exit` for exit codes, not the return value)

Additionally, JSDoc comments with backtick-enclosed glob patterns containing `**/*.test.ts` were converted to plain `//` comments to avoid premature `*/` comment termination by the TypeScript parser.

## Carry-Over Knowledge

- The shared runner uses `globalThis.console.log` (not `console.log`) to avoid ESLint's `no-console` rule — same pattern as the original scripts
- The `TestRunResult` return type is declared but `process.exit()` is called before return for CLI compatibility; callers that import `runParallelTests` programmatically should be aware of this exit behavior
- JSDoc comments should not contain backtick-enclosed strings with `*/` patterns (e.g., `**/*.test.ts`); use `//` line comments instead for such patterns
- The `scripts/test/` directory was created for this task — future shared test utilities should live here
