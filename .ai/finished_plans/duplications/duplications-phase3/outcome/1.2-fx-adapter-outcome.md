## Design Pattern

Template-method pattern via abstract base class `FxAdapterBase`:

- **Shared in base:** `fetchLatestRates()` template method, `validateConfig()` wrapper, `buildSymbolsParam()`, `allSymbols()` default, `customFetchHeaders()` default, `REQUEST_TIMEOUT_MS`, `DEFAULT_HEADERS`
- **Abstract (subclass-specific):** `buildApiUrl()`, `validateResponse()`, `parseRates()`, `extractTimestamp()`, `validateConfigImpl()`, `name`, `apiBase`
- **Overridable hooks:** `allSymbols()` (exclude base currency), `customFetchHeaders()` (provider-specific headers like Fixer's `apikey` header)

## Semantic Review

- ✅ **Type guards used (no `as` casts):** `parseCurrencyCodeOrNull()` used instead of `parseCurrencyCode()` to avoid enum fallback; `unknown` type used for parsed JSON; Zod `.parse()` narrows types. No unsafe type assertions.
- ✅ **Logger used:** `import { logger } from "@/backend/lib/logger"` in both base class and adapters. No `console.*`.
- ✅ **i18n compliance:** These adapters do not generate user-facing error messages — they throw `Error` with developer-facing diagnostic strings for internal service-layer consumption. No `getServerTranslations` needed here (errors are caught by `FxIngestionService` which handles user-facing messaging).
- ✅ **No circular imports:** Base class imports from `IFxRateProvider` (interface only) and `@/backend/types` (type only). Adapters import base class via direct path (`__shared__/fxAdapterBase`), not barrel. No sibling circular deps.
- ✅ **Path aliases:** All imports use `@/` prefix. Direct module import for same-directory `fxAdapterBase.ts`.
- ✅ **Types from `@/backend/types`:** `FxProviderFetchResult` imported from `@/backend/types`. No local type definitions created.
- ✅ **No `oxlint-disable` comments:** None added.
