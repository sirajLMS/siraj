## Factory API

```typescript
// test/ui/components/helpers/sessionActivateButtonTests.ts

export interface SessionActivateButtonTestCase {
  readonly name: string;
  readonly run: () => void | Promise<void>;
}

/**
 * Returns shared test cases for SessionActivateButton desktop and mobile variants.
 * Both tier components share SessionActivateButtonProps, so assertions are identical —
 * only the component reference differs.
 * Call test(tc.name, tc.run) for each entry inside a describe in the consumer test file.
 */
export function makeSessionActivateButtonTests(
  Component: ComponentType<SessionActivateButtonProps>,
): readonly SessionActivateButtonTestCase[];
```

### Consumer Pattern

```typescript
// SessionActivateButton.desktop.test.tsx
describe("SessionActivateButtonDesktop", () => {
  const cases = makeSessionActivateButtonTests(SessionActivateButtonDesktop);
  for (const tc of cases) {
    test(tc.name, tc.run);
  }
});
```

## Design Decisions

1. **Factory returns test case objects (not `test()` calls)**: The factory returns `SessionActivateButtonTestCase[]` (array of `{ name, run }` tuples) rather than calling `test()` internally. This is required because the `sonarjs/no-empty-test-file` ESLint rule checks for `test()` or `it()` `CallExpression` nodes in the file's AST — test files that only call a factory function with no visible `test()` calls are flagged as empty. By returning test cases, the consumer test files contain real `test()` calls inside `describe`, satisfying the linter.

2. **Uses `createElement` instead of JSX**: The factory file uses `.ts` extension (not `.tsx`) — `createElement(Component, props)` avoids JSX syntax, keeping the file type-checkable without a `.tsx` extension and avoiding `react/jsx-no-undef` lint issues. This also makes it clear the factory is a utility, not a test file.

3. **`describe` stays in the test file**: Each consumer test file owns its own `describe` block with the tier-specific label (`"SessionActivateButtonDesktop"` / `"SessionActivateButtonMobile"`). The factory doesn't create `describe` blocks — it just provides the test case data.

4. **Props type imported from canonical source**: `SessionActivateButtonProps` is imported from `@/frontend/common/views/dashboard/teachers/dashboard/types/teacherDashboardComponentProps` — the shared tier-neutral type already used by both desktop and mobile components.
