## Type Error Fix Applied

### `scheduling-queries.repository.helpers.ts`

The previous agent extracted join conditions into a `parentUserJoins` tuple array with `as const`:

```ts
const parentUserJoins = [
  [students, eq(classInstances.studentId, students.id)],
  [parents, eq(students.parentId, parents.id)],
  [users, eq(parents.userId, users.id)],
] as const;
```

Then accessed joins via index lookups: `.innerJoin(parentUserJoins[0][0], parentUserJoins[0][1])`.

**Problem:** Drizzle's `.innerJoin()` method overloads couldn't resolve the table + condition types from indexed tuple access, producing 3 tsgo errors:
- `TS2304: Cannot find name 'SelectedFields'` (line 12)
- `TS2304: Cannot find name 'PgSelectBuilder'` (line 13)
- `TS7006: Parameter 'row' implicitly has an 'any' type` (line 227)

**Fix:** Replaced the tuple array with named join condition constants and inlined the join chain using those constants:

```ts
const studentJoin = eq(classInstances.studentId, students.id);
const parentJoin = eq(students.parentId, parents.id);
const userJoin = eq(parents.userId, users.id);

function selectSingleInstanceParentUser(q: QueryDbHandle | DBTransaction) {
  return q
    .select(singleInstanceSelect)
    .from(classInstances)
    .innerJoin(students, studentJoin)
    .innerJoin(parents, parentJoin)
    .innerJoin(users, userJoin);
}
```

This preserves the DRY extraction (join conditions are module-level constants shared across both helpers) while allowing Drizzle's type inference to work correctly with direct table references.
