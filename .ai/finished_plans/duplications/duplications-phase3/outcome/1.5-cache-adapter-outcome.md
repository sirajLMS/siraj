## Design Decisions

1. **Template Method Pattern**: `CacheAdapterBase` uses the template method pattern — `stats()` is a concrete method that calls abstract `getProviderName()` and `getCacheSize()`. This allows each adapter to specify only its provider-specific logic while sharing the stats aggregation and error handling.

2. **Discriminated Union for Type-Safe Cache Hit**: `CacheHit<T> = { hit: true; data: T } | { hit: false }` allows TypeScript to narrow `cached.data` to `T` when `cached.hit === true`, avoiding `as T` casts (which oxlint's `no-unsafe-type-assertion` flags).

3. **`__shared__` directory**: Follows the design spec's convention for cross-adapter shared code. The double-underscore prefix groups shared infrastructure separately from the adapters themselves.

4. **No circular imports**: `CacheAdapterBase` imports from `EntityCacheService` (for `getEntityCacheStats`), `ICacheService`, and `CacheInterface` — but `EntityCacheService` does not import `CacheAdapterBase`, so there is no circular dependency. Adapters import `CacheAdapterBase`, and `CacheServiceFactory` imports adapters — the dependency chain flows one direction.

5. **PascalCase file naming**: The existing codebase uses PascalCase for adapter files, so `CacheAdapterBase.ts` follows the same convention (the task spec's camelCase was incorrect per the actual codebase).
