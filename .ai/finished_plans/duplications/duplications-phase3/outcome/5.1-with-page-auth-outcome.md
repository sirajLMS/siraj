# Task 5.1 — withPageAuth Helper Extraction

## Summary

Extracted the duplicated auth triplet pattern (`getServerUserContext` + permission check + redirect) found in ~65 app router page files into a single higher-order function `withPageAuth` in `backend/lib/auth/withPageAuth.ts`. Refactored 59 page files to use the HoF, eliminating ~177 lines of duplicated boilerplate (3 lines × 59 files).

## Files Created

- `backend/lib/auth/withPageAuth.ts` — The HoF that wraps the standard auth triplet
- `backend/lib/auth/index.ts` — Added `export * from "./withPageAuth"` to barrel

## withPageAuth API

```typescript
type PageAuthContext = {
  userId: string;
  context: UserPermissionContext | null;
  locale: string;
};

function withPageAuth<T>(
  permissions: readonly AppPermission[] | null,
  handler: (auth: PageAuthContext, props: T) => Promise<PageReturn> | PageReturn
): (props: T) => Promise<PageReturn>
```

- `permissions: null` — auth-only (no permission check), used for teacher-scoped pages and profile redirects
- `permissions: [AppPermission.X, ...]` — calls `requirePermissionForPage` after auth
- `T` is unconstrained — each page declares its own params/searchParams shape explicitly
- `PageReturn = ReactElement | null | undefined` (not `JSX.Element` — that causes TS2503 in Next.js 16)
- Internally calls `getLocale()` and `getServerUserContext()`, so handler receives `locale` and `context`

## Patterns Identified & Refactored

### Pattern A — Standard auth + permission (most common)
```typescript
// Before
const { userId, context } = await getServerUserContext();
if (!userId) { await redirectToLogin(); }
await requirePermissionForPage(userId, permissions, locale, context);
return <Component />;

// After
export default withPageAuth([AppPermission.X], async () => {
  return <Component />;
});
```

### Pattern B — auth + requireTeacherIdForPage (teacher-scoped)
```typescript
export default withPageAuth(null, async ({ userId, context, locale }) => {
  const teacherId = await requireTeacherIdForPage(userId, locale, context);
  return <Component teacherId={teacherId} />;
});
```

### Pattern C — auth-only + redirect (profile redirects)
```typescript
export default withPageAuth(null, async () => {
  redirect("/teachers/me/profile");
});
```

### Pattern E — auth + feature flag redirect (staff/parents/teachers/users)
```typescript
export default withPageAuth([AppPermission.X], async () => {
  if (await isUsersDirectoryEnabled()) { redirect("/users?tab=..."); }
  return <Component />;
});
```

## Behavior Changes

### Feature flag redirect ordering (staff/parents/teachers/users)
- **Before**: `isUsersDirectoryEnabled()` check ran BEFORE auth — unauthenticated users visiting `/staff` would be redirected to `/users?tab=staff` without hitting login
- **After**: Auth runs first via `withPageAuth` — unauthenticated users get redirected to login first, then after auth, redirected to `/users?tab=staff` if the feature flag is enabled
- **Impact**: One extra redirect hop for unauthenticated users. The end destination is the same (login → back to page → redirect to /users). This is arguably more correct (authenticate before feature-gated redirects).

### `parents/[id]/lifecycle` context check
- **Before**: Checked `!userId || !context` and called `redirectToLogin()` if either was falsy
- **After**: `withPageAuth` only checks `!userId`. If `context` is null but `userId` exists, the handler still runs.
- **Impact**: Minimal — `ParentLifecycleService.getParentLifecycleData(id)` doesn't use `context`. The original code's `context` check was redundant since `redirectToLogin()` throws (never returns), so no code after it executed anyway.

## Key Design Decisions

1. **Unconstrained generic `T`**: Initially tried `T extends PageAuthProps` but TypeScript couldn't narrow `params.id` properly. Making `T` unconstrained and having each page declare its own type (e.g., `withPageAuth<{ readonly params: Promise<{ readonly id: string }> }>`) resolved this.

2. **`ReactElement` not `JSX.Element`**: Using `JSX.Element` as return type caused TS2503 ("Cannot find namespace 'JSX'") in Next.js 16. Used `ReactElement | null | undefined` imported from "react" instead.

3. **`permissions: null` for auth-only**: Instead of a separate `withPageAuthOnly` function, used `null` to indicate no permission check needed. This covers teacher-scoped pages (requireTeacherIdForPage handles access) and profile redirect pages.

4. **`locale` in handler context**: The HoF calls `getLocale()` internally and passes it to the handler, eliminating the need for pages to call it separately. This also ensures the locale is available for error messages in `requirePermissionForPage`.
