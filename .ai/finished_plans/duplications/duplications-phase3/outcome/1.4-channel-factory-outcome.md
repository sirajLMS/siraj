## Pattern Used

**Generic factory function** (`createChannelFactory<TChannel>()`) — chosen over abstract class because:
1. The three factories are function-based (not class-based), using module-level singletons
2. The shared logic is lifecycle management (singleton init, reset, facade delegation) — naturally fits a higher-order function
3. Each channel needs only to provide its `createAdapter` function and config — no method overrides needed

### Shared Logic Extracted
1. **Singleton lifecycle:** `instance` + `initializationPromise` with lazy init + error handling
2. **Provider resolution:** `resolveEnvConfig` → validate → fallback to default
3. **Channel creation:** log provider, delegate to adapter creator
4. **Reset:** disconnect instance, null state, invalidate env-config caches
5. **Facade:** `send`/`validateConfig`/`disconnect` delegators

### Channel-Specific Logic Kept
- Email: `createResendAdapter()` — dynamic import + `resolveEnvConfigMany` for `RESEND_API_KEY`/`RESEND_FROM_EMAIL` + validation
- Push: `createFcmAdapter()` — dynamic import + `resolveEnvConfigMany` for `FIREBASE_*` credentials
- SMS: `createTwilioAdapter()` — dynamic import + `resolveEnvConfigMany` for `TWILIO_*` credentials + validation
