## Base Types Created

### `backend/types/meeting/meeting-config-base.types.ts`

1. **`MeetingConfigDetails`** — Moved from `meeting-config.types.ts` to avoid circular import (base file is imported by meeting-config.types.ts). Re-exported from meeting-config.types.ts for backwards compatibility.
2. **`MeetingConfigBaseSelectType`** — Shared select fields: id, providerId, label, isDefault, details, encryptedSecret, providerMetadata, createdAt, updatedAt
3. **`MeetingConfigBaseInsertType`** — Same fields with optional modifiers on id, createdAt, updatedAt, encryptedSecret, providerMetadata
4. **`MeetingConfigBaseReturnType`** — Extends BaseSelectType with `hasSecret?` and `provider?`
5. **`MeetingConfigBaseSubmitInput`** — Omit id/createdAt/updatedAt/encryptedSecret/providerMetadata from BaseInsertType, adds `password?`

### `backend/types/shared/pagination.types.ts`

6. **`PaginationArgsShape`** — Canonical shape for pagination parameters. Used by:
   - `PaginationArgs` constructor parameter type (replaces inline 8-field type)
   - `PaginationInput` type (via `Omit<PaginationArgsShape, "defaultCount">`)

## Design Decisions

1. **Flat convention — no `__shared__/` subdirectory** — The base type file lives at `backend/types/meeting/meeting-config-base.types.ts` (not in a `__shared__/` subdir). This matches the existing `meeting/` directory structure and the design's instruction that `backend/types/` uses flat `{entity}.types.ts` naming.

2. **`MeetingConfigDetails` moved to base file** — The original `MeetingConfigDetails` was defined in `meeting-config.types.ts`, but `class-meeting-config.types.ts` imported it. Since both consumer files now import base types from `meeting-config-base.types.ts`, moving `MeetingConfigDetails` there avoids a circular import (base→meeting-config→base). The type is re-exported from `meeting-config.types.ts` so all existing imports continue to work without changes.

3. **Pagination: `PaginationArgsShape` extracted** — The 8-field pagination shape appeared three times: as class properties (lines 18-25), as the constructor parameter destructuring type (lines 37-44), and in `PaginationInput` (lines 92-99, minus `defaultCount`). Extracting `PaginationArgsShape` as a shared type and deriving `PaginationInput` via `Omit` eliminates the intra-file duplication. The class properties remain as-is (they are runtime declarations, not type-level duplicates — TypeScript class properties can't "extend" a type).

4. **Class properties changed from optional to definite** — Original properties were declared as `first?: number | null` (optional). Changed to `first: number | null` (definite) because the constructor ALWAYS assigns all of them (with `null` defaults). Since every property is assigned in the constructor, they are never `undefined`, making the `?` modifier semantically misleading. This is a tightening of the type, not a behavioral change.

5. **`MeetingConfigBaseReturnType` extends `MeetingConfigBaseSelectType`** — Both `ClassMeetingConfigReturnType` and `UserMeetingConfigReturnType` had `hasSecret?` and `provider?` added on top of their Select types. The base ReturnType captures this, so consumer types only need to add their specific fields (e.g., `classInstanceId`, `recurringScheduleId`, or `userId`).
