## Slot Props Design

```typescript
export interface EditCategoryDialogSlotProps {
  readonly dialogProps: Readonly<Record<string, unknown>>;
  readonly actionsSx: SxProps<Theme>;
  readonly actionButtonsFullWidth: boolean;
  readonly cancelButtonSx: Record<string, unknown> | undefined;
  readonly saveButtonSx: Record<string, unknown> | undefined;
  readonly actionOrder: "cancel-first" | "save-first";
}
```

**`dialogProps`**: Spread onto the `<Dialog>` component. Desktop passes `{ fullWidth: true, maxWidth: "sm", "aria-labelledby": ... }`, mobile passes `{ fullScreen: true, "aria-labelledby": ... }`.

**`actionsSx`**: Applied to `<DialogActions sx={...}>`. Desktop uses `{ px: 3, pb: 3 }` (horizontal row), mobile uses `{ px: 3, pb: 3, flexDirection: "column", gap: 1 }` (vertical stack).

**`actionButtonsFullWidth`**: Controls `fullWidth` prop on both action buttons. Desktop: `false` (auto width), mobile: `true` (stretch to fill).

**`cancelButtonSx` / `saveButtonSx`**: Extra style objects merged into the button's base `sx` callback. Desktop: `undefined` (no extra styles). Mobile: `{ py: 1.5 }` (taller touch targets).

**`actionOrder`**: Controls the render order of cancel/save buttons. Desktop: `"cancel-first"` (Cancel left, Save right), mobile: `"save-first"` (Save top, Cancel bottom in stacked layout).

## Button Sx Merging Strategy

The scaffold uses a simple spread approach instead of MUI `SxProps` array syntax:

```typescript
function cancelSx(theme: Theme): Record<string, unknown> {
  return { color: theme.palette.text.secondary, fontWeight: 700, borderRadius: 1.5 };
}

// In the component:
sx={theme => ({ ...cancelSx(theme), ...extraSx })}
```

This avoids:
1. MUI v9 `SxProps` array type inference issues (tsgo TS2769 errors)
2. `no-unsafe-type-assertion` oxlint violations from `as Record<string, unknown>` casts
3. Complex type guard helpers for a simple object merge
