# Tasks 2.1 & 2.2: System Group Permission Bundle Editing

## Summary

Enabled editing of permission bundles for system permission groups via `updateGroup`
while keeping name/slug/description immutable and delete blocked. Both the repository
layer and service layer were updated.

## Files Changed

- `backend/db/repo/permissions/permission-management.repository.ts` — `updateGroup`
- `backend/services/auth/permission-management.service.ts` — `updateGroup`

## Task 2.1: Repository `updateGroup`

### Before (lines 352-354)

```typescript
if (existing.isSystem) {
  throw new Error(errorsTranslations.permissionManagement.cannotModifySystemPermissionGroup);
}
```

All updates to system groups were blocked with an error.

### After

```typescript
if (existing.isSystem) {
  // System groups: only permissionIds can be updated; name/slug/description are immutable
  if (input.permissionIds === undefined) {
    const gpList = await t.select().from(groupPermissions).where(eq(groupPermissions.groupId, input.id));
    return toGroupReturn(existing, gpList.map(gp => gp.permissionId), locale);
  }
  // Skip name/slug/description update; only replace permissionIds
  await t.delete(groupPermissions).where(eq(groupPermissions.groupId, input.id));
  if (input.permissionIds.length > 0) {
    await t.insert(groupPermissions).values(
      input.permissionIds.map(permissionId => ({ groupId: input.id, permissionId }))
    );
  }
  const gpList = await t.select().from(groupPermissions).where(eq(groupPermissions.groupId, input.id));
  return toGroupReturn(existing, gpList.map(gp => gp.permissionId), locale);
}
```

### Behavior Matrix

| Condition | Result |
|-----------|--------|
| System group + `permissionIds` provided | Delete old group_permissions + insert new ones; name/slug/description unchanged |
| System group + `permissionIds: []` | Clear all group_permissions; name/slug/description unchanged |
| System group + `permissionIds: undefined` | No-op — return existing group as-is |
| Non-system group | Existing behavior (lines 369-411) unchanged |

### `deleteGroup` guard preserved

The `deleteGroup` `isSystem` guard (throwing `cannotDeleteSystemPermissionGroup`)
remains unchanged. System groups cannot be deleted.

## Task 2.2: Service `updateGroup`

### Before (lines 289-319)

```typescript
export async function updateGroup(actorUserId, input, tErrors, locale) {
  await requireManageAccess(actorUserId, tErrors);

  let slug: string | undefined;
  if (input.name !== undefined) {
    const validated = await validateGroupName(input.name, tErrors);
    slug = validated.slug;
  }

  return PermissionManagementRepository.updateGroup(
    { id: input.groupId, name: input.name, slug,
      description: trimLocalizedString(input.description), permissionIds: input.permissionIds },
    locale
  );
}
```

The service always called `validateGroupName` when `input.name` was provided and passed
the name/description through to the repository. For system groups, the frontend always
sends `name` even for permission-only updates, so this would trigger validation and pass
the name through — previously blocked by the repository's `isSystem` throw.

### After

```typescript
export async function updateGroup(actorUserId, input, tErrors, locale) {
  await requireManageAccess(actorUserId, tErrors);

  const group = await requireGroupExists(input.groupId, tErrors);

  let slug: string | undefined;
  if (input.name !== undefined && !group.isSystem) {
    const validated = await validateGroupName(input.name, tErrors);
    slug = validated.slug;
  }

  return PermissionManagementRepository.updateGroup(
    {
      id: input.groupId,
      name: group.isSystem ? undefined : input.name,
      slug,
      description: group.isSystem ? undefined : trimLocalizedString(input.description),
      permissionIds: input.permissionIds,
    },
    locale
  );
}
```

### Key changes

1. **Fetch group first**: `const group = await requireGroupExists(input.groupId, tErrors)` —
   uses the existing helper (line 97-101) to fetch the group and check `isSystem`.
2. **Skip `validateGroupName` for system groups**: the `if` guard now checks
   `!group.isSystem` so slug derivation is skipped for system groups.
3. **Pass `name: undefined` for system groups**: `group.isSystem ? undefined : input.name`
   tells the repository to leave the name untouched.
4. **Pass `description: undefined` for system groups**: `group.isSystem ? undefined : trimLocalizedString(input.description)`
   tells the repository to leave the description untouched.
5. **`permissionIds` always passed through**: unchanged — system groups can have their
   permission bundle replaced.
