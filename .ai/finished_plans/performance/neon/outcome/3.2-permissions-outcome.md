# Task 3.2 Outcome: DataLoader Batching (permissions Domain)

**Date:** 2026-07-31
**Task:** Fix N+1 pattern for `assignedUsers` on `PermissionGroup`
**Status:** ✅ Completed

---

## Summary

Eliminated the N+1 pattern for `assignedUsers` resolution on `PermissionGroup` by pre-computing group users in the service layer and switching from `t.field()` with a per-group resolver to `t.expose()`. Removed the module-level cache that partially mitigated the issue.

---

## Changes Made

### 1. `backend/types/permissions/permission-management.types.ts`
- Added `assignedUsers: GroupUserEntity[]` to `GroupWithPermissionIds` type

### 2. `backend/db/repo/permissions/permission-management.repository.ts`
- Added `assignedUsers: []` default to `toGroupReturn()` so all repo-returned groups satisfy the new type

### 3. `backend/services/auth/permission-management.service.ts`
- **`listGroups()`**: After fetching groups from repo, batch-fetches all group users via `listAllGroupUsers()` and attaches `assignedUsers` to each group
- **`getGroup()`**: After fetching single group, batch-fetches all group users and attaches only the matching group's users

### 4. `backend/graphql/pothos/permissions/permission-management.pothos.ts`
- Changed `assignedUsers` from `t.field()` with async resolver to `t.expose("assignedUsers", { type: [GroupUserObject] })`
- Removed module-level `groupUsersCache`, `clearGroupUsersCache()`, and `getGroupUsersMap()` helper
- Removed `PermissionManagementRepository` import (no longer needed in Pothos layer)
- Removed `clearGroupUsersCache()` calls from mutation helpers and query resolvers

---

## Before / After

**Before (N+1):**
```
permissionGroups { assignedUsers { id name email } }
→ 1 query for groups + N queries for group users (cached to 1 on subsequent calls)
→ module-level cache: fragile state management with clear on mutations
```

**After (pre-computed, no cache):**
```
permissionGroups { assignedUsers { id name email } }
→ 1 query for groups + 1 batched query for all group users
→ No cache, no N+1, assignedUsers pre-attached in service layer
```
