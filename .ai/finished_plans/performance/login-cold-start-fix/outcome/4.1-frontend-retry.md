# Phase 4: Frontend Auto-Retry — Outcome

## Summary

Implemented frontend retry logic as a **last resort** when the backend cannot recover within a single Vercel function invocation. The ViewModel now uses `useMutation` directly (instead of `useAuth().login()`) to access GraphQL error codes, specifically `SERVICE_UNAVAILABLE`.

## Key Technical Decisions

1. **`useMutation` direct call**: Apollo v4 `useMutation` returns `MutateResult` which doesn't destructure as `{ data, errors }`. Used try/catch pattern — errors are thrown, not returned in the result object.

2. **`performLoginRef` pattern**: The recursive retry call inside `useCallback` triggers `react-hooks/immutability` ("accessed before declared"). Fixed by storing the function in a ref and calling `performLoginRef.current()` for the recursive call. The ref is updated in a `useEffect`.

3. **Type guard for error code**: `extensions.code` is typed as `unknown` (from `Record<string, unknown>`). Used `typeof code === "string" ? code : undefined` instead of `as string | undefined` to satisfy `no-unsafe-type-assertion`.

4. **Separated retry/error alerts**: `isRetrying || finalLoginResult` triggered `prefer-nullish-coalescing` lint. Split into two independent conditional blocks: `{isRetrying && <Alert>}` and `{!isRetrying && finalLoginResult != null && <Alert>}`.

## Carry-Forward Knowledge

- Apollo v4 `useMutation` result: use try/catch, NOT destructuring of `{ data, errors }` — errors are thrown
- `performLoginRef` pattern: store `useCallback` function in a ref when it needs to call itself recursively
- `CombinedGraphQLErrors.is(error)` from `@apollo/client` is the type guard for Apollo error objects
- `prefer-nullish-coalescing` lint rule fires on `||` in JSX conditionals — split into separate `{cond && <JSX>}` blocks
