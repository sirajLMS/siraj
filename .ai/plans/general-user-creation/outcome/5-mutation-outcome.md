The Pothos-generated input type allows `null` for optional fields (`phone`, `status`), but `GeneralUserCreateInput` types them as `string | null` (phone) and `AccountStatus | undefined` (status, no null). The resolver explicitly maps:

```typescript

  email: args.input.email,
  password: args.input.password,

  status: args.input.status ?? undefined,

```

- `phone`: `args.input.phone ?? null` — normalizes `undefined` → `null` (Pothos optional string → `string | null | undefined`)
- `status`: `args.input.status ?? undefined` — normalizes `null` → `undefined` (Pothos optional enum → `AccountStatus | null | undefined`, backend type is `AccountStatus | undefined`)
