# IDOR & BOLA Security Assessment — Siraj LMS

## Executive Summary

| Severity | Count |
|---|---|
| CRITICAL | 3 |
| HIGH | 4 |
| MEDIUM | 3 |
| LOW / VERIFY | 3 |

The codebase invests heavily in **permission-based (BFLA) gating** via `authScopes` + service-layer `PermissionsService` checks, and that layer is broadly consistent. The systemic weaknesses are (a) **association/ownership checks are missing on several read paths that accept foreign IDs**, (b) **storage access falls open for unlinked files**, and (c) **RLS policies are effectively non-protective because `app.current_user_id` is never populated by the Drizzle/GraphQL request path** (defense-in-depth gap).

# IDOR & BOLA Remediation Plan

## CRITICAL & HIGH BOLA Fixes

### H1 — Cross-Tenant Invoice History / Billing Summary (Parent A → Parent B)

**File**: `backend/services/billing/billing-history.service.ts` (lines 33–50, 77–86)
**PoC**:

```graphql
# Authenticated as Parent A (parent_default includes billing.view_history)
query {
  parentBillingSummary(userId: "<parent-B-user-id-uuid>", parentId: null) {
    outstandingBalance
    paidThisTerm
  }
}
# or
query { parentInvoiceHistory(parentId: "<parent-B-parent-uuid>") { rows { amount currency studentName } } }
# Returns Parent B's financial ledger
```

**Root cause**: `resolveParentId()` uses the argument directly; `assertBillingViewPermission` only checks the *capability* (`BILLING_VIEW_HISTORY`), which the legit parent role carries for its own portal.

**Fix** (production-ready):

```typescript
// backend/services/billing/billing-history.service.ts
async function assertParentOwnershipOrAdmin(
  actorUserId: string,
  resolvedParentId: string,
  context: { isSuperAdmin?: boolean; permissions?: string[] } | null,
  tErrors: ErrorsLabels
): Promise<void> {
  const isAdmin =
    context?.isSuperAdmin === true ||
    context?.permissions?.includes(AppPermission.BILLING_VIEW_UNPAID_INVOICES) === true;
  if (isAdmin) return;
  const parent = await ParentRepository.findByUserId(actorUserId);
  if (!parent || parent.id !== resolvedParentId) {
    throw new ForbiddenError(tErrors.insufficientPermissions);
  }
}

// in both entrypoints, after computing resolvedParentId:
const ctxProbe = await PermissionsService.getUserContext(actorUserId);
await assertParentOwnershipOrAdmin(
  actorUserId,
  resolvedParentId,
  { isSuperAdmin: ctxProbe.isSuperAdmin, permissions: ctxProbe.permissions },
  tErrors
);
```

Thread `ctx` from the GraphQL resolvers (`parentInvoiceHistory`, `parentBillingSummary`) so the `UserPermissionContext` is passed (also fixes the cold-start extra query).

### H2 — Unlinked Storage Files Default-Allow

**File**: `backend/services/storage/storage.service.ts` (`checkFileAccess`, line ~140) + `app/api/storage/files/[[...path]]/route.ts` (line 120+)
**PoC**:
1. Authenticated attacker uploads/observes file path `private/billing/<uuid>.pdf` before junction row is committed.
2. `GET /api/storage/files/private/billing/<uuid>.pdf` → `usages.length === 0` → access granted.

**Fix**:

```typescript
export async function checkFileAccess(userId, filePath, locale?): Promise<{error;status}|null> {
  const tErrors = getServerTranslations(locale ?? "en").errorsTranslations.file;
  const file = await StorageDbRepository.fileByPath(filePath);
  if (file?.isProtected) {
    const usages = await StorageDbRepository.getFileUsages(filePath);
    // protected file must be explicitly linked + ownership-cleared
    if (usages.length === 0) return { error: tErrors.forbidden, status: 403 };
  }
  const usages = await StorageDbRepository.getFileUsages(filePath);
  if (usages.length === 0) return { error: tErrors.forbidden, status: 403 }; // default-deny change
  // ...existing user/superadmin/teacher/parent checks...
}
```

Keep a static allowlist for `public/` path prefix handled earlier in the route (already unauthenticated by design).

### H3 — Manual Class Entry BOLA + Credit Tamper

**File**: `backend/services/teacher/teacher-dashboard.service.ts` (`createManualEntry`, lines 71–119)
**PoC** (teacher Alice):

```graphql
mutation {
  createTeacherManualClassEntry(input: {
    studentId: "<foreign-student>",
    teacherId: "<foreign-teacher-B>",
    subjectId: "<any-subject>",
    scheduledStartAt: "...", scheduledEndAt: "...", durationMinutes: 60,
    classType: REGULAR
  }) { id }
}
```
→ Creates instance owned by teacher B, deducts foreign student's credit/quota.

**Fix**:

```typescript
export async function createManualEntry(userId: string, input: ManualEntryInput, tErrors: ErrorsLabels) {
  await assertPermission(userId, AppPermission.TEACHER_VIEW_DASHBOARD, tErrors);
  const actorTeacher = await TeacherRepository.findByUserId(userId);
  const isAdmin = await PermissionsService.hasAnyPermission(userId, [
    AppPermission.SCHEDULE_CREATE_CLASS, AppPermission.SESSION_OVERRIDE_ACTIONS,
  ]);
  if (!isAdmin) {
    if (!actorTeacher || input.teacherId !== actorTeacher.id) {
      throw new UnauthorizedError(tErrors.unauthorizedAction);
    }
    const assigned = await StudentRepository.hasTeacherAssignment(input.studentId, actorTeacher.id);
    if (!assigned) throw new UnauthorizedError(tErrors.unauthorizedAction);
  }
  // ...remainder unchanged
}
```

### H4 — Payment Method Enumeration (Masked but Leaky)

**File**: `backend/services/payment-method/payment-method.service.ts` (`listUserPaymentMethods`, line ~160)

```typescript
export async function listUserPaymentMethods(actorUserId, userId, direction?, _locale?) {
  await assertActorCanManageTarget(actorUserId, userId, getServerTranslations(_locale ?? "en").errorsTranslations);
  const rows = await UserPaymentMethodRepository.listByUserId(userId);
  const revealSensitive = actorUserId === userId || (await hasAdminPaymentAccess(actorUserId));
  const filtered = direction ? rows.filter(row => row.direction === direction || row.direction === PaymentDirection.BOTH) : rows;
  return buildMaskedPaymentMethods(filtered, revealSensitive);
}

export async function getUserPaymentMethod(actorUserId, id, locale?) {
  const existing = await UserPaymentMethodRepository.getById(id);
  if (!existing) return null;
  await assertActorCanManageTarget(actorUserId, existing.userId, getServerTranslations(locale ?? "en").errorsTranslations);
  const revealSensitive = actorUserId === existing.userId || (await hasAdminPaymentAccess(actorUserId));
  return buildMaskedPaymentMethod(existing, revealSensitive);
}
```

### H6 — RLS Defense-in-Depth: Wire `app.current_user_id` + Tighten Policies

**Problem**: RLS policies exist (`students`, `class_instances`, `student_progress`, `users`, invoices etc.) but no request path executes `SET LOCAL app.current_user_id = ...`, so `current_user_id()` returns NULL and policies degrade to "any non-parent/non-teacher sees everything" (e.g. parents are protected, but any staff/admin works under `FORCE RLS` with full access — if the app ever uses a non-table-owner role, invoices are wide open).

**Fix (pattern)** in the DB connection/transaction wrapper:

```typescript
// backend/db/index.ts — wrap every request-scoped tx
export async function withRlsContext<T>(userId: string | null, fn: (t: DBTransaction) => Promise<T>) {
  return db.transaction(async t => {
    await t.execute(sql`SELECT set_config('app.current_user_id', ${userId ?? ""}, true)`);
    return fn(t);
  });
}
```

Invoke `withRlsContext(ctx.user?.id ?? null, ...)` in the GraphQL context factory service delegation, and in API route handlers. Then tighten `invoices` policy:

```sql
CREATE POLICY invoices_tenant_policy ON invoices AS RESTRICTIVE
FOR ALL USING (
  deleted_at IS NULL
  AND (
    parent_id = (SELECT id FROM parents WHERE user_id = current_user_id())
    OR EXISTS (SELECT 1 FROM users u WHERE u.id = current_user_id() AND u.is_super_admin)
    OR current_user_id() IS NULL — service/system role bypasses via table owner
  )
);
```

(Regenerate with explicit parent/student/teacher joins for payments, quotas, quota_ledger, credit_transactions, lesson_reports, teacher_dues.)
