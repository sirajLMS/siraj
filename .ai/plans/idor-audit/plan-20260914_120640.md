# IDOR & BOLA Security Assessment — Siraj LMS

## Executive Summary

| Severity | Count | Theme |
|---|---|---|
| **CRITICAL** | 4 | `_view_other` over-grants in default groups; RLS GUC set never observed; payment-method cross-user reference |
| **HIGH** | 5 | Student profile field-scaffold leak; payment links/PII via role views; parent invoice storage-file access regression (functional authz break); log-injection surface |
| **MEDIUM** | 6 | Snapshot/PII leakage thresholds, second-order/queue trust, user enumeration |
| **LOW** | 3 | Info disclosure, rate-limit, misconfigured defaults |
| **VERIFY** | 4 | Pipeline-dependent items requiring runtime confirmation |

The codebase has a genuinely strong *service-layer* authorization discipline (most mutations/queries funnel through `PermissionsService.hasPermission` + association helpers). The systemic weaknesses are: **(1) default permission-group grants that nullify the `_view_other`/`_edit_other` model; (2) the RLS layer depending on a GUC the application never demonstrably sets; (3) shallow “loggedIn” authScopes with ad-hoc ownership checks inside resolvers not always applied.**

## CRITICAL & HIGH BOLA Fixes

### H1 — Revoke `_view_other` + `payment_methods.view_other` grants from parent_default & teacher_default
**Files:** `backend/db/migration/6a-profile-field-permissions.sql` (write NEW forward migration `48-prune-view-other-defaults.sql`), and verify `6d-profile-fine-grained-only.sql` idempotency.

**PoC:**
```
# Login as Parent A (parent_default group)
parentProfile(parentId: "PARENT-B-ID") { email phone address feeAmount facebook whatsapp }
→ returns full payload (expected: FORBIDDEN/narrowed)
profileByUserId(userId: "USER-C") { paymentMethods { details { phone } } }
→ returns masked wallet tail (expected: null)
```

**Fix (new migration, pseudo-SQL):**
```sql
DELETE FROM group_permissions gp
USING permission_groups g, permissions p
WHERE gp.group_id = g.id AND gp.permission_id = p.id
  AND g.slug IN ('parent_default','teacher_default')
  AND p.key::text ~ '^(profile\.[a-z_]+\.(view_other|edit_other))$';
-- keep *_view_own / *_edit_own intact
```

Additionally, code hardening in `backend/services/student/student-profile.service.ts`:
```ts
async function assertCanViewStudentProfile(actorUserId: string, studentId: string, t): Promise<void> {
  const ctx = await PermissionsService.getUserContext(actorUserId);
  if (ctx.isSuperAdmin) return;
  const associated = await resolveIsAssociatedViewer(actorUserId, studentId);
  if (associated) { /* require relevant *_view_own */ return; }
  const canViewOther = await PermissionsService.hasPermission(actorUserId, AppPermission.STUDENT_IDENTITY_VIEW_OTHER);
  if (!canViewOther) throw new Error(t.insufficientPermissions);
}
```
And include contact/identity fields in a `student_identity`/`student_parent` group path so the field filter actually strips them.

### H2 — RLS GUC enforcement (bypass elimination / grounding)
**Files:** `backend/db/repo/shared/` (add `withCurrentUser.ts`), all repos consuming identity-scoped policies (`students`, `user_payment_methods`, `payments`, `quota_ledger`, `meeting_provider_tokens`, `teacher_dues`, `student_progress`, `notification prefs`, `class_instances`).

**Fix:**
```ts
export async function withTenantScope<T>(userId: string, fn: (tx: DBTransaction) => Promise<T>): Promise<T> {

}
```
