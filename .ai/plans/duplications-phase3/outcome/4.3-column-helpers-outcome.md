## Helper API (matches design §8.3 spirit, adapted to actual schema patterns)

The design simplified the schema patterns; actual tables uniformly use
`{ withTimezone: true, precision: 3 }` options and conditionally apply
`.defaultNow()` / `.$onUpdate()`. Three variants observed:

1. `timestamp(...).notNull()` — service/repository supplies value (users, billing, teachers)
2. `timestamp(...).notNull().defaultNow()` — DB sets default (storage junctions, audit logs)
3. `updatedAt: timestamp(...).notNull().defaultNow().$onUpdate(() => new Date())` — auto-update on row change (whatsapp-accounts only)

The helpers preserve exact semantics via TypeScript overload-free options:

```ts
primaryKeyColumn()                                   // { id: uuid("id").defaultRandom().primaryKey() }
timestampColumns({ withDefaultNow, withOnUpdate })  // { createdAt, updatedAt }
createdAtColumn({ withDefaultNow })                 // { createdAt } for append-only tables
```

All helpers spread the returned object into `pgTable` config. Spread produces
**byte-identical Drizzle columns** — confirmed by `bun run db generate`.

## Design Deviations

The design §8.3 specified:
```typescript
function timestampColumns() {
  return {
    createdAt: timestamp("created_at").defaultNow().notNull(),
    updatedAt: timestamp("updated_at").$onUpdate(() => new Date()).notNull(),
  };
}
```

**Actual schema does NOT match this simplified form uniformly:**
1. Every real timestamp uses `{ withTimezone: true, precision: 3 }` options — design omitted these
2. `.defaultNow()` is conditional per-table, not universal — design applied it always
3. `.$onUpdate()` is used exactly once (whatsapp-accounts.ts), not on every `updatedAt`

**Adapted implementation:** Annotated the helper with a flexible `options` bag
(`withDefaultNow`, `withOnUpdate`) so each call-site matches its existing declaration
exactly. The design intent — eliminate duplication — is preserved; only the
parameter signature evolved to fit reality.
