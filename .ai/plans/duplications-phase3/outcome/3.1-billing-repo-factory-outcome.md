# Task 3.1 — Billing Repository CRUD Factory

## Summary

Eliminated cross-file CRUD duplication across the three "supported" billing repositories
(`supported-mobile-wallet`, `supported-online-account`, `supported-payment-link`) by extracting
a generic `makeBillingRepo()` factory and a shared `directionFilter()` helper into
`__shared__/`. Each consumer now delegates 8 identical CRUD methods to the factory and retains
only its entity-specific `upsertMany` and `toSelectType` mapper.

## Design Decisions

1. **`PgColumn` / `PgTable` from `drizzle-orm/pg-core`** — The generic `Column` from `drizzle-orm` is too abstract for `eq()` / `orderBy()` calls; `PgColumn` provides the correct type compatibility with Drizzle's query builder methods.

2. **` BillingTableShape` uses simple property names** (`id`, `slug`, `isActive`, `supportedDirections`) matching the schema column names — consumers pass `supportedMobileWallets.id`, etc. directly without renaming.

3. **`deactivateInput` config field** — Instead of hardcoding `{ isActive: false }` in the factory, each consumer passes its typed `Update*Input` partial. This avoids `as unknown as TUpdateInput` casts and keeps the factory generic.

4. **`extraActiveFilters` callback** — Mobile wallet needs a `countryCode` filter in `listActive` that the other two don't. Rather than duplicating `listActive` or adding a complex filter system, a simple optional callback returns `SQL | undefined`.

5. **`.then()` typing** — Drizzle's `.then()` callback receives `{ [x: string]: unknown }[]` (not `TRow[]`). The factory uses `(rows: unknown[]) => rows.map(r => toSelectType(r as TRow))` — the `as TRow` is a widening cast from `unknown` (safe, not flagged by oxlint).

6. **`BillingRepoConfig` has 4 generic params** (`TRow`, `TSelect`, `TUpdateInput`, `TFilters`); `makeBillingRepo` adds a 5th (`TInsert`) — `TInsert` is used only in the function signature, not in the config interface, to avoid unused generic param lint errors.
