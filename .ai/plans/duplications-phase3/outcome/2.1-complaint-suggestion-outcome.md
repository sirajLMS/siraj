## Shared Helpers Created

### `backend/services/communication/__shared__/complaintSuggestionBase.ts`

1. **`assertPermission(actorUserId, permission, locale): Promise<void>`** — Generic permission gate; throws localized `insufficientPermissions` error on failure
2. **`requireParentByActorUserId(actorUserId, permission, locale): Promise<{ id: string }>`** — Permission gate + parent lookup; returns parent, throws localized `parentNotFound` error if missing
3. **`resolveEntityById<T extends BaseEntity>(args): Promise<T>`** — Generic permission-gated entity resolution; fetches entity via `findFn`, throws localized not-found error if missing, optional info logging
4. **`softDeleteEntityLog(args): Promise<{ readonly deletedAt: string }>`** — Executes soft-delete via `deleteFn`, emits info log on success, re-throws with error log on failure; returns ISO date
5. **`buildResolutionResponse(resolved, resolution): ResolutionResult`** — Pure `ResolutionResult` constructor for admin response endpoints

## Types Created

### `backend/types/communication.types.ts`

- `BaseEntity` — Minimal entity shape with `readonly id: string`
- `BaseRepo<T extends BaseEntity>` — Repository interface with optional `getById`/`getByIds`

## Design Decisions

1. **Helper functions, not a class** — The design suggested `ComplaintSuggestionBaseService`, but the two services have different entity types (`ComplaintSelectType` vs `SuggestionSelectType`) with identical flow logic. Free-standing generic functions with `<T extends BaseEntity>` type parameters are more natural than forcing a class hierarchy.

2. **`resolveEntityById` keyed by `ResolveNotFoundErrorKey`** — The union `"complaintNotFound" | "suggestionNotFound"` is narrowed from `ErrorsLabels` keys to ensure type-safe indexing into the `ErrorsLabels` interface without unsafe `as` casts.

3. **`softDeleteEntityLog` separates permission from deletion** — The caller is responsible for permission gating (typically via `resolveEntityById`) so the soft-delete helper focuses on the delete+log+ISO-date pattern only. This avoids coupling the delete helper to a specific permission enum value.

4. **`markAsDuplicate` uses `assertPermission` but keeps entity lookups local** — The method fetches two entities (`sourceSuggestion`, `targetSuggestion`) with complex validation between them (self-duplicate check, target-already-duplicate check, circular duplicate check). Using `resolveEntityById` for each would duplicate the `tErrors` lookup and lose the inter-entity validation ordering. Only the permission gate was extracted.

5. **`getComplaintFiles` left unchanged** — Has a dual-permission gate (either `COMPLAINTS_LIST` OR `SUPPORT_VIEW_HISTORY`) that's specific to complaints and doesn't match the single-permission `assertPermission` pattern.

6. **Direct module import for `__shared__/complaintSuggestionBase.ts`** — Per policy, no barrel import when caller and shared file are in the same barrel scope.
