## 1. SimulationBannerShared ✅

### Problem
`GroupSimulationBanner.tsx` (79 lines) and `ImpersonationBanner.tsx` (81 lines) shared ~60 lines of identical layout structure:
- `Box` with sticky positioning, flex layout, and theme-based borders
- `Typography` for the message text
- `Link` button for the end action

Differences were limited to:
- **Color scheme**: `secondaryContainer`/`onSecondaryContainer` vs `warningContainer`/`onWarningContainer`
- **Active condition**: `isSimulatingGroup + status?.groupName` vs `isImpersonating + status?.targetUser`
- **Message function**: `t.bannerSimulatingAs(groupName)` vs `t.bannerLoggedInAs(targetName)`
- **End action**: `endSimulation()` vs `endImpersonation()`
- **Link label**: `t.returnToNormalRole` vs `t.returnToNormalLogin`
- **ImpersonationBanner** had an extra `targetName` derivation step

### Solution
Created `frontend/common/components/auth/__shared__/simulationBannerShared.tsx` (76 lines) with a `SimulationBannerShared` scaffold component.

**Slot props:**
- `active: boolean` — whether to show the banner
- `message: ReactNode` — the Typography content
- `endLabel: string` — Link text
- `onEnd: () => void` — click handler
- `loading: boolean` — disabled state
- `bannerSx: (theme) => Record<string, unknown>` — color customization for the Box container
- `linkSx: (theme) => Record<string, unknown>` — color customization for the Link

**Refactored components:**
- `GroupSimulationBanner.tsx` — 79 → 27 lines (66% reduction)
- `ImpersonationBanner.tsx` — 81 → 29 lines (64% reduction)

**Type approach:** Used `SxCallback = (theme: Theme) => Record<string, unknown>` instead of `SxProps<Theme>` to avoid MUI v9's complex `SystemStyleObject` type constraints. The callback returns a plain object spread into the base `sx` styles, with `as SxObject` cast for type compatibility.

### Imports
All imports use `@/` path alias. The `__shared__` file is imported directly (no barrel export), following the pattern established in `baseDeleteDialogShared.tsx`.

## 2. ProfileEditFormShared ⏭️ Skipped (<50 lines)

### Evaluation
Analyzed 4 profile edit forms:
- `ParentProfileEditForm.tsx` (296 lines) — `ParentAdminEditFormData`
- `StaffProfileEditForm.tsx` (269 lines) — `StaffAdminEditFormData`
- `TeacherProfileEditForm.tsx` (118 lines) — `TeacherOwnEditFormData` (own-scope only)
- `TeacherAdminEditForm.tsx` (239 lines) — `TeacherAdminEditFormData`

### Shared structure (~25-30 lines of JSX)
1. `Stack spacing={3}` outer wrapper (1 line)
2. `Box component="form" onSubmit={...}` (1 line)
3. Inner `Stack spacing={3}` (1 line)
4. `AvatarImageField` (conditional, 5-7 lines — conditions differ)
5. Sections `Box sx={{ display: "grid", ... gridTemplateColumns }}` (10 lines)
6. `AdminResetPasswordSection` (conditional, 5-7 lines — admin scope only)
7. `PrimaryPageAction` (3 lines)
8. `ChangePasswordSection` (conditional, 1 line — own scope only)
9. `FormSuccessSnackbar` + `FormErrorSnackbar` (4 lines each)

### Why skipped
- **Shared structural code is <50 lines** — the outer layout shell is ~25-30 lines of JSX, below the 50-line extraction threshold defined in the design.
- **Each form already encapsulates its own logic** — Parent has `useParentEditForm`, `useParentSubmitFeedback`, `ParentEditFormSections`, `ParentEditFormSnackbars`; Staff has `buildSectionLabels`, `buildCompensationViewLabels`, `CompensationSectionRenderer`, `useFormSubmitHandler`, `useFormResetEffect`; TeacherAdmin has `TeacherFormSectionsGrid`, `useTeacherEditForm`, `useSubmitFeedbackStates`.
- **Form data types differ** — `ParentAdminEditFormData`, `StaffAdminEditFormData`, `TeacherOwnEditFormData`, `TeacherAdminEditFormData` have incompatible shapes, schemas, and default values.
- **Submit feedback already varies** — Parent extracts to a hook, Staff to a module-level function, Teacher is inline. Each has a slightly different "what happens after submit" flow (Parent checks reset password data, Staff does the same but via a function, TeacherAdmin uses `useCallback`).
- **TeacherAdminEditForm has different JSX nesting** — Snackbars are inside the `Box component="form"` wrapper, not outside like the other 3.
- A shared scaffold would need so many slots (sections, avatar field, reset password, submit feedback, snackbar pair, change password) that it would become a pass-through wrapper with no meaningful deduplication.

### Note
The `SECTION_GRID_SX` constant (the grid layout for sections) is already extracted as a module-level constant in `ParentProfileEditForm.tsx` but inlined in `StaffProfileEditForm.tsx` and `TeacherAdminEditForm.tsx`. This is a 7-line object — too small to justify a shared file but could be moved to a profile shared constants file in the future.
