## 1. Summary

Implemented the Neon HTTP single-fetch query helper in `backend/db/http-client.ts`. This helper provides zero-pool HTTP fetch execution (`neon(url)`) for stateless single-roundtrip database queries, bypassing WebSocket connection setup overhead when executing isolated read queries on Vercel/serverless environments.

---

## 2. Implementation Details

Created `backend/db/http-client.ts` with two main exported helpers:

```typescript
import { neon, type NeonQueryFunction } from "@neondatabase/serverless";
import { drizzle as drizzleNeonHttp, type NeonHttpDatabase } from "drizzle-orm/neon-http";
import { relations } from "@/backend/db/drizzleRelations";
import { getEnvironmentConfig } from "@/backend/lib/env";

let httpClient: NeonQueryFunction<boolean, boolean> | null = null;
let httpDbInstance: NeonHttpDatabase<typeof relations> | null = null;

/**
 * Get or initialize the Neon HTTP single-fetch query client.
 * Uses HTTP fetch (`neon(url)`) for stateless single-roundtrip queries without WebSocket pool overhead.
 */
export function getNeonHttpClient(): NeonQueryFunction<boolean, boolean> {
  if (!httpClient) {
    httpClient = neon(getEnvironmentConfig().databaseUrl);
  }
  return httpClient;
}

/**
 * Get or initialize the Drizzle ORM Neon HTTP database client for stateless queries.
 */
export function getNeonHttpDb(): NeonHttpDatabase<typeof relations> {
  if (!httpDbInstance) {
    const client = getNeonHttpClient();
    httpDbInstance = drizzleNeonHttp({ client, relations });
  }
  return httpDbInstance;
}
```

---

## 3. Technical Decisions & Characteristics

- **Zero WebSocket Overhead:** `getNeonHttpClient()` uses raw HTTP POST fetch queries directly to Neon's HTTP endpoint. It does not establish a persistent WebSocket socket or connection pool.
- **Drizzle ORM Compatibility:** `getNeonHttpDb()` wraps `getNeonHttpClient()` with `drizzle-orm/neon-http`, enabling full Drizzle schema query builder support over HTTP fetch.
- **Stateless Isolation:** Best suited for single read operations outside transactions. Multi-query transactions (`runInTransaction`) MUST continue using the WebSocket/pool client (`NeonPool` / `pg-pooled`).

## 5. Carry-Over Points for Future Tasks

1. **Usage Recommendation:** When refactoring read-only GraphQL resolvers or repository methods that perform single queries outside transactions, consider using `getNeonHttpDb()` when `DB_PROVIDER === "neon"` on Vercel to cut ~30ms of WebSocket connection overhead.
2. **Transaction Guard:** Never attempt to execute `db.transaction(...)` or multi-statement write sequences using the HTTP client; transactions require `drizzleNeon` (`@neondatabase/serverless` Pool) or `drizzlePostgres`.
