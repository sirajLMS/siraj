## Pattern Applied

All refactored methods follow the pilot pattern from `user.repository.ts`:

```typescript
// Module-level prepared statement
const findByIdPrepared = db
  .select()
  .from(table)
  .where(eq(table.id, sql.placeholder("id")))
  .prepare("descriptive_name");

// Method using prepared statement with transaction fallback
export const findById = async (id: string, tx?: DBTransaction) => {
  if (!tx) {
    const result = await findByIdPrepared.execute({ id });
    return result[0] ?? null;
  }
  // Fall back to regular query for transactions
  const [row] = await tx.select().from(table).where(eq(table.id, id)).limit(1);
  return row ?? null;
};
```

## Methods Intentionally Skipped

The following method categories were NOT refactored:
- **Write operations** (insert, update, delete, upsert) — not suitable for prepared statements
- **Methods requiring mandatory `tx`** (ReadExecutor/DBTransaction) — prepared statements can't be used inside transactions
- **Complex dynamic WHERE clauses** — `sql.placeholder()` can't handle optional/conditional conditions
- **Methods with complex joins and sub-selects** — exceed the simple `eq(column, placeholder)` pattern
- **Methods using raw SQL template literals** — not compatible with `.prepare()`
