## DataLoader Batching Architecture

```
GraphQL Query (e.g., users { id name role teacherId parentId permissions })
  │
  ├─ UserPothosObject.load(ids) → UserRepository.loadByIds(ids)  [1 query, batched]
  │
  ├─ role.loadable.load(ids) → PermissionsService.getUserContexts(ids)  [3 queries, batched]
  ├─ teacherId.loadable.load(ids) → TeacherRepository.findByUserIds(ids)  [1 query, batched]
  ├─ parentId.loadable.load(ids) → ParentRepository.findByUserIds(ids)  [1 query, batched]
  └─ permissions.field → PermissionsService.getUserContexts([user.id])  [per-user, not batched*]
```

*`permissions` cannot use `t.loadable` because Pothos DataLoader doesn't support list-typed returns. This is a known limitation. The field still benefits from the batch infrastructure since `getUserContexts` is called with a single-element array.

**Before (N+1):** For N users: 1 (user load) + N (role) + N (teacherId) + N (parentId) + N (permissions) = 1 + 4N queries  
**After (batched):** For N users: 1 (user load) + 3 (role batch) + 1 (teacherId batch) + 1 (parentId batch) + N (permissions) = 6 + N queries

## Carry-Over Knowledge for Task 3.2 (GraphQL Rollout)

### Pattern to Replicate
1. **`t.loadable()` for scalar fields**: Use `t.loadable({ type: "String", load: (ids) => batchService(ids), resolve: parent => parent.id })` for fields that need batching
2. **`t.loadable()` for object references**: Use `t.loadable({ type: SomePothosObject, load: (ids, ctx) => SomePothosObject.getDataloader(ctx).loadMany(ids), resolve: parent => parent.someId })` for cross-type relations
3. **Batch service methods**: Create `resolveXxxForUsers(ids: string[])` methods that return `Map<string, T | null>`
4. **Batch repository methods**: Create `findByUserIds` / `findByIds` methods with prepared statements using `inArray(col, sql.placeholder("ids"))`

### Limitations
- **`t.loadable` doesn't support list types** (e.g., `[AppPermissionPothosEnum]`). Fields returning arrays must use `t.field()` with per-item resolution
- **Prepared statements can't be used inside transactions** — always provide the `tx` fallback pattern
