# Task 3.2 Outcome: GraphQL DataLoader Auth Domain

**Date:** 2026-07-31  
**Task:** 3.2 Auth Domain N+1 Fix (ImpersonationStatus)  
**Status:** ✅ Completed

---

## Summary

Eliminated N+1 query patterns in the `ImpersonationStatus` GraphQL object type by replacing `t.field()` resolvers with `t.loadable()` DataLoader-batched field resolvers for both `targetUser` and `actorUser` fields.

---

## Changes Made

### `backend/graphql/pothos/auth/impersonation.pothos.ts`

**Pattern 1: `targetUser` field** (line 22-27)
- Before: `t.field()` calling `UserRepository.findById(parent.targetUserId)` per parent
- After: `t.loadable()` delegating to `UserPothosObject.getDataloader(ctx).loadMany(ids)` — batched via existing User DataLoader

**Pattern 2: `actorUser` field** (line 28-33)
- Before: `t.field()` calling `UserRepository.findById(parent.actorUserId)` per parent
- After: `t.loadable()` delegating to `UserPothosObject.getDataloader(ctx).loadMany(ids)` — batched via existing User DataLoader

**Removed imports:**
- `UserRepository` from `@/backend/db/repo` (no longer needed)
- `AuthUtils` from `@/backend/utils` (no longer needed)

---

## N+1 Reduction

| Field | Before (N parents) | After (N parents) |
|---|---|---|
| `targetUser` | N queries (`findById` per parent) | 1 batched call to User DataLoader |
| `actorUser` | N queries (`findById` per parent) | 1 batched call to User DataLoader |

**Before:** 2N database queries for N `ImpersonationStatus` objects  
**After:** 2 DataLoader calls (batched into queries proportional to unique IDs)
