## Test Coverage

### Tier 1 — Happy Paths (100% branch coverage)
- `getAppearance()` — returns null on empty DB, returns row after upsert, upsert-seeds on first access
- `getFirstAppearancePublished()` — cached read, returns null when no published row
- `saveDraft()` — creates/updates draft fields
- `publish()` — copies draft to published, revalidates cache, logs audit
- `resetDraft()` — resets draft to published values
- `getResolvedAppearance()` — tiered resolution (memory → cache → env → defaults)

### Tier 2 — Boundary Cases
- Null logo URL handling
- Maximum-length strings (siteName 80, siteTitle 120, siteDescription 300)
- Special characters (emoji, Arabic RTL, HTML-like tags)

### Tier 3 — Chaos / Fallback
- Empty `NEXT_PUBLIC_APP_BRANDING` falls back to defaults
- Malformed JSON in env var falls back to defaults
- Zod validation failure in `saveDraft` falls back to `DEFAULT_APPEARANCE_FIELDS` (AC-38)
- Audit-log failure in `publish` is swallowed (best-effort, never throws)
- DB failure in `getResolvedAppearance` propagates (does NOT silently fall back)

### Tier 4 — Security
- **Permission gating** (AC-7): `saveDraft`, `publish`, `resetDraft` all throw `insufficientPermissions` when actor lacks `SETTINGS_APPEARANCE_MANAGE`
- **Optimistic concurrency** (AC-33): stale `expectedUpdatedAt` throws `AppearanceConflictError`; matching `expectedUpdatedAt` succeeds; omitting `expectedUpdatedAt` bypasses the check (Overwrite escape hatch); first-write seeding skips the check
