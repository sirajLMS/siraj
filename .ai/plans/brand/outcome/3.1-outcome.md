# Task 3.1 — Backend i18n error keys for appearance

## Summary

Added a new `appearance` sub-namespace to the compile-time i18n `errors`
namespace (per `shared/AGENTS.md` §Translation System) covering the four
backend error strings required by the Site Appearance Customization plan:

| Key | Purpose | AC |
|-----|---------|----|
| `appearance.saveDraftFailed` | Localized error thrown when `saveAppearanceDraft` fails | AC-24 |
| `appearance.publishFailed`   | Localized error thrown when `publishAppearance` fails | AC-24 |
| `appearance.resetFailed`     | Localized error thrown when `resetAppearanceDraft` fails | AC-24 |
| `appearance.unauthorized`    | Localized error thrown when a caller lacks `SETTINGS_APPEARANCE_MANAGE` | AC-7 |

All four keys were added to (a) the type definition, (b) the `en`
implementation, and (c) the `ar` implementation. No existing keys were
renamed or removed — the new sub-namespace is purely additive.

## Requirements Coverage

- **AC-7** — `appearance.unauthorized` gives the GraphQL mutation layer a
  localized message to attach to `GraphQLError` when a user without
  `SETTINGS_APPEARANCE_MANAGE` attempts Save / Publish / Reset.
- **AC-24** — All four keys live under the compile-time translation system
  (`shared/locale/`), surfaced via `ctx.t("errors").appearance.*`. No
  hardcoded UI strings introduced.

## Placement Rationale

- The `errors` namespace is structured as one sub-interface per domain
  (`AuthErrors`, `BillingErrors`, `FileErrors`, `FxErrors`, etc.). An
  `AppearanceErrors` sub-interface mirrors this pattern and avoids polluting
  the top-level `ErrorsLabels` surface with 4 flat keys.
- Insertion at the end of the `ErrorsLabels` `extends`/sub-namespace list
  (after `classInstance`) keeps the diff purely additive and avoids
  disturbing the existing grouping/comments.
- In the `en`/`ar` implementations, the new `appearance: { ... }` block was
  placed immediately after the `session: { ... }` block (the last fully-
  inlined sub-namespace), before the shorthand `classSubject, leaveQuota, ...`
  aliases — matches the existing style of grouping inlined blocks together.
- `appearance.unauthorized` was added as a dedicated key rather than reusing
  the existing top-level `unauthorized` or `permissionManagement.unauthorized`
  because (a) the task explicitly listed it as a new key, and (b) it carries
  a more specific "manage site appearance" message distinct from the generic
  auth/permission-management variants, which improves UX per AC-24.
