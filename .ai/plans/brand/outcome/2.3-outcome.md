## Implementation Details

### Exports
- `NAME_APPEARANCE = "appearance"` — cache tag constant
- `DEFAULT_APPEARANCE_FIELDS: AppearanceFields` — default brand values (primary/secondary colors, site name/title/description, default color scheme)
- `GetAppearanceOptions` interface — options for `getAppearance`
- `AppearanceSettingsService` namespace with:
  - `getAppearance(options?)` — returns the full row; upsert-seeds on first access if `actorUserId` provided
  - `getFirstAppearancePublished()` — cached via `unstable_cache` with tag `"appearance"`, returns published `AppearanceFields` or null
  - `saveDraft(input, actorUserId, tErrors, tx?)` — requires `SETTINGS_APPEARANCE_MANAGE`, replaces `draftFields`
  - `publish(actorUserId, tErrors, tx?)` — requires permission, copies draft → published, `revalidateTag("appearance")`, audit entry
  - `resetDraft(actorUserId, tErrors, tx?)` — requires permission, resets draft to published values

### Key Design Decisions
- **Permission enforcement**: All write methods (`saveDraft`, `publish`, `resetDraft`) enforce `SETTINGS_APPEARANCE_MANAGE` via `PermissionsService`
- **Cache strategy**: `getFirstAppearancePublished` uses `unstable_cache` with tag `"appearance"`; `publish` calls `revalidateTag("appearance")` to invalidate
- **Audit logging**: `publish` emits a best-effort audit entry with the new published values
- **BOLA defense**: `actorUserId` stamped on `updatedByUserId` (decision #20)
- **Seeding**: `getAppearance` upsert-seeds on first admin access; `getFirstAppearancePublished` does NOT seed (no user context on SSR)
