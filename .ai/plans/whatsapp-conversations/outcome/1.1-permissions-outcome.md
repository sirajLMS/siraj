# 1.1 + 1.2 — Permissions enum + custom migrations outcome

Date: 2026-09-10.

## Summary

Added the two `whatsapp.conversations_*` permissions end-to-end: `AppPermission` enum
members, unit-test coverage, and a two-phase idempotent custom migration pair that
inserts the permission rows and grants them to the locked group set.

## Files changed

- `backend/enum/permissions/permission.enum.ts`
  - `WHATSAPP_CONVERSATIONS_VIEW = "whatsapp.conversations_view"`
  - `WHATSAPP_CONVERSATIONS_MANAGE = "whatsapp.conversations_manage"`
  - Placed directly after the `WHATSAPP_INBOX_*` block with a domain comment
    (view gates list/read, manage gates send/recipients).
- `backend/enum/permissions/permission.enum.test.ts`
  - New `AppPermission whatsapp conversations` describe block (value keys,
    `isAppPermission` acceptance, `parseAppPermission` resolution).
  - Two typo-rejection entries (`*_typo`) in the existing rejection test.
- `backend/db/migration/46a-whatsapp-conversations-permissions-enum.sql` — `ALTER TYPE
  app_permission ADD VALUE IF NOT EXISTS` for both values (own transaction, committed
  before data phase per PostgreSQL `check_safe_enum_use`).
- `backend/db/migration/46b-whatsapp-conversations-permissions-data.sql` — mirror of the
  41b pattern: `DISABLE TRIGGER trg_protect_system_permissions` → permissions upsert
  (ar/en jsonb description + category, `is_system = true`) → trigger re-enable →
  `group_permissions` grants with `ON CONFLICT DO NOTHING`.
  - `whatsapp.conversations_view` → super_admin, academy_admin, staff_default,
    supervisor_default.
  - `whatsapp.conversations_manage` → super_admin, academy_admin.
- Final custom number: **46a/46b** (highest pre-existing was `45-expenses-table.sql`;
  no `46*` existed. Naming uses the on-disk convention without a `custom_` prefix,
  matching `41a-…` / `41b-…` — the generated drizzle bundles get the `custom_` prefix
  automatically).
