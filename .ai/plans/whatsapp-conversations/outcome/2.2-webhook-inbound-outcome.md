# Outcome 2.2 — Webhook ingest tracks `last_inbound_message_at`

Status: done (2026-09-10).

## What changed

- `backend/db/repo/whatsapp/whatsapp-conversation.repository.ts` —
  `touchLastMessage` now accepts an optional `inboundAt` in the rollup argument.
  When present it advances `whatsapp_conversations.last_inbound_message_at`
  under its own last-writer-wins guard (separate guarded `UPDATE`), so:
  - an echo posted after the user's message does not refuse the inbound stamp
    (the general `last_message_at` guard failing never blocks the inbound one);
  - a stale/out-of-order replay never moves the column backwards.
  When `inboundAt` is omitted/`null`, behavior is byte-identical to before.
- `backend/services/whatsapp/whatsapp-webhook-inbox.helpers.ts` —
  `persistMessageRow` (the single conversation-touch patch point for all
  persisted message rows: live inbound, history, echoes, media follow-ups)
  passes `inboundAt` only when `ctx.direction === WhatsappMessageDirection.INBOUND`.
  ECHO rows (business-app mirrors, history `to*` messages) pass `null` and never
  touch the new column. API_OUTBOUND rows are not persisted via webhook ingest at
  all, so they inherit the same guarantee.

Schema was untouched (column delivered in 1.3); `WhatsappConversation*Type` are
`$infer`-based so no type file needed a change.

## Tests

- `backend/db/test/repo/whatsapp/whatsapp-conversation.repository.test.ts` —
  two new `touchLastMessage` cases: inbound stamp advances and refuses older
  replays / echo-only touches leave the column null; and a stale general rollup
  does not refuse a first inbound stamp. 17/17 pass.
- `backend/services/whatsapp/test/whatsapp-webhook-ingest.test.ts` — new

  stamps `touchLastMessage` with `inboundAt` equal to the webhook timestamp;
