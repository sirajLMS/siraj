# Outcome 3.1–3.4 — GraphQL Pothos surface for WhatsApp Conversations

Date: 2026-09-10.

## Canonical GraphQL names (EXACT — frontend documents agent consumes these verbatim)

### Enums (registered in `backend/graphql/pothos/shared/enum.pothos.ts`)
- `WhatsappTestRecipientStatus` — values `PENDING` | `ALLOWED`
- `WhatsappConversationSendMode` — values `TEXT` | `TEMPLATE`

### Object types
- `WhatsappTestRecipientPothosObject` (GraphQL name `WhatsappTestRecipient`), backed by
  `WhatsappTestRecipientReturnType`:
  `id: String!`, `accountId: String!`, `phoneNumber: String!`,
  `status: WhatsappTestRecipientStatus!`, `note: String`,
  `lastCheckedAt: DateTime`, `lastErrorCode: String`, `createdAt: DateTime!`, `updatedAt: DateTime!`
- `WhatsappConversationSendResultPothosObject` (GraphQL name `WhatsappConversationSendResult`):
  `id: String!` (resolved from `message.id`), `message: WhatsappMessage!`
  (reuses the inbox `WhatsappMessagePothosObject` — no second message object type).
- `WhatsappConversationThreadPothosObject` (GraphQL name `WhatsappConversationThread`), backed by
  `WhatsappConversationThreadResult` (`{ conversation, messages }`): conversation fields
  `id, accountId, waId, userId, username, displayName, lastMessageAt, lastMessagePreview,
  accountPurpose, createdAt, updatedAt` (identical to `WhatsappConversation`, resolved off the
  embedded conversation row) plus `messages: WhatsappConversationMessagesResult!`
  (reuses the inbox paginated messages wrapper).
- `WhatsappAccountPothosObject` gained `isTestNumber: Boolean!` (topic 2.6's server-derived flag).

### Input types
- `WhatsappTestRecipientAddInput` (Pothos export `WhatsappTestRecipientAddInputPothosObject`):
  `accountId: String!`, `phoneNumber: String!`, `note: String`
- `WhatsappConversationSendInput` (Pothos export `WhatsappConversationSendInputPothosObject`):
  `accountId: String!`, `conversationId: String`, `to: String!`,
  `mode: WhatsappConversationSendMode!`, `templateName: String`, `templateLanguage: String`,
  `body: String`

### Queries (authScopes `permission: WHATSAPP_CONVERSATIONS_VIEW`; service re-gates)
- `whatsappConversationThreads(accountId: String, pagination: PaginationArgs): WhatsappConversationsResult`
  (reuses inbox list envelope `WhatsappConversationsResultPothosObject`)
- `whatsappConversationThread(id: String!, pagination: PaginationArgs): WhatsappConversationThread`
- `whatsappTestRecipients(accountId: String!): [WhatsappTestRecipient!]!`

### Mutations (authScopes `permission: WHATSAPP_CONVERSATIONS_MANAGE`; service re-gates)
- `addWhatsappTestRecipient(input: WhatsappTestRecipientAddInput!): WhatsappTestRecipient!`
- `removeWhatsappTestRecipient(recipientId: String!): Boolean!` (true on success)
- `verifyWhatsappTestRecipient(recipientId: String!): WhatsappTestRecipient!`
- `sendWhatsappConversationMessage(input: WhatsappConversationSendInput!): WhatsappConversationSendResult!`

All resolvers pass `UserPermissionContext` from ctx and `actorUserId` from `requireAuth(ctx)`;
`actorUserId` is never client-supplied. Errors bubble up as DomainError `extensions.code`
(values in outcome 2.4/2.5: `WHATSAPP_RECIPIENT_LIMIT_REACHED`, `WHATSAPP_RECIPIENT_CONFLICT`,
`WHATSAPP_RECIPIENT_NOT_ALLOWED`, `WHATSAPP_OUTSIDE_SERVICE_WINDOW`,
`WHATSAPP_CONVERSATION_SEND_FAILED`, `WHATSAPP_CONFIG`, `WHATSAPP_ACCOUNT_NOT_FOUND`,
`WHATSAPP_TEST_RECIPIENT_NOT_FOUND`, `WHATSAPP_CONVERSATION_NOT_FOUND`, `VALIDATION`, `FORBIDDEN`).
