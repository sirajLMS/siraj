## ViewModel state machine (`useWhatsappConversationsViewModel`)

- **Accounts**: `whatsappAccountsQueryDocument`; option list = active accounts with
  `{ id, label, isActive, isTestNumber }`. Default selection = first option; re-anchors when the
  selected id disappears. Switching accounts resets search/page/thread/composer/registry notice.
- **List**: `whatsappConversationsListQueryDocument(accountId, pagination)` — 30s polling paused
  while `document.hidden` (via `useSyncExternalStore`, not effect-set-state); client search filter
  over the current page; clamped 0-based page.
- **Thread**: `whatsappConversationThreadQueryDocument(id, pagination 50)`, skipped until a
  conversation is selected.
- **Service window**: latest `INBOUND` message `sentAt` + 24h vs a **mount-time `Date.now()`
  snapshot** (the repo-sanctioned `useState(() => Date.now())` pattern — `Date.now()` during
  render trips the React Compiler purity lint). Hint copy interpolates `{duration}` via
  `Intl.RelativeTimeFormat` (hours ≥ 60 min, else minutes). Meta/server remains the authoritative
  gate: an actually-closed window still rejects with `WHATSAPP_OUTSIDE_SERVICE_WINDOW`, which is
  mapped to a translated message.
- **Composer**: `mode` (`WhatsappConversationSendMode.Text|Template`), `textBody`,
  `templateName`, `templateLanguage` (empty → null → server default), recipient state
  (registry select value or custom recipient). Validation (translated `sendBlockReason`):
  inactive account → `whatsappAccountOffboarded`; TEXT without an open window →
  `whatsappOutsideServiceWindow`; TEXT empty body → `whatsappMessageRequired`; TEMPLATE without a
  template name → `whatsappTemplateRequired`; missing target silently disables send.
- **Send**: `sendWhatsappConversationMessageMutationDocument` with `errorPolicy: "none"`;
  success clears the text body and refetches list + open thread; failure reads
  `extensions.code` (`CombinedGraphQLErrors`) → mapped errors-namespace strings, falling back to
  the server-localized message, then `whatsappConversationSendFailed`.
- **Registry** (only when `isTestAccount`): `whatsappTestRecipientsQueryDocument(accountId)`;
  add/remove/verify mutations with dialogs; conflict/limit codes map to
  `whatsappRecipientConflict` / `whatsappRecipientLimitReached`; verify failures surface as a
  panel notice. Recipient rows are pre-shaped with interpolated `recipientLastChecked` /
  `recipientErrorCode` strings.

## Deviations (documented)

1. **Template select → free-text template name field**: there is no `whatsappTemplates` query in
   the Pothos schema — the settings codebase documents this as a missing backend resolver (the
   templates document remains a commented-out stub, and synced templates only exist transiently
   on the sync mutation result). `ComposerShared` therefore uses typed template name + language
   fields; the server enforces template presence for TEMPLATE mode. A synced-template picker can
   replace it once a templates query exists. This deviates from design-04 ("template select from
   synced templates document") and from specs-3 #6 ("defaults hello_world when present" — no
   presence signal is queryable).
2. **Thread pane re-implemented locally** (`ConversationThreadPaneShared`): the settings
   `ConversationThread` hard-codes a read-only notice footer ("The inbox is read-only…") which is
   false on this page, and direction of Messages/dead-line helpers lived module-private.
   Settings files were not edited per scope; reused **imports**: `getWhatsappMessageDirectionLabel`,
   `whatsappInboxDirectionLabel` types, `textDirection`, inbox row types, and the whole
   `WhatsappInboxLabels` namespace for message chrome (direction labels, revoked/media markers,
   back-button aria-label).
3. **Account selector shows active accounts only** (same filter as the inbox VM); the
   deactivated-account composer hint path (`whatsappAccountOffboarded`) is kept in the VM as a
   defensive branch since selector filtering makes it unreachable in practice.
