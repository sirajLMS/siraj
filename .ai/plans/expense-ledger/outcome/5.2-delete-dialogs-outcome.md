# Task 5.2 Outcome — Expense delete confirmation dialogs (single + bulk)

- **Date**: 2026-09-07
- **Status**: ✅ Complete

## Files

### Created

- `frontend/common/views/dashboard/accounting/expenses/useExpenseConfirmAction.ts` —
  expense variant of the carryover confirm hook (carryover's `useCarryoverConfirmAction`
  hardcodes the `carryoverBalances` eviction field, so it is not directly reusable).
  Generic over mutation document/variables; takes `row`, `buildVariables(row)` (null =
  inert), `successMessage`, `fallbackErrorMessage`, and an `isBlockingError(error)`
  classifier. Semantics:
  - one write per dialog session (`startedRef` re-arms on failure; reset on each
    `open` rise — the "clientRequestId-like" single-mutation-per-open guarantee,
    since `DeleteExpenseInput`/`BulkDeleteExpensesInput` carry no clientRequestId),
  - `client.cache.evict({ fieldName: "expenses" })` + `gc()` after success
    (aggregates depend on every row — carryover precedent),
  - error toast via `getGraphQLErrorMessage` for ordinary rejections,
  - `blocked: true` (state, reset per dialog session) when `isBlockingError` matches,
    letting the consumer render a persistent in-dialog explanation instead of a toast.
  Also exports `ExpenseConfirmRow` (`Pick` of `id | title | expenseValue |
  expenseCurrency` from `ExpensesQuery_expenses_rows`), the
  `EXPENSE_DELETE_VIA_UNPAY_CODE` constant, and the
  `isExpenseDeleteViaUnpayError` guard (matches `extensions.code` on
  `CombinedGraphQLErrors`).
- `frontend/common/views/dashboard/accounting/expenses/DeleteExpenseDialog.tsx` —
  `{ open, row, onClose, onDone }`. Restates `title (value currency)` via the
  typed `modal.delete.summary(title, value, currency)` interpolation (value through
  `formatAccountingMoney`); optional **reason** `TextField` (multiline,
  `htmlInput.maxLength = 500`, mirroring the `deletedReason` column ceiling) sent as
  `input.reason` (`null` when blank); session reason resets on each open via the
  render-time prev-open compare (carryover `UnpayCarryoverDialog` convention).
  On an `EXPENSE_DELETE_VIA_UNPAY` rejection the dialog stays open and renders a
  **non-dismissible** `role="alert"` banner (`errorContainer`/`onErrorContainer` theme
  pair + `ErrorOutlined` icon, RTL-safe flex) with `error.deleteViaUnpay` — the copy
  directs the operator to the carryover Unpay flow — and the destructive confirm is
  disabled via the scaffold's new `confirmDisabled` prop. Uses
  `deleteExpenseMutationDocument` → `{ input: { id, reason } }`.
- `frontend/common/views/dashboard/accounting/expenses/BulkDeleteExpensesDialog.tsx` —
  `{ open, rows, onClose, onDone }`. Single
  `bulkDeleteExpensesMutationDocument` call per open (`startedRef`), variables
  `{ input: { ids, reason: null } }`; summary details (per-row `title → value
  currency`), CLDR-plural `modal.bulkDelete.title(count)` title,
  `success.bulkDeleted(count)` toast, `expenses` cache evict + `gc()`. Because the
  batch is atomic server-side, a protected row (e.g. `EXPENSE_DELETE_VIA_UNPAY`)
  rejects the whole call and the server-localized message is toasted — nothing is
  deleted client-side on error.

### Edited (additive, backward-compatible)

- `frontend/common/views/dashboard/accounting/carryover/CarryoverConfirmScaffold.tsx` —
  added optional `confirmDisabled?: boolean` (default `false`) so a blocking banner
  can disable the destructive confirm independently of `busy`. Existing call sites
  (`DeleteCarryoverDialog`, `UnpayCarryoverDialog`, `BulkDeleteCarryoverDialog`) are
  unaffected — the prop is omitted everywhere and the button renders exactly as before.

## Reuse decision

The carryover confirm scaffold is fully parameterized (open/busy/title/labels/children/
onClose/onConfirm), so both dialogs import `CarryoverConfirmScaffold`,
`CarryoverConfirmDetails`, and `CarryoverConfirmDetail` directly instead of cloning the
148-line dialog shell. Only the mutation/effect hook needed an expense variant
(eviction field + blocking-error classification vs the row-type lock-in of the
carryover hook).
