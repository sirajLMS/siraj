### Harness

Same in-process pattern as the carryover sibling
(`backend/graphql/mutation/teachers/carryover.mutation.test.ts`): mock only the
`ExpenseService` export on the `@/backend/services` barrel (real barrel spread
underneath so the builder's import graph stays linkable; the mock includes

plus the query module (non-empty Query root), and execute real documents via
`graphql()`.

### Coverage (25 tests)

- **Happy-path result shapes (all 4)**: `createExpense` / `updateExpense` return the
  full `Expense` row shape via `expectExpenseRowShape` (19 fields, incl. `type`
  serialized as the enum key, `DateTime` fields asserted as `Date` instances);
  `deleteExpense` returns `{ id, deleted: true }` mapped from the service's
  `ExpenseRow`; `bulkDeleteExpenses` returns `{ id: "bulk-delete-expenses-result",
  deleted, auditLogIds }` as-is.
- **Permission guard**: every mutation rejects a VIEW-only actor
  (`ACCOUNTING_EXPENSES_VIEW`) and a logged-out caller with `FORBIDDEN` +
  `insufficientPermissions` and never invokes the service; a single parameterized
  loop covers all four; unrelated permission (`SESSION_RESCHEDULE`) rejected for all
  four; super-admin without the explicit permission runs all four; a permissioned
  but anonymous context reaches the resolver and fails `requireAuth` with
  `UNAUTHENTICATED`.
- **Argument forwarding / actor injection**: every input field passed with
  meaningful values on each happy path; `createExpense` gets `createdByUserId` from
  the context (both the input field and the separate `actorUserId` service argument
  asserted), the other three get `actorUserId`; passing `actorUserId` inside
  `CreateExpenseInput` fails variable coercion (field does not exist in the schema).
- **`clientRequestId` forwarding**: dedicated test asserts the value reaches the
  `createExpense` service input verbatim.
- **Salaries rejection**: `createExpense` with `type: SALARIES` surfaces the
  service's `DomainError("EXPENSE_SALARIES_VIA_CARRYOVER_ONLY", …)` with
  `extensions.code` preserved and the localized
  `errors.expenses.salariesViaCarryoverOnly` message (the mock mirrors the real
  service contract, same as the carryover sibling's empty-selection mimic).
- **Paid-carryover guard**: `deleteExpense` with the service throwing
  `DomainError("EXPENSE_DELETE_VIA_UNPAY", …)` surfaces the code and the localized
  `errors.expenses.deleteViaUnpay` message.
- **Empty-ids guard**: `bulkDeleteExpenses` with `ids: []` is rejected **in the
  resolver** (before the service) with `VALIDATION` + `errors.invalidInput` — the
  carryover sibling asserted the service-level rejection; here the guard lives in
  the resolver itself, so the mock is never invoked (asserted).
- **Oversized selection (501 ids)**: rejected by the `@constraint` plugin
  (`maxItems: 500` on `BulkDeleteExpensesInput.ids` from Task 2.1) via an in-process
  Apollo server with `createApollo4QueryValidationPlugin()`; `BAD_USER_INPUT` +
  "no more than 500 in length", service never invoked.
- **Null-optional passthrough**: parameterized `nullOptionalsCases` loop over all
  four mutations — create (`teacherId`/`note`/`clientRequestId` null), update
  (full-null patch), delete and bulkDelete (`reason: null`) — each asserted against
  an explicit `expectedServiceInput` map (create takes `createdByUserId`, the rest
  `actorUserId`).

### Gotchas encountered (worth noting for the parallel query-test file)

- `ExpenseTypePothosEnum` is registered from the TS enum, so **GraphQL variables
  take the enum keys** (`"MARKETING"`, …) while resolvers receive the enum **values**
  (`"Marketing"`); the test passes keys in variables and maps to values via
  `ExpenseType[input.type]` in the shared `serviceInputFromVariables` helper before
  comparing against captured service inputs. Row-shape assertions compare `type`
  against the serialized key (`"MARKETING"`).
- The `DateTime` scalar returns real `Date` instances in-process; row-shape
  timestamp assertions use `toEqual(new Date(...))`.
