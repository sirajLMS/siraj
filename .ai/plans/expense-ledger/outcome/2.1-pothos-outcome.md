## Placement decision (requested by assignment)

`backend/graphql/pothos/expenses/` — **not** `pothos/billing/`. Reasons:
implementation.md §4.1 and trackable-tasks 2.1 both pin `pothos/expenses/`;
plan-review R2's billing relocation (items 5–8) covered `types/`, `query/`,
`mutation/`, `sharedDocuments/` only and deliberately left the pothos path
alone. Pothos dirs are per-domain (e.g. `pothos/accounting/`,
`pothos/teachers/`); expenses is its own domain, same call the carryover module
made for `pothos/teachers/carryover.pothos.ts`.

## Adaptations from the plan (noted)

- **Result-object export names prefixed** (`ExpenseDeleteResultPothosObject`,
  `ExpenseBulkDeleteResultPothosObject`, refs likewise) — the plan's verbatim
  names `DeleteResultPothosObject` / `BulkDeleteResultPothosObject` (and their
  refs) are already exported by `pothos/teachers/carryover.pothos.ts`; unprefixed
  names would collide at the `pothos/index.ts` `export *` root barrel (TS2308).
  GraphQL type names are the unique `"ExpenseDeleteResult"` /
  `"BulkDeleteExpensesResult"` (carryover used `"CarryoverDeleteResult"` /
  `"BulkDeleteCarryoverResult"`).
- **Enum registered in `shared/enum.pothos.ts`**, not the domain file (CRITICAL
  rule; see above).
- **`ExpensePage.aggregates` resolvers**: plan snippet's flattened fields kept,
  resolving from `page.aggregates.*` because the backend `ExpensePage` type is
  nested; GraphQL field names unchanged from the plan.
- Constraint directives added on date/title inputs (carryover sibling
  convention): `format: "date"` on payment dates, `maxLength: 200` on title
  (matches the `title varchar(200)` column), `maxItems: 500` on bulk ids.
- Plan-snippet typo `t.booleanColumn` → `t.boolean` (no such Pothos helper).
- `CreateExpenseInput` intentionally omits `teacherName` (plan verbatim);
  the service derives the snapshot. `UpdateExpenseInputPothos` keeps it
  (plan verbatim).
