## What was implemented

### `backend/graphql/query/billing/expense.query.ts` (NEW)

Two root query fields, both gated by
`authScopes: { permission: AppPermission.ACCOUNTING_EXPENSES_VIEW }`, with
`actorUserId` from `requireAuth(ctx)` and errors localized via
`ctx.t().errorsTranslations` (handed straight to the service):

- **`expenses(filter, limit, offset)`** → `ExpensePagePothosObject`. Maps the
  `ExpenseFilterPothosInput` onto the canonical `ExpenseFilters` (absent field →
  `null`) and calls
  `ExpenseService.getReport(actorUserId, filters, { limit, offset }, tErrors)`.
  `limit` carries the payroll/session-audit constraint directive
  (`min: 1, max: 200`, default 50); `offset` defaults to 0.
- **`expense(id)`** → `ExpensePothosObject`, drill-down by ID; calls
  `ExpenseService.getById(actorUserId, id, tErrors)` (the service already
  shape-checks the id and throws the localized `EXPENSE_NOT_FOUND`).

**`types` needs no manual narrowing** (per the 2.1 carry-forward):
`ExpenseFilterPothosInput.types` is declared as `[ExpenseType!]` over
`ExpenseTypePothosEnum`, which is registered from the real `ExpenseType` TS
enum — args arrive as `ExpenseType[] | null | undefined`, GraphQL itself rejects
unknown literals at parse time, and the value passes straight into
`ExpenseFilters.types` (`readonly ExpenseType[] | null`).

**`includeDeleted` is re-gated at the entry point** (backend/graphql AGENTS.md
privileged-flag rule, session-audit precedent): when the caller requests
`includeDeleted: true`, the flag is silently stripped unless
`ctx.isSuperAdmin || ctx.permissions.includes(AppPermission.ACCOUNTING_EXPENSES_MANAGE)`.
This mirrors the CSV export route so soft-deleted rows never surface through
one entry point when the other would strip them. `false`/absent pass through
unchanged.

All Pothos symbols imported from `@/backend/graphql/pothos/expenses`
(shortest barrel, per the 2.1 carry-forward); service from `@/backend/services`;
types from `@/backend/types`.
