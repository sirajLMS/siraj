# Task 2.5 Outcome — Expense Ledger CSV export route

- **Date**: 2026-09-06
- **Status**: ✅ Complete

## What was implemented

**`app/api/expenses/export/route.ts`** — Next.js Route Handler,
`GET /api/expenses/export`, mirroring the carryover export route contract
(`app/api/carryover/export/route.ts`) one-for-one:

- **Auth**: `getServerUserContext()` → 401 when unauthenticated (locale parsed
  from `accept-language`, Arabic default); then
  `requirePermission(userId, AppPermission.ACCOUNTING_EXPENSES_VIEW, tErrors)`
  → 403 on `ForbiddenError`. Both gates run before any expense data is read.
- **Filter parsing** from the query string onto `ExpenseFilters` (field names
  mirror the filter contract verbatim):
  `title` (trimmed, ≤ 200 chars), `types` (comma-separated, trimmed, each
  entry must be an `ExpenseType`), `expenseDate` (strict `YYYY-MM` with real
  month 01–12), `paymentDateFrom` / `paymentDateTo` (strict `YYYY-MM-DD`
  calendar check that rejects impossible days), `includeDeleted`
  (`true`/`false`, absent → null so the service default — exclude deleted —
  applies). Malformed values → 400 `ValidationError` (`tErrors.invalidInput`).
- **Report read**: `ExpenseService.getReport(userId, filters,
  { limit: EXPORT_ROW_LIMIT, offset: 0 }, tErrors)` with
  `EXPORT_ROW_LIMIT = 10_000`.
- **CSV serialization** inline in the route file (route files export only
  HTTP handlers): one column per `ExpenseRow` field in declaration order
  (19 columns, `id` first … `updatedAt` last), RFC 4180 quoting plus formula
  injection neutralization (`=`, `+`, `-`, `@`, tab, CR get a `'` prefix),
  CRLF line separators, trailing newline.
- **Headers**: `Content-Type: text/csv; charset=utf-8`,
  `Content-Disposition: attachment; filename="expenses-<YYYY-MM-DD>.csv"`,
  `X-Export-Truncated: true|false` (true when `totalCount > 10_000`).
- `logger.info` on success (actor, filters, rowCount, truncated);
  unexpected errors → `logger.error` + 500 with localized message.

**`app/api/expenses/export/route.test.ts`** — 18 tests, barrel-mock style
identical to the carryover test: `@/backend/lib` (auth context, error
classes, logger) and `@/backend/services` (`ExpenseService.getReport`,
`requirePermission`) mocked via `mock.module`; the inline CSV serializer runs
for real so body assertions exercise the production escaping and column
contract. Covers: 401 (en + ar fallback copy), 403 with the exact
`ACCOUNTING_EXPENSES_VIEW` permission, happy path (all six filters mapped +
column contract + headers + pagination args), default filter set on
absent/blank params, `X-Export-Truncated` true above 10 000 and false at
exactly 10 000, 500 on report failure, 400s (malformed `paymentDateFrom`,
impossible calendar day, out-of-range `expenseDate` month, unknown `types`
entry, non-boolean `includeDeleted`, over-long `title` + exact-limit
acceptance, service-side `ValidationError`), and CSV formula-injection
hardening (prefix chars incl. tab/CR, comma/quote escaping, Arabic/RTL
passthrough).

## Shared-helper decision

No generic CSV helper had emerged since the carryover wave:
`backend/services/accounting/session-audit-csv.serializer.ts` is bound to
`SessionAuditReportRow` columns (per-domain, fourth occurrence of the
pattern). Per the task instruction the serializer/query-param scaffolding is
inlined, matching the carryover/payroll precedent. The helper set
(`readTrimmedParam` / `isCalendarDate` / `readValidatedParam` / `toCsvCell` /
`serialize*Csv` / `buildCsvResponseHeaders`) now exists in four routes —
the carryover 2.5 outcome's carry-forward recommendation to extract a shared
utility still stands and is worth doing before a fifth route.

## Carry-forward

- **Query-param names** are `title`, `types`, `expenseDate`, `paymentDateFrom`,
  `paymentDateTo`, `includeDeleted` — the ViewModel's Export CSV handler must
  build the query string with exactly these names (`types` comma-separated,
  values are the display-form enum members `Salaries|Marketing|Logistics|Technology`).
- `X-Export-Truncated` is sourced from `ExpenseService.getReport`'s
  `totalCount`; the UI should read it to show the truncation toast (E13).
- Meta note: `ExpenseType` and `CurrencyCode` serialize as their enum string
  values; the column contract above is the one the tests pin.
