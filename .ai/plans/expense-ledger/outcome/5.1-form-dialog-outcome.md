# Outcome — Task 5.1: Expense Add/Edit form dialog + form ViewModel

- **Date**: 2026-09-07
- **Status**: ✅ Complete

## What was done

Created the expense add/edit dialog and its form ViewModel in
`frontend/common/views/dashboard/accounting/expenses/`, mirroring the carryover
pair (`useCarryoverFormViewModel.ts` + `CarryoverFormDialog.tsx`): RHF 3-generic
`useForm<Input, undefined, Output>` + `zodResolver` with a schema factory fed by
namespaced validation copy, one `clientRequestId` per dialog open with a
one-submit token guard, `useMutation(createExpenseMutationDocument /
updateExpenseMutationDocument)` with `errorPolicy: "none"`, aggregate-safe cache
eviction of the `expenses` root field + `gc()`, and success/error toasts via
`useNotifications`.

### Form fields (AC-3.1)

- `title` — required, maxLength 200 (`EXPENSE_TITLE_MAX_LENGTH` mirror).
- `type` — MUI Select over all four `ExpenseType` values; the `Salaries`
  MenuItem renders **disabled** with a persistent helper hint
  (`modal.form.salariesHint`) because create rejects it
  (`EXPENSE_SALARIES_VIA_CARRYOVER_ONLY`, AC-2.5).
- `teacher` — optional `TeacherAutocomplete` (create sends `teacherId`; update
  sends `teacherId` + `teacherName` together so the name snapshot follows the id).
- `expenseValue` — numeric text input (string, decimal) with the selected
  currency code as end adornment; seeded from `row.expenseValue` in edit mode.
- `expenseCurrency` — required `CurrencySelect`.
- `paymentDate` — `AppDatePicker` (full date).
- `expenseMonth` — `AppDatePicker` with `views={["year","month"]}`,
  `openTo="month"`, `format="yyyy-MM"` (same convention as the filter bar),
  serialized to `YYYY-MM` on submit.
- `note` — optional multiline, maxLength 2000 (`EXPENSE_NOTE_MAX_LENGTH`).
- Add-mode-only banner: `modal.form.sourceBanner(labels.source.Manual)` with an
  info icon (matches the prototype's "recorded as source: Manual" row).

### Salaries edit lock (AC-3.3 + Q5)

`salariesLocked = row.type === ExpenseType.Salaries` disables the `type` and
`expenseValue` fields and shows the immutable-field hints. On update of a
Salaries row, `type` and `expenseValue` are **omitted from the patch**
(`buildUpdateExpenseInput`) so the payload cannot trip the server-side
immutability guards.

### Error mapping

- `EXPENSE_SALARIES_VIA_CARRYOVER_ONLY` → inline on `type` (server-localized
  message, fallback `error.typeImmutableForSalaries`).
- `EXPENSE_TYPE_IMMUTABLE_FOR_SALARIES` → inline on `type`.
- `EXPENSE_VALUE_IMMUTABLE_FOR_SALARIES` → inline on `expenseValue`.
- Everything else → toast with the server-localized message
  (`getGraphQLErrorMessage`) or `commonLabels.operationFailed`.

### i18n additions (discovered missing keys)

Added to `types` + `en` + `ar` leaves of `dashboard.accounting.expenses` — all
three files are new/untracked from task 3.3, so edits were plain content edits:

- `modal.form.salariesHint` — helper under the type select ("Salary expenses are
  created automatically through the carryover settlement flow." / AR).
- `modal.form.sourceBanner(source)` — typed interpolation for the add-mode
  footer banner; renders `labels.source.Manual` so the token is localized too.
- `validation.typeRequired` — type-select presence message.
- `validation.titleTooLong` — 200-char ceiling (matches `EXPENSE_TITLE_MAX_LENGTH`).
- `validation.valueInvalid` — amount shape mismatch (up to 12 digits + 2 decimals,
  mirroring the mutation-test round-trip `AMOUNT_PATTERN`).
- `validation.noteTooLong` — 2000-char ceiling (matches `EXPENSE_NOTE_MAX_LENGTH`).
