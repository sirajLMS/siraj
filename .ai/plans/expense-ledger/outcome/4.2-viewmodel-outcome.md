- **Date**: 2026-09-06

## Deliverable

`frontend/common/views/dashboard/accounting/expenses/useExpensesViewModel.ts` (new,
~355 LoC) — `useExpensesViewModel()` built one-to-one on the carryover
`useCarryoverViewModel` composable pattern (sub-hooks assembled top-down,
module-scope helpers):

- **Filter store composition** — `useExpenseFilterSlice()` pulls every
  `useExpenseFilterStore` field and action (`title`, `types`, `expenseDate`,
  `paymentDateFrom`, `paymentDateTo`, `includeDeleted`, `page`, `pageSize`,
  `selectedIds` + setters, `toggleSelected`, `clearSelection`, `clearFilters`)
  into an `ExpenseFilterSlice`; the ViewModel spreads it so tier views consume
  one flat object. (`expenseFilterStore.ts` is task 4.3, landed concurrently.)
- **Debounced title search** — local `useDebouncedTitle(title)` (300 ms), same
  convention as carryover: the store holds the raw text, the debounced value
  feeds both the query filter and the export URL.
- **GraphQL** — `useQuery(expensesQueryDocument, { variables, fetchPolicy:
  "cache-and-network", skip: !canViewExpenses })` (never `useLazyQuery`).
  Variables: `{ filter, limit: pageSize, offset: page * pageSize }`;
  `buildExpenseFilter()` returns `null` when no filter is active (empty title,
  no types, no dates, includeDeleted off) and otherwise maps each field onto
  the `ExpenseFilter` input one-to-one (`types` spread to satisfy the mutable
  `Array<ExpenseType>` codegen shape).
- **Aggregates** — `toExpenseAggregates()` normalizes the flattened page fields
  (`totalValue`, `dominantCurrency`, `rowCountByType`); the JSON-scalar
  `rowCountByType` (`unknown`) is narrowed with an `isRowCountByType` guard
  (Reflect.get per key, no `as` casts) to `Readonly<Record<string, number>>`,
  defaulting to `{}` on shape mismatch.
- **Pagination** — `page`/`pageSize` store state with `onPageChange` /
  `onPageSizeChange` callbacks and `pageSizeOptions = EXPENSE_PAGE_SIZE_OPTIONS`
  (from the store, for the list pager).
- **CSV export (E13)** — exported `buildExpensesExportCsvUrl()` serializes onto
  `/api/expenses/export` with the route's exact param names (`title`, `types`,
  `expenseDate`, `paymentDateFrom`, `paymentDateTo`, `includeDeleted`);
  empty/absent filters are omitted and `includeDeleted` is always sent so the
  export matches the on-screen grid exactly. **`types` translation**: the route
  validates against the backend enum's display values (`Salaries|Marketing|
  Logistics|Technology`) while the store/query carry the GraphQL enum members
  (serialized `SALARIES|…`), so `EXPENSE_TYPE_EXPORT_VALUE`
  (`Record<ExpenseType, string>`) maps them for the export path only — the
  GraphQL filter keeps the enum untouched. `handleExportCsv()` fetches with
  `fetch` + blob + synthetic anchor (keeps `Content-Disposition` /
  `X-Export-Truncated` headers readable, server filename honored, `expenses.csv`
  fallback), never rejects — resolves `{ truncated }` or `null` on
  failure/backend error (logged via `logger.error`). The consumer
  (grid/toolbar) owns the toast.
- **Permissions** — `canViewExpenses` (`AppPermission.AccountingExpensesView`,
  also gates the query via `skip`) and `canManageExpenses`
  (`AppPermission.AccountingExpensesManage`) via `useUserStore(s => s.hasPermission)`.
- **Labels** — `useAppTranslation(DashboardAccountingExpenses) →
  `labels: ExpensesLabels` grouped per Rule 7 (no `*Label` fields).
