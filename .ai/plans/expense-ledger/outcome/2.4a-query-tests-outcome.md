`frontend/common/graphql/test/`. The new file sits at

## Coverage (16 tests, 99 expect() calls, all green)

### `expenses(filter, limit, offset)`

- **Page shape**: rows with all 19 exposed fields (nullable provenance fields
  included), `totalCount`, and the flattened aggregates (`totalValue`,
  `dominantCurrency`, `rowCountByType` as JSON); DateTime scalar serialization
  asserted via ISO instant; service called with `USER_ID`, default
  `{ limit: 50, offset: 0 }`, and the context-bound error labels.
- **Pagination**: explicit `limit`/`offset` pass-through; `null`/`null` falls
  back to the `{ 50, 0 }` defaults.
- **Filter mapping**: full filter (title, two `types` members, expenseDate,
  paymentDateFrom/To, includeDeleted=false) forwarded verbatim with the TS enum
  values; absent `filter` and omitted `filter` both map to the all-null
  `ExpenseFilters` (absent-field → `null`, not `undefined`).
- **`includeDeleted` re-gating (2.2 contract)**: view-only caller requesting
  `includeDeleted: true` gets it silently stripped to `false`; callers holding
  `ACCOUNTING_EXPENSES_MANAGE` keep `true`; super admins without the explicit
  manage permission keep `true`; explicit `false` passes through unchanged.
- **Auth gating**: missing `ACCOUNTING_EXPENSES_VIEW` → `FORBIDDEN` +
  `errors.insufficientPermissions`, no service call; logged-out context → same
  `FORBIDDEN`; permissioned context with no `user.id` → `UNAUTHENTICATED` from
  `requireAuth`; super admin without the explicit permission is allowed through.

### `expense(id)` drill-down

- Returns the row resolved by id, asserted across the carryover-settlement
  provenance surface (`sourceEntity: "carryover_balances"`, `sourceEntityId`,
  teacher snapshot, `Salaries` type); `getById(actorUserId, id, tErrors)` call
  args asserted.
- Missing view permission → `FORBIDDEN`, no service call.

### Cross-cut

- An unrelated-permission holder (`SESSION_RESCHEDULE`) gets `FORBIDDEN` on both
  expense reads with no service calls.

## Fixes en route (in-file only)

- **Enum variable serialization**: GraphQL variable values and response enum
  fields serialize by enum member *name* (`MARKETING`), not the TS enum value
  (`"Marketing"`). The full-filter test now sends `types: ["MARKETING",
  "LOGISTICS"]` as variables while asserting the service receives
  `[ExpenseType.MARKETING, ExpenseType.LOGISTICS]`; row assertions compare
  against the serialized names. (Carryover did not hit this: its enums have
  name == value.)
