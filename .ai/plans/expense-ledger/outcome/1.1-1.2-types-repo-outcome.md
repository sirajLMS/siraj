### 1.2 Repository — `backend/db/repo/expenses/expense.repository.ts`
(`backend/db/repo/expenses/index.ts` barrel + `./expenses` in `backend/db/repo/index.ts`.)

`ExpenseRepository` namespace:

- `findFiltered(filters, pagination, tx?)` → `ExpensePageResult` — ILIKE title with
  wildcard escaping (`escapeLikeWildcards` + `caseInsensitiveLike`), `type IN (...)` via
  `inArray`, `expenseDate =`, `paymentDate` lexicographic range (ISO text columns), default
  `deletedAt IS NULL` unless `includeDeleted`. Joins `users` for `createdByName`. Newest-first
  ordering with `id` tiebreak; `totalCount` covers the full filtered set.
- `getById(id, tx?)` / `getByIdForUpdate(id, tx)` — tx-required locking read (FOR UPDATE) for
  the update/soft-delete paths.
- `create(input: ExpenseInsertType, tx?)`, `update(id, patch, tx?)` (bumps `updatedAt`),
  `softDelete(id, actorUserId, reason, tx?)`, `bulkSoftDelete(ids, actorUserId, reason, tx?)`
  (empty-array short-circuit, single UPDATE … IN). Soft-delete sets
  `deletedAt`/`deletedByUserId`/`deletedReason` + `updatedAt`. All writes accept the caller's
  `tx` so settlement flows stay atomic.

defaults + null provenance, salaries row with teacher snapshot + `carryover_balances`

`findFiltered` rows — the exact inputs Phase 1.10's `getReport` will consume).
