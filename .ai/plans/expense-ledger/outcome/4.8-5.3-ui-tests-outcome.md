## Written-but-unexecuted — what a first run must verify

These suites have never been executed (the wave policy forbids running UI tests).
First-run risks, in rough likelihood order:

1. **MUI X date/month picker typing** — `fillDate` uses `fireEvent.change` on the
   picker textboxes (`"09/01/2026"` for the full date, `"2026-09"` for the
   `views={["year","month"]}` month picker). The year-month picker has no repo
   test precedent at all; if its textbox is read-only or does not commit on
   change, `expenseDate` stays unset and every create/edit assertion that depends
   on the exact input fails. Carryover's full-date precedent (`MM/dd/yyyy`) is
   the only analog and is itself unexecuted in this wave's harness.
2. **MUI Select drive-through** — `fireEvent.mouseDown` on the type combobox +
   `click` on the option assumes the standard MUI select menu behavior; the
   `aria-disabled` Salaries assertion assumes the MenuItem carry-over of
   `disabled` → `aria-disabled`.
3. **Option accessible names** — the currency option regex `/EGP/` and teacher
   option `RegExp(name)` assume the autocomplete option's accessible name
   contains those strings (source reads support this; unverified at runtime).
4. **Autocomplete mount query** — `teachersMock()` is provided unconditionally on
   the assumption `TeacherAutocomplete` queries on mount; an unused extra mock is
   harmless.
5. **Drawer source chip role** — the clickable MUI Chip is expected to expose
   `role="button"`; if it renders differently the provenance-navigation test
   needs a different query (the Manual chip non-interactive assertion is the
   inverse of that assumption).
6. **Summaries split across elements** — the delete-summary assertion matches the
   interpolated `summary(title, value, currency)` string against a single
   `Typography`; if the text is broken across nodes a function matcher is needed.
7. **Axe** — `color-contrast` disabled everywhere (Happy DOM has no styles); the
   container test also disables `heading-order` (owned by shared layout
   primitives), same exclusions as the carryover sibling.

First-run command (when the policy allows):
`bun run test/scripts/run-test.ts frontend/common/views/dashboard/accounting/expenses/<file>` —
the suites run through the single-file runner, not `test:ui:components`
(co-located suites self-register Happy DOM).
