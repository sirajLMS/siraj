### Prior State
Three tier-specific badge components existed with ~199 lines / 1224 tokens of jscpd-detected triplication:
- `frontend/common/components/ui/badge/StatusBadge.tsx` (270 lines) — common/viewport-agnostic tier

All three contained **100% identical** shared logic:

- **Typography**: mobile has optional `labelSm` variant with custom fontSize + textTransform: uppercase; common/desktop use `labelUppercase`

**Key implementation details**:

- All styling via `sx` prop callbacks returning single objects (MUI v9 compliant)
- Theme callback pattern for all palette access
- No direct style props (`fontWeight`, `textAlign`, `mb`, `p`, `display`, etc.)
- `"use client"` directive
- `Readonly<>` wrapper on component props

## Carry-Over Knowledge

- **Scaffold pattern established**: `*Shared.tsx` with `SharedProps` + `SlotProps` interfaces, exported via barrel
- **Slot prop design**: Use typed configuration objects (`chipDimensions`, `typographyProps`) instead of `SxProps` callbacks to avoid MUI v9 `sx` array typing issues — MUI v9 expects single object returns from `sx` callbacks
- **Dynamic palette access**: Use `Reflect.get(theme.palette.status, key)` instead of `as keyof typeof` casts to satisfy `no-unsafe-type-assertion`
- **Task 2.2 (common StatusBadge refactor)** can now consume this scaffold with common tier's slot props
- **Tasks 2.3/2.4 (desktop/mobile refactors)** will consume with their respective slot props
