## Key Design Decisions

### Slot Props Pattern
The scaffold uses a slot props pattern where each variant passes tier-specific components:
- **Common tier**: `LocalizedStringFormField`, `CountryAutocomplete`, `CurrencySelect`, `PaymentMethodSelect`, `PhoneFormField`, `TagInput`
- **Desktop tier**: `LocalizedStringFormFieldDesktop`, `CountryAutocompleteDesktop`, `CurrencySelectDesktop`, `PaymentMethodSelectDesktop`, `PhoneFormFieldDesktop`, `TagInputDesktop`
- **Mobile tier**: `LocalizedStringFormFieldMobile`, `CountryAutocompleteMobile`, `CurrencySelectMobile`, `PaymentMethodSelectMobile`, `PhoneFormFieldMobile`, `TagInputMobile`

### Shared Options
- `stackSpacing`: Number for Stack gap (common/desktop: 2, mobile: 2 via `sx={{ gap: 2 }}`)
- `textFieldSize`: Optional TextField size ("small" for mobile)

### TypeScript Invariance Fix
The `Control<T>` (where `T extends FieldValues`) is invariant and cannot be implicitly assigned to `Control<FieldValues>`. Fixed by:
1. Slot prop types use `name: string` instead of `FieldPath<FieldValues>` for covariance
2. Slot prop types use `control: Control` (default type parameter = `Control<FieldValues>`)
3. Scaffold casts `control as Control` (safe, documented with eslint-disable comment)
