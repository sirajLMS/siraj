## Key Technical Decisions

1. **Shared enums defined in `shared/constants/`** — Following the pattern from task 1.10, enum definitions were moved to `shared/constants/` rather than importing from `@/backend/enum` (which violates layer isolation per `shared/AGENTS.md`).

2. **Backend enum values used as canonical** — The shared enums use backend database values (e.g., `NOT_ACTIVATED`, `COMPLETED`) rather than GraphQL codegen values (e.g., `NotActivated`, `Completed`).

3. **Frontend-only functions retained** — Functions that use GraphQL codegen types (`parseCountryCode`, `parseBookingStatus` with uppercase, `parseIanaTimezoneGQL`) remain in `frontend/common/lib/enum.ts` and re-export from shared.

4. **Backwards compatibility barrel** — `backend/lib/enum.ts` kept as a re-export barrel to avoid breaking existing imports from `@/backend/lib` across the codebase.
