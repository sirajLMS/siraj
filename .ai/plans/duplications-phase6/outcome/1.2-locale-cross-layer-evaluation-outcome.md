### Analysis:
The frontend file defines view-specific label types (`TeacherViewLabels`, `StudentViewLabels`) that are **structurally derived subsets** of the canonical `ClassDetailsLabels` from `shared/locale/types/`. The duplication is in the type signature shape — the frontend interfaces mirror the structure of sections from the canonical type (e.g., `timezone`, `instanceDetails`, `remarks`, `performance`, `actions`).

This is **structural duplication** by design:
1. The frontend types are **view-shaped** — they pick specific sections needed by teacher/student/admin views, not the full canonical type
2. The canonical `ClassDetailsLabels` defines ALL fields; the frontend types define only the subset each view needs
3. Per `frontend/common/views/AGENTS.md` Rule 7, view-layer types may `Pick`/compose canonical `*Labels` — but these are manual interface definitions, not `Pick` aliases
4. Consolidating to `Pick<>` aliases would require extensive refactoring of the builder functions for marginal benefit

The 3 frontend↔shared locale type pairs (115t, 102t, 79t) are **structural** — they represent the i18n type system pattern where view-layer types mirror canonical type shapes.
