## Extraction Decisions

### Options Pattern (style/config differences)
Used `*Shared.options.ts` files exporting `DESKTOP_OPTIONS` and `MOBILE_OPTIONS` typed to a `<Component>SharedOptions` interface. Differences encoded as:
- `SxProps<Theme>` for MUI sx prop differences (spacing, flex direction, button styles)
- Plain config objects for non-style differences (Grid sizes, Dialog props, Tabs variant)

### Slots Pattern (component reference differences)
Used `ComponentType<...>` typed slot fields in a `<Component>SharedSlots` interface. Differences encoded as:
- `ComponentType<{ readonly children: ReactNode }>` for PageContainer-like slots
- `ComponentType<Readonly<...Props>>` for domain-specific component slots
- Named prop interfaces (`PageHeaderSlotProps`, `PrimaryPageActionSlotProps`) for components with non-overlapping prop sets

### userOverridesDataGrid — Structural Difference Handling
Desktop uses `DesktopAppDataGrid` with `useMemo` columns; mobile uses `MobileCardList` with custom card rendering. These are fundamentally different container components and cannot share a top-level container. Instead, extracted the **shared rendering helpers** that both tiers use inside their respective containers:
- `UserGroupsChips` — group chip rendering (secondary container styled boxes)
- `EditOverridesButton` — edit overrides button (uppercase, labelMd, fontWeight 700)
- `StatisticBox` — mobile statistic box (label + content vertical layout)
- `OverridesCellBox` — wrapper around `OverridesCell` for grants/revokes/status
- `StyledUserAvatar` — styled avatar with initials
- `getAvatarInitials` — extracted to `.helpers.ts` file (non-component) to satisfy `react-refresh/only-export-components`

## Key Type Resolution Patterns

- **PageContainer slot type**: `ComponentType<{ readonly children: ReactNode }>` works for `DesktopPageContainer`/`MobilePageContainer` (which use internal hooks like `useThemeMode`). The `children` must be `ReactNode` (required, not optional) to match both component prop signatures.
- **StatusBadgeCategory**: Imported from `@/frontend/common/components/ui/badge` (not `string`) for badge slots.
- **UiTypographyVariant**: Imported from `@/frontend/common/types/shared.types` for typography variant slots (equals `NonNullable<TypographyProps["variant"]>`).
- **LocalizedStringFormField**: Must import `LocalizedStringFormFieldProps` from the shared file directly (`@/frontend/common/components/ui/input/localizedString/localizedStringFormFieldShared`), not the barrel — the barrel doesn't export the type.
- **Generic components**: `LocalizedStringFormField<T extends FieldValues>` is a generic function component. Making the scaffold generic causes type errors with react-hook-form's invariant `Control<T>`. Fix: bind directly to the concrete form data type (`PermissionGroupFormData`).
- **react-refresh/only-export-components**: Non-component exports (e.g., `getAvatarInitials`) must live in a `.ts` companion file, not the `.tsx` component file.

## Codescene Large Method Fix (permissionManagementViewShared)

The main `PermissionManagementViewShared` function started at 127 lines, triggering codescene "Large Method" warning. Resolved by extracting module-scope helper functions:
- `buildTabs(t)` — builds the AdminQueueTabBar tab array
- `renderHeaderActions(ctx)` — renders the "Add Permissions" action button
- `renderSingleGroupView(ctx)` — renders the single-group view branch
- `renderTabContent(ctx)` — renders the tab content branch (header + tab bar + permission tab content)
- `renderDialogs(ctx)` — renders all management dialogs

Context objects (`RenderContext`, `DialogContext`) use `Pick<PermissionManagementViewModel, ...>` to ensure type safety without manually repeating 50+ prop types.
