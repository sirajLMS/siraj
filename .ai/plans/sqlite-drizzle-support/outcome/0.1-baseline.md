### The 9 consumer tsgo errors (categorized into 3 clusters)

**Cluster A — nullable FK columns passed where `string` expected (4 errors, 4 files)**
Root cause: `uuidDefaultColumn` (used for FK columns) infers `string | null` (FK is nullable). Consumers pass these to helpers typed `(id: string) => ...` without null-guarding. Pre-existing latent type-unsafety surfaced by the port (PG `uuid` FK also nullable, but tsgo inferred differently before).
- `backend/services/payment-method/payment-method.service.ts:270` — `string | undefined` -> `string`
- `backend/services/seed/leave-request-seed.service.ts:37` — `(string | undefined)[]` -> `string[]`
- `backend/services/seed/student-seed.service.ts:92` — `{studentId: string|undefined; classInstanceId: string|undefined}[]` -> non-nullable
- `backend/services/seed/teacher-payment-seed.service.ts:45,47` — `string | undefined` -> `string` (2 errors)

**Cluster B — `bigintColumn` union return type (1 error, 1 file)**
Root cause: `bigintColumn` maps PG `bigint` (returns `string`) + SQLite `blob({mode:"bigint"})` (returns `bigint`) -> tsgo infers `string | number | bigint`. Consumer expects `bigint`.
- `backend/services/storage/storage.service.ts:138` — `fileSize: string | number | bigint` -> `bigint`

**Cluster C — `createPool()` returns null for SQLite (3 errors, 1 file)**
Root cause: `factory.ts:createPool()` returns `null` for SQLite (no separate pool — libsql manages connections). `getDrizzleDbPool()` returns `PgPool | Pool | null`. Consumer (`custom-sql.adapter.ts`) does not null-guard.
- `backend/services/cron/queue-adapters/custom-sql.adapter.ts:95` — `pool is possibly null` (TS18047) + `not callable` (TS2349)
- `backend/services/cron/queue-adapters/custom-sql.adapter.ts:97` — `Pool | Pool | null` -> `QueryablePool` (TS2322)
