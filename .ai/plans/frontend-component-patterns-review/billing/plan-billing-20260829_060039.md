**Most critical (verified)**: `frontend/desktop/views/dashboard/billing/paymentsLedger.desktop.tsx` is a wholesale custom implementation — hand-rolled `Table`/`TableHead`/`TableRow` with zebra styling, bespoke `ChildHourBalanceCard` metric cards with a **per-card `useQuery` (N+1)**, raw `useQuery` + `useRouter` in the view, hardcoded English strings with zero i18n, and no permission gating in the file.

**Original headline claim retracted**: the `parentBillingShared.options.tsx` "CRITICAL tier isolation violation" is NOT a rule violation — dual-tier options modules (`DESKTOP_OPTIONS`/`MOBILE_OPTIONS`) are the documented repo convention (`frontend/AGENTS.md`) used by ~10 domains. The genuine (smaller) cost is bundle-level: because each tier wrapper imports the shared options module, both `BillingSectionDesktop` and `BillingSectionMobile` land in both tier chunks. Fix via the local-options idiom, not via switcher changes — the switcher already lazy-loads correctly.
