# Executive Summary — `teachers` View Audit

The `teachers` domain is **largely compliant** with the component-patterns mandate: all list surfaces use `DesktopAppDataGrid`/`MobileCardList` with `paginationOptions`, tier isolation is clean (switchers + lazy views, no `useViewport` leaks in tier views), metrics flow through `DesktopMetricCardGrid`/`MobileMetricCardGrid`, and person display is dominated by `PersonProfileLink` / `StatusBadge`. The remaining debt concentrates in **form dialogs** (raw MUI `Dialog`/`Select`/time inputs), **two hand-rolled person-link cells**, **duplicated dismiss buttons**, and **one tier view reaching into a Zustand store directly**.
