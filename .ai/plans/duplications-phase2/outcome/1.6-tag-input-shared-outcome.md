# Task 1.6: TagInputShared Scaffold & Variant Refactoring

## Summary

Created `TagInputShared.tsx` scaffold in the common tier and refactored all 3 TagInput variants (common, desktop, mobile) to consume it via slot props. Eliminated all TagInput-specific code clones.

## Files Created

- `frontend/common/components/ui/input/tagInput/TagInputShared.tsx` — Scaffold with shared business logic, styled components, and slot props for tier-specific styling differences.

## Files Refactored

- `frontend/common/components/ui/input/tagInput/TagInput.tsx` — Common variant: thin wrapper, defaults only (chipSize "small", no sx extensions).
- `frontend/desktop/components/ui/input/tagInput/tagInput.desktop.tsx` — Desktop variant: thin wrapper, passes `inputSxExt` with `{ margin: 0.5, flexGrow: 1 }`.
- `frontend/mobile/components/ui/input/tagInput/tagInput.mobile.tsx` — Mobile variant: thin wrapper, passes `chipSize="medium"`, `chipSxExt`, `labelSxExt`, `inputSxExt`, `chipEditInputSxExt` for mobile-specific sizing.

## Slot Props Design

The scaffold exposes `TagInputSlotProps` with:
- `chipSize` — Chip size ("small" for common/desktop, "medium" for mobile)
- `chipSxExt` — Extra sx merged into each Chip (mobile adds `minHeight` + `fontSize`)
- `labelSxExt` — Extra sx merged into the label Typography (mobile adds `fontSize`)
- `inputSxExt` — Extra sx merged into the main InputBase (desktop/mobile add `margin` + `flexGrow`)
- `chipEditInputSxExt` — Extra sx merged into the chip-edit InputBase (mobile adds larger sizes)

All extensions are merged via `mergeSx` utility, not replacing the base styles.

## Business Logic Unification

The scaffold unifies to the desktop/mobile pattern:
- Uses `useTagInputEditing` and `useTagInputDeletion` hooks directly
- Uses `useEffect` for `onChange` propagation (matching desktop/mobile)
- The common variant's `onChangeRef` pattern was replaced with the simpler `useEffect` approach (functionally equivalent — both fire `onChange` when tags change)
