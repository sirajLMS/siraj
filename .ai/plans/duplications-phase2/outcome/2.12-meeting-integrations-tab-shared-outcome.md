## Slot Props Design

```typescript
export interface MeetingIntegrationsTabSlotProps {
  /** Layout for the AccordionSummary header — desktop uses inline row, mobile wraps to two rows. */
  readonly summaryContentSx: SxProps<Theme>;
  /** Inner wrapper layout within summary — desktop keeps chips inline, mobile wraps reauth chip below. */
  readonly summaryRowSx: SxProps<Theme>;
  /** Padding for AccordionDetails — desktop uses px: 2, mobile uses px: 1. */
  readonly detailsSx: SxProps<Theme>;
}
```

The only tier-specific variations between desktop and mobile are 3 layout sx objects:

| Slot | Desktop | Mobile |
|------|---------|--------|
| `summaryContentSx` | `{ display: "flex", alignItems: "center", gap: 1 }` (inline row) | `{ display: "flex", flexDirection: "column", gap: 0.5 }` (column wrap) |
| `summaryRowSx` | `{ display: "flex", alignItems: "center", gap: 1 }` | `{ display: "flex", alignItems: "center", gap: 1 }` |
| `detailsSx` | `{ px: 2, pb: 2 }` | `{ px: 1, pb: 2 }` |

All other rendering (loading guard, error guard, health headers, accordion expansion, provider label switch, credential form, test connection panel, connected accounts table, revoke dialog, token metadata dialog) is identical and lives in the scaffold.
