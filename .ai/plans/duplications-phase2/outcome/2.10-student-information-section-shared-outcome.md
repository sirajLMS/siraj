## Scaffold Design

### Slot Props Interface (`StudentInformationSectionSlotProps`)

Tier-specific primitives are injected through these slots:

- **`DatePicker`** — the tier's date picker (`AppDatePicker` for desktop, `MobileAppDatePicker` for mobile). The scaffold passes `{ value, onChange, slotProps }` whose shape matches both implementations. Because `AppDatePicker` is typed with MUI's `DatePickerProps` and `MobileAppDatePicker` is typed with a narrower `MobileAppDatePickerProps`, each tier file casts its picker to `ComponentType<StudentInfoDatePickerProps>` — this cast is a widening/interface-mapping cast between structurally compatible prop types, not a narrowing `as` pattern.
- **`SectionHeader`** — a tier-specific wrapper around `SectionHeaderDesktop` (`desktopIcon` prop) or `SectionHeaderMobile` (`mobileIcon` prop). The slot normalizes the icon-prop name via thin `DesktopSectionHeader`/`MobileSectionHeader` helpers in each tier file so the scaffold can call `<SectionHeader title icon />`.
- **`sectionHeaderIcon`** — `BadgeOutlined` for both tiers.
- **`rootGap`** — outer container gap (4 desktop, 3 mobile).
- **`fieldsGap`** — fields container gap (4 desktop, 2 mobile).
- **`gridTemplateColumns`** — `"1fr 1fr"` (desktop two-col) vs `"1fr"` (mobile single column).
- **`genderFieldPx`** — `0` desktop, `0.5` mobile (kept the slight horizontal padding the mobile variant had on the gender `FormControl`).
- **`rootSx`** — optional `SxProps<Theme>` overrides; unused today but available for future minor tweaks.

### Shared body inside the scaffold

The scaffold re-implements every per-field component that was previously duplicated:

- `StudentNameField`, `DateOfBirthField`, `LanguageField`, `GenderField` — verbatim from the originals, all MUI v9 `sx` styling, `*Outlined` icon family not used here (the only icon is the section header's which is supplied by the slot).
- `isQuotaFieldKey` type guard + `parseDateValue` helper — moved into the scaffold; the mobile variant's equivalent `getFieldLabel` helper is no longer needed because the scaffold uses the same `isQuotaFieldKey` approach the desktop variant used.
- Access-gated short-out (`ProfileRestrictedSection` when `!canView("student_identity")`) lives in the scaffold so both tiers render the restricted state identically.

### No circular dependencies

All imports go to direct file paths:

- `studentInformationSectionShared.tsx` imports `studentInformationSectionShared.types` (same folder), `quotaFieldStyles`, `quotaFormAccessContext`, `profile/useStudentFieldAccess`, `profile/shared/sections/ProfileRestrictedSection`, `common/lib/locale`, `common/providers/localeContext`, `common/components/ui/display/localeEmoji/LocaleEmoji`. None come from `frontend/mobile` or `frontend/desktop`, and none come through barrel `index.ts` files.
- The desktop tier imports the scaffold via `@/frontend/common/views/dashboard/students/quota/components/studentInformationSectionShared`, plus `AppDatePicker` from `@/frontend/common/components/ui/form` and `SectionHeaderDesktop` from `@/frontend/desktop/views/dashboard/students/quota/components/sectionHeader.desktop`.
- The mobile tier imports the scaffold via the same direct path, plus `MobileAppDatePicker` from `@/frontend/mobile/components/ui/form/date` and `SectionHeaderMobile` from `@/frontend/mobile/views/dashboard/students/quota/components/sectionHeader.mobile`.

## Clone Elimination

- **Before (baseline)**: `studentInformationSection.desktop.tsx` ↔ `studentInformationSection.mobile.tsx` was cluster #20 in the baseline (3 clones, ~923 tokens, ~160 lines — see `0-baseline-outcome.md`).
- **After**: running `bun check:duplicates` shows **0** clones containing the string `studentInformationSection`. The only remaining `quota/components/` clones are `contextualHelperCards.desktop.tsx` ↔ `contextualHelperCards.mobile.tsx` which are out of scope for Task 2.10.
- The desktop and mobile files are now ~34 lines each of trivial slot plumbing; the cloneable field logic lives in a single scaffold.

## Notes

- The two original files used different label helpers (`isQuotaFieldKey` on desktop, `getFieldLabel` on mobile) for the gender option labels; both resolve to the same `t.fields[option.labelKey]` lookup, so the scaffold's single `isQuotaFieldKey` covers both cases.
- The `ProfileRestrictedSection` short-out (rendered when the logged-in user lacks `student_identity` view permission) now lives in the shared scaffold so both tiers render exactly the same restricted state with no per-tier duplication.
