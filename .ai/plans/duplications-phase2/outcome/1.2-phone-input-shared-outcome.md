## Slot Props Design

```typescript
export type PhoneInputSlotProps = {
  readonly LocaleEmojiComponent: React.FC<{ readonly emoji: string }>;
  readonly PhoneCountryPickerComponent: React.FC<{
    readonly country: CountryType | undefined;
    readonly onSelectAction: (country: CountryType) => void;
  }>;
  readonly PrefixInputElement: React.FC<
    React.InputHTMLAttributes<HTMLInputElement> & {
      readonly sx?: SxProps<Theme>;
      readonly ref?: React.Ref<HTMLInputElement>;
    }
  >;
  readonly resolveHelperText: (params: {
    readonly prefixInvalid: boolean;
    readonly showRequiredError: boolean;
    readonly phoneInvalid: boolean;
    readonly helperText: string | undefined;
    readonly t: { readonly invalidPrefix: string; readonly required: string; readonly invalidPhone: string };
  }) => string | undefined;
  readonly useOnNationalInput: boolean;
};
```

### Remaining Clones Explanation

The remaining clones are:
1. **`PhoneInputProps` type definition** (~14 lines, ~90 tokens per pair) — Each variant exports its own `PhoneInputProps` type for its consumers. This is intentional per the delegation pattern; consumers import from the variant, not the scaffold.
2. **Prop forwarding JSX block** (~28-31 lines, ~113-119 tokens per pair) — The `<PhoneInputShared value={...} onChangeAction={...} ... />` block that forwards all props to the scaffold. This is inherent to the delegation pattern and must match across variants.

These remaining clones are structural boilerplate (type definitions and prop pass-through), not duplicated logic. The actual presentation logic (253/229 lines of hook usage, state management, event handlers, adornment rendering, helper text resolution) is now fully shared via the scaffold.

## Technical Decisions

### `ref` Handling on `PrefixInputElement`

React 19 treats `ref` as a regular prop for function components. The `PrefixInputElement` type includes `readonly ref?: React.Ref<HTMLInputElement>` to allow the scaffold to pass `prefixInputRef` to the tier-specific prefix input element. The `BoxPrefixInput` wrapper (common/mobile) explicitly destructures `ref` and forwards it to `<Box component="input" ref={ref}>`. The desktop `StyledInput` (styled component) handles `ref` natively.

### `useOnNationalInput` Boolean Slot

Instead of passing a function slot (which wouldn't work because the hook is called inside the scaffold), the scaffold destructures both `onNationalInput` and `resetNationalDisplay` from the `usePhoneInput` hook and selects between them using the `useOnNationalInput` boolean. Common uses `true` (rich handler that handles programmatic fills via Playwright `.fill()`); desktop/mobile use `false` (simple handler that just resets the display).

### Helper Text Resolution Order Preserved

The original variants had different helper text resolution orders: common checked `helperText` before `phoneInvalid`, while desktop/mobile checked `phoneInvalid` before `helperText`. This behavioral difference is preserved exactly in the respective `resolveHelperText` slot implementations.
