## Slot Props Design

```typescript
export interface PaymentMethodDisplaySlots {
  StatusBadge: React.ComponentType<{
    category: "paymentMethod";
    status: string;
    label: string;
    size: "small";
  }>;
  CountryDisplay: React.ComponentType<{ code: string }>;
  CurrencyDisplay: React.ComponentType<{ code: string }>;
  LocalizedStringDisplay: React.ComponentType<{
    value: LocalizedString;
    typographyVariant?: UiTypographyVariant;
    sx?: SxProps<Theme>;
  }>;
  PhoneDisplay: React.ComponentType<{ phone: string; masked?: boolean }>;
}

export interface PaymentMethodDisplaySharedOptions {
  readonly outerSpacing?: readonly [number, number];
  readonly headerGap?: number;
  readonly detailSpacing?: number;
  readonly labelTypography?: UiTypographyVariant;
  readonly labelMinWidth?: number;
  readonly detailRowGap?: number;
  readonly titleTypography?: UiTypographyVariant;
}
```

The tier-specific differences are entirely captured by 5 slot components (tier-specific display/badge components) and 7 option values (spacing/typetry differences). All other logic (header spec building, detail row building, text/ltr text formatting, status badge rendering, chip rendering) is shared.

## Technical Notes

### `getLabel` Parameter Type

The `getLabel` callback is typed as `(labels: object, key: string) => string`. Initially used `Record<string, string>`, but TypeScript interfaces like `PaymentMethodTypeLabels` and `PaymentMethodDirectionLabels` don't have string index signatures, making them incompatible with `Record<string, string>`. Using `object` as the parameter type allows both the common/desktop `isKeyOf` pattern and the mobile `Object.hasOwn` + `Reflect.get` pattern to work without type errors.

### `UiTypographyVariant`

Used `NonNullable<TypographyProps["variant"]>` (aliased as `UiTypographyVariant` from `@/frontend/common/types/shared.types`) for typography variant props in the options interface, ensuring type safety for MUI v9 typography variants like `"labelSm"`, `"labelMd"`, `"titleLg"`, `"titleMd"`.

### Mobile Spacing Differences

The mobile variant uses compact spacing compared to common/desktop:
- Outer Stack: `[0.75, 1]` vs default `[1, 1.5]`
- Header gap: `0.75` vs default `1`
- Detail Stack spacing: `0.5` vs default `0.75`
- Label typography: `"labelSm"` vs default `"labelMd"`
- Label min width: `72` vs default `96`
- DetailRow gap: `0.75` vs default `1`
- Title typography: `"titleLg"` vs default `"titleMd"`

These are all captured via the `PaymentMethodDisplaySharedOptions` prop with fallback defaults for common/desktop.
