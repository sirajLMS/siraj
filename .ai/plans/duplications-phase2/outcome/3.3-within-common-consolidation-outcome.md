## Notes

- **Cluster 1**: `StudentPersonalFields.tsx` was dead code — never imported anywhere. Created shared `StudentExtensionFields.tsx` and deleted the dead file.
- **Clusters 2-3**: All three profile loading skeleton files (parent/staff/teacher) were dead code — exported but never imported. Created a shared config-driven `ProfileLoadingSkeleton.tsx` that accepts a card configuration array.
- **Cluster 4**: react-hook-form generics don't work with simple `Record<string, unknown>` constraints. Used a non-generic shared presentational component accepting already-resolved props (MeetingProviderFieldsFragment, TextField props, FieldError).
- **Clusters 5 & 10**: Same file pair, two clone instances. The main card components differ (pre-built styled components vs custom definition) but the skeleton and empty state are identical. Extracted both.
- **Cluster 6**: The `students/` version's `mapStudentHistorySessions` was dead code (never imported). Only `mapStudentHistoryMetrics` is used from that file. The shared module uses `effectiveMeeting: unknown` to avoid generics; the `student/` consumer uses a type guard (`isEffectiveMeeting`) to narrow it back.
- **Cluster 7**: `toParentLifecycleStatus` differs behaviorally between the two files — `directory.ts` throws on unknown status, `ParentsViewTypes.ts` defaults to "regular". Consolidated all shared types/interfaces but kept both function variants.
- **Cluster 8**: The admin-specific `label-mappers.ts` was dead code. The common version already had the full superset of fields (merged at some earlier point). Simple deletion.
- **Cluster 9**: Edit mode differs significantly (parent has accountStatus select only; teacher has nationalId text field + status select). Shared component only covers view mode; edit mode stays in each wrapper. The `InfoField` component is passed as a prop to avoid cross-directory imports.
