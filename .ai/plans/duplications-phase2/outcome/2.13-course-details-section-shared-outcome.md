## Slot Design

The scaffold uses `renderHeader: (title: string) => ReactNode` instead of a typed `ComponentType` slot for the section header. This avoids TypeScript incompatibility between `SectionHeaderDesktop` (requires `desktopIcon`) and `SectionHeaderMobile` (requires `mobileIcon`).

### Slot Props

- `renderHeader` — Renders tier-specific section header
- `teacherLabelId` — Unique ID for teacher select's InputLabel
- `rootGap` — Outer container gap (desktop: 4, mobile: 3)
- `fieldsContainerSx` — CSS layout (desktop: grid 3-col, mobile: flex column)
- `overrideEndAdornment` — Icon, font size, box/typography styles for "override active" adornment
- `overrideNotice` — Icon (optional), font size, typography styles for notice text
- `classesLeftInputSx` — Factory `(theme) => SystemStyleObject<Theme>` for TextField outlined-input root

## Technical Notes

- `SystemStyleObject` imported from `@mui/system/styleFunctionSx` (not `@mui/material`) for the `ClassesLeftInputSxFactory` return type — needed because `SxProps` includes arrays which aren't assignable to MUI's `sx` prop.
- All imports use direct file paths (no barrel re-exports) to avoid circular dependencies.
- Translation labels (`t.fields.overrideActive`, `t.fields.overrideNotice`) come from `useQuotaFormAccess()` inside the scaffold, not passed as slot props.
- No `oxlint-disable` comments. No `console.*`. All styling via `sx` prop (MUI v9 compliance).
