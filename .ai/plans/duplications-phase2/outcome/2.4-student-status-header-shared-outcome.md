# Task 2.4: StudentStatusHeader Shared Scaffold — Outcome

## Scaffold Interface

### File: `frontend/common/views/dashboard/students/status/components/studentStatusHeaderShared.tsx`

The scaffold exports `StudentStatusHeaderShared`, a `React.FC<StudentStatusHeaderSharedProps>` that encapsulates ALL shared presentation logic for the student status header component.

### Props (`StudentStatusHeaderSharedProps`)

```typescript
interface StudentStatusHeaderSharedProps {
  readonly student: StudentStatusPageData;
  readonly embedded: boolean;
  readonly slots: StudentStatusHeaderSlotProps;
}
```

### Slot Props (`StudentStatusHeaderSlotProps`)

| Slot Prop | Type | Purpose |
|-----------|------|---------|
| `AvatarComponent` | `React.ComponentType<{ src?, label, size?, sx? }>` | Renders the student avatar (DesktopUserAvatar or MobileUserAvatar) |
| `StatusDot` | `React.ComponentType<{ student }>?` | Optional status-dot overlay inside avatar (mobile-only) |
| `StatusBadgeComponent` | `React.ComponentType<{ category, status, label }>` | Renders the status badge (DesktopStatusBadge or MobileStatusBadge) |
| `buttonFullWidth` | `boolean` | Whether action buttons use `fullWidth` (mobile=true, desktop=false) |
| `embeddedWrapperSx` | `SxProps<Theme>?` | sx for the embedded-mode outer wrapper Box |
| `embeddedInnerWrapperSx` | `SxProps<Theme>?` | sx for an optional inner wrapper in embedded mode (desktop uses maxWidth) |

### Types File: `frontend/common/views/dashboard/students/status/types/studentStatusHeaderShared.types.ts`

Exports: `StudentStatusAvatarSlotProps`, `StudentStatusBadgeSlotProps`, `StudentStatusHeaderSlotProps`, `StudentStatusHeaderSharedProps`.

## What Was Extracted to the Scaffold

1. **Shared constants**: `STATUS_BADGE_MAP` and `getBadgeStatusKey` — removed from both variants
2. **StudentAvatar**: Avatar rendering with optional `StatusDot` slot (desktop has no status dot, mobile has colored dot overlay)
3. **StudentInfo**: Name, status badge, and teacher name rendering with field-access gating
4. **HeaderActions**: History + Contact Parent buttons with routing via `useRouter`
5. **Main header layout**: The full card layout (Box with paper/background, border, shadow, responsive flex)
6. **Embedded layout**: Embedded mode rendering with configurable wrapper sx

## What Remained Tier-Specific

### Desktop (`studentStatusHeader.desktop.tsx` — ~37 lines)
- Passes `DesktopUserAvatar` as `AvatarComponent`
- Passes `DesktopStatusBadge` as `StatusBadgeComponent`
- No `StatusDot` (desktop has no status dot overlay)
- `buttonFullWidth: false`
- `embeddedWrapperSx` with centered layout + `embeddedInnerWrapperSx` with `maxWidth: 720`

### Mobile (`studentStatusHeader.mobile.tsx` — ~67 lines)
- Passes `MobileUserAvatar` as `AvatarComponent`
- Passes `MobileStatusBadge` as `StatusBadgeComponent`
- Passes `MobileStatusDot` component (local) as `StatusDot` slot
- `STATUS_DOT_COLOR_MAP` and `getStatusDotColor` kept locally (mobile-only feature)
- `buttonFullWidth: true`
- `embeddedWrapperSx` with `flex-end` layout, no inner wrapper

## Behavioral Changes

**None.** The scaffold is a pure extraction — all behavioral logic was moved verbatim from the original variants. Tier-specific differences (avatar component, status dot overlay, status badge component, button fullWidth, embedded layout) are passed as slot props.

## Cross-File Dependencies

- Desktop and mobile variants import **ONLY** from the scaffold path `@/frontend/common/views/dashboard/students/status/components/studentStatusHeaderShared` — never from each other.
- The scaffold imports types from `@/frontend/common/views/dashboard/students/status/types/studentStatusHeaderShared.types`.
- No circular dependencies — all imports use direct file paths, not barrel re-exports.
