## Slot Props Design

```typescript
export type UserPaymentMethodAutocompleteSlotProps = {
  readonly optionSx?: SxProps<Theme>;
};
```

The only tier-specific piece is the option row's `sx` prop. Mobile uses larger touch targets (`px: 1.5, py: 1.25, minHeight: 48`), while common and desktop use the default (`px: 2, py: 1`). All other logic (filtering, label resolution, autocomplete rendering, input adornments, error state) is shared.

## Technical Notes

### `SxProps<Theme>` vs `React.CSSProperties`

Initially, `optionSx` was typed as `React.CSSProperties`, which caused a tsgo failure on the mobile variant because `React.CSSProperties` does not accept MUI shorthand props like `px`, `py`, `minHeight` (with numeric values). Fixed by using `SxProps<Theme>` from `@mui/material/styles`, which correctly accepts MUI's responsive shorthand syntax.

### `PaymentMethodLabels` Type

The desktop variant had a locally-defined `PaymentMethodLabels` type. Verified no external imports of it from the desktop file — safe to remove. The scaffold imports `PaymentMethodLabels` from `@/shared/locale`.

### Stories File Compatibility

Both `userPaymentMethodAutocomplete.desktop.stories.tsx` and `userPaymentMethodAutocomplete.mobile.stories.tsx` import `UserPaymentMethodAutocompleteProps` from their respective variant files. Both variants re-export the type from the scaffold via `export type { UserPaymentMethodAutocompleteProps }`.
