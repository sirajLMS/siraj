## API surface (carry-forward for 5.4 / 5.5 / 5.6)

Import: `import { useCreditAdjustFormStore } from "@/frontend/common/stores/creditAdjustFormStore";`
(queries/selectors via the standard Zustand hook, e.g.
`useCreditAdjustFormStore(s => s.hours)`).

Exported type: `CreditAdjustFormState` (exported interface; the private
`CreditAdjustFormFields` base holds the data-half).

**State fields** (all readonly):

| Field | Type | Default |
|---|---|---|
| `studentId` | `string \| null` | `null` |
| `adjustmentType` | `CreditAdjustmentType` (**shared enum** `ADD \| SUBTRACT \| SUBTRACT_WITH_CARRYOVER` from `@/shared/constants/billing`) | `ADD` |
| `hours` | `number \| null` | `null` |
| `notes` | `string` (rich-text HTML) | `""` |
| `carryoverTeacherId` | `string \| null` | `null` |
| `fromDate` / `toDate` / `paymentDate` | `string \| null` — **ISO date strings**, matching the repo's store convention (DatePicker boundary converts via `parseDateInput`/`new Date(...)` on read and formats back on change); the GraphQL input also takes strings | `null` |
| `clientRequestId` | `string` (UUIDv4) | `crypto.randomUUID()` |

**Actions**:

- `setStudentId(studentId: string | null)`
- `setAdjustmentType(adjustmentType: CreditAdjustmentType)`
- `setHours(hours: number | null)`
- `setNotes(notes: string)`
- `setCarryoverTeacherId(id: string | null)`
- `setFromDate(fromDate: string | null)`, `setToDate(toDate: string | null)`, `setPaymentDate(paymentDate: string | null)`
- `clearCarryover()` — nulls `carryoverTeacherId`, `fromDate`, `toDate`, `paymentDate` only (E3).
- `regenerateClientRequestId()` — fresh UUIDv4; **call on form mount** to get the
  "one token per form session" semantics (task 5.6) without wiping a student
  preselected from `?studentId=`.
- `reset()` — restores all defaults AND rotates `clientRequestId`.

## Consumer guidance (agreed shapes)

- **5.5 `AdjustmentTypeRadioGroup`**: on change → `setAdjustmentType(next)`; if
  `next !== CreditAdjustmentType.SUBTRACT_WITH_CARRYOVER` also call
  `clearCarryover()` (store deliberately does not auto-clear on type change —
  the radio owns the E3 interaction explicitly).
- **5.4 `CarryoverBanner`**: bind the three DatePickers via
  `parseDateInput(store.fromDate)` / `setFromDate(formatDateInput(date))`
  (helpers in `frontend/common/components/intl/dateFormat.ts` /
  the opt-in `optInHistoryHelpers.ts` pattern). Store keeps strings only.
- **5.6 `CreditAdjustForm`**: on mount call `regenerateClientRequestId()`;
  submit maps the shared enum to the GraphQL enum values
  (`ADD→CreditAdjustmentAdd`, `SUBTRACT→CreditAdjustmentSubtract`,
  `SUBTRACT_WITH_CARRYOVER→CreditAdjustmentCarryover`); **never** include
  `clientRequestId` in the mutation input — idempotency is derived server-side.
