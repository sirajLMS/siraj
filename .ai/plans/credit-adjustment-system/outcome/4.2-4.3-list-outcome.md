### Mock data contract note (for future component tests of this view)

Rows MUST include `__typename: "StudentDirectoryRow"` — Apollo's cache write
silently fails (data undefined, rows never render) when mock rows lack it,
because the gql-tag adds `__typename` selections at runtime. The empty-state
test passes regardless (nothing to normalize), which can mislead debugging.
Initial run: 2 pass / 3 fail purely from missing `__typename`.

## Carry-forward knowledge (Phase 5 form agent)

- **URL contract**: `/accounting/credits/adjust?studentId=<id>` —
  `CreditAdjustForm` receives `studentId: string | null`; the list already
  deep-links with this exact param.
- **Cache interplay**: the list uses `studentsDirectoryQueryDocument` with
  `fetchPolicy: "cache-and-network"`. The mutation document
  (`recordCreditAdjustmentMutationDocument`, Task 4.1) returns
  `studentId` + `changeAmount` but NOT the recalculated
  `classesRemaining`/`classesTotal` — so a successful adjustment will **not**
  auto-update the list grid row via `StudentDirectoryRow` normalization.
  Plan: after `recordCreditAdjustment` resolves, the form should
  `refetchQueries` / `cache.evict` the `studentsDirectory` root field (or the
  view's `cache-and-network` policy will refresh on next visit anyway).
  Flag this in the form outcome either way.
- **Row id safety**: `id` is `string | null` in the generated type; the row
  action renders nothing and never pushes a URL with `"null"` when the id is
  absent (Tier-1 null branch).
- **Balance chip thresholds** (list-only, non-authoritative):
  error ≤ 0, warning ≤ 3, else success — prototype-derived, centralized in
  `creditBalanceColor()`; the form's `validation.insufficientClasses` message
  is independent of this.
- **No Store was created** for the list: search state is local (single-file
  component per scope); the form's `useCreditAdjustFormStore`
  (Task 5.1, already done) is unaffected.
