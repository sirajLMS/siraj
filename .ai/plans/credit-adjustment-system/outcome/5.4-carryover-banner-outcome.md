### Store coupling (5.1 contract)

Reads `fromDate`, `toDate`, `paymentDate` + all four setters via
`useCreditAdjustFormStore` selectors; DatePicker boundary converts
`string | null` ⇄ `Date | null` via `parseDateInput` / `formatDateInput`
(ISO `YYYY-MM-DD` strings in store, `Date` objects in pickers) — exactly the
binding agreed in `5.1-store-outcome.md` consumer guidance.

The banner is the sole writer of the carryover fields while mounted (the form
renders it only for `SUBTRACT_WITH_CARRYOVER`; `clearCarryover()` / `reset()`
both move the type off carryover and unmount it, so the local teacher option
state always resyncs naturally on remount — no mirror effect needed).

### Date constraint wiring (mirrors server rules from 1.9 / AC-4.3, AC-4.4)

| Field | Constraint | Rationale |
|---|---|---|
| From Date | `maxDate = toDate` | `fromDate > toDate` is rejected server-side |
| To Date | `minDate = fromDate` | same rule, opposite direction (bidirectional, sibling-change propagation) |
| Payment Date | `maxDate = today + 1 day` (`addDays(new Date(), 1)`) | `paymentDate > now + 1 day` rejected server-side |

`E4` (future fromDate), `E5` (fromDate == toDate), `E6` (past paymentDate)
all stay selectable — only the two invariant fences are enforced.

### Validation interplay (for 5.6/5.7)

Optional prop `errors?: CarryoverBannerErrors` (`{ teacher?, fromDate?,
toDate?, paymentDate? }` message strings) — the form computes mirror
validation (required fields, `fromAfterTo`, `paymentTooFar`, E8
`TEACHER_NOT_FOUND` highlight) and passes messages down; each populated key
sets `error` + `helperText` on the corresponding field
(`slotProps.textField` for pickers). With no `errors` prop the banner is
purely constraint-driven.

## Semantic review

- Constraint wiring is coherent and bidirectional: changing fromDate updates
  toDate's `minDate`; changing toDate updates fromDate's `maxDate`;
  `maxDate` on the payment picker recomputes every render
  (`addDays(new Date(), 1)`), so a long-open form cannot drift past the
  server-side "now + 1 day" fence.
- `parseDateInput` returns `null` for blank/invalid store strings, so a
  partially-cleared picker degrades to an empty field, not "Invalid Date".
- No plan/task tags in code comments; JSDoc describes domain behavior only.
- No cross-layer imports (`@/backend/*` untouched); no `console.*`; no new
  locale keys, barrels, or dependencies (date-fns already a direct dep and the
  picker's registered adapter).
