## Task 7.2 — Accessibility pass

### Audit findings (already compliant)

- **AdjustmentTypeRadioGroup**: `FormControl` + `FormLabel id` wired to
  `RadioGroup aria-labelledby`; native radio semantics; focusable hidden `Radio` with
  `focus-within` outline on the card; icons `aria-hidden`. No change.
- **CarryoverBanner**: all four fields carry MUI labels (via `slotProps.textField` for the
  date pickers), `error`/`helperText` wired. No change.
- **CreditAdjustForm**: student picker, hours `TextField`, reason editor, and both buttons all
  labeled; hours field sets `aria-invalid` on error. No change.
- **RichTextEditor**: toolbar `aria-label`, `aria-pressed` toggles, editor `role="textbox"` +
  `aria-labelledby`/`aria-label`. Two gaps found and fixed (below).

### A11y edits made

1. `frontend/common/components/ui/input/richText/RichTextEditor.tsx` — the MUI `error` /
   `required` / `helperText` props were visual-only: the contenteditable node carried no
   `aria-invalid`, no `aria-required`, and no association with the helper text. Added a
   dedicated sync effect that mirrors `aria-required` / `aria-invalid` onto
   `editor.view.dom` and points `aria-describedby` at the (now `id`-bearing)
   `FormHelperText`; cleared when no helper text is present.
2. `frontend/common/views/dashboard/accounting/credits/StudentCreditsList.tsx` — the toolbar
   search `TextField` had only a `placeholder` (not an accessible name; an axe `label`-rule
   violation). Added `htmlInput` slot `"aria-label": directory.searchPlaceholder` +
   `autoComplete: "off"`, mirroring the existing `PaginationControlsShared` /
   `PhoneInputShared` idiom.

### axe-core test assertions (new)

Repo had **no existing axe usage** (grep: zero hits in `test/`, only a transitive install via
`@storybook/addon-a11y` / `eslint-plugin-jsx-a11y`). Established the pattern here:
`axe-core@^4.12.1` (the exact version already in `bun.lock`) promoted to an explicit
devDependency (`package.json` + `bun.lock`, one line each — `bun install` verified clean).

`test/ui/components/accounting/CreditAdjustForm.test.tsx` (+2 tests / 43 expects total, was 8/39):

- shared helper `expectNoAxeViolations(container)` — `run(container)` with `color-contrast`
  disabled (Happy DOM cannot compute visual styles; the rule lands in `incomplete`, and
  contrast is already owned by the theme token system). Uses the named `run` export because
  eslint `import-x/no-named-as-default-member` rejects `axe.run` on the default export.
- **default Add state**: zero axe violations.
- **carryover-expanded state**: radio switched to `subtractWithCarryover`, banner mounted,
  zero axe violations.
