## E3 carryover-clearing contract

On change:

```ts
const next = parseAdjustmentType(value);      // raw string → enum, null on unknown
setAdjustmentType(next);
if (next !== CreditAdjustmentType.SUBTRACT_WITH_CARRYOVER) {
  clearCarryover();
}
```

- The store intentionally does **not** auto-clear on type change; this control
  owns the pairing.
- Both actions are called synchronously in the same React event handler, so
  React 19 automatic batching collapses them into one render — no transient
  intermediate state (carryover fields with a non-carryover type) is ever
  observed by consumers such as the CarryoverBanner.
- Raw radio `value` strings are parsed through an explicit literal parser
  (`parseAdjustmentType`) instead of an `as` cast — satisfies
  `typescript/no-unsafe-enum-comparison` without `no-unnecessary-type-conversion`.
