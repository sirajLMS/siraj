Added the `ACCOUNTING_CREDITS_MANAGE = "accounting.credits_manage"` permission end-to-end:
TypeScript enum value, idempotent custom SQL migration (permission row + group grants),
generated drizzle migration folder, and a new enum test covering both the happy path
(Tier 1) and the unknown-slug rejection paths (Tier 4).

## Files NOT changed, and why

- `backend/db/seeds/**` — NOT touched. `backend/db/seeds/AGENTS.md` explicitly FORBIDS seeding
  system permissions from seeders: `permissions`, `permission_groups`, and `group_permissions`
  rows must come from SQL under `backend/db/migration/` + drizzle migrations. The task prompt's
  "permission-group seeds under `backend/db/seeds/permissions/`" location does not exist in this
  repo anymore; the actual mechanism is the custom-migration pipeline, which was used instead.
- `backend/db/schema/enums.ts` — NOT touched. `app_permission` is declared via
  `createPgEnumFromEnum("app_permission", AppPermission)`, so it derives the new value from the
  TS enum automatically (DB-side value is applied by the `ALTER TYPE ... ADD VALUE` in the SQL).
- No "Accounting" / "Finance Manager" permission group exists in the system. The full group slug
  set is: `super_admin`, `academy_admin`, `teacher_default`, `parent_default`, `staff_default`,
  `system_automated`, `supervisor_default`, `student_default`. Following the exact precedent of
  `accounting.payments_manage`, the grant went to `super_admin` + `academy_admin` (the groups that
  own all `accounting.*` / `billing.*` manage permissions). Documented here as the
  seed-group decision in case a dedicated accounting group is introduced later — it would need
  its own follow-up grant migration.
