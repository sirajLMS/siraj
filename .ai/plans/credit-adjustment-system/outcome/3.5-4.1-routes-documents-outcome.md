## Task 4.1 — Apollo documents

### `frontend/common/graphql/sharedDocuments/billing/credit-adjustment.documents.ts` 🆕
`recordCreditAdjustmentMutationDocument: TypedDocumentNode<RecordCreditAdjustmentMutation,
RecordCreditAdjustmentMutationVariables>` via the `gql` helper (this repo's convention is
`gql` from `@apollo/client` + generated operation types, **not** the `graphql()` codegen
helper — verified against `credit-lms.documents.ts`). Matches the actual backend
signature from `backend/graphql/mutation/billing/credit-adjustment.mutation.ts`:

```graphql
mutation RecordCreditAdjustment($input: CreditAdjustmentInput!) {
  recordCreditAdjustment(input: $input) {
    id
    studentId
    changeAmount
    changeAmountHours
    reason
    adjustmentType
    carryoverTeacherId
    carryoverFromDate
    carryoverToDate
    carryoverPaymentDate
    notes
    creditedByUserId
    createdAt
    updatedAt
  }
}
```

- `id` included for Apollo cache normalization (rule).
- `adjustmentType` + 4 `carryover*` fields included — the form needs to echo them back
  in the success toast / carryover path.
- **`sourcePaymentId`, `classInstanceId`, `idempotencyKey` omitted** — null/`null`-ish
  for manual adjustments and not needed by the form; the mutation is "mutation errors"
  free (GraphQL errors propagate with `extensions.code` per Phase 2, no union payload).
- **`clientRequestId` intentionally absent** — Phase 2 outcome: it never existed on
  `CreditAdjustmentInput`; idempotency is derived server-side
  (`deriveAdjustmentIdempotencyKey`).

 ); rows already carry `classesRemaining`/`classesTotal`.
- **List locale namespace**: `dashboardTranslations.billingCreditAdjustment` for page
  chrome (title, adjustCredits, validation, success.*); nav label `accountingCredits`
  lives in `dashboard.core.nav`.
