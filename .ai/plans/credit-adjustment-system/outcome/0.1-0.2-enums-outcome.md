# Outcome — Tasks 0.1 + 0.2: Credit Adjustment Enums

- **Status**: ✅ Done
- **Date**: 2026-08-29

## Summary

Task 0.1 introduced `CreditAdjustmentType` (`ADD | SUBTRACT | SUBTRACT_WITH_CARRYOVER`,
SCREAMING_SNAKE_CASE per every other PG enum in the repo) following the repo's
cross-layer enum convention: the canonical `enum` lives in `shared/constants/` and
`backend/enum/` holds a value re-export shim (identical to the existing
`CreditReason` pattern). Task 0.2 extended `CreditReason` with three new values
(`CREDIT_ADJUSTMENT_ADD`, `CREDIT_ADJUSTMENT_SUBTRACT`, `CREDIT_ADJUSTMENT_CARRYOVER`)
in the single canonical shared definition, and registered
`CreditAdjustmentTypePothosEnum` in the shared Pothos enum registry so later phases
can use it as a field type.

## Files Created

- `shared/constants/billing/credit-adjustment.enum.ts` — canonical `CreditAdjustmentType` enum.
- `backend/enum/billing/credit-adjustment.enum.ts` — value re-export shim
  (`export { CreditAdjustmentType } from "@/shared/constants/billing/credit-adjustment.enum";`),
  matching `backend/enum/billing/credit.enum.ts`.
- `shared/constants/billing/index.ts` — new barrel for the previously barrel-less
  `shared/constants/billing/` directory (returns `credit-adjustment.enum`, `credit.enum`,
  `invoice-file-usage`, `payment-proof`, `polling`).

## Files Modified

- `backend/enum/billing/index.ts` — added `export * from "./credit-adjustment.enum";`.
- `shared/constants/billing/credit.enum.ts` — extended `CreditReason` with the three
  `CREDIT_ADJUSTMENT_*` values.
- `backend/graphql/pothos/shared/enum.pothos.ts` — imported `CreditAdjustmentType`
  and registered `CreditAdjustmentTypePothosEnum` via the enum-object form
  (`gqlSchemaBuilder.enumType(CreditAdjustmentType, { name: "CreditAdjustmentType" })`).
- `.ai/plans/credit-adjustment-system/trackable-tasks.md` — appended `✅ DONE` to the
  `### 0.1` and `### 0.2` heading lines (headings only; file structure unchanged).
