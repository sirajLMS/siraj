# Visual Fix 5 — Carryover Banner Wide-Layout Breakpoint + Notch Label Surface (CarryoverBanner)

At desktop 1440x900 the carryover banner in `frontend/common/views/dashboard/accounting/credits/CarryoverBanner.tsx` collapsed its fields into a narrow left column with ~45% dead space on the right: the 1-col(xs) → 2-col(sm) → 4-col(xl) grid only engaged its wide layout at MUI's `xl` breakpoint (1536px), so the very common 1440px desktop still got the 2-column/tall arrangement. The fix lowers the wide layout to `lg` (1200px) and rebalances it: `gridTemplateColumns` is now `xs: "1fr"`, `sm: "repeat(2, 1fr)"` (unchanged for tablets), `lg: "repeat(3, 1fr)"` — the teacher picker keeps its full-width row (`gridColumn: "1 / -1"`, now a constant since it spans at every breakpoint, previously keyed to `xl`) and the From/To/Payment date pickers share one 3-column row below it (CarryoverBanner.tsx `FIELDS_GRID_SX` / `TEACHER_FIELD_SX`). Mobile (`xs`) and tablet (`sm`) behavior is untouched. The secondary LOW fix paints the floating outlined-input notch labels (`& .MuiInputLabel-root, & .MuiPickersInputLabel-root` inside the Alert sx) with `theme.palette.successContainer` — the same tone as the banner surface — so the notch reads as part of the banner instead of letting the page background show through; theme tokens only, no hardcoded colors, mirrors the notched-outline intent of the RichTextEditor pattern without inventing a custom fieldset.
