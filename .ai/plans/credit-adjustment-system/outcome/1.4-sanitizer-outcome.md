## Summary

Delivered `sanitizeRichText` — the server-side sanitization control for the
rich-text Reason persisted to `credit_transactions.notes` (specs AC-5.2/AC-5.4,
edge case E12). Implemented as a **pure, zero-dependency allowlist string
rewriter**, NOT DOMPurify+jsdom — see "Design deviation" below; the deviation
satisfies the same security contract with strictly stronger runtime safety on
Vercel.

## Signature (exact — later tasks depend on this)

```ts
// backend/lib/sanitize/richTextSanitizer.ts
export function sanitizeRichText(html: string): string;
export const RICH_TEXT_ALLOWED_TAGS: readonly ["b","br","em","i","li","ol","p","strong","u","ul"];
```

- Pure, synchronous, never throws; empty input → `""`; idempotent
  (`sanitizeRichText(sanitizeRichText(x)) === sanitizeRichText(x)`).
- No module-level mutable state (the only ambient binding is a `const`
  `RegExp` lastIndex-set per scan iteration); no per-call jsdom windows —
  there is no DOM at all, so the SR leak concern is void by construction.
- `implementation.md` call sites (`notes: sanitizeRichText(input.notes)` in
  §addCredit/subtractCredit/subtractWithCarryover snippets) are compatible
  as-is; the doc's `sanitizeHtml` naming resolves to this canonical export.

## Final allowlist (SEC — the security contract)

- **Tags**: `b`, `br`, `em`, `i`, `li`, `ol`, `p`, `strong`, `u`, `ul`
  (exactly the TipTap StarterKit output set for the toolbar in
  implementation.md §5.6: Bold/Italic/Underline/BulletList/OrderedList +
  paragraphs, plus `b`/`i` aliases).
- **Attributes**: **none, on any tag.** Every tag is re-emitted as a bare
  canonical tag, so `on*=` handlers, `style`, `href`, `src`, and all future
  attribute vectors are dropped by construction — protocol allowlisting of
  URLs is unnecessary because no URL-bearing attribute can survive.
- **Containers removed with contents**: `script`, `style`, `iframe`,
  `object`, `embed`, `svg`, `math` (linear `indexOf` scan; unmatched opener
  truncates the tail so payload text cannot outlive its container).
- **Stray `<` escaping**: any `<` not part of an allowlisted tag becomes
  `&lt;`, closing the concatenation vector where an unterminated tag
  (e.g. `<img src=x onerror=…` with no `>`) would be completed by markup
  rendered after the sanitized fragment.
- Neutralized-and-tested payload classes: plain/uppercase/attributed
  `<script>`, `<img onerror>`, `javascript:`/`data:`/entity-obfuscated
  `href`, `<svg onload>` and `<svg><script>`, mXSS foreign-content
  (`<math>/<style>` breakout, `<listing>`), `iframe`/`object`/`embed`,
  `formaction`, `form`, `body onpageshow`, `details ontoggle`, nested
  tag-obfuscation (`<scr<script>ipt>`), `<style>@import`, unterminated tags,
  event handlers and `style` on allowed tags. Benign formatting
  (`<p><b><i><u><strong><em><ul><ol><li><br>`, unicode/RTL Arabic) survives
  byte-identical.

## Design deviation (DOMPurify+jsdom → zero-dependency rewriter) — rationale

The plan (implementation.md §5.6/§10, task 1.4) specifies "DOMPurify + jsdom
on the server". **Not implemented as specified**, because
`shared/lib/appearance.helpers.ts` (lines 24–46) carries an explicit,
production-incident-backed ban, discovered during IV:

> Banned: `isomorphic-dompurify`, `dompurify` + `jsdom` (or happy-dom /
> linkedom wired for DOMPurify), any sanitizer that pulls `jsdom` /
> `html-encoding-sniffer` / `@exodus/bytes` into the Next.js server / Vercel
> serverless graph. Why (production incident 2026-08-26): Vercel's Node
> function runtime disables `require(ESM)`; `isomorphic-dompurify → jsdom@30+
> → html-encoding-sniffer@6 → @exodus/bytes` (ESM-only) throws
> `ERR_REQUIRE_ESM` and takes down the entire web handler.

The mutation service that will call `sanitizeRichText` runs inside exactly
that Vercel serverless graph, so the mandated dependency chain would have
re-created the outage. The same header prescribes the remedy: a tight
zero-dependency allowlist sanitizer. AC-5.4 binds the *behavior* ("strip
`<script>`, event handlers, and `javascript:` URLs using the shared
sanitization helper"), which this implementation meets; TB.3/TB.4
penetration checks should target behavior, which is fully covered here.

**Dependencies added: NONE.** `package.json`/lockfile untouched (`jsdom` was
already a devDependency and remains unused by this module).
