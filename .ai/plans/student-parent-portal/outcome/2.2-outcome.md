## Summary

Created the Monthly Appraisal service layer and its 4-tier test suite.

1. `backend/services/monthly-appraisal/monthly-appraisal.service.ts` — `export namespace MonthlyAppraisalService` with 5 public methods:
   - `submitAppraisal(input, teacherUserId, locale?)` — teacher submits/updates; resolves teacherId from auth context; asserts `APPRAISAL_SUBMIT`; verifies teacher-teaches-student via `StudentRepository.hasTeacherAssignment`; validates grades 1–5 (integers, null allowed = sparse rubric); normalizes `month` to first-of-month; explicit field mapping to repo input (BOPLA).
   - `addFeedback(input, authorUserId, locale?)` — parent/student appends; asserts `APPRAISAL_FEEDBACK`; loads appraisal; tenancy check (author is the student, or parent of the student, or teacher of the student); validates non-empty body (trimmed).
   - `getMyMonthlyAppraisal(studentUserId, month, locale?)` — student views own; asserts `APPRAISAL_VIEW`; resolves studentId from userId; returns `null` for not-found (R1.6 empty state).
   - `getStudentMonthlyAppraisals(viewerUserId, studentId, locale?)` — parent/teacher/student views; asserts `APPRAISAL_VIEW`; tenancy: parent owns student OR student is self OR teacher teaches student.
   - `getTeacherMonthlyAppraisalStudents(teacherUserId, month?, locale?)` — teacher lists assigned students; asserts `APPRAISAL_SUBMIT`; cross-references appraisals for the month.
2. `backend/services/monthly-appraisal/test/monthly-appraisal.service.test.ts` — 43 tests across 4 tiers (Tier 1: branches; Tier 2: boundaries; Tier 3: out-of-order; Tier 4: security/tenancy) + a shared `expectRejects` helper and module-scope mock builders (`buildMockTeacherSelect`, `buildMockStudentSelect`, `buildMockParentSelect`, `callGetTeacherAppraisalStudents`, `expectAddFeedbackRejects`).

Updated barrels:

## 2.2.SR Semantic Review checklist

- [x] Teacher identity always from auth context (`teacherUserId` → `TeacherRepository.findByUserId`), NEVER from client input (Tier 4 test "forged teacherId in input is ignored" verifies the service ignores any client-supplied teacherId).
- [x] No client-supplied IDs pass unmatched through to repo — `studentId` is tenancy-checked (`assertTeacherTeachesStudent` / `assertCanViewStudentAppraisals`); `teacherId` is auth-derived.
- [x] No `...input` spread into repo writes (BOPLA) — explicit field mapping in `submitAppraisal` → `MonthlyAppraisalRepository.upsert({ studentId, teacherId, month, behaviorGrade, ... })`.
- [x] Grade validation at service layer (1–5 integers, null allowed) — `validateGrade` helper throws `ValidationError` for out-of-range/non-integer.
- [x] Month normalization to first-of-month at service layer — `normalizeToFirstOfMonth(date)` sets day=1, hours=0.
- [x] Tenancy: parent → own children only (via `ParentRepository.getAssociatedStudentById`); student → self only; teacher → assigned students (via `StudentRepository.hasTeacherAssignment`).
- [x] No read-then-write without atomicity — upsert is idempotent (repo handles conflict); appendFeedback is a pure insert.
- [x] No module-level mutable state.
- [x] No dead branches.
- [x] No cross-layer imports (service imports only from `@/backend/db/repo`, `@/backend/types`, `@/backend/enum`, `@/backend/lib`, `@/shared/locale`, `@/backend/services/auth`).
- [x] Enums value-imported when used at runtime (`AppPermission.APPRAISAL_SUBMIT` etc).
- [x] No `resolveEnvConfig` keys in this task (time-lock is F2, not F1).

## Carry-forward knowledge for future subtasks

- `TeacherRepository.findByUserId(userId, tx?): Promise<TeacherSelectType | null>` — returns the teacher row or null.
- `StudentRepository.getStudentIdByUserId(userId, tx?): Promise<string | null>` — resolves studentId from userId (used in `getMyMonthlyAppraisal`).
- `StudentRepository.hasTeacherAssignment(studentId, teacherId, tx?): Promise<boolean>` — teacher-teaches-student check.
- `ParentRepository.findByUserId(userId, tx?): Promise<ParentSelectType | null>` — parent lookup.
- `ParentRepository.getAssociatedStudentById(parentId, studentId, tx?)` — parent-owns-student check.
- `StudentRepository.getAssignedToTeacher(teacherId, tx?): Promise<{ rows: TeacherAssignedStudentReturnType[]; totalCount: number }>` — teacher's student list.
- Locale error keys: `getServerTranslations(locale).errorsTranslations` has generic keys; appraisal-specific keys (`appraisalNotFound`, `teacherNotAssigned`) are NOT in the locale system yet — 3.1 Pothos resolvers may add them via a new i18n namespace, OR reuse generic `NotFoundError("APPRAISAL", tErrors.notFound)`. **Decision: reuse generic keys for now; 4.1 frontend will add the `monthlyAppraisal` i18n namespace for UI strings.**
