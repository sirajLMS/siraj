## Carry-forward knowledge for future subtasks

- `bun run generate:gqlSchema` runs BOTH schema generation AND codegen (no separate `bun codegen` needed). Single command.
- Permission migration pattern: `ALTER TYPE app_permission ADD VALUE IF NOT EXISTS 'key'` MUST run before any INSERT/CAST referencing the new value. `ALTER TYPE ADD VALUE` cannot run inside a transaction block — keep it as a standalone statement (the `DO $$ ... $$` trigger disable/enable block is separate).
- The test DB (`siraj_test`) does NOT share enum types with the dev DB — new `app_permission` values must be added to BOTH DBs. The migration SQL with `ALTER TYPE ... ADD VALUE IF NOT EXISTS` is idempotent and safe to run on both.
- Pothos `inputRef<Shape>` requires the Shape to match the implemented fields exactly. For input types where some fields are resolved from auth context (not client input), use `inputRef<Omit<FullShape, "authContextField">>` and implement only the client-facing fields.
- Pothos `authScopes: { permission: AppPermission.X }` checks permission at the schema layer; `requireAuth(ctx)` checks authentication at the resolver layer. Both are in play — for unauthenticated requests, the auth-scope may reject before the resolver; for authenticated-but-unauthorized, the resolver's permission check OR `requireAuth` throws.
- Integration test `expectUnauthenticated`: the test client may carry session cookies, so an "unauthenticated" request (empty headers) may still be authenticated. The codebase convention (`assertOperationDenied`) only asserts the operation is denied (thrown OR error present), not the specific error code. Follow this convention.
- `NotFoundError("APPRAISAL", msg)` produces error code `APPRAISAL_NOT_FOUND` (constructor builds `${entity}_NOT_FOUND`). Integration tests asserting IDOR probes on non-existent appraisals should expect `APPRAISAL_NOT_FOUND`, not `NOT_FOUND`.
- `MonthlyAppraisalStudentEntry` type includes: id, name, studentAvatarUrl, parentId, parentName, parentAvatarUrl, status, hoursPerWeek, classesRemaining, classesTotal, appraisalForMonth. The sharedDocuments query for `teacherMonthlyAppraisalStudents` only selects id/name/studentAvatarUrl/appraisalForMonth (sparse) — can be extended in 4.x frontend if more fields are needed.
- Full `test:graphql` suite has a pre-existing flaky test: `class-session.test.ts > "teacher marks a class past waiting period as absent"` fails with "Teacher is already booked at this time" (scheduling conflict). This is NOT caused by this plan. Filter it during post-implementation review using the Phase 0 baseline.
