## Repository API

```ts
export namespace MonthlyAppraisalRepository {
  upsert(input: MonthlyAppraisalSubmitInput, tx?: DBTransaction): Promise<MonthlyAppraisalReturnType>;
  findById(id: string, tx?: DBTransaction): Promise<MonthlyAppraisalReturnType | null>;
  findForStudentMonth(studentId: string, month: Date, tx?: DBTransaction): Promise<MonthlyAppraisalReturnType | null>;
  listForStudent(studentId: string, tx?: DBTransaction): Promise<MonthlyAppraisalReturnType[]>;
  listForTeacherStudents(teacherId: string, studentIds: readonly string[], tx?: DBTransaction): Promise<MonthlyAppraisalReturnType[]>;
  appendFeedback(input: AppraisalFeedbackInput, tx?: DBTransaction): Promise<AppraisalFeedbackReturnType>;
}
```

### Key implementation notes

- **Upsert target**: `[monthlyAppraisals.studentId, monthlyAppraisals.teacherId, monthlyAppraisals.month]`
  — matches the unique index `monthly_appraisals_student_teacher_month_unique_idx` created in task 1.1.
- **Explicit column lists** on both insert and `onConflictDoUpdate` set — NO `...input` spread (BOPLA).
  The `set` block overwrites all 8 rubric fields + `learningTargets` + `updatedAt`; `id`, `createdAt`,
  and the unique-key columns are preserved.
- **Feedback batch-load**: single `inArray(appraisalFeedback.appraisalId, ids)` query joined via
  `leftJoin(users, eq(appraisalFeedback.authorUserId, users.id))` for `authorName`. Grouped by
  `appraisalId` and attached to each appraisal row via the private `withFeedback` helper.
  - **NO prepared statements** with `inArray` (per `backend/db/repo/AGENTS.md` rule — PG prepared
    statement protocol treats `$1` as a single scalar and cannot expand array parameters for `IN`).
- **Read paths**: all use `queryDb(tx)` (Neon HTTP rule) — `findById`, `findForStudentMonth`,
  `listForStudent`, `listForTeacherStudents`, and the feedback batch-load.
- **Write paths**: all use `executor = tx ?? db` — `upsert` and `appendFeedback`.
- **Tenancy**: repo is tenant-neutral. All methods accept `studentId` / `teacherId` as plain params;
  the service layer (task 2.2) owns `teacher.teaches(student)` + `parent.owns(student)` verification.

   appraisal repo only requires valid `studentId` + `teacherId` FK references. The
   `teacher.teaches(student)` tenancy check is enforced at the service layer (task 2.2).
6. **Repo upsert unique-key target**: `[monthlyAppraisals.studentId, monthlyAppraisals.teacherId,
   monthlyAppraisals.month]` — matches the unique index
   `monthly_appraisals_student_teacher_month_unique_idx` created in task 1.1.
7. **Feedback batch-load via `inArray` MUST NOT use prepared statements** (PG protocol limitation).
   The repo's private `loadFeedbackByAppraisalIds` helper uses
   `queryDb(tx).select().from().leftJoin(users).where(inArray(appraisalFeedback.appraisalId, ids))`
   directly. Reuse this pattern in 3.1 if a DataLoader is added.
8. **Defensive `if (!row) throw` guard pattern** — used to narrow Drizzle's
   `.returning()` `T | undefined` to `T` for the downstream call. Unreachable in normal operation
   but consistent with the codebase convention. Uncovered line reported as the throw statement
   (line 135 in this repo).
9. **Bun coverage report columns**: `% Funcs | % Lines | Uncovered Line #s` (NO branches column).
   AGENTS.md rule 14 ("100% lines and functions") is the operative constraint.
10. **`bun test --coverage` is blocked** by a project guard (`scripts/test-runner-guard.ts`) —
    bypass with `SIRAJ_TEST_RUNNER_OK=1` prefix for local coverage checks. For CI/regression
    checks, use `bun run test:db:coverage` (the approved runner).
11. **Lint rule `sonarjs/prefer-specific-assertions`** — use `expect(X).toHaveLength(N)` instead
    of `expect(X.length).toBe(N)` for any array/string length assertion.
12. **Instruction file path**: `.agents/instructions/backend.instructions.md` (NOT
    `.agents/instructions/...` — that path was a typo in task 1.1's outcome).
13. **Test file size limit for SSH exec**: 26KB+ files cannot be sent via a single
    `echo '<base64>' | base64 -d > <remote>` command — the SSH exec channel buffer truncates.
    Workaround: split the file into ≤8KB chunks locally (`split -b 8000`), then append each
    chunk via `echo '<chunk_b64>' | base64 -d >> <remote>` in sequence.
14. **`runInRollback` + `Promise.allSettled` interaction**: when firing concurrent ops against
    the same `tx` (rollback transaction), Postgres serializes them within the transaction.
    The unique index + `onConflictDoUpdate` clause ensures both promises settle without
    duplicate-key hard errors — one row wins, the other updates via conflict. Verified by the
    Tier 3 concurrency test.
15. **`run-test.ts` log path**: `logs/<timestamp>/<relative-path>.log` — view last result via
    `bun run test/scripts/run-test.ts --last <path>`.
16. **Tier 4 invalid-id behavior (recorded)**: passing a non-UUID string (`"not-a-uuid"`) to
    `findById` / `findForStudentMonth` / `listForTeacherStudents` causes Postgres to throw
    `invalid input syntax for type uuid: "not-a-uuid"` (error code `22P02`). The repo does NOT
    gracefully return null — the error propagates up. Tests catch it via try/catch and assert
    `error !== null || result === null`. Service layer (2.2) should validate id shapes BEFORE
    calling repo methods (Zod schema on the input).
17. **`month` parameter handling**: the repo accepts any `Date` and stores it as-is (no
    normalization). The service layer (2.2) MUST normalize to first-of-month before calling
    `upsert` / `findForStudentMonth` — otherwise mid-month timestamps won't match first-of-month
    queries (verified by the Tier 2 mid-month boundary test).
