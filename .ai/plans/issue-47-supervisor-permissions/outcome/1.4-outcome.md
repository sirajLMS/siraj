## Root-cause enum fix (pre-existing database state corruption)

The migration initially failed with
`invalid input value for enum app_permission: "auth.view_own_profile"` and
later `"teacher.view_profile"`, even though those keys were supposed to have
been added by earlier custom migrations (`6a-profile-field-permissions.sql`
adds `teacher.view_profile` at line 5).

Investigation traced the root cause to Drizzle migration
`backend/drizzle/20260731035353_parched_mister_fear/migration.sql` (lines 11-18),
which did:

```sql
ALTER TABLE permissions ALTER COLUMN key SET DATA TYPE text;
DROP TYPE app_permission;
CREATE TYPE app_permission AS ENUM (...226 values...);
ALTER TABLE permissions ALTER COLUMN key SET DATA TYPE app_permission;
```

The recreated enum was missing ~13 enum values that earlier migrations had
added via `ALTER TYPE ... ADD VALUE`. The missing values included
`auth.view_own_profile`, `teacher.view_own_profile`, `parent.view_own_profile`,
`parent.view_profile`, `staff.edit_profile`, `user.view_profile`,
`teacher.view_profile`, `auth.edit_own_profile`, `teacher.edit_own_profile`,
`parent.edit_own_profile`, `user.edit_profile`, and a few others.

This is a pre-existing database state corruption issue, NOT caused by
Tasks 1.1–1.3. It is out of scope for this task except insofar as the
migrations being applied need those enum values to exist.

### Fixes applied to source SQL files

To unblock the migrations, `ALTER TYPE app_permission ADD VALUE IF NOT EXISTS`
declarations were added to the tops of two source files (NOT to existing
Drizzle mirror folders, per the plan's rule):

1. **`backend/db/migration/3-system_permissions_and_groups.sql`** (lines 19-24):
   Added 6 declarations for the enum values referenced by plain
   `p.key IN (...)` clauses in this file:
   `auth.view_own_profile`, `teacher.view_own_profile`,
   `parent.view_own_profile`, `parent.view_profile`, `staff.edit_profile`,
   `user.view_profile`.

2. **`backend/db/migration/6-lms-permissions-and-groups.sql`** (line 14):
   Added 1 declaration for `teacher.view_profile`, which is referenced in the
   `supervisor_default` INSERT block (`p.key IN (...)` at line 228) where the
   plain string literal would otherwise fail to cast to the enum.

   The `6d-profile-fine-grained-only.sql` file references
   `auth.edit_own_profile`, `parent.edit_own_profile`, `teacher.edit_own_profile`,
   `teacher.view_profile`, and `user.edit_profile` only in `p.key::text IN (...)`
   DELETE clauses (safe text comparison), so no enum additions were needed
   there. After `6-lms` added `teacher.view_profile`, `6d-profile` applied
   cleanly on the next run.

## Sidecar manipulation performed

`backend/drizzle/.custom-migrations.json` was manually edited to revert the
`sha256` entries for `6-lms-permissions-and-groups.sql` and
`6d-profile-fine-grained-only.sql` back to their HEAD (pre-Task-1.1/1.2)
values, forcing `applyCustomMigrations.ts` to detect them as deltas and
regenerate mirror folders. The `manifestHash` was recomputed accordingly.

This was needed because the first migration run had generated empty/orphaned
mirror folders for those two files (which had not recorded any applied
migrations), and the subsequent failed runs left orphaned folders on disk
that had to be cleaned up.
