## Design Decisions

### Fresh entities for permission-based tests

Each academy_admin and supervisor test provisions a **fresh** student (+teacher) as
super admin instead of reusing the shared `studentId`/`newTeacherId` from the initial
setup test. This avoids state coupling issues:
- The super admin reassign test already moved the shared student to `newTeacherId`
- Each fresh entity starts in `REGULAR` status and with the default teacher assignment

The `provisionTestEntities` mutation only requires `loggedIn: true` authScope, so it
works correctly with the super admin token.

### Permission scope bypass confirmed

The `permission` authScope resolver (line 123 of `gqlSchemaBuilder.ts`) is:
```typescript
permission: (key: AppPermission) => ctx.isSuperAdmin || ctx.permissions.includes(key),
```
This means superAdmins (like the existing `super_admin` login) automatically pass the
permission check via `ctx.isSuperAdmin`, so existing superAdmin tests remain valid
without any changes.
