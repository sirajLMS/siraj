# Task 2.3: Update permission management service test

## Summary

Updated `backend/db/test/logic/permissions/permission-management.service.test.ts` to reflect the new
backend behavior where `updateGroup` on system groups succeeds for permission-only updates while
silently ignoring name/slug/description changes.

## Files Changed

- `backend/db/test/logic/permissions/permission-management.service.test.ts`

## Changes Made

### 1. Replaced: test expecting throw for system group update (old lines 306-312)

The old test used `testSystemGroupGuard` to assert that `updateGroup` throws
`cannotModifySystemPermissionGroup` when called on a system group with a name change.

**New test: "updateGroup on system group with permissionIds only should succeed"**

Calls `updateGroup` with only `permissionIds` (no name/description) on a system group and
verifies:
- The returned group has the correct `id` (matching the system group)
- The returned `permissionIds` array contains the provided permission ID

### 2. Added: test verifying name/description silently ignored

**Test: "updateGroup on system group should silently ignore name/description changes"**

Calls `updateGroup` with `name`, `description`, AND `permissionIds` on a system group and
verifies:
- The returned group's `name` matches the original system group name (not the attempted new name)
- The returned `slug` matches the original slug
- The returned `description` matches the original description
- The returned `permissionIds` contains the new permission (proving the permission update DID apply)

This confirms the service passes `name: undefined` and `description: undefined` for system groups,
and the repository skips name/slug/description updates for system groups.

### 3. Added: test verifying empty permissionIds clears all permissions

**Test: "updateGroup on system group with empty permissionIds should clear all permissions"**

Calls `updateGroup` with `permissionIds: []` on a system group and verifies:
- The returned group has the correct `id`
- The returned `permissionIds` is an empty array (all permissions cleared)

### 4. Kept: deleteGroup on system group still throws (unchanged)

The `testSystemGroupGuard` for `deleteGroup` (old lines 314-318) is unchanged — system groups
cannot be deleted, and the test continues to verify the `cannotDeleteSystemPermissionGroup` error.
