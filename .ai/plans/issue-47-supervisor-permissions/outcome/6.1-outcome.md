# Task 6.1 Outcome: Update Supervisor Navigation Test

## Summary

Updated `test/ui/components/supervisorNavigationConfig.test.ts` to reflect Task 5.1's change: `applySupervisorNavOverrides` no longer hides `teachers`, `students`, and `permissions` from supervisors. These items now rely on permission-based filtering via `getNavItemsForPermissions`.

## Changes Made

1. **Added new permissions to `SUPERVISOR_PERMISSIONS` array** (8 new entries):
   - `AppPermission.TeachersCreate`
   - `AppPermission.TeachersEdit`
   - `AppPermission.TeachersManageSchedule`
   - `AppPermission.StudentsCreate`
   - `AppPermission.StudentsEdit`
   - `AppPermission.StudentReassignTeacher`
   - `AppPermission.StudentManageStatus`
   - `AppPermission.StaffViewDirectory`

2. **Updated assertions in "shows supervisor portal items for supervisor users" test**:
   - Changed `expect(keys).not.toContain("students")` → `expect(keys).toContain("students")`
   - Added `expect(keys).toContain("teachers")`
   - Added `expect(keys).not.toContain("permissions")` (supervisor lacks `PermissionGroupsManage`)

3. **Kept existing assertions** for items that should still be hidden:
   - `home`, `own-profile`, `search-schedule`, `schedule-tracking`, `status-tracking`, `schedule-alerts` (hidden by `applySupervisorNavOverrides`)
   - `feedback-manage` (hidden by override + no permission)
   - Teacher/parent/student portal items (audience-gated)
   - `supervisor-profile`, `logout` (not in SIDEBAR_NAV_ITEMS)

## Rationale

- Supervisors with `StaffViewDirectory` + `TeachersList` permissions pass the `PAGE_PERMISSIONS.teachers` OR-logic check → `teachers` nav item visible
- Supervisors with `StudentsList` permission pass the `PAGE_PERMISSIONS.students` check → `students` nav item visible
- Superviors lack `PermissionGroupsManage` → `permissions` nav item still hidden by permission filter
- The new permissions mirror the updated `supervisor_default` seed group grants from Phase 1 migrations
