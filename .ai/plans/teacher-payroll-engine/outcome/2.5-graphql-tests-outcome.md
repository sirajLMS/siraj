## Security audit

- **Scope-auth envelope asserted against the real pipeline.** Verified in
  `backend/graphql/gqlSchemaBuilder.ts:154–162`: `unauthorizedError` inspects
  `hasLoggedInFailure(result.failure)` → `UNAUTHENTICATED` (message
  `tErrors.unauthorized`) vs `FORBIDDEN` (message
  `tErrors.insufficientPermissions`). The payroll fields use the `permission`
  scope only (`buildAuthScopes`: `ctx.isSuperAdmin ||
  ctx.permissions.includes(key)`), so a logged-out caller produces a pure
  permission-scope failure with **no** `loggedIn` failure in the result →
  **FORBIDDEN even when logged out**. The tests assert exactly this actual
  behavior.
  - *Carry-forward correction:* the 2.3–2.4 outcome's parenthetical
    "(UNAUTHENTICATED when logged out)" is imprecise for permission-only
    scopes. `UNAUTHENTICATED` surfaces only when the scope **passes** but
    `requireAuth` finds no `ctx.user.id`
    (`backend/graphql/utils/requireAuth.ts`), which both suites cover with a
    dedicated "permissioned context without a user id" test. Tests assert
    behavior, not the imprecise prediction — recorded here as the correction.
- **Denial is side-effect-free, proven not assumed:** every denial test
  asserts the stub's call-recording array has length 0 (service never invoked),
  matching AC-7.3's "shall not execute the underlying query" and AC-7.4's
  "shall not touch any row".
- **Actor spoofing impossible at the schema layer:** `PayrollOverrideInput`
  has no `actorUserId` field; the coercion-rejection test proves a client
  cannot even smuggle one (rejected before the resolver runs). Injection order
  in the resolver guarantees the context actor wins even if a same-named key
  existed.
- **No secrets, tokens, credentials, network, filesystem, or DB access.**
  Execution is in-memory `graphql()`; the only stubbed external
  (`PayrollCalculationService`) records calls and returns fixtures. The real
  services barrel is imported for graph linkability only — no DB connection is
  exercised (suites pass without any DB bootstrapping; the runner's per-suite
  logs show no DB activity).
- **Quality-rule greps (both files):** `console.*` = 0; `any`-types = 0;
  `oxlint-disable`/`eslint-disable`/`biome-ignore` = 0; `.skip`/`.only`/
  `.todo` = 0; plan-artifact references
  (`REQ-|task [0-9]|phase [0-9]|.ai/plans|specs.md|tasks.md|trackable|implementation.md|AC-[0-9]`) = **0** (one case-insensitive hit on
  `clientRequestId: "req-1"` — a domain fixture value, not a plan artifact);
  `TODO|FIXME|XXX|HACK` = 0.
