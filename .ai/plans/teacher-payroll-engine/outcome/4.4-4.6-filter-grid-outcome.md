## Task 4.4 — filter bar detail

- **Props**: `PayrollReportsFilterBarProps = Pick<PayrollReportsViewModel, …>`
  (labels + statusLabels + rows + the six filter fields + their store setters +
  `clearFilters` + `hasActiveFilters`). Flat-props convention per
  `SettingsAuditFilterBar` / `RegisteredStudentsSection`; the 4.7 container can
  spread the whole view model in (`<PayrollReportsFilterBar {...viewModel} />`).
- **Search**: bound to the raw `search` (store holds text as typed — the 4.2
  view model owns the 300 ms debounce; the input never debounces locally).
  `SEARCH_INPUT_MAX_LENGTH = 200` on `slotProps.htmlInput.maxLength` **resolves
  D20** exactly as the ledger prescribed. `aria-label` +
  `autoComplete: "off"` on the input; search icon start adornment
  (StudentCreditsList precedent).
- **Teacher/student**: reuse the tier-neutral `TeacherAutocomplete` /
  `StudentAutocomplete` from `@/frontend/common/components/ui/input/userSelect`
  (implementation.md §5.3 mandate; NOT the desktop/mobile wrappers — this is a
  common-layer component and cross-tier imports are forbidden). The
  `PersonOption ↔ store-id` bridge is the payments sibling pattern
  (`usePaymentsPersonFilterSelection`): picked option in local state, with the
  loaded report rows as the display-name fallback after remount / external
  clear; `setTeacherId/setStudentId(next?.id ?? null)`. Extracted once as
  `usePersonFilterSelection` (parameterized by row id/name accessors) — no
  duplicated teacher/student blocks.
- **Date range**: repo `AppDateRangePicker` (settings-audit precedent) with
  `labels.filters.dateRange/dateFrom/dateTo`; emits `""` on clear → bridged to
  `null` for `setDateFrom`/`setDateTo` (`YYYY-MM-DD` storage format matches the
  route's strict calendar-date validation).
- **Status multi-select**: MUI `Select multiple` + `renderValue` chips
  (searchSchedule precedent) over `Object.values(CalculationStatus)`; labels via
  the view model's enum-keyed `statusLabels` Record (no switch, no unsafe enum
  comparison); `isCalculationStatus` type guard filters the DOM's string
  payload; empty selection renders `filters.all` in `onSurfaceVariant`. Menu
  items + chips + collapsed preview all use the same Record.
- **Clear**: `ClearOutlined` icon button rendered only while
  `hasActiveFilters` (payments precedent), `aria-label` + tooltip.

## Task 4.6 — data grid detail

- **Props**: `PayrollReportsDataGridProps = Pick<PayrollReportsViewModel, …>` +
  `onOverride: (row: PayrollReportRow) => void` — the contract the brief
  mandated for the parallel 5-a dialog work; the 4.7 container wires it.
- **Grid**: repo-standard `AppDataGrid<PayrollReportRow>` (never raw
  `DataGrid`), `getRowId = instanceId ?? id ?? ""`, `emptyMessage` =
  `labels.empty`, `ariaLabel` = `labels.title`, `disableColumnMenu` (sorting
  stays available on header clicks — the misleading per-page filter menu goes,
  payments/StudentCreditsList precedent).
- **Columns** (12, in AC-1.3 order): scheduled start (locale-aware
  `formatAccountingDate`), teacher, student, subject (new `column.subject`
  key), scheduled duration, actual duration (derived from
  `actualStartAt/actualEndAt`, null-safe), calculated duration, paid amount +
  currency (payments' baseline-stack cell), status (`CalculationStatusChip`,
  em-dash null marker per the chip's documented contract), partial % (new
  `column.partialPercentage` key), note (Tooltip with one-line ellipsis,
  sortable: false), actions. Headers for teacher/student reuse
  `filters.teacher`/`filters.student` (D9 reuse guidance); all other headers
  from `column.*`.
- **Override gating**: the actions column is **only appended when
  `canManagePayroll`** (the view model's `ACCOUNTING_PAYROLL_MANAGE` check) —
  without the permission the column does not exist at all, satisfying "hidden
  without MANAGE" more strictly than a null-rendering cell.
- **Aggregate footer card**: `SectionPanel` under the grid with
  `aggregate.totalPaid` (formatted via `formatAccountingMoney`, currency beside
  when present) and `aggregate.rowCount` — all six statuses rendered as
  `CalculationStatusChip` + count, iterating `aggregates.rowCountByStatus`
  (zero-filled until loaded, so the card never flashes partial data). Spec
  (footer card) followed over the prototype's right-sidebar placement.
- **CSV export**: repo `ExportButton` preset (id
  `payroll-reports-export-csv`), disabled while in flight; handler awaits
  `onExportCsv()` → `null` ⇒ error toast `labels.exportFailed`; `truncated` ⇒
  warning toast `labels.exportTruncated` (E17); toasts via the repo-standard
  `useNotifications` from `@toolpad/core/useNotifications`.
- **Pagination**: `buildServerPaginationOptions({ page, pageSize, totalCount,
  onPageChange, onPageSizeChange, pageSizeOptions: PAGE_SIZE_OPTIONS })` —
  server mode with the store's 25/50/100 size options; offset math stays in
  the view model.

## Deviations

1. **Grid exports, not the filter bar, own the Export CSV button.** The
   prototype places the button in the filter card, but the dispatch brief and
   task 4.6 assign "CSV export button (awaits onExportCsv, toasts truncated
   warning)" to the grid component; the toasts need the export outcome which
   the grid handler owns. The 4.7 container may relocate the button visually.
2. **Aggregate footer card follows the spec, not the prototype** — a footer
   `SectionPanel` under the grid (implementation.md §5.3 "Aggregate footer
   card: total paid amount + currency, status counts"), not the prototype's
   right-sidebar summary. Status dots reuse `CalculationStatusChip` colors
   instead of ad-hoc dots.
3. **`exportFailed` key added beyond D9's three strings** — the mandated
   `null → error toast` needs a message and no shared/common key existed
   (`CommonLabels` has no generic export-failure string); additive, same
   four-artifact pattern. Same rationale for `filters.dateFrom/dateTo` (the
   `AppDateRangePicker` requires all three label props), `filters.clear`,
   `filters.all`, `column.partialPercentage`, and `column.actions`.
4. **Actual-duration column derives its value** from `actualStartAt`/
   `actualEndAt` (the row has no `actualDuration` field; §7.1 expects the
   "Actual duration (min)" column) — computed null-safely in
   `actualDurationMinutes`, clamped at 0.
