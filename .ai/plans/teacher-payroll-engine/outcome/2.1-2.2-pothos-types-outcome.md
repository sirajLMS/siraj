## Security audit

- **No client-supplied actor**: `PayrollOverrideInputPothos` deliberately EXCLUDES
  `actorUserId` (the TS `PayrollOverrideInput` contract carries it, but Pothos
  inputRefs must cover every key of their backing shape — a typed
  `inputRef<PayrollOverrideInput>` would have forced a client-writable actor field).
  The string-named `inputType("PayrollOverrideInput", …)` form (whatsapp / cron /
  permissions precedent, sanctioned by `backend/graphql/AGENTS.md`'s WhatsApp
  input-pattern note) keeps the actor server-side; task 2.4's resolver injects it
  via `requireAuth(ctx)` + spread.
- **Constraint directives** bound the GraphQL input surface: `partialPercentage`
  min 0 / max 100 (integer — AC-6.5), `note` maxLength 2000 (DB varchar + sanitizer
  ceiling), `search` maxLength 200, `dateFrom`/`dateTo` `format: "date"` (accounting
  filter precedent). Deeper validation (selectable target statuses, note-required
  rules) stays in `PayrollCalculationService.applyOverride` (task 1.7, already
  permission-gated + localized).
- No secrets, tokens, credentials, I/O, or network access in the new file; no
  module-level mutable state (declarative type registrations only); no
  `console.*`, no dynamic imports, no `oxlint-disable`.
- Injection surfaces: none new (no resolver logic beyond direct field exposure /
  constant synthetic ids; the free-text `search`/`note` are bounded above and
  wildcard-escaped / sanitized downstream in the repo + service layers).

## Deliberate deviations from implementation.md §4.1 snippets

1. **No `CalculationStatusPothosEnum` registration** (D6) — import-only, per the
   0.1–0.3 outcome's hard requirement (the snippet's re-registration triggers the
   Pothos "already declared" runtime error).
2. **`PayrollOverrideInputPothos` uses the string-named `inputType`** instead of a
   typed inputRef — the TS `PayrollOverrideInput` includes `actorUserId`, which
   must never be client-suppliable; a typed ref would force it into the GraphQL
   input. (Same reason the snippet's mutation spreads `{...args.input, actorUserId}`.)
3. **Aggregates exposed as a nested `PayrollReportAggregates` object** instead of
   the snippet's flattened resolvers (`t.exposeString("totalPaidAmount")` would not
   even typecheck — the parent type nests it under `aggregates`). The nested shape
   mirrors the `PayrollReportPage` contract 1:1 and matches the task wording
   ("rows + totalCount + aggregates {…}").
4. **`force: t.boolean(...)`** instead of the snippet's `t.booleanColumn(...)` —
   no such method exists on the Pothos input field builder (plan typo).
5. **Apollo `id` fields added** on Row / Page / Aggregates / OverrideResult
   (AGENTS.md critical rule; synthetic-id precedents: `teacher-pending-dues-summary`,
   `supervisor-dashboard`, `teacher-dashboard-metrics`; natural-key ids resolve to
   `instanceId`). The snippet omitted them; the repo instruction outranks the
   snippet, and task 4.1's documents step explicitly selects `instanceId`-equivalent
   fields for cache updates.
6. **Constraint directives added** (0–100 percentage, 2000-char note, date-format
   date range, 200-char search) — following the accounting-filter / cron-input /
   credit-adjustment precedents; the snippet had none.
