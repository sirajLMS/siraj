## Spec-snippet adaptations (mechanical, semantics preserved)

- `teacher_paid_amount = '0'` (string literal) instead of §2.3's `= 0`: the column is TEXT
  (`textColumn` per R2-se), and PG has no `text = integer` operator — `= 0` would fail at
  DDL time. ⚠️ Phase 1 carry-forward: the REFUND zeroing write MUST use the canonical
  string `"0"` (text equality — `"0.00"` would VIOLATE the constraint).
- `timestampColumn("payroll_calculated_at")` — the helper accepts only a name; `withTimezone:
  true, precision: 3` are built in, so the §2.3 options object is not expressible/needed.
- `isPartialPercentage` uses `integerColumn` (repo convention for smallint semantics — no
  `smallint` helper exists in `dialectAwareBuilder`; `leave_quota_usage.period_year`
  precedent) with a domain comment documenting the 0–100 range.
- `checkConstraint(name, pgSql, sqliteSql)` takes 3 args in this repo (§2.3 shows 2); both
  dialect branches carry identical SQL — no PG-only functions involved.

   line of defense.

   does text equality, not numeric (see Spec-snippet adaptations).

4. `classInstances.payrollCalculatedByUser` relation exists for Phase 2 GraphQL exposure;
   users-side back-reference intentionally NOT added (matches repo convention —
   `activatedByUserId` etc. have no users-side many-relation either).
5. `SYSTEM_SETTINGS_DATA` is now exported — any future settings test can seed the real
