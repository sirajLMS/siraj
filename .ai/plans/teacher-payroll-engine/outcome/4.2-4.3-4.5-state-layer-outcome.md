## The one fix (task 4.2)

**Gap**: the interrupted dispatch's view model returned `labels: PayrollLabels`
but no enum-keyed status-label record, while `CalculationStatusChip` (correctly)
takes `labels: Record<CalculationStatus, string>`. The locale namespace's status
block uses literal SCREAMING_SNAKE keys (`status.NOT_CALCULATED`, per §7.1 /
MP-types LOW finding) but the generated `CalculationStatus` enum members are
PascalCase (`NotCalculated`) — someone must bridge the two, and every sibling
precedent puts that bridge in the view model, never the view:

- `useStudentProfilePageViewModel.ts:33` — `buildStudentStatusLabel(tStatus):
  Record<StudentStatus, string>` (module-scope builder + VM field)
- `frontend/common/views/dashboard/billing/types/parentInvoiceList.types.ts:74,101`
  — `creditStatusLabels: Record<StudentCreditStatus, string>` on the VM interface
- `frontend/common/views/dashboard/billing/utils/label-mappers.ts` —
  `statusLabels: labels.invoiceStatus` bridging into grid label bundles

Without the bridge, task 4.6's grid would have had to build the Record inline in
the view layer, violating `frontend/common/views/AGENTS.md` Rule "ViewModel owns
all view-layer translations … domain components receive `labels` via props".

**Fix landed** (3 atomic edits, VM 323 → 338 lines):

```ts
/** Bridges the locale status labels (literal keys) onto the generated enum keys the status chip consumes. */
function buildStatusLabels(status: PayrollLabels["status"]): Record<CalculationStatus, string> {
  return {
    [CalculationStatus.NotCalculated]: status.NOT_CALCULATED,
    [CalculationStatus.Calculated]: status.CALCULATED,
    [CalculationStatus.Partially]: status.PARTIALLY,
    [CalculationStatus.Refund]: status.REFUND,
    [CalculationStatus.WaitingPaid]: status.WAITING_PAID,
    [CalculationStatus.Paid]: status.PAID,
  };
}
```

…wired as `readonly statusLabels: Record<CalculationStatus, string>;` on
`PayrollReportsViewModel` and `statusLabels: buildStatusLabels(t.status)` in the
return object. Direct call without memo — identical to the student-profile
precedent (object build is trivial).
