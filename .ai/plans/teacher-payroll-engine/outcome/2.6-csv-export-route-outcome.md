## Summary

Created `app/api/payroll/export/route.ts` — a GET Next.js Route Handler that
exports the filtered payroll report as CSV:

1. **Auth**: `getServerUserContext()` from `@/backend/lib` (the
   invoices-download route's exact convention — no `requireAuth` helper exists
   for app routes; that name belongs to the GraphQL context layer). Null
   `userId` → 401 JSON with the localized `tErrors.unauthorized`.
2. **Permission gate BEFORE any data access**:
   `requirePermission(userId, AppPermission.ACCOUNTING_PAYROLL_VIEW, tErrors)`
   (shared guard from `@/backend/services` barrel → billing/permission-utils)
   runs before query parsing and before the service call; its
   `ForbiddenError` → 403 with `tErrors.insufficientPermissions`. The service's
   internal `getReport` gate (1.6–1.8) re-checks the same permission — defense
   in depth, both layers localized.
3. **Report read**: `PayrollCalculationService.getReport(userId, filters,
   { limit: 10_000, offset: 0 }, tErrors)` — the export ceiling is enforced
   server-side as the pagination limit; no client-supplied limit is honored.
4. **CSV serialization** (route-local — a repo-wide search found NO existing
   server-side CSV writer; the three client-side builders are naive
   no-escaping blob builders): RFC 4180 quoting (`"` doubling, comma/quote/CR/LF
   quoting, CRLF row separator, trailing CRLF) plus **OWASP CSV-injection
   hardening** — any cell starting with `=`, `+`, `-`, or `@` is prefixed with
   a single quote. All 20 `PayrollReportRow` fields become columns, in the
   row-contract declaration order, with machine field-name headers.
5. **Headers**: `Content-Type: text/csv; charset=utf-8`,
   `Content-Disposition: attachment; filename="payroll-report-YYYY-MM-DD.csv"`
   (UTC date stamp), and `X-Export-Truncated` — always present: `"true"` when
   `totalCount > 10_000`, `"false"` otherwise (explicit false is friendlier to
   the Phase-4 truncation toast than an absent header).
6. **Filter mapping** (query params mirror the `payrollReport` GraphQL filter
   1:1): `teacherId`, `studentId`, `dateFrom`, `dateTo` (strict `YYYY-MM-DD`
   real-calendar validation — JS `Date` rollover for impossible days like
   2026-02-30 is explicitly rejected), `calculationStatuses` (BOTH repeatable
   `?calculationStatuses=A&calculationStatuses=B` AND comma-separated
   `?calculationStatuses=A,B`), `search` (≤ 200 chars, the same bound as the
   Pothos filter input from 2.1–2.2). Absent/blank params → `null` (no
   filter); malformed values → 400 with the localized `tErrors.invalidInput`.

Locale resolution mirrors the invoices-download route verbatim
(`accept-language` first segment, `"ar"` fallback) with
`getServerTranslations(locale).errorsTranslations` from `@/shared/locale`.

## Security audit

- **Permission gate before data access**: `requirePermission` is the first
  statement after the 401 check; the 403 test proves `getReport` runs 0 times
  on the denied path. The service's internal gate re-checks before its repo
  reads (belt and suspenders). Deny-by-default: no payroll row, aggregate, or
  even filter validation feedback leaks to an unauthorized caller.
- **CSV injection hardening**: every cell passes `toCsvCell`; cells starting
  with `=`, `+`, `-`, `@` get a `'` prefix (OWASP guidance) BEFORE quoting, so
  the neutralizer cannot be bypassed by separator tricks. Proven for all four
  prefixes across the hardening tests (`=`, `+` with embedded quotes, `@`, and
  `-` via the payrollNote fixture). Nulls → empty cells; booleans/numbers are
  native strings that can never start a formula.
- **No unbounded reads**: the 10 000-row ceiling is the server-chosen
  pagination limit (client cannot raise it — there is no limit/offset query
  param at all); `X-Export-Truncated` is computed from the service's
  `totalCount`, so it is honest even when the full set exceeds the page.
- **Input validation**: strict date format + real-calendar check, enum-value
  whitelist for statuses (`Object.values(CalculationStatus)` in a `Set`), 200-char
  search bound, trimmed non-empty ids — all malformed inputs → localized 400,
  never a 500, never a service call. No SQL surface of its own (the service
  layer owns parameterized queries; the search filter is wildcard-escaped in
  the repo per 1.2).
- **No secrets/tokens/credentials**; no filesystem/network access beyond the
  service call; no module-level mutable state (all module constants immutable;
  the one `Set` is built once from enum values); logger used instead of
  `console.*`.

## Deliberate decisions (documented for reviewers)

1. **`getServerUserContext` instead of a literal `requireAuth`** — the task
   said "requireAuth … mirror the existing route conventions"; the repo has no
   `requireAuth` outside GraphQL context (`requireAuth(ctx)` from
   `backend/graphql/utils/requireAuth` needs a GraphQL context object). The
   app-route equivalent used by BOTH existing auth'd routes (invoices
   download, vercel-upload) is `getServerUserContext()`. Mirrored exactly.
2. **Route-level `requirePermission` even though `getReport` re-checks** —
   mandated by the task ("permission gate BEFORE any data access"); costs one
   cached permission read; gives the route its own honest 403 without relying
   on service internals.
3. **Filename `payroll-report-YYYY-MM-DD.csv`** — implementation.md §4.4 says
   `payroll-report.csv`; the dispatch instruction says "date-stamped filename
   per implementation.md". Synthesized: base name from §4.4 + UTC date stamp.
4. **`X-Export-Truncated` always present (`"false"` when not truncated)** —
   "absent/false otherwise" allowed either; explicit false is more
   discoverable for the Phase-4 toast (E17) than an absent header.
5. **No UTF-8 BOM** — matches every existing CSV export in the repo (the three
   client-side Blob builders emit no BOM); `charset=utf-8` is declared in the
   Content-Type. Revisit only if accounting operators report Excel mojibake
   (D17).
6. **Machine field-name headers, not localized labels** — AC-1.6 requires
   "one row per class instance" without specifying headers; field names keep
   the file schema-stable across locales and parseable by tooling. Phase 4
   can localize if users ask (D17).
7. **CSV writer is route-local** — the repo has no shared CSV util (verified
   by repo-wide `csv` search); a shared util would have been a cross-file
   scope violation. The 20-column table is data-driven (`CSV_COLUMNS`), so
   extracting it later is mechanical.

## Carry-forward knowledge (for Phase 4's Export CSV button)

- **URL**: `GET /api/payroll/export` with query params (exact names):
  `teacherId`, `studentId`, `dateFrom` (YYYY-MM-DD), `dateTo` (YYYY-MM-DD),
  `calculationStatuses` (repeatable AND/OR comma-separated), `search`
  (≤ 200 chars). Param names are identical to the `PayrollReportFilter`
  GraphQL input fields — the button can serialize the grid's current filter
  object 1:1 (statuses array → repeatable params or one comma-joined value).

  client involvement; the route is NOT in the Apollo surface).
- **Response**: `text/csv; charset=utf-8`, RFC 4180 CRLF, trailing CRLF, no
  BOM; 20 columns in `PayrollReportRow` declaration order with field-name
  headers.
- **Truncation toast (E17)**: read the `X-Export-Truncated` response header —
  `"true"` means the filtered set exceeded 10 000 rows. Fetch the response
  (fetch + blob download) rather than a plain anchor if the toast is
  required; otherwise an anchor click cannot read headers.
- **Error contract**: 401 `{error}` (login expired), 403 `{error}`
  (insufficient permissions), 400 `{error}` (invalid filter — check the
  date pickers/status chips), 500 `{error}` — all `{ error: string }` JSON.
- **Filename**: `payroll-report-<UTC date>.csv` (Content-Disposition).
