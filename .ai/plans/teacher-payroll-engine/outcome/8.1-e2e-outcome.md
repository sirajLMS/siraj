## Data-prerequisite decision

- Demo seeds do NOT create payroll snapshots: the report lists every non-deleted class instance
  (calculation_status defaults NOT_CALCULATED), and CALCULATED rows exist only after the calculator or
  the one-shot backfill (`scripts/payroll-backfill.ts`) ran on terminal sessions.
- **Strategy (chosen)**: locate an existing CALCULATED row through the UI itself — status filter →
  CALCULATED, then wait for a calculated chip. If none surfaces within `devWaitTimeout`, the spec FAILS
  with an explicit diagnostic (statuses visible before filtering, whether the empty-state message
  rendered, and the backfill-script remediation) — never a silent skip and never a bare timeout.
- **Rerun-robustness**: the trailing restore-to-Calculated override returns the consumed row to a
  calculated snapshot, so consecutive runs re-target the same newest calculated row instead of draining
  the CALCULATED pool one row per run.
- Alternative rejected: seeding payroll snapshots from the spec (e.g. calling the backfill or mutation
  directly) — the journey is defined through the UI, and mutating demo data outside the product surface
  would blur the spec's role.

## Assumptions

- `academy_admin` (and `super_admin`) demo groups hold both payroll permissions — granted by migration
  `backend/db/migration/36-accounting-payroll-permissions.sql` to exactly those two groups; the teacher
  demo group holds neither (basis for the negative test).
- The e2e server DB contains ≥1 CALCULATED payroll row at run time (see the decision above for the
  failure mode when it does not).
- The flow test carries an explicit 180 s timeout because `bunfig.toml`'s 60 s default is too tight for
  a multi-override journey under dev-mode compilation latency.
- The partial-override paid amount is deliberately NOT asserted: after a refund the proration base is
  zero, so the amount is `0.00` by construction — the percentage is the contract under test.
- CSV notes avoid commas/quotes/newlines by construction, so cells stay unquoted; the parser handles
  quoting anyway for safety.
