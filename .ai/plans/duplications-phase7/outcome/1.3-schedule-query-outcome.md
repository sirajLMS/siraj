## What Was Done

Following the same pattern used by `backend/graphql/query/billing/__shared__/makeSupportedPaymentListQueryField.ts`, two module-scope helper functions were extracted to eliminate the duplication:

1. **`teacherWeeklyArgs(t: QueryFieldBuilder)`** — builds the shared args object (`teacherId?`, `weekDate`) via Pothos `t.arg.string(...)` calls, returning a typed args shape.
2. **`teacherWeeklyResolve<TResult>(getService)`** — returns a Pothos resolve function that performs `requireAuth(ctx)`, extracts `ctx.t().errorsTranslations`, and delegates to `getService`.

Both factory functions now call `teacherWeeklyArgs(t)` and `teacherWeeklyResolve(getService)` within their `t.field({...})` config, reducing each `queryField` block to a 4-line body that differs only in field name and `returnType`/`getService` type parameters.

### Key design decisions

- **`QueryFieldBuilder` type alias** — Added `RootFieldBuilder<BuilderTypes, unknown, "Query">` type alias (matching the pattern in `makeSupportedPaymentListQueryField.ts`) so `teacherWeeklyArgs` can accept the Pothos root field builder `t` without the caller needing to annotate.
- **No leading underscore** — Both helpers are named without leading underscores (oxlint `no-underscore-dangle` rule).
- **No generic `t.field()` extraction** — A fully generic factory was attempted but failed tsgo because Pothos' `Resolver` conditional type cannot be evaluated for a generic `TResult`. The `teacherWeeklyArgs` + `teacherWeeklyResolve` split avoids this by keeping the `t.field({...})` call concrete in each function while sharing the duplicated parts.
