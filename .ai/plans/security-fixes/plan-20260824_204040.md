### H1 — Unescaped LIKE wildcards in student filter builder (3 sinks, same file)

- **File:** `backend/utils/student.filterUtils.ts`
- **Lines:** 26, 35, 38
- **Layer:** Repository filter builder (invoked by `studentDirectory` + `students` GraphQL queries, permission `STUDENTS_LIST`).
- **Problem:** Three raw `` ` LIKE '%${value}%' ` `` interpolations never pass through `escapeLikeWildcards()`. An authenticated STAFF/TEACHER with `students.list` can inject `%`/`_` metacharacters to force unbounded prefix scans across the students table (`students.name` has a GIN trigram index which is bypassed by leading-`%` patterns), producing measurable timing differences → enumeration oracle + DB CPU DoS.
- **Fix:** Import and apply `escapeLikeWildcards()` on all three branches.

```typescript
// backend/utils/student.filterUtils.ts
import { asc, desc, eq, gt, gte, isNull, like, lt, lte, not, notLike } from "drizzle-orm";
import type { PgSelect } from "drizzle-orm/pg-core";
import { fullTextSearch } from "@/backend/db/query.extensions";
import { students } from "@/backend/db/schema";
import { OrderSortDirection } from "@/backend/enum";
import { StudentsOrderByColumn } from "@/backend/enum/students";
import type * as Types from "@/backend/types";
import { escapeLikeWildcards } from "@/backend/utils";

export namespace StudentFilterUtils {
  function applyNameFilters<T extends PgSelect>(qb: T, args: Types.StudentFilterArgs): T {
    const ftsLang = "simple";
    if (args.name) {
      const ftsCondition = fullTextSearch(students.name, args.name, ftsLang);
      if (ftsCondition) {
        qb = qb.where(ftsCondition);
      }
    }
    if (args.nameNotContains) {
      qb = qb.where(notLike(students.name, `%${escapeLikeWildcards(args.nameNotContains)}%`));
    }
    if (args.nameEquals) {
      qb = qb.where(eq(students.name, args.nameEquals));
    }
    if (args.nameNotEquals) {
      qb = qb.where(not(eq(students.name, args.nameNotEquals)));
    }
    if (args.nameStartsWith) {
      qb = qb.where(like(students.name, `${escapeLikeWildcards(args.nameStartsWith)}%`));
    }
    if (args.nameEndsWith) {
      qb = qb.where(like(students.name, `%${escapeLikeWildcards(args.nameEndsWith)}`));
    }
    return qb;
  }
  // ... remainder unchanged
}
```

> Note: `escapeLikeWildcards` is already exported from `@/backend/utils` — verify no circular-import issue; if `filterUtils` and `utils/index.ts` barrel causes a cycle, import directly from `./db.utils`.

### H2 — OAuth state not session-bound, replayable across browser contexts

- **File:** `app/api/oauth/shared/oauth-callback-handler.ts` (lines 13–50) + `backend/services/meeting/integrations/meeting-oauth.service.ts` (lines 57–78)
- **Layer:** API route / OAuth handshake.
- **Problem:** `signOAuthState` produces a JWT containing `userId`, `providerSlug`, `returnPath`, `nonce`, but `verifyOAuthState` only checks signature/expiry. The `nonce` is never stored or consumed; there is no comparison between the browser session completing the callback and the `userId` embedded in the state. An attacker who initiates an OAuth flow, captures the `state` + authorization `code`, and coerces a victim's browser into hitting the callback will link the attacker's provider account (or vice versa) to a different user, enabling meeting-creation theft under the wrong identity.
- **Fix:** (a) Bind the nonce to the initiating session via Redis (`session:{id}:oauth:nonce`); (b) require `ctx.sessionId` user match on callback; (c) consume (delete) the nonce after successful verify.

```typescript
// backend/services/meeting/integrations/meeting-oauth.service.ts
import { SessionRepository } from "@/backend/db/repo/shared";
import { getRedisService } from "@/backend/services";

const OAUTH_NONCE_TTL_SECONDS = 600; // 10 minutes, mirrors JWT expiry

export async function signOAuthState(
  userId: string,
  providerSlug: MeetingProvider,
  returnPath: string,
  sessionId: string
): Promise<string> {
  const nonce = randomUUID();
  const redis = await getRedisService();
  // Session-bound nonce — single use, keyed by initiating session.
  await redis.set(`oauth-state-nonce:${sessionId}:${nonce}`, `${userId}:${providerSlug}`, {
    ex: OAUTH_NONCE_TTL_SECONDS,
  });
  return new SignJWT({ userId, providerSlug, returnPath, nonce, sessionId })
    .setProtectedHeader({ alg: "HS256" })
    .setIssuedAt()
    .setExpirationTime(OAUTH_STATE_EXPIRY)
    .sign(getStateSigningSecret());
}

export async function verifyAndConsumeOAuthState(
  state: string,
  currentSessionId: string | undefined
): Promise<MeetingOAuthStatePayload | null> {
  try {
    const { payload } = await jwtVerify(state, getStateSigningSecret());
    if (!isOAuthStatePayload(payload)) return null;
    if (!currentSessionId || payload.sessionId !== currentSessionId) return null;
    const redis = await getRedisService();
    const key = `oauth-state-nonce:${currentSessionId}:${payload.nonce}`;
    const stored = await redis.get(key);
    if (!stored) return null; // replayed or expired
    await redis.del(key); // consume — single use
    return payload;
  } catch {
    return null;
  }
}
```

```typescript
// app/api/oauth/shared/oauth-callback-handler.ts — replace verifyOAuthState call-site

if (!statePayload) {
  return NextResponse.json({ error: tErrors.invalidOrExpiredOAuthState }, { status: 400 });
}
```

### H3 — Refresh-token rotation never validates the presented refresh token

- **File:** `backend/graphql/mutation/auth/auth.mutation.ts` (lines 124–138), `backend/lib/auth/createAuthSession.ts` (line 18)
- **Layer:** Auth mutation / session lifecycle.
- **Problem:** `createAuthSession` stores `payload: {"createdAt": ...}` — the refresh token's `jti` is never recorded. When the session cookie is present, `validateRefreshTokenJti` returns `true` unconditionally (`if (!refreshToken && resolvedViaSessionId) return true;` and the mismatch branch only *warns*). Consequence: a stolen refresh token never expires in practice — an attacker holding any refresh token can rotate forever; rotation-theft detection (RFC 6819 §[IP_REDACTED]) is absent.
- **Fix:** Persist the refresh token JTI at session creation and enforce mismatch → hard rotation invalidation.

```typescript
// backend/lib/auth/createAuthSession.ts
export async function createAuthSession(userId: string, email: string): Promise<CreateAuthSessionResult> {
  const accessToken = await generateAccessToken(userId, email);
  const refreshToken = await generateRefreshToken(userId, email);
  const sessionId = randomUUID();
  const refreshPayload = await verifyToken(refreshToken);
  const session = await SessionRepository.create({
    hashedId: sessionId,
    userId,
    payload: JSON.stringify({
      createdAt: new Date().toISOString(),
      refreshTokenJti: refreshPayload?.jti ?? null,
    }),
  });
  return { accessToken, refreshToken, sessionId, session };
}
```

```typescript
// backend/graphql/mutation/auth/auth.mutation.ts — replace validateRefreshTokenJti body
async function validateRefreshTokenJti(
  refreshToken: string | undefined,
  session: SessionSelectType,
  _resolvedViaSessionId = false
): Promise<boolean> {
  if (!refreshToken) return false; // session-only rotation no longer permitted once a refresh cookie exists
  const refreshPayload = await verifyToken(refreshToken);
  if (!refreshPayload?.jti) return false;
  const sessionData = session.payload ? parseSessionPayload(session.payload) : null;
  const sessionJti = sessionData?.refreshTokenJti;
  if (typeof sessionJti === "string" && sessionJti !== refreshPayload.jti) {
    // Stale token reuse detected — revoke session entirely, force re-login.
    await SessionService.logoutUser({ sessionId: session.hashedId, accessToken: null });
    return false;
  }
  return true;
}
```

> Migration note: legacy sessions carry a payload without `refreshTokenJti` — treat `null` as "accept once, then pin" for a rolling 7-day cutover (R2).

### H4 — `recordPayment` accepts arbitrary financial ledger entries

- **File:** `backend/graphql/mutation/billing/billing-payments.mutation.ts` (lines 14–59)
- **Layer:** GraphQL mutation → `PaymentMethodService.recordPayin`.
- **Problem:** A user with `billing.update_status_paid` can record a payment against **any** `invoiceId` with **any** amount string (no positivity check), **any** currency (no match against invoice currency), and **any** `userPaymentMethodId` (no check that the method belongs to the paying parent). The idempotency key `payin:${invoiceId}:${method}:${Date.now()}` is also never unique, defeating replay protection.
- **Fix:** Validate invoice existence/state/currency/ownership before dispatching to `recordPayin`; reject non-positive or non-numeric amounts.

```typescript
// backend/services/payment-method/payment-method.service.ts — recordPayin guard block
export async function recordPayin(input: ..., tErrors: ErrorsLabels, tx?: DBTransaction) {
  const invoice = await BillingRepository.getInvoiceById(input.invoiceId, tx);
  if (!invoice || invoice.deletedAt) {
    throw new Error(tErrors.billing.invoiceNotFound(input.invoiceId));
  }
  if (invoice.status !== "UNPAID" && invoice.status !== "PAYMENT_PENDING") {
    throw new Error(tErrors.billing.invoiceAlreadyPaid({ id: invoice.id, status: invoice.status }));
  }
  const amount = Number.parseFloat(input.amount);

    throw new Error(tErrors.billing.invalidInvoiceAmount);

    throw new Error(tErrors.billing.invalidInvoiceAmount);

    if (method.userId !== actorUserId /* pass actorUserId in */) {
      throw new Error(tErrors.insufficientPermissions);
```

### H6 — `proxy.ts` has no protected-route authentication gate

- **File:** `proxy.ts` (lines 20–61)
- **Layer:** Next.js 16 edge middleware (formerly `middleware.ts`).
- **Problem:** The middleware performs locale resolution and CSP header injection but never checks session cookies or redirects unauthenticated visitors away from protected prefixes (`/dashboard`, `/students`, `/teachers`, `/billing`, `/reports`, `/settings`, ...). All protection relies on nested server-component `withPageAuth` + GraphQL `authScopes` — a single missed scope fires the protected page shell and leaks layout data (sidebar route shape, permission-driven nav). This is defense-in-depth only, but is currently the *only* middleware-level guardrail — and it's missing entirely.
- **Fix:** Add a protected-prefix check backed by session cookie presence:

```typescript
// proxy.ts — insert before CSP header assembly
const PROTECTED_PREFIXES = [
  "/dashboard",
  "/students",
  "/teachers",
  "/staff",
  "/parents",
  "/billing",
  "/reports",
  "/settings",
  "/resources",
  "/schedule",
  "/complaints",
  "/suggestions",
  "/cron",
  "/supervisor",
] as const;

function isProtectedPath(pathname: string): boolean {
  return PROTECTED_PREFIXES.some(prefix => pathname === prefix || pathname.startsWith(`${prefix}/`));
}

export default function proxy(request: NextRequest) {
  const pathname = request.nextUrl.pathname;
  // Fail-closed auth gate — session_id must be present; full session validation
  // happens in server components / GraphQL context (middleware cannot hit the DB).
  if (isProtectedPath(pathname) && !request.cookies.get("session_id")?.value) {
    const loginUrl = new URL("/login", request.url);
    loginUrl.searchParams.set("next", pathname);
    return NextResponse.redirect(loginUrl);
  }
  // ... existing locale + CSP logic unchanged
}
```

### H7 — Cross-account PII write via `parentPhone` student profile edit

- **File:** `backend/services/student/student-profile.service.ts` (lines 273–278)
- **Layer:** Service — `applyStudentProfileEdit` writes to the parent's `users` row based on a *student-scoped* field ACL.
- **Problem:** When `input.parentPhone` is present, the code calls `UserRepository.updateProfileFields(profile.parentUserId, { phone: input.parentPhone })`, mutating a *different* user account's contact data. The authorization check (`canEditStudentFieldGroup` on `student_parent`) is satisfied by `student_default`'s `student.student_parent.edit_own` grant — i.e., a student (or anyone with that own-scope grant) can overwrite the parent's phone number, intercepting SMS/WhatsApp notification routing for that account.
- **Fix:** Route parent-side writes through parent-scope validation, not student-scope, or remove the cross-account write entirely.

```typescript
// backend/services/student/student-profile.service.ts — replace the parentPhone branch
if (input.parentPhone !== undefined) {
```

### H8 — WhatsApp opt-in mutation lets an admin silently flip arbitrary users' WhatsApp channel globally

- **File:** `backend/graphql/mutation/whatsapp/whatsapp-account.mutation.ts` (lines 97–111) + `backend/services/whatsapp/whatsapp-account.service.ts` (`setUserWhatsappOptIn`, line 687+)
- **Layer:** GraphQL mutation + service.
- **Problem:** `setUserWhatsappOptIn` uses `WHATSAPP_CONFIG_MANAGE` at the schema and `assertSuperAdmin` only when `userId !== actorUserId` — but the service then calls `batchUpsert(userId, inputs)` toggling **all** template-mapped WhatsApp event types with no per-event granularity and no confirmation token / secondary approval. Additionally, the mutation grants `WHATSAPP_CONFIG_MANAGE` holders an unrestricted toggle for any user once that user resolves. The audit log records it but there is no rate limit, and the `"me"` shortcut lets a caller self-flip without any confirmation flow.
- **Fix:** Add a per-event scope, require a recent-auth assertion for self-service, and rate limit the mutation.

```typescript
// backend/graphql/mutation/whatsapp/whatsapp-account.mutation.ts
```

```typescript
export function setAuthCookies(
  cookies: ResponseCookies | undefined,
  sessionId: string,
  refreshToken: string | undefined,
  accessToken?: string
): void {
  if (!cookies) return;
  const isSecure = process.env.NODE_ENV === "production" && process.env.AUTH_COOKIE_SECURE !== "false";
  const options = { httpOnly: true, secure: isSecure, sameSite: "lax" as const, path: "/" };

  }
  if (accessToken) cookies.set("access_token", accessToken, { ...options, maxAge: 60 * 15 });
}
```
