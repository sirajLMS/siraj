## Exported API (exact contracts for Phase 1 predicate agent / later waves)

### Type

```ts
export type SessionAuditStatus = "open" | "end" | "Absent" | "absent_student";
```

Status values (verbatim, case-sensitive — note `"Absent"` is capitalized, `"absent_student"` is snake_case):

| Status | Meaning |
|---|---|
| `open` | Session not really finished for audit purposes (includes RUNNING, ACTIVATED, NOT_ACTIVATED, all ON_DEMAND_* states, and any unmatched combo) |
| `end` | `COMPLETED + TAKEN` — session taken and ended |
| `Absent` | `COMPLETED + ABSENT` with `actualStartAt IS NULL` — teacher never joined |
| `absent_student` | `COMPLETED + ABSENT` with `actualStartAt IS NOT NULL`, or `COMPLETED + LEAVE` — teacher joined, student did not |

### Function

```ts
export function mapToSessionAuditStatus(
  executionState: ClassExecutionState | null | undefined,
  outcome: ClassOutcome | null | undefined,
  actualStartAt: Date | string | null | undefined,
): SessionAuditStatus;
```

- Pure function, no I/O, no side effects.
- Lives in `shared/` so server (Pothos resolver, repository query builder) and client (chips, Storybook fixtures) share one rule — no cross-layer imports, imports only `@/shared/constants/class-instance-detail.enum` value enums (`ClassExecutionState`, `ClassOutcome`).
- Decision logic: only `executionState === ClassExecutionState.COMPLETED` branches further; `TAKEN → "end"`; `ABSENT → "Absent" if actualStartAt == null else "absent_student"`; `LEAVE → "absent_student"`; every other state/combo (including null/undefined/empty inputs) falls through to `"open"`. Null/undefined checks use `== null`, so both `null` and `undefined` count as "not joined".

### Constant

```ts
export const STATUS_TO_PREDICATE_KEY: Record<SessionAuditStatus, string> = {
  open: "open",
  end: "end",
  Absent: "Absent",
  absent_student: "absent_student",
};
```

Predicate keys are identity with the status strings (this is the contract Phase 1 codifies). The repository agent must expand each key into the SQL triple per implementation.md §3.4:

- `open` → NOT (`COMPLETED` + `TAKEN`) AND NOT (`COMPLETED` + `ABSENT`) AND NOT (`COMPLETED` + `LEAVE`) — i.e. the complement of the terminal branches (specs AC-2.2/2.7/2.8)
- `end` → `execution_state = 'COMPLETED' AND outcome = 'TAKEN'`
- `Absent` → `execution_state = 'COMPLETED' AND outcome = 'ABSENT' AND actual_start_at IS NULL`
- `absent_student` → `execution_state = 'COMPLETED' AND (outcome = 'LEAVE' OR (outcome = 'ABSENT' AND actual_start_at IS NOT NULL))`
