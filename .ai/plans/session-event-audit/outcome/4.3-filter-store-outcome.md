## Store contract (for view-model 4.2, filter bar 4.6, and page-test 4.9 agents)

### State

```ts
interface SessionAuditFilterState {
  teacherId: string | null;            // default null  — filter: teacher UUID
  studentId: string | null;            // default null  — filter: student UUID
  dateFrom: string | null;             // default null  — inclusive ISO date (YYYY-MM-DD)
  dateTo: string | null;               // default null  — inclusive ISO date (YYYY-MM-DD)
  currentStatuses: readonly SessionAuditStatus[];      // default [] (all statuses)
  search: string;                      // default ""   — raw as typed; VIEW-MODEL debounces 300 ms
  sortField: SessionAuditReportSortField;              // default ScheduledStartAt
  sortDirection: OrderSortDirection;                   // default Desc
  page: number;                        // default 0    — 0-based server page index
  pageSize: number;                    // default 50   (SESSION_AUDIT_DEFAULT_PAGE_SIZE)
}
```

- `SessionAuditStatus`, `SessionAuditReportSortField`, `OrderSortDirection` are the **codegen enums** from `@/frontend/common/graphql/generated/gql/graphql` (status wire values: `open`, `end`, `Absent`, `absent_student` — including the capitalized `Absent` and snake_case `absent_student`).
- All types/imports come straight from `graphql.ts` — zero local redefinitions, zero mapping layers.

### Actions

- `setTeacherId`, `setStudentId`, `setDateFrom`, `setDateTo`, `setCurrentStatuses`, `setSearch` — each resets `page` to 0.
- `setSort(sortField, sortDirection)` — single action (matches DataGrid's `onSortModelChange` shape); resets `page` to 0.
- `setPage(page)` — clamps negative/fractional/NaN to a valid 0-based index.
- `setPageSize(pageSize)` — clamps to ≥ 1; resets `page` to 0.
- `clearFilters()` — clears the six filter fields + returns to page 0; **keeps sort and pageSize**.
- `reset()` — full restore of all defaults (incl. sort + pageSize).
- `hydrateFromUrl(search?: string)` — one-shot URL → state for page mount; `search` defaults to the live `window.location.search`; no-ops server-side. **Resets the store to `defaultState()` first** (FIX-R, review finding: URL params previously merged over stale module state, leaking filters across navigations); absent URL keys therefore always fall back to defaults, never to leftover values.

### URL sync plumbing

- `startSessionAuditUrlSync(): () => void` — subscribes to the store; every change rewrites the URL via `window.history.replaceState` (**replace, never push**) after a **100 ms debounce** (`SESSION_AUDIT_URL_SYNC_DEBOUNCE_MS`). Returns the unsubscribe/cleanup (also clears the pending timer).
- Intended wiring (view-model `useEffect`, runs once): call `hydrateFromUrl()` first, then `return startSessionAuditUrlSync()`.
- Plain module functions — the store is usable outside React (`getState()`/`setState()`/`subscribe()`), and nothing imports `next/navigation`, so no router mock is needed anywhere.
- Sync **preserves unrelated query params** (e.g. `openOverride=1` on the page URL): it deletes only its own keys, applies the serialized ones, and leaves foreign params untouched.

## URL parameter names + defaults (the shared contract)

| Param | Format in URL | Serialized when | Hydration resilience |
|---|---|---|---|
| `teacherId` | string | ≠ null/blank | blank → ignored |
| `studentId` | string | ≠ null/blank | blank → ignored |
| `dateFrom` / `dateTo` | `YYYY-MM-DD` | ≠ null | strict calendar-date check (`2026-02-30` dropped); each date validated independently; **range inversion is NOT dropped here — the filter bar surfaces `error.dateRangeInvalid`** |
| `currentStatuses` | comma-joined wire values (repeatable params also accepted on read): `open`, `end`, `Absent`, `absent_student` | length > 0 | unknown members dropped, list deduped, order preserved |
| `search` | string | ≠ "" | trimmed; blank → ignored |
| `sortField` | enum wire value: `scheduledStartAt`, `scheduledEndAt`, `actualStartAt`, `actualEndAt`, `durationMinutes`, `calculatedDuration`, `teacherPaidAmount`, `calculationStatus`, `teacherName`, `studentName` | non-default sort | unknown → **whole pair ignored** |
| `sortDirection` | lowercase `asc` \| `desc` (matches the CSV export route contract; library-agnostic) | non-default sort | case-insensitive; unknown or half-pair → default sort kept |
| `page` | integer, **0-based** (matches the store index and MUI DataGrid `paginationModel.page`) | > 0 | negative/decimal/zero-padded (`1.5`, `03`, `-1`) → ignored |
| `pageSize` | integer ≥ 1 | ≠ 50 | `0`/malformed → ignored |

- **Default-valued fields are omitted** from the URL entirely, so bookmarked links inherit future default changes.
- The pair contract and `currentStatuses`/`dateFrom` formats deliberately mirror the CSV export route (`/api/accounting/reports/export`) so the view-model can reuse the same serialization for the export URL.
- GraphQL variable conversion note for the view-model: store carries the **codegen enums** directly; `sortDirection` in the URL is a **lowercase** rendering of `OrderSortDirection` (`OrderSortDirection.Asc`/`Desc` in state). Statuses and sortField are already the GraphQL wire values — pass through unchanged.

## Deviations / decisions to propagate

1. **`page` param is 0-based** in the URL (no `+1` humanization) — keeps the round-trip lossless with the store/MUI page index. Any UX decision to show 1-based URLs must be a view-model concern, not a serializer change.
2. **`decode` of statuses is order-preserving and deduped** — chip rendering order in the filter bar may follow this order.
3. **URL uses lowercase `asc`/`desc`** while state holds `OrderSortDirection.Asc`/`Desc` — parse is case-insensitive; the lowercase form was chosen to match the CSV export route contract.
4. **Hydration never validates `dateFrom ≤ dateTo`** — both dates hydrate independently; the UI's `error.dateRangeInvalid` copy handles the inverse-range case without breaking link sharing.
