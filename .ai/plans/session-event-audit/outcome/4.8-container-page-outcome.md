## Final component tree (how the page is mounted)

```
app/(dashboard)/accounting/reports/page.tsx          (server, withPageAuth[ACCOUNTING_REPORTS_VIEW])
└── SessionAuditReportsContainer                     ("use client", composition root)
    ├── useSessionAuditReportsViewModel()            (labels, filter slice, query, aggregates, export handler)
    ├── SessionAuditCsvExportButton                  (container-owned; id "session-audit-export-csv")
    │     ExportButton + FileDownloadOutlined → viewModel.handleExportCsv()
    │     → truncated result → useNotifications().show(labels.exportTruncated, warning, 5 s)
    └── ResponsiveViewSwitch(props = { ...viewModel, exportAction })
          ├── lazy → SessionAuditReportsDesktopView  (session-audit-reports.desktop.tsx)
          │     DesktopPageContainer
          │       ├── DesktopPageHeader (labels.title)
          │       └── DesktopSectionPanel (title=labels.title, actions=<SessionAuditFilterBar {...props} />)
          │             └── Box (p: 2) → SessionAuditDataGrid (spread props, incl. `exportAction` slot)
          │                   ├── exportAction row (end-aligned, container's CSV button)
          │                   ├── ErrorState (error !== null, onRetry=refetch) — grid-owned
          │                   ├── AppDataGrid (server sort/pagination, loading skeleton, empty state)
          │                   └── SessionAuditAggregateCard (only when aggregates.totalPaidCurrency ≠ null)
          └── lazy → SessionAuditReportsMobileView   (session-audit-reports.mobile.tsx)
                MobilePageContainer
                  ├── MobilePageHeader (labels.title)
                  └── Stack → MobileContentInset[SessionAuditFilterBar] → MobileContentInset[SessionAuditDataGrid]
```

The page imports the **container** directly (not a separate `XxView` switcher file) —
mirroring the payroll reports page, whose container is itself the switcher composition
root. The App Router page is therefore a 5-statement server component.

## Contract conformance

- **View-model (4.2)**: `SessionAuditReportsViewProps extends SessionAuditReportsViewModel`
  and adds `readonly exportAction: ReactNode`. The container passes
  `{ ...viewModel, exportAction: <SessionAuditCsvExportButton … /> }` into the switcher.
- **Filter bar (4.6)**: tier views render `<SessionAuditFilterBar {...props} />`; the
  props Pick is a structural subset of the view model — spreads directly, per the 4.6
  hand-off note ("No extra wrapping needed").
- **Data grid (4.7)**: tier views render `<SessionAuditDataGrid {...props} />`; the
  container's CSV export control flows through the grid's `exportAction` slot
  (rendered end-aligned above the grid). The grid owns loading/empty/error states,
  so the tier views deliberately do **not** wrap it in `DesktopListStateGate` /
  `MobileListErrorNotice` (unlike payroll, whose grid lacks an error state).
- **Export notice**: the truncation snackbar follows the payroll convention
  (`useNotifications().show(…, { severity: "warning", autoHideDuration: 5000 })`).
  There is **no** failure toast: the namespace has no `exportFailed` key (3.3 scope),
  and the view-model handler already logs failures via `logger.error` (resolves `null`).
- **Route page (3.5)**: metadata title from
  `getTranslations(locale).dashboardTranslations.sessionAudit.title` via `getLocale()`;
  permission gate mirrors `app/(dashboard)/accounting/payroll/page.tsx`.

## Deviations

1. **Permission gate spelling**: the brief mentioned `PAGE_PERMISSIONS.accountingReportsView`,
   but no `app/` page consumes the frontend `PAGE_PERMISSIONS` map (it is frontend-codegen-
   enum typed, for nav/client gating). The page uses the backend
   `AppPermission.ACCOUNTING_REPORTS_VIEW` with `withPageAuth`, exactly mirroring
   `app/(dashboard)/accounting/payroll/page.tsx`. The wire value is identical to
   `PAGE_PERMISSIONS.accountingReportsView` (`"accounting.reports_view"`), so behavior
   matches the 3.1–3.2 registration.
2. **No `DesktopListStateGate` / `MobileListErrorNotice`** in the tier views (payroll uses
   both): this grid renders its own `ErrorState` + pagination/loading/empty states
   (4.7 contract), so an outer gate would double-render error UI.
