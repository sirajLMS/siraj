## Component props interface (verbatim contract)

```tsx
export interface SessionAuditStatusChipProps {
  /** Audit status of the report row; drives both chip color and label. */
  readonly status: SessionAuditStatus;
  /** Localized per-status labels from the session-audit namespace. */
  readonly labels: SessionAuditLabels["status"];
  /** Room-entry timestamp of the row; required to trigger the live pulse. */
  readonly actualStartAt?: Date | string | null;
  /** Room-exit timestamp; a session that has ended never pulses. */
  readonly actualEndAt?: Date | string | null;
  /** Clock override in epoch milliseconds for deterministic rendering (tests); defaults to the current time. */
  readonly now?: number;
}
```

- `status` is the shared-literal union from `@/shared/constants/classes/session-audit-status`
  (`"open" | "end" | "Absent" | "absent_student"`).
- `labels` is the `status` section of `SessionAuditLabels`
  (`@/shared/locale/types/dashboard/reports`) — keyed by the same union members,
  including the intentional capital-`A` `Absent` key. Following the ViewModel/Rule-7
  convention (and the `CalculationStatusChip` precedent in
  `frontend/common/views/dashboard/accounting/payroll/`), the Component does not call
  `useAppTranslation`; the grid/ViewModel passes `labels.status` down.
- Exported constant: `SESSION_AUDIT_PULSE_WINDOW_MS = 24 * 60 * 60 * 1000`.

## Rendered behavior

- **Color** (`Chip` `color` prop → resolves through `theme.palette`, no hardcoded
  colors): `open → info` (blue), `end → success` (green), `Absent → error` (red),
  `absent_student → warning` (amber).
- **Label / a11y**: `label` and `aria-label` are both the full localized status text
  (chip exposes the full status text per the accessibility requirement of the audit
  grid task list).
- **Pulse**: only when `status === "open"` AND `actualStartAt` is set (valid date)
  AND `actualEndAt == null` AND the entry is within the last
  `SESSION_AUDIT_PULSE_WINDOW_MS` of the mount-time clock (0 ≤ elapsed ≤ window).
  Implemented as an expanding `boxShadow` keyframe on the chip via a theme-callback
  `sx` (`alpha(theme.palette.info.main, …)`), with
  `"@media (prefers-reduced-motion: reduce)": { animation: "none" }` in the same sx
  object (the CSS-based reduced-motion pattern from `docs/frontend/quota-ui-patterns.md`).
- **Testability hook**: the pulsing state is surfaced as `data-pulse-active="true"`
  (absent when not pulsing), since sx-driven emotion classes are not stably
  assertable in Happy DOM.
- **Lint-driven clock handling**: `Date.now()` cannot run during render
  (oxlint `react(purity)`) nor inside a synchronous `useEffect`
  (`react(set-state-in-effect)`), so the component captures the clock once via the
  sanctioned `useState(() => now ?? Date.now())` lazy-initializer pattern (same as
  `useMeetingConfigsManagerViewModel.ts`). A stale clock only matters at the coarse
  24h-window boundary, which is acceptable for a pulse affordance.
