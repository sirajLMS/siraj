## Exact GraphQL contract (verbatim from the generated schema — Wave G must match)

### Root query field

```graphql
sessionAuditReport(
  filter: SessionAuditReportFilter
  sort: SessionAuditReportSort
  limit: Int = 50     # constraint directive min 1 / max 200
  offset: Int = 0
): SessionAuditReportPage
```

Permission: `AppPermission.ACCOUNTING_REPORTS_VIEW` via Pothos `authScopes`
(denial → `FORBIDDEN`; unauthenticated → `FORBIDDEN` from scope-auth before the
resolver, `UNAUTHENTICATED` from `requireAuth` if a user-less context slips
through with the permission set). The resolver re-delegates to
`SessionAuditService.getReport(actorUserId, filters, sort, { limit, offset }, ctx.t().errorsTranslations)`,
which re-checks the permission itself (`ForbiddenError`/`FORBIDDEN`).

### Input types

```graphql
input SessionAuditReportFilter {
  teacherId: ID
  studentId: ID
  dateFrom: String        # constraint format date
  dateTo: String          # constraint format date
  currentStatuses: [SessionAuditStatus!]
  search: String          # constraint maxLength 200
  includeDeleted: Boolean
}

input SessionAuditReportSort {
  field: SessionAuditReportSortField!
  direction: OrderSortDirection!   # ASC | DESC — REUSED, not a new "SortDirection"
}
```

Post-review (see `fix-r-backend-outcome.md`): `dateFrom`/`dateTo` are
additionally validated service-side with a strict calendar-date check — the
`format: date` constraint does not reject impossible calendar days — and a
filter with neither bound receives the service's default 30-day window (UTC).
Both rules live in `SessionAuditService.getReport`, so the query and the CSV
export route share them.

## Key design decisions (deviations from the implementation.md sketches)

1. **Real TS enums, not literal arrays.** The sketches called
   `enumType(SessionAuditStatus, …)` / `values: [...]` — the AGENTS.md critical
   rule requires a real TS enum from `backend/enum/`, and the canonical
   `SessionAuditStatus` is a shared **string-literal union** (types-level, no
   runtime value). Resolution: `SessionAuditStatusEnum` /
   `SessionAuditReportSortFieldEnum` in `backend/enum/billing/session-audit.enum.ts`
   with member keys = values so the GraphQL wire values match the canonical
   union exactly (`open`, `end`, `Absent`, `absent_student`; camelCase sort
   fields).
2. **Enum ⇄ union converters, zero casts.** `t.expose`/`inputRef` can't bridge
   nominal TS enums and the domain unions, so: row side uses
   `t.field({ resolve: row => STATUS_TO_POTHOS_ENUM[row.currentStatus] })` in the
   pothos file (`Record<SessionAuditStatus, SessionAuditStatusEnum>`, exhaustive);
   the query maps `currentStatuses`/`sort.field` back through exhaustive
   `Record<enum, union>` lookups and `direction === OrderSortDirection.ASC ? "asc" : "desc"`.
   Inputs are therefore untyped `inputType(...)` (like `PayrollOverrideInputPothos`),
   which `backend/graphql/AGENTS.md` explicitly permits for input types.
3. **Sort direction reuses `OrderSortDirection`** (ASC/DESC — the existing
   shared Pothos enum, used by student/storage sorts) instead of declaring a
   lowercase `SortDirection`; trackable-tasks' "reuse if it exists" clause wins.
   The lowercase `asc`/`desc` in `SessionAuditReportSort` stay service-side.
4. **Aggregates are a nested object** (`SessionAuditReportAggregates` with
   `rowCountByStatus`/`rowCountByPaid` as `JSON` fields exposing
   `aggregates.*`), matching the locked `SessionAuditReportPage` type and the
   payroll report precedent — not the flat page fields of the sketch.
5. **Default sort stays server-side**: the resolver passes `null` when `sort`
   is omitted; the service owns the `scheduledStartAt desc` default (1.4).
6. **Test builder sharing**: the test registers DateTime/JSON scalars behind the
   same process-global flag (`siraj.payrollTest.scalarsRegistered`) that the two
   payroll GraphQL tests use, since all schema-backed tests share the single
   `gqlSchemaBuilder` instance within one `bun test` process.
