## Carry-Forward (for Phase 4/5 frontend tasks)

- **Labels path**: `ProfitLossLabels` lives at
  `ctx.t().dashboardTranslations.accountingProfitLoss` — NOT at the top level of
  `Translations` (it sits under `DashboardTranslations`, message.ts:158).
- **GraphQL schema deltas**: the Expenses/Income aggregate objects do NOT
  expose `totalOriginalCurrency` (only `ProfitLossPaymentsAggregate` does —
  it is a tab-specific extra field in the Pothos type). Frontend documents must
  not select it on those tabs.
- **Apollo normalization ids**: every P&L object exposes a synthetic `id` via
  resolver fields (report: `${month}-${currency}`, pages, aggregates, summary,
  warnings, and rows keyed by `instanceId`/`id`/`paymentId`), so frontend
  documents can select `id` everywhere for cache normalization.
- **Codegen**: `bun codegen` only emits types for documents under
  `frontend/common/graphql/sharedDocuments/` — no `ProfitLossReportQuery`
  operation type exists until the Apollo document (Task 5.1) is written; then
  rerun `bun codegen`.
- Test scaffolding reusable: real-builder + `mock.module("@/backend/services")`
  pattern (see the test file header comments) works for any new accounting
  query; the `SHARED_TEST_SCALARS` global flag means this file co-exists with
  `session-audit.query.test.ts` in one bun process.
- Fixtures: `buildReport()` in the test file builds a full valid
  `ProfitLossReport` and may be reused by the CSV route tests (Task 2.4).
