## Summary

Created `frontend/common/views/dashboard/accounting/profit-loss/ExpensesTab.tsx`: the Expenses
tab of the P&L dashboard. Data comes exclusively from the `useProfitLossViewModel` slice
(`Pick<ProfitLossViewModel, "labels" | "expensesPage" | "month" | "currency" | "isLoading" |
"onExpensesPageChange" | "pageSize">`) plus a single per-field Zustand selector for the
current expenses page index (`useProfitLossFilterStore(s => s.expensesPage)`), the same
store-read idiom `GlobalFilterBar` uses — the ViewModel does not expose the page index itself.

### Grid (AC-4.1 / AC-4.2)

`AppDataGrid<ProfitLossExpenseRow>` with server pagination
(`buildServerPaginationOptions({ page: expensesPageIndex, pageSize, totalCount, onPageChange:
onExpensesPageChange })`). Columns per AC-4.2:

| Column | Field | Notes |
|---|---|---|
| Payment date | `paymentDate` | `formatAccountingDate(dateCell(...))` from the shared accounting formatters |
| Type chip | `type` | local chip cell — see "Chips" below; muted `—` when null |
| Title | `title` | `labels.column.title` |
| Teacher | `teacherName` | `labels.column.teacher`, `—` when unset |
| Value + currency | `expenseValue` | `formatAccountingMoney` + `expenseCurrency` in `onSurfaceVariant` |
| Source chip | `sourceEntity` | Manual / From Carryover (clickable, see below) |
| Note | `note` | header from the expenses namespace's `column.note` (no `column.note` key exists in `ProfitLossLabels`) |

### Footer (AC-4.3 + count-by-type + export)

- **Total Expenses** = `aggregate.totalExpenses` formatted with `formatAccountingMoney`, shown
  with `aggregate.dominantCurrency ?? currency`.
- **Dominant currency** caption (`labels.aggregate.dominantCurrency`) when reported.
- **Count-by-type** tallies: `aggregate.rowCountByType` (JSON scalar, `unknown` in codegen) is
  narrowed with a type-guard helper (`toTypeTallies`), keys mapped back onto the codegen
  `ExpenseType` via the same `AGGREGATE_KEY_BY_TYPE` bridge `ExpensesDataGrid.tsx` uses
  (server tallies are keyed by the backend display value "Salaries", rows carry "SALARIES"),
  each rendered as the same `StatusBadge` the rows show plus its count. Unknown keys are
  skipped (`null`) rather than crashing.
- **FX-excluded rows** caption (`labels.aggregate.excludedRows(count)`) when
  `aggregate.excludedRowCount > 0`.
- **Export CSV** (AC-4.6): `ExportButton` → GET `/api/profit-loss/expenses/export?month&currency`
  (route from Task 2.4), blob-download pattern identical to `useExpensesViewModel`'s export
  (objectURL anchor click + revoke), honors `X-Export-Truncated` (truncation logged as a
  warning — no toast framework is wired in this tab; see Carry-forward), busy-locked and
  disabled while loading or when the month has no rows.

### Drill-downs (AC-4.4 / AC-4.5)

- **Row click** → `router.push(\`/accounting/expenses/${row.id}\`)` — the Plan 6 detail route
  `app/(dashboard)/accounting/expenses/[id]/page.tsx` exists, so Task 6.3 is already satisfied
  by this implementation. Click wired through the `GridRowParams` adapter (the codegen row type
  is not directly assignable to MUI's event handler param).
- **"From Carryover" chip click** → opens Plan 5's `CarryoverDetailDrawer`
  (`frontend/common/views/dashboard/accounting/carryover/CarryoverDetailDrawer.tsx`, props
  `{ carryoverId, open, onClose }`) with the row's `sourceEntityId`. The chip stops propagation
  so the row navigation never fires; non-carryover marker rows render a plain "Manual" badge;
  a carryover row without a resolvable `sourceEntityId` renders the chip unclickable. Phase 6.2
  is therefore already wired (no deferred item needed for the drawer).

### Chips (Plan 6 reuse — deferred)

No `ExpenseTypeChip` / `ExpenseSourceChip` components exist anywhere in `frontend/` (verified
by search). Per the task's fallback rule the tab renders locally, but **delegates all
coloring/labeling to the shared `StatusBadge`** with `category="expenseType"` /
`category="expenseSource"` — the exact primitive, palette mapping, and label catalog the
Plan-6 expense ledger grid (`ExpensesDataGrid.tsx`) renders inline, so the P&L tab and the
expense ledger show identical chips. Type/source label copy reuses the existing
`dashboard.accounting.expenses` namespace (`type.*`, `source.Manual`, `source.FromCarryover`)
via `useAppTranslation(DashboardAccountingExpenses)` — the chip labels are shared domain
vocabulary that must stay in sync with the ledger grid, and `ProfitLossLabels` has no per-type
or per-source keys. Recorded as deferred item **D4** in `deferred-items.md`.
