## 7.3 — RTL pass

Verified; **no code changes required**:

- Direction is set at `app/layout.tsx` (`dir="rtl"` + `lang="ar"` when locale
  is `ar`) and Emotion's RTL cache uses `stylisPlugins: [rtlPlugin]` with the
  prefixer correctly excluded (`frontend/common/lib/emotion-cache.tsx`), per
  the frontend rules.
- All P&L styling uses logical properties only: `paddingInline`
  (StatusBadgeShared), `textAlign: "start"` / `"end"` (ProfitsTab summary
  table), `justifyContent: "flex-end"`, `alignItems`, `gap` — no physical
  `left`/`right` CSS properties and no `text-align: left` anywhere in the
  P&L views, tier views, or chips. Flexbox (not float/absolute left) drives
  layout, so it mirrors automatically under `direction: rtl`.
- The only `"right"` occurrences are DataGrid column `align`/`headerAlign`
  props (PaymentsTab ×4, ExpensesTab ×1). These are grid-semantics value
  enums (MUI X applies them via RTL-aware `direction: ltr`-style internal
  handling and the same sibling accounting grids use them everywhere
  (ExpensesDataGrid, CarryoverDataGrid, PayrollReportsDataGrid) — consistent
  with the repo convention and mirrored correctly under the RTL stylis
  plugin).
- `LtrScope`/per-element `direction: "ltr"` exists in the repo for
  numeric/code strings where needed; the P&L rows use standard
  `formatAccountingMoney`/`formatLockedAmount`, shared with the rest of
  accounting.
