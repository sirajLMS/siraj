## Summary

Created `frontend/common/views/dashboard/accounting/profit-loss/useProfitLossViewModel.ts` — the
viewport-agnostic business-logic hook for the P&L dashboard. It composes:

- **Persisted Zustand store** (`useProfitLossFilterStore`): month, currency, activeTab, per-tab
  page indexes, pageSize — all read via per-field selectors; the setters back `onTabChange` and
  the three page-change handlers (`useCallback`-wrapped so consumers get stable identities).
- **Apollo query**: stateful `useQuery(profitLossReportQueryDocument, ...)` imported from
  `@apollo/client/react` (no `useLazyQuery`) with `fetchPolicy: "cache-and-network"` and
  `notifyOnNetworkStatusChange: true`. Variables derive from the store:
  `{month, currency, paymentsLimit: pageSize, paymentsOffset: paymentsPage * pageSize, ...}`
  for all three tabs, memoized on the six store fields.
- **Permission gate**: `canView = hasPermission(AppPermission.AccountingProfitsView)`; the query
  is `skip`ped without it (same idiom as `useExpensesViewModel` / `useCarryoverViewModel`).
- **Per-tab pages**: `paymentsPage` / `expensesPage` / `incomePage` each expose
  `{rows, totalCount, aggregate}` from the generated types; module-level stable empty-page
  constants keep referential equality pre-first-fetch. `rowCountByType` (JSON scalar) is
  normalized via the repo's `isRowCountByType` type-guard pattern.
- **FX-warning passthrough**: `fxWarnings` is bridged onto the canonical `FxWarning` from
  `@/backend/types` (the shape `GlobalFilterBar`'s chip prop expects) plus an aggregated
  `fxExcludedRowCount` (sum of pair row counts) for the chip label.
- **Derived**: `summary` (profits-summary object, null-safe), `isEmptyMonth` (all three
  `totalCount`s zero — for the Phase 5 empty state), `isLoading`, `error ?? null`, `refetch`
  (void-wrapped).
- **Labels**: `labels: ProfitLossLabels` via `useAppTranslation(DashboardAccountingProfitLoss)`
  — the ViewModel owns translations per the views-layer rule; tier views must not call
  `useAppTranslation`.

## Key design note: dual CurrencyCode enums (carry-forward)

The codegen enum (`@/frontend/common/graphql/generated/gql/graphql`, keys `Aed`, `Usd`, …) and
the domain enum (`@/shared/constants/currency.enum`, keys `AED`, `USD`, …) enumerate the same
ISO 4217 value strings but have different member names, so they are **structurally incompatible
in TypeScript**. Backend canonical types (`@/backend/types`, incl. `FxWarning`) use the domain
enum. The ViewModel bridges via `String`-value + `isDomainCurrencyCode` type guard
(`toDomainCurrencyCode`). **Any future ViewModel field typed as a backend `CurrencyCode` needs
this same bridge** — pass generated-enum values straight through only where consumers expect the
codegen type.
