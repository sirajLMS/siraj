## Deviations from the Plan (intentional, rule-driven)

- `calculationStatus` uses `CalculationStatus` from `@/backend/enum` (re-export of
  `@/shared/constants/teachers/payroll-calculation.enum`) instead of the plan's plain
  `string` — the `class_instances.calculation_status` column is a pgEnum backed by this type
  (`backend/db/schema/enums.ts:185`), and the carryover sibling types status fields with the
  enum (`carryover-balance.types.ts:313` `currentStatus: CalculationStatus`).
- `paymentMethodType` uses `PaymentMethodType` from `@/backend/enum` (re-export of
  `@/shared/constants/billing.enum`) instead of the plan's plain `string` — the
  `payment_method_type` pgEnum is backed by this type (`backend/db/schema/enums.ts:112`).
- Currency fields use `CurrencyCode` from `@/shared/constants/currency.enum`, matching all
  sibling billing types.
- Page aggregate containers keep the plan's singular `aggregate` key (not the siblings'
  plural `aggregates`) because the GraphQL/service subtasks in this plan reference
  `.aggregate`; noted here so reviewers don't flag the cross-plan naming difference.
