## API (carry-forward for Tasks 4.2 / 4.4 / 4.5)

- `useProfitLossFilterStore` — hook (created via `create<ProfitLossFilterStore>()(persist(...))`)
- `PROFIT_LOSS_TABS` — exported `readonly ["payments", "expenses", "income", "profits"]` tuple (tab order for MUI `Tabs`)
- `ProfitLossTab` — exported union type for tab identifiers
- Setters: `setMonth`, `setCurrency`, `setActiveTab`, `setPaymentsPage`, `setExpensesPage`,
  `setIncomePage`, `reset`
- `setMonth` also zeroes all three page indexes (a new month changes every tab's result set)
- Page setters clamp via `toNonNegativePage` (NaN/∞ → 0, negatives → 0, truncation), so a
  stale persisted page can never produce a negative GraphQL offset
- `reset` restores the pristine state including a fresh current-month default
- Persist options: `{ name: "profit-loss-filter" }` — all state is JSON-serializable
  (strings/numbers/enum value), no `partialize` needed, satisfying the stores-layer
  serialization rule
- Default `pageSize` is `25`, matching `payrollReportsFilterStore.ts`; the plan text did not
  specify a value. The pager UI (Phase 5 tabs) may offer the standard `[25, 50, 100]` options
  like the siblings.

## Design decisions / deviations

- **`CurrencyCode` imported from the generated GraphQL types**
  (`@/frontend/common/graphql/generated/gql/graphql`) as a *value* import — required because
  `CurrencyCode.Sar` is used in the runtime default state; the stores layer AGENTS.md
  mandates generated types as the single source of truth.
- **Tab list exported as a const tuple + derived union** rather than inline string-literal
  unions — gives the Tabs UI an ordered, typed list and keeps the union in one place
  (avoids `ProfitLossFilterState["activeTab"]` indexed-access in consumers).
- **No stores barrel exists** (`frontend/common/stores/` has no `index.ts`); sibling filter
  stores are imported directly, so no barrel registration was needed.
- **No user-facing strings** in the store — no i18n keys required (labels live in the
  `dashboard.accounting.profitLoss` namespace, Tasks 3.3/3.4).
- **No tests created** — per task instructions (no UI/component/e2e tests for this store).
