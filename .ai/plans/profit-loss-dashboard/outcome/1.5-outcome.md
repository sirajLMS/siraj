## Method signature & return shape

```ts
CreditRepository.findSubtractCreditsByInstanceIds(
  instanceIds: string[],
  tx?: DBTransaction
): Promise<Map<string, { amount: number; currency: null }>>
```

- **amount**: `COALESCE(SUM(ABS(change_amount)), 0)` mapped with `Number` per the repo
  AGENTS conditional-aggregation rule (`sql<number>` + `.mapWith(Number)`). Subtract rows
  persist negative deltas (e.g. `-2`, `-5`), so the map carries the **positive subtracted
  magnitude** — the caller (Payments tab service) can display it and add it into
  "Total Payments" directly without negating.
- **currency**: always `null` at the repo level. `credit_transactions` carries no currency
  column, and the existing `CreditRepository` has no currency convention anywhere (verified
  by grep over the file) — the plan's `ProfitLossPaymentRow` types the currency as
  `CurrencyCode | null`, so enrichment from a monetary source (e.g. the session's
  `studentPaidCurrency`) is the service layer's concern.
- **Empty input**: `instanceIds.length === 0` returns an empty `Map` before querying —
  an `inArray` filter over an empty array is invalid SQL on PostgreSQL (documented in the
  method JSDoc). Mirrors the sibling `findByIdempotencyKeys` empty-guard convention.
- **Missing instances**: pre-existing rows for other instances (or unknown/random UUIDs) are
  simply absent from the map — the caller uses `.get(id) ?? null` (the service spec does
  exactly this). Note: this intentionally does NOT pre-initialize the map with nulls as the
  repo AGENTS DataLoader rule suggests, because the task spec explicitly requires missing
  instances to be absent (not null-mapped).

## Deviations from the Plan (rule-driven, for reviewer/service-subtask awareness)

- **File/namespace**: method lives in `CreditRepository` (`credit.repository.ts`), not a new
  `credit-transactions.repository.ts` / `CreditTransactionRepository` — no such file exists
  in the repo and the repo layer mandates one canonical `{Entity}Repository` namespace per
  file. The plan's Phase-1/Phase-2 spec pseudo-code references
  `CreditTransactionRepository.findSubtractCreditsByInstanceIds(...)`; downstream tasks
  (1.7 service, 2.1 GraphQL) should import `CreditRepository` from `@/backend/db/repo`
  instead.
- **`amount` is `number`** (integer credit count summed), not a decimal string — the ledger
  `change_amount` is an integer column, and the plan's `manualSubtractCredits: string | null`
  serialization (`String(amount)` in the service) is a service-layer concern.
