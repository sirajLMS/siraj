## Summary

Created `frontend/common/views/dashboard/accounting/profit-loss/GlobalFilterBar.tsx`: the
P&L dashboard's global filter bar. It reads/writes the persisted Zustand store
(`useProfitLossFilterStore`) and renders three elements inside the shared accounting
`FilterBarShellShared` (same outlined Paper + wrap stack as `ExpenseFilterBar`):

1. **Month picker** — `AppDatePicker` (wraps MUI X DatePicker) in month mode:
   `views={["year", "month"]}`, `openTo="month"`, `format="yyyy-MM"`. The store's
   `YYYY-MM` string is parsed via `date-fns parse` and written back via `format`.
   `aria-label` + `autoComplete: "off"` on the htmlInput (MUI v9 `slotProps.textField.slotProps.htmlInput`
   pattern, matching the sibling ExpenseFilterBar). Null/invalid dates are ignored
   (month is always required, so there is no "all months" mode here).
2. **Currency picker** — reused the existing `CurrencySelect` component
   (`@/frontend/common/components/ui`), which is a searchable MUI Autocomplete fed by
   `useCurrencyCatalog()` over the canonical `frontend/common/lib/currency.ts` catalog.
   This is the same currency selection UX other dashboards/forms use; no new options
   list was created. Value is a `CurrencyOption`; the store keeps the bare
   `CurrencyCode`, bridged via `getCurrencyByCode` / `option.code`.
3. **FX-warning chip** — rendered **only when `fxWarnings.length > 0`**. Warning-
   colored outlined `Chip` with `WarningAmberOutlined` icon; label is
   `t.fx.chip(totalExcludedRows)` (pluralization handled by the locale function) and a
   `Tooltip` with `t.fx.tooltip(pairs)` where `pairs` is the caller-joined list of
   `"ORIGINAL → TARGET (rowCount)"` entries separated by `" · "` (per Task 3.3's
   carry-forward contract: the tooltip function receives the pre-joined string).

**URL search-param sync (both directions):**
- *Store → URL*: a `useUrlSearchParamSync` effect mirrors the settled month + currency
  into `?month=YYYY-MM&currency=CODE` via `router.replace(..., { scroll: false })`,
  skipping the write when the query string already matches (no history spam / render
  loops). Pattern follows `useRecurringSchedulesListViewModel.ts`.
- *URL → store*: `useFilterDeepLink` adopts a shared link's `month` (validated
  `YYYY-MM` via date-fns `isValid(parse(...))`) and `currency` (validated against the
  canonical catalog via `getCurrencyByCode`) into the store; invalid/absent values
  leave the persisted defaults untouched. Note `router.replace` keeps the params in the
  address bar (unlike the class-audit deep link which strips them), because these
  params are a shareable state snapshot, not a one-shot action.

All strings come from `useAppTranslation(DashboardAccountingProfitLoss)` —
`dashboard.accounting.profitLoss` namespace (keys `filter.month`, `filter.currency`,
`fx.chip`, `fx.tooltip`); zero hardcoded strings. No hardcoded colors — the chip uses
the `warning` palette via `color="warning"`; RTL-safe (flex-wrap stack, `→` pair arrow
is a bidi-neutral separator inside the localized tooltip sentence).

- `FxWarning` is imported **type-only** from `@/backend/types` (canonical

## Design decisions / deviations

- **`CurrencySelect` reuse instead of a bare MUI Autocomplete**: the task said "MUI
  Autocomplete … reuse the app's existing currency list". The existing component *is*
  an Autocomplete over the canonical catalog with symbols, flags, locale-aware labels,
  and search — using it satisfies both the letter (Autocomplete) and the reuse mandate,
  and avoids a jscpd clone of the input rendering.
- **No debouncing on month/currency**: unlike the expenses title search, both controls
  commit on selection (date pick / option pick), so a debounce would only delay the
  refetch. The plan's 300 ms debounce note (implementation.md §10 test table) applies
  to typed input, which these pickers don't have.
- **Required flag dropped on CurrencySelect**: the store always holds a currency, so a
  required-empty error state would be dead code.
- **`isMonthParam` guard** instead of regex: date-fns `parse` + `isValid` rejects
  `2024-1`, `2024-13` etc. the same way the backend `validateMonth` does.
- **No tests created** — per the explicit instruction (no UI/component/e2e tests).
