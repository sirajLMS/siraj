## Summary

Implemented the four per-tab CSV export Route Handlers under
`app/api/profit-loss/<tab>/export/route.ts` (`payments`, `expenses`, `income`,
`summary`). Each route:

1. Resolves locale from `accept-language` (primary subtag, fallback `ar`) and pulls
   `tErrors` (`errorsTranslations`) + `tLabels`
   (`dashboardTranslations.accountingProfitLoss`) via `getServerTranslations` from
   `@/shared/locale/server-graphql`.
2. Checks the session with `getServerUserContext` → 401 with the localized
   `unauthorized` message when absent.
3. Parses `month` + `currency` query params via the shared
   `parseProfitLossExportInput` → 400 with `tErrors.invalidInput` for a
   missing/blank month or an unsupported ISO-4217 code (validated against
   `CurrencyCode` enum values).
4. Calls `ProfitLossService.getReport(userId, input, pagination, tErrors, tLabels)`
   with the tab's limit knob set to `PROFIT_LOSS_EXPORT_ROW_LIMIT` (10_000):
   `{ paymentsLimit }` / `{ expensesLimit }` / `{ incomePaymentsLimit }`
   respectively; the summary route passes `{}` (default page limits suffice —
   the summary is composed from per-tab aggregates, and aggregate sums are
   computed over the fetched page).
5. Serializes the tab with the shared serializer (RFC 4180 + OWASP CSV
   formula-injection neutralization: `=`, `+`, `-`, `@`, tab, CR get a `'`
   prefix; separator/quote/newline-bearing cells are quoted with `""` escapes).
6. Sets `Content-Type: text/csv; charset=utf-8`, `Content-Disposition:
   attachment; filename="profit-loss-<tab>-<month>.csv"`, and
   `X-Export-Truncated: true|false` (`true` when the tab's `totalCount >
   10_000`). The summary route always emits `false` (fixed 4-line summary —
   never truncated), keeping the header contract uniform across tabs.
7. Error mapping: `ForbiddenError` (thrown by `requirePermission` inside
   `getReport`) → 403 `tErrors.insufficientPermissions`;
   `ValidationError` → 400 with the error message; `DomainError` with code
   `MONTH_INVALID` (thrown by `validateMonth` inside `getReport`) → 400 with
   `tLabels.error.monthInvalid`; anything else → 500 with
   `tErrors.internalServerError` + `logger.error`.

Permission gating (`ACCOUNTING_PROFITS_VIEW`) is enforced inside
`ProfitLossService.getReport` via `requirePermission` (Task 1.7 contract), so the
routes do not duplicate a permission check — they only map the resulting
`ForbiddenError` to a 403 response.

## Design decisions

- **Shared serializer module** (`backend/services/accounting/profit-loss-csv.serializer.ts`):
  the four routes share the CSV cell hardening, header building, input parsing,
  and truncation flag. Inlining these four times would have tripped the
  duplicates gate (jscpd threshold 100, minTokens 75 — the `toCsvCell` +
  header-builder block alone is >75 tokens) and duplicated a security-relevant
  sanitizer. This mirrors the existing `session-audit-csv.serializer.ts`
  precedent (service-adjacent pure serializer, exported through the
  `@/backend/services` barrel). No changes were made to the three pre-existing
  export routes (`expenses`, `carryover`, `payroll`, `session-audit`).
- **`X-Export-Truncated` on summary**: the summary is a fixed 4-metric payload,
  so it can never exceed the export ceiling; the route sends `false` explicitly
  so the frontend can treat all four download responses uniformly.
- **Filename**: `profit-loss-<tab>-<month>.csv` (uses the validated month rather
  than today's date — the file is month-scoped data, which makes saved exports
  distinguishable across months).
- **401 before parse**: unauthenticated callers are rejected before any query
  param validation, matching the expenses-export route pattern.

## Carry-forward knowledge

- `ProfitLossService.getReport(actorUserId, { month, currency }, pagination, tErrors: ErrorsLabels, tLabels: ProfitLossLabels)` — the labels bundle is `getServerTranslations(locale).dashboardTranslations.accountingProfitLoss`; `tLabels.aggregate.*` keys double as the summary CSV metric labels.
- `validateMonth` throws `DomainError` with code `"MONTH_INVALID"` and message `tLabels.error.monthInvalid` — API routes must map that code to 400 (the GraphQL layer gets it for free via the error extension).
- Truncation contract for consumers: `X-Export-Truncated: true` iff the tab's `totalCount > 10_000`; the CSV then contains only the first 10_000 rows. The UI (Task 4.x) should show a toast when the header is `true`.
- Reusable exports from `@/backend/services` (barrel): `serializeProfitLoss{Payments,Expenses,Income,Summary}Csv`, `parseProfitLossExportInput`, `buildProfitLossCsvHeaders`, `isProfitLossExportTruncated`, `PROFIT_LOSS_EXPORT_ROW_LIMIT`.
- Mock pattern for route tests: `await mock.module("@/backend/services", async () => {...})` with a dynamic re-import of the real serializer module inside the factory — mock `ProfitLossService.getReport` per-route, keep the CSV helpers real so body assertions exercise production escaping.
