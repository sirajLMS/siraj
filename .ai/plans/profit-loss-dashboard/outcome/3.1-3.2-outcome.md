### Deviations from the plan (intentional, rule-driven)

- **Enum member name**: plan §6.2 wrote `AppPermission.ACCOUNTING_PROFITS_VIEW`,
  but the frontend imports `AppPermission` from the *generated GraphQL types*
  (`frontend/common/graphql/generated/gql/graphql.ts`), where the enum member
  is PascalCase: `AccountingProfitsView = 'ACCOUNTING_PROFITS_VIEW'` —
  consistent with every sibling entry (`AccountingPaymentsView`,
  `AccountingExpensesView`, …). The backend source enum
  (`backend/enum/permissions/permission.enum.ts`) is the
  `ACCOUNTING_PROFITS_VIEW = "accounting.profits_view"` form per plan §2.1;
  both spellings refer to the same GraphQL enum value.
- **Icon**: plan §6.1 proposed `iconKey: "insights"`, but `"insights"` is not a
  valid `NavIconKey` (`frontend/common/views/dashboard/config/navIconKeys.ts`)
  and adding to `navIconKeys.ts` is outside this task's file scope. Used
  `"assessment"` — the existing analytics/report icon already used by
  `accounting-reports` and `quotas-insights`.
- **Label key**: `accountingProfits`, per plan §6.1 and the existing nav
  convention (`accountingExpenses`, `accountingPayroll`, `accountingReports`).
  It resolves via `DashboardNavigationLabels` — the `dashboard.core.nav`
  namespace used by ALL other nav items (`NavItem.labelKey` is typed
  `keyof DashboardNavigationLabels`), NOT via the
  `dashboard.accounting.profitLoss` feature namespace (that namespace provides
  in-page copy; nav chrome copy lives in `core.nav`).
