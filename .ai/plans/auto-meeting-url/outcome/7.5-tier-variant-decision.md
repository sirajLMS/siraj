# 7.5 Tier Variant Decision — Mobile/Desktop Isolation

## Decision

The Profile Meeting Configs section follows the project's Mobile/Desktop tier separation:

- **Shared logic**: `frontend/common/views/dashboard/profile/shared/meeting-configs/`
  - `useMeetingConfigsManagerViewModel.ts` — state management, mutations, OAuth callbacks
  - `ReauthNeededBanner.tsx` — shared banner component
  - `ConnectProviderAccount.tsx` — shared connection flow
  - `LinkedClassInstancesList.tsx` — shared list component

- **Mobile tier**: `frontend/mobile/views/dashboard/profile/shared/meeting-configs/`
  - Thin wrapper that imports shared logic and applies mobile-specific layout

- **Desktop tier**: `frontend/desktop/views/dashboard/profile/shared/meeting-configs/`
  - Thin wrapper that imports shared logic and applies desktop-specific layout

## Rationale

All business logic (state management, GraphQL mutations, error handling, reauth detection)
lives in the `common/` shared layer. Tier-specific files only handle layout, spacing,
and component composition differences between mobile and desktop. This follows the
project's AGENTS.md tier separation rules.

## Compliance

- ✅ `frontend/views/AGENTS.md` — shared logic in common, tier wrappers import from common
- ✅ `frontend/mobile/AGENTS.md` — mobile wrapper is thin import
- ✅ `frontend/desktop/AGENTS.md` — desktop wrapper is thin import
- ✅ `mobile-desktop.instructions.md` — no logic in tier files
