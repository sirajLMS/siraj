# Task 5.6 — ViewModel Hook + Apollo Documents + Zustand Store

## What was done

Implemented the `useMeetingIntegrationsViewModel` hook that orchestrates Apollo queries/mutations and local UI state via a Zustand store. Created GraphQL documents for the four meeting-integration operations and two query hooks wrapping the Apollo queries.

## Files created

- `frontend/common/graphql/sharedDocuments/settings/meeting-integrations.documents.ts` — 4 documents: `MeetingIntegrationProvidersQueryDocument`, `MeetingIntegrationConnectedAccountsQueryDocument`, `TestMeetingProviderConnectionMutationDocument`, `AdminRevokeMeetingProviderTokenMutationDocument` (all include `id` field for Apollo cache normalization)
- `frontend/common/stores/meetingIntegrationsSettingsStore.ts` — Zustand store managing local UI state (selected provider, credential form values, test result, dialog open state, loading flags)
- `frontend/common/views/dashboard/settings/tabs/meetingIntegrations/useMeetingIntegrationsViewModel.ts` — hook binding Apollo operations to the store, exposing typed handlers for provider selection, credential save, test connection, and token revoke
- `frontend/common/hooks/settings/useMeetingIntegrationProvidersQuery.ts` — query hook for fetching meeting integration providers
- `frontend/common/hooks/settings/useMeetingIntegrationConnectedAccountsQuery.ts` — query hook for fetching connected accounts for a given provider

## Files modified

- `frontend/common/hooks/settings/index.ts` — added barrel exports for the two new query hooks
