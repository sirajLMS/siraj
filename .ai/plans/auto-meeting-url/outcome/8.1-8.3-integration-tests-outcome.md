## Notes
- All three integration test files use the `describeLiveWhen(configPredicate, label)` helper imported from `@/test/integration/helpers/describe-live`. When the relevant env config is absent, the `describe` block is a no-op — tests are skipped by default, so `bun run test:integration` does not fail on a developer machine without live provider credentials.
- Each integration file has exactly **one smoke test** (a single round-trip against the live provider API), per the project convention in `backend/services/AGENTS.md` — "Each integration file gets **one** smoke test (single API call) to confirm the adapter reaches the live provider — not full service or app behaviour."
- To run the live smoke tests, set the provider env vars (e.g. `ZOOM_ACCOUNT_ID`, `ZOOM_CLIENT_ID`, `ZOOM_CLIENT_SECRET`, or the per-provider OAuth equivalents) and run `bun run test:integration` — the parallel runner picks up all three files.
- The Google Meet adapter smoke test intentionally omits `deleteMeeting` because the Google Meet (Google Calendar API) space DELETE is a no-op on the provider side; the test only confirms `validateConfig` + `generateMeeting` complete against the live API.
- Tests were added under `test/integration/meeting/` (a new directory) alongside the existing `test/integration/` layout; the parallel runner's glob (`test/integration/**/*.test.ts`) picks them up automatically with no `package.json` change required.
