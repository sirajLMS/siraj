### Files Modified
- `backend/services/AGENTS.md` — added a **Meeting Provider Adapters (CRITICAL)** section documenting the canonical patterns:
  - All meeting URL generation MUST go through `MeetingChannelFactory.getMeetingChannel(slug)` (or the `meetingChannel` delegating object) — never construct `ZoomMeetingAdapter`/`GoogleMeetAdapter`/`MicrosoftTeamsAdapter` directly (race-safe per-slug singletons, env resolution, credential-change cache invalidation).
  - Hybrid auth resolution order: org-level credentials first, per-user OAuth refresh-token fallback second (`MeetingProviderTokenRepository.getByUserAndProvider`), `NoOrgCredentialsNoUserTokenError` if neither available.
  - `providerKindToSlug(providerKind)` canonical mapping from `meeting_providers.provider_kind` to adapter slug; unknown kinds throw `UnsupportedProviderKindError`.
  - Booking-time generation is non-blocking (`maybeGenerateUrl` runs outside the booking DB transaction).
  - Cross-reference to `docs/services/meeting-providers.md` for the complete pattern reference.
- `backend/AGENTS.md` — added `docs/services/meeting-providers.md` to the Important References list (meeting provider adapter/factory pattern reference).
- `backend/db/repo/AGENTS.md` — added a **Meeting Provider Tokens (`meeting_provider_tokens`)** section documenting:
  - Encrypted storage (CRITICAL): `access_token` and `refresh_token` use the `encryptedText` custom Drizzle type; the `MeetingProviderTokenRepository` handles encryption/decryption transparently — never write plaintext tokens to a side table or log them.
  - Refresh-token rotation: Zoom rotates refresh tokens on every exchange; after `refreshAccessToken` succeeds, the service layer must call `upsert` with the rotated `refresh_token` value. Never assume the stored refresh token is still valid after a refresh.
  - Cross-reference to `docs/services/meeting-providers.md`.
- `frontend/views/AGENTS.md` — added an **auto-generation affordance pattern** section documenting the UI contract for auto-meeting-URL support affordances on the profile meeting-configs view (the teacher has no required action; the view surfaces `AutoGeneratedBadge` + `ViewBookingsLink` + `LinkedClassInstancesList` through `MeetingConfigList`'s `renderRowExtra` hook). Cross-reference to `docs/services/meeting-providers.md` for backend adapter/factory details.
