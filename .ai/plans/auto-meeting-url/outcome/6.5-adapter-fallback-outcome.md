# Task 6.5 — Per-User OAuth Fallback in Adapters

## Status
Complete

## Changes

### Files Created
- `backend/services/meeting/integrations/token-refresh.ts` — `refreshAccessToken()` shared utility that exchanges a stored refresh token for a new access token across all three providers (Zoom, Google Meet, Microsoft Teams). Handles provider-specific token endpoint URLs, request bodies, and response parsing. Returns `{ accessToken, refreshToken, expiresIn }` and throws `ProviderReauthRequiredError` on `invalid_grant`.

### Files Modified
- `backend/services/meeting/channels/zoom/ZoomMeetingAdapter.ts` — added per-user OAuth fallback in `generateMeeting`: org credentials first → per-user token via `MeetingProviderTokenRepository.getByUserAndProvider` + `refreshAccessToken` → `NoOrgCredentialsNoUserTokenError` if neither available. Token cache keyed by `actorUserId`.
- `backend/services/meeting/channels/google-meet/GoogleMeetAdapter.ts` — same hybrid auth resolution: org service-account creds first, per-user OAuth refresh-token fallback second, `NoOrgCredentialsNoUserTokenError` if neither.
- `backend/services/meeting/channels/microsoft-teams/MicrosoftTeamsAdapter.ts` — same hybrid auth resolution: org client-credentials first, per-user OAuth refresh-token fallback second, `NoOrgCredentialsNoUserTokenError` if neither.
- `backend/services/meeting/channels/zoom/test/ZoomMeetingAdapter.test.ts` — 3 new tests for per-user fallback (token used when org creds missing and `actorUserId` provided; `NoOrgCredentialsNoUserTokenError` when no token row and no org creds; `ProviderReauthRequiredError` when refresh token is `invalid_grant`).
- `backend/services/meeting/channels/google-meet/test/GoogleMeetAdapter.test.ts` — 3 new tests for per-user fallback.
- `backend/services/meeting/channels/microsoft-teams/test/MicrosoftTeamsAdapter.test.ts` — 3 new tests for per-user fallback.
