## What was built

Props `{ carryoverId: string, open: boolean, onClose: () => void }` exactly as tasked.

- Right-side MUI `Drawer` (`anchor` computed from `theme.direction` — flips to
  `left` in RTL), paper width `460` on `sm+` / full width on `xs`,
  `aria-label` bound to the teacher name (fallback `labels.title`).
- Data: `useQuery(carryoverBalanceQueryDocument, { variables: { id }, fetchPolicy:
  "cache-and-network", skip: !open })` — never fetched while closed, per the
  no-`useLazyQuery` convention.
- Header (`DrawerHeader`): teacher name as `titleLg` title + `PaidStatusChip` /
  `DisabledTeacherChip` chips (reused from tasks 4.5) + close `IconButton`
  (`commonLabels.ariaClose`).
- Body states: centered `CircularProgress` (`aria-label` =
  `commonLabels.loading`) while first fetch runs; `Alert severity="error"` with
  `labels.loadError` on failure; otherwise the summary grid.
- Summary grid (`BalanceSummary` + reusable `DetailField`, 2-col on `sm+`,
  1-col on `xs`, `labelUppercase` captions in `palette.onSurfaceVariant`):
  teacher (avatar + name, `column.teacher`), currency (`modal.form.currency`),
  students count (`column.studentsCount`), duration (`column.totalDuration`),
  from/to (`column.fromDate`/`column.toDate`), paid chip (`column.paid`),
  payment date (`column.paymentDate`), payable as `headlineMd` primary-colored
  value via `formatLockedAmount(payable, teacherCurrency, locale)`
  (`useAppLocale` locale), students list text (`column.studentsText`), and the
  note full-width (`modal.form.note`). Every nullable field falls back to
  `commonLabels.notSet`.
- Prototype `carryover-detail-drawer-desktop.png` inspected (the task's
  `carryover-detail-drawer.png` filename does not exist; the `-desktop` file
  is the matching asset). Header field layout, status chip, and oversized
  payable treatment mirror the prototype; all prototype strings/data treated as
  placeholders, none copied.
- i18n: zero hardcoded user-facing strings — two namespaces
  (`DashboardAccountingCarryover` + `Translation.Common`), matching the
  form-dialog sibling's two-namespace pattern.
- Footer `Unpay`/`Edit` buttons from the prototype intentionally omitted — the
  tasked prop surface carries no such callbacks; wiring actions belongs to the
  page/container owner.
