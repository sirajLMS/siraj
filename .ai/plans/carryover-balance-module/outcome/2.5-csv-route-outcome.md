# Task 2.5 Outcome — Carryover CSV export route

- **Date**: 2026-09-05
- **Status**: ✅ Complete

## What was implemented

**`app/api/carryover/export/route.ts`** — Next.js 16 Route Handler,
`GET /api/carryover/export`, modeled on the sibling payroll/session-audit
export pattern:

- **Auth**: `getServerUserContext()` → 401 when unauthenticated (locale parsed
  from `accept-language`, Arabic default); then
  `requirePermission(userId, AppPermission.ACCOUNTING_CARRYOVER_VIEW, tErrors)`
  → 403 on `ForbiddenError`.
- **Filter parsing** from the query string onto `CarryoverFilters`:
  `teacherId` (trimmed), `paidStatus` (`Paid`/`Unpaid`/`Both` via type-guard),
  `dateFrom`/`dateTo` (strict `YYYY-MM-DD` calendar check), `search`
  (≤ 200 chars), `includeDisabledTeachers` (`true`/`false`, absent → null so
  the service default applies). Malformed values → 400 `ValidationError`.
- **Report read**: `CarryoverBalanceService.getReport(userId, filters,
  { limit: EXPORT_ROW_LIMIT, offset: 0 }, tErrors)` with
  `EXPORT_ROW_LIMIT = 10_000`.
- **CSV serialization** inline in the route file (route files may not export
  non-HTTP-module helpers): one column per `CarryoverRow` field in
  declaration order (19 columns, `id` first), RFC 4180 quoting plus formula
  injection neutralization (`=`, `+`, `-`, `@`, tab, CR get a `'` prefix),
  CRLF line separators, trailing newline.
- **Headers**: `Content-Type: text/csv; charset=utf-8`,
  `Content-Disposition: attachment; filename="carryover-balances-<YYYY-MM-DD>.csv"`,
  `X-Export-Truncated: true|false` (true when `totalCount > 10_000`).
- `logger.info` on success (actor, filters, rowCount, truncated);
  unexpected errors → `logger.error` + 500 with localized message.

**`app/api/carryover/export/route.test.ts`** — 16 tests, barrel-mock style
(identical structure to `app/api/accounting/reports/export/route.test.ts`):
`@/backend/lib` (auth context, error classes, logger) and `@/backend/services`
(`CarryoverBalanceService.getReport`, `requirePermission`) are mocked via
`mock.module`; the inlined CSV serializer runs for real so the body
assertions exercise the production escaping. Covers: 401 (en + ar fallback
copy), 403 with the exact `ACCOUNTING_CARRYOVER_VIEW` permission, happy path
(all filters mapped + column contract + headers), default filter set on
absent/blank params, `X-Export-Truncated` true above 10 000 and false at
exactly 10 000, 400s (bad date, impossible calendar day, unknown
`paidStatus`, non-boolean `includeDisabledTeachers`, over-long search,
service-side `ValidationError`), 500 on report failure, and CSV formula
injection hardening (prefix chars incl. tab/CR, comma/quote quoting).

## Carry-forward

- The `readTrimmedParam` / `isCalendarDate` / `readValidatedParam` /
  `toCsvCell` helpers now exist in a third route (`payroll/export`,
  `accounting/reports/export`, `carryover/export`). jscpd did not flag a
  third copy, but a future export route should extract a shared CSV/query
  utility (e.g. into `backend/lib/` or a shared app helper) instead of a
  fourth copy.
- `X-Export-Truncated` consumes `report.totalCount` from
  `CarryoverBalanceService.getReport`; the UI task should read this header to
  show the truncation toast (spec E20).
- `includeDisabledTeachers` absent → `null` is passed through to
  `getReport`; the repository treats null as the default (exclude disabled).
  Keep the frontend filter wiring consistent with this three-state contract.
