### Cross-cutting design decisions

- **Idempotency (60 s replay window).** The plan's `AuditLogRepository.findRecentByActorAndHash`
  does not exist; the actual audit repo surface is `AuditRepository.queryAuditLogs`. The service
  implements the same semantics: inside the transaction it takes a key-scoped
  advisory lock (`acquireAdvisoryLock`, no-op on SQLite), then queries audit rows filtered by
  `actorUserId` + `action` + `createdAt >= now-60s` and matches `metadata.idempotencyKey` in memory
  (guards in `readMetadataKey`). Replay reconstruction rebuilds the original result from audit
  metadata (`teacherId`, `instanceIds`, `payable`, `currency`, …); a malformed metadata row falls
  through to normal processing (which the ALREADY_LINKED guard then rejects) instead of emitting a
  corrupt replay. Note: the plans' replay lookup keyed on the fictional `"CARRYOVER_CREATE_BULK"`
  action, which the written audit rows never carry — keyed on `CARRYOVER_CREATE` /
  `CARRYOVER_TO_EXPENSE` + metadata hash instead (the hash is the real discriminator).
- **Replay pre-check ordering**: advisory lock → replay lookup → row locks/guards, per the
  `backend/services/AGENTS.md` idempotent-transaction rule.
- **Locks**: `SchedulingRepository.getByIdsForUpdate` (sessions, bulk create),
  `CarryoverBalanceRepository.getByIdsForUpdate` (carryovers; also used single-id for update /
  unpay / delete since no single-id `FOR UPDATE` repo method exists).
- **Money math**: integer minor-unit BigInt (`toAmountMinorUnits` / `formatAmountMinorUnits` /
  `convertAmountWithRate` accepting ≤6-decimal rates, half-up) — no float drift (payroll pattern).
  Aggregate totals in `getReport` sum minor units.
- **FX**: `BillingRepository.getLatestExchangeRateForDisplay` (non-throwing, tx-aware); missing or
  stale rate → `DomainError("CARRYOVER_FX_RATE_MISSING")`. The throwing `getLatestExchangeRate`
  variant wraps misses in generic localized `Error`s and cannot be mapped to the domain code.
- **Events**: per-session `PAYROLL_STATUS_TRANSITION` rows via `ClassStatusEventsRepository.createMany`
  (session updates sequential over the shared tx connection via a reduce-chain helper —
  `oxlint no-await-in-loop` clean), then one batched event insert. Emitted on create-link,
  settle-to-PAID, unpay-revert, and delete-restore (delete restores each session's
  `originalStatus` snapshot from the items table).
- **Audit**: one `audit_logs` row per affected carryover via `AuditService.createManyAuditLogs`,
  `entityType "CARRYOVER_BALANCE"`, actions `CARRYOVER_CREATE` / `CARRYOVER_TO_EXPENSE` /
  `CARRYOVER_UNPAID` / `CARRYOVER_DELETE`; the CRUD update additionally writes an `"UPDATE"` row
  with full previous/new state snapshots.
- **Errors**: `NotFoundError("CARRYOVER"/"TEACHER"/"CLASS_INSTANCE", …)` per plan-review R2;
  `ValidationError` for empty selections / invalid period / bad payable; `DomainError` with the
  spec codes (`CARRYOVER_SESSION_NOT_AUDITED`, `CARRYOVER_SESSION_ALREADY_LINKED`,
  `CARRYOVER_FX_RATE_MISSING`, `PAYMENT_DATE_REQUIRED`, `EXPENSE_DATE_INVALID`,
  `CARRYOVER_ALREADY_PAID`, `CARRYOVER_NOT_PAID`, `CARRYOVER_PAID_CANNOT_DELETE`,
  `CARRYOVER_TEACHER_IMMUTABLE`, `CARRYOVER_TO_EXPENSE_FAILED`).
  `Object.hasOwn(input, "teacherId")` drives the immutability guard (E10).
- **Structured logging** (`logger.info`) on every bulk-create / to-expense / unpay / create /
  update / delete (NFR-11); `logger.warn` on students-text truncation (E11) and on the expense
  stub path.
- **i18n**: all user-facing messages from `tErrors.carryover.*` (+ existing `scheduling.*`,
  `teacher.*`, `unknownName`, `internalServerError`).

## Expense-ledger stub decision

Plan 6 (`expense-ledger`) has not landed — no `expenses` table, no `ExpenseService`.
The stub lives **inline in the service file** as the module-private adapter
(`ExpenseCreateCommand` + `createExpenseRecord` / `softDeleteExpenseRecord`):

- `createExpenseRecord(command) → { id: string }` — mints the expense reference id
  (`randomUUID`), logs a `logger.warn` that no ledger row was persisted, and returns the
  reference; the full payload (`amount`, `currency`, `paymentDate`, `expenseDate`,
  `sourceEntity = "carryover_balances"`, `sourceEntityId`) is persisted in the conversion
  audit metadata, so settlements remain fully auditable. This is coherent with the schema's
  deliberate non-FK `expenseId` soft link (see outcome 0.2) and with E17's tolerance for
  missing expense rows on unpay.
- `softDeleteExpenseRecord(expenseId, actorUserId)` — warns + no-op (nothing can exist yet).
- Call-site is wrapped: any throw from the adapter becomes
  `DomainError("CARRYOVER_TO_EXPENSE_FAILED")`, rolling back the whole batch (AC-3.6).
- Swapping in the real ledger later changes only these two functions; the public service
  surface, result types, and audit trail are unchanged.
- `EXPENSE_TYPE_SALARIES = "Salaries"` is a local constant matching the future ledger's
  `ExpenseType.SALARIES` (the enum doesn't exist yet).
