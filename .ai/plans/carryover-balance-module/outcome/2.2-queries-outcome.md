## What was implemented

### `backend/graphql/query/teachers/carryover.query.ts` (NEW)

Two root query fields, both gated by `authScopes: { permission: AppPermission.ACCOUNTING_CARRYOVER_VIEW }`,
`actorUserId` from `requireAuth(ctx)`, and errors localized via `ctx.t().errorsTranslations`:

- **`carryoverBalances(filter, limit, offset)`** → `CarryoverPagePothosObject`. Maps the
  `CarryoverFilterPothosInput` onto the canonical `CarryoverFilters` (absent field → `null`),
  then calls `CarryoverBalanceService.getReport(actorUserId, filters, {limit, offset}, tErrors)`.
  `limit` carries the payroll/session-audit constraint directive (`min: 1, max: 200`, default 50);
  `offset` defaults to 0.
- **`carryoverBalance(id)`** → `CarryoverBalancePothosObject`, drill-down by ID; calls
  `CarryoverBalanceService.getById(actorUserId, id, tErrors)`.

**`paidStatus` narrowing** (per the 2.1 carry-forward): the input type surfaces `paidStatus` as a
plain String, so a module-level `PAID_STATUS_VALUES` set plus an `isCarryoverPaidStatus` type
predicate narrow the wire string to `CarryoverPaidStatusFilter` before the service call. Absent or
blank means "no filter" (`null`); an unknown non-blank value rejects with
`ValidationError(tErrors.invalidInput)` — identical semantics to the CSV export route's parser, so
both entry points enforce the same closed set (`"Paid" | "Unpaid" | "Both"`).

### `backend/graphql/query/teachers/index.ts`

Added `import "./carryover.query";` (side-effect registration, per the query-layer barrel rule).

## Location decision (documented per task instruction)

Placed under `query/teachers/`, **not** `query/billing/`:

- Trackable-tasks 2.2 names `backend/graphql/query/teachers/carryover.query.ts` explicitly, and
  task 2.1's outcome states the R2 `billing/` move was superseded by trackable-tasks; the Pothos
  types therefore live in `pothos/teachers/`.
- The dominant colocation precedent is payroll: `pothos/teachers/payroll.pothos.ts` pairs with
  `query/teachers/payroll.query.ts`, and carryover is its direct sibling in service location
  (`services/teachers/carryover-balance.service.ts`) and domain (teacher financials). Matching the
  Pothos barrel's domain folder keeps the feature in one column of every GraphQL directory.
- The one counter-example (`query/billing/session-audit.query.ts` consuming `pothos/accounting/`)
  is itself inconsistent (pothos and query in different folders), so it is not a pattern to copy.
