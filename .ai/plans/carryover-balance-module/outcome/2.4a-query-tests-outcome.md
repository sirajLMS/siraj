## Placement decision (task asked to verify)

GraphQL query tests for this codebase do **not** live in `frontend/common/graphql/test/` (that
host is for the Apollo `testClient` integration suite). Domain query-unit tests live beside the
resolver they test: `backend/graphql/query/teachers/payroll.query.test.ts` and
`backend/graphql/query/billing/session-audit.query.test.ts` are the sibling precedents. The new
file therefore sits at `backend/graphql/query/teachers/carryover.query.test.ts`, matching the take
of trackable-tasks 2.4, and uses the same in-process harness: mock the
`CarryoverBalanceService` export of the `@/backend/services` barrel, keep the real Pothos builder
(so the scope-auth plugin runs against the real `authScopes`), register the shared DateTime/JSON
scalars behind the same `siraj.payrollTest.scalarsRegistered` global flag, and execute with the
`graphql()` function directly against a hand-built `BaseContext` (no server, no `testClient`).

## Coverage (13 tests, all green)

### `carryoverBalances(filter, limit, offset)`

- Page shape: rows with all 19 exposed fields, `totalCount`, and `aggregates`
  (`totalPayable`/`totalPaid`/`dominantCurrency`/`rowCountByPaid`); DateTime scalar serialization
  asserted via ISO instant; service called with `USER_ID`, default `{limit: 50, offset: 0}`, and
  the context-bound error labels.
- `limit`/`offset` pass-through, and `null` → default pagination.
- Filter mapping: full filter (teacherId, paidStatus `"Paid"`, dateFrom/dateTo,
  includeDisabledTeachers, search) forwarded verbatim; absent filter → all-null `CarryoverFilters`
  (matching the resolver's absent-field → `null` semantic).
- `paidStatus` narrowing: blank `""` and whitespace-only values become `null` (no filter); an
  unknown value (`"Partially"`) is rejected with `extensions.code: "VALIDATION"` and message
  `errors.invalidInput`, and the service is never called.
- Permission gating: missing `ACCOUNTING_CARRYOVER_VIEW` → `FORBIDDEN` +
  `errors.insufficientPermissions`, no service call; logged-out context → same `FORBIDDEN`;
  permissioned context with no `user.id` → `UNAUTHORIZED`-style `UNAUTHENTICATED` from
  `requireAuth`; super-admin without the explicit permission is allowed through.

### `carryoverBalance(id)`

- Returns the row resolved by id; `getById(actorUserId, id, tErrors)` call args asserted.
- Missing view permission → `FORBIDDEN`, no service call.
