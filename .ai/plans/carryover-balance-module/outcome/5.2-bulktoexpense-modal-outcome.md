## What was built

Props per task: `{ open, carryoverIds: readonly string[], rows: readonly BulkToExpenseRow[],
onClose, onDone? }` where `BulkToExpenseRow = Pick<CarryoverBalancesQuery_carryoverBalances_rows,
"id" | "payable" | "teacherCurrency">` (grid rows satisfy it).

- **Fields** — Payment Date (`AppDatePicker`), Expense Date (`AppDatePicker` with
  `views={["year", "month"]}`, `openTo="month"`, `format="yyyy-MM"` — no AppMonthPicker exists
  in the codebase; the shared picker wraps MUI X and passes these through), optional multiline
  note (`CARRYOVER_NOTE_MAX_LENGTH` reused from `useCarryoverFormViewModel`). Both date fields
  `required`, `fullWidth`, disabled while submitting.
- **Summary (dominant-currency rule)** — an `Alert severity="info"` above the fields rendering
  `labels.modal.bulkToExpense.summary(count, amount, currency)`. Count = `carryoverIds.length`;
  currency = most-selected-rows currency, ties to earliest-seen (mirrors backend
  `pickDominantCurrency`); amount = sum of all selected `payable` values (v1 single-dominant-
  currency assumption, same convention as the page aggregates) formatted via
  `Intl.NumberFormat(locale, 2 fraction digits)` with `useAppLocale()`. Summary hidden when the
  selection is empty.
- **Submit gating** — submit disabled unless both dates are valid (`Date` non-null and not
  NaN — picker keystrokes can hand over invalid Dates) and `carryoverIds.length > 0`; after an
  `CARRYOVER_ALREADY_PAID` rejection the submit stays disabled (selection is fixed per open, so
  a same-session retry can never succeed).
- **Idempotency** — `clientRequestIdRef` regenerated via `crypto.randomUUID()` on every open
  (open effect); `submittedTokenRef` guard makes a double-click produce exactly one mutation;
  the guard re-arms on failure so the reused token keeps retries server-idempotent. Session
  fields + rejection banner reset via the render-phase prevOpen adjustment (payroll sibling
  pattern) — no setState-in-effect.
- **Submit** — `useMutation(bulkCarryoverToExpenseMutationDocument, { errorPolicy: "none" })`
  with `BulkToExpenseInput`: `carryoverIds`, `paymentDate` (`formatDateInput` → YYYY-MM-DD),
  `expenseDate` (date-fns `format(date, "yyyy-MM")`), trimmed note or null, `clientRequestId`.
- **CARRYOVER_ALREADY_PAID** — non-dismissible `<Alert severity="error">{labels.error.alreadyPaid}</Alert>`
  (no `onClose` prop, dialog stays open); all other rejections toast the server-localized
  message via `getGraphQLErrorMessage` with `commonLabels.operationFailed` fallback.
- **Success** — `cache.evict({ fieldName: "carryoverBalances" })` + `cache.gc()` (aggregates
  live on the list query), toast `labels.success.bulkedToExpense(count)`, `onDone?.()`,
  `onClose()`.
- **UX extras** — picking a payment date pre-seeds the (still empty) expense month with that
  date's month, matching the server default `expenseDate ?? paymentDate.slice(0, 7)`; close
  IconButton + Escape/backdrop disabled while submitting; `aria-busy` on submit.
- **i18n** — only `dashboard.accounting.carryover` keys (`modal.bulkToExpense.*`,
  `error.alreadyPaid`, `success.bulkedToExpense`) + `Translation.Common` (`ariaClose`,
  `operationFailed`). Zero hardcoded strings; theme-callback sx only; flex/grid layout is
  direction-agnostic (RTL-safe).
