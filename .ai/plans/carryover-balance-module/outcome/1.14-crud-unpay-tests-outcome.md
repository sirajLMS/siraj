### Coverage (task bullets → tests)

- **create happy path** — `isDisabledTeacher: true` snapshot persisted to the insert
  payload (and echoed on the returned row), `CARRYOVER_CREATE` replay lookup observed,
  advisory lock `carryover-create:<hash>` acquired, audit row carries
  `{ teacherId, payable, currency, instanceIds: [] }` metadata, `payable "250.50"` passthrough.
- **update happy path** — patch applied to in-memory row (`payable "500"` → `"500.00"`
  normalization), row lock read observed, `"UPDATE"` audit row with previous/new state
  snapshots.
- **update rejects teacherId** — `DomainError` `CARRYOVER_TEACHER_IMMUTABLE` thrown
  *before* the transaction body (asserted: zero lock reads, zero repo writes).
- **delete happy path** — two linked sessions with item snapshots (`CALCULATED` /
  `PARTIALLY` originals) are reverted per-session via `updatePayrollCalculation`,
  sessions unlinked in one call, carryover row hard-deleted, two
  `PAYROLL_STATUS_TRANSITION` events emitted, `CARRYOVER_DELETE` audit row written.
- **delete on paid** — `CARRYOVER_PAID_CANNOT_DELETE`, no revert/unlink/delete/audit.
- **bulkDelete atomic** — batch `[unpaid, paid]` rejects with
  `CARRYOVER_PAID_CANNOT_DELETE`; the store retains both rows and zero writes occurred.
- **unpay happy path** — carryover patched to `{ isPaid: false, paid: "0",
  paymentDate/expenseId/paidAt/paidByUserId: null }`, linked sessions moved
  `PAID → WAITING_PAID` with event, `CARRYOVER_UNPAID` audit metadata carries the
  cleared `expenseId` + operator note, and the expense-adapter stub's
  soft-delete no-op logs its `logger.warn` (asserted via `spyOn`).
- **unpay when the expense is already gone** — carryover still linked to an id the
  ledger no longer holds: the stub tolerates it, the revert completes, and the audit
  metadata records `{ expenseId, reason: null }`.

## Carry-forward knowledge

- The service's `createCarryoverBalance` advisory-lock key prefix is
  `carryover-create:` (not the idempotency scope `carryover-crud-create` used by
  `deriveCrudIdempotencyKey`) — my first assertion guessed wrong; the tests now
  pin the actual value.
- `errorsEn` (from `@/shared/locale/en/errors`) is directly assignable to
  `ErrorsLabels` and sidesteps the test-loader stall from
  `getServerTranslations` (see `meeting-integrations.service.test.ts` precedent);
  use it instead of hand-stubbing error labels.
- For "apply only non-undefined patch keys" in repo fakes, prefer a
  `... as const satisfies readonly (keyof PatchType)[]` key list over
  `Object.keys(...) as ...` — it satisfies both oxlint `no-unsafe-type-assertion`
  and sonarjs `different-types-comparison`.
- Bun: asserting logger stub warnings works via
  `spyOn(logger, "warn").mockImplementation(() => undefined)` with
  `mockRestore()` in `finally`.
- Bun's `mock.module` on the `@/backend/services/system/audit.service` leaf is
  required even when `@/backend/db/repo` (which the real audit service imports)
  is already mocked — the mock must replace the leaf module itself.
