# Task 4.3 Outcome — Zustand carryover filter store

- **Date**: 2026-09-05
- **Status**: ✅ Complete

## Deliverable

`frontend/common/stores/carryoverFilterStore.ts` (new, 120 lines) — flat
non-persisted Zustand store following the `payrollReportsFilterStore` /
`sessionAuditFilterStore` precedents:

- **State**: `teacherId` (`string | null`), `paidStatus`
  (`"Paid" | "Unpaid" | "Both"`, default `"Both"` per AC-5.2/5.6 reset
  semantics), `dateFrom` / `dateTo` (ISO `YYYY-MM-DD`, null = unbounded),
  `includeDisabledTeachers` (boolean, default off per AC-5.6),
  `search` (raw text; consumers debounce), `page` (0-based), `pageSize`
  (default 50 = `carryoverBalances` resolver default, exported as
  `CARRYOVER_DEFAULT_PAGE_SIZE`), `selectedIds` (`readonly string[]`).
- **Actions**: `setTeacherId`, `setPaidStatus`, `setDateFrom`, `setDateTo`,
  `setIncludeDisabledTeachers`, `setSearch`, `setPage`, `setPageSize`,
  `toggleSelected(id)`, `clearSelection()`, `clearFilters()`, `reset()`.
- **Semantics** (mirroring precedent): every filter setter resets `page` to 0;
  `setPage` clamps to a non-negative integer; `setPageSize` clamps to ≥1 and
  resets the page; `clearFilters()` restores default filters + page 0 and
  **clears the selection** (selected rows may leave the filtered set, so stale
  bulk-action ids must not survive) while keeping the chosen `pageSize`;
  `reset()` restores the pristine state including default `pageSize`.
- Also exports `CARRYOVER_PAGE_SIZE_OPTIONS` (`[25, 50, 100]`) for the pager.

## Design decisions

- **`paidStatus` type**: local `export type CarryoverPaidStatusFilter =
  "Paid" | "Unpaid" | "Both"`. The GraphQL schema declares
  `CarryoverFilter.paidStatus` as a plain `String` (task 2.1), so codegen will
  never emit an enum for it; the backend owns the same union as
  `CarryoverPaidStatusFilter` in `backend/types/` (used by
  `carryover.query.ts`). This is not a codegen redefinition — no
  codegen-supplied type exists for the closed set.
- **Selection shape**: `readonly string[]` (array), matching the repo's only
  existing selection precedent (`teacherDuesStore.ts`); no `Set`/`Record`
  precedent exists in `frontend/common/stores/`.
- **No URL sync / hydration**: unlike `sessionAuditFilterStore` (which owns
  deep-link query-string contracts), the plan (§5.8, trackable-tasks 4.3)
  specifies a plain filter+selection store, so no `hydrateFromUrl` /
  `history.replaceState` machinery was added.
- **No Storybook mock store**: the `mock*Store` convention applies only to
  `userStore`; filter-store precedents (`sessionAuditFilterStore`,
  `payrollReportsFilterStore`) ship no mock — stories/tests seed the real
  store via actions.
