## Columns / Indexes Summary

### `carryover_balances`
- Columns: `id` (uuid PK via `uuidColumn`), `teacherId` (NOT NULL, FK→teachers, restrict),
  `studentsCount` (int, nullable), `studentsText` (varchar 500), `totalDuration` (text),
  `payable` (text, NOT NULL), `teacherCurrency` (currencyCodeEnum), `paid` (text, NOT NULL,
  default "0"), `fromDate`, `toDate`, `paymentDate` (text, nullable), `isDisabledTeacher`
  (bool, NOT NULL, default false), `isPaid` (bool, NOT NULL, default false),
  `expenseId` (uuid, nullable — **no FK reference**, expenses table owned by Plan 6),
  `note` (text), `createdByUserId` (NOT NULL, FK→users, set null), `paidByUserId`
  (nullable, FK→users, set null), `paidAt`, `createdAt`, `updatedAt` (timestamps,
  NOT NULL + defaultNow except `paidAt`).
- Indexes (7 + 1 unique): `teacher_id`, `is_paid`, `payment_date`, `(from_date, to_date)`,
  `is_disabled_teacher`, `expense_id`, `created_by_user_id`, plus
  `carryover_balances_expense_id_unique_idx` implemented as **`uniqueIndex`** on
  `expenseId`. The plan's explanatory comment states uniqueness intent ("a carryover can
  only be linked to one expense"); a plain `index()` with a `_unique_idx` name would not
  enforce anything, so `uniqueIndex` was used. No `WHERE` needed — both PG and SQLite
  treat distinct NULLs as non-conflicting in unique indexes.

### `carryover_balance_items`
- Columns: `id` (uuid PK), `carryoverId` (NOT NULL, FK→carryover_balances, cascade),
  `classInstanceId` (NOT NULL, FK→class_instances, cascade), `originalAmount` (text,
  NOT NULL), `originalCurrency` (currencyCodeEnum), `originalStatus` (varchar 32,
  NOT NULL), `convertedAmount` (text, nullable), `convertedCurrency` (nullable),
  `createdAt` (NOT NULL, defaultNow).
- Indexes (2): `carryover_id`, `class_instance_id`.

## Adaptations from plan code (required by actual helpers)

- **Plan pseudo-imports dropped**: the plan block imports raw PG builders
  (`boolean`, `date`, `index`, `numeric`, `pgTable`, …); the codebase convention is
  the dialect-aware helpers from `@/backend/db/schema/__shared__/dialectAwareBuilder`
  (matches `teacher-dues.ts`).
- **`uuidColumn("id")` used bare** — the helper already applies `.defaultRandom().primaryKey()`;
  chaining them again (as printed in the plan) is not supported by the helper's return type.
- **`timestampColumn(name)` takes no options** — the helper already sets
  `{ withTimezone: true, precision: 3 }` on PG and `integer timestamp_ms` on SQLite.
  Plan's `{ withTimezone: true, precision: 3 }` arguments were dropped.
- **No CHECK constraints** — §2.3/§2.4 specify none; R2 review confirmed "No check()
  violations". `checkConstraint` from `dialectAwareBuilder.ts` is the helper if needed later.
- **Kept as written (even though it looks odd)**: `createdByUserId` is NOT NULL with
  `onDelete: "set null"` — copied verbatim from §2.3 per instructions to trust the plan
  text; PG would only fail if a creator user row is actually deleted.
- **Kept as written**: monetary/date columns (`payable`, `paid`, `totalDuration`,
  `originalAmount`, `convertedAmount`, `fromDate`, `toDate`, `paymentDate`) are
  `textColumn(...)` WITHOUT precision/scale (per R2 fix #2; exact-precision money as text
  matches the SQLite branch where numeric degrades to text).
