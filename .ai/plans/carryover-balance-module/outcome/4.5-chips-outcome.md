# Outcome — Task 4.5: Carryover chips (PaidStatusChip + DisabledTeacherChip)

## What was done

Created the two row-status chips for the Carryover Balance list grid
(§5.3, trackable-tasks §4.5). Both are `"use client"` MUI v9 components in the
new `frontend/common/views/dashboard/accounting/carryover/` folder, consuming
the `dashboard.accounting.carryover` namespace via
`useAppTranslation(DashboardAccountingCarryover)` (task 3.3 keys `chip.paid` /
`chip.unpaid` / `chip.disabledTeacher`). Per `frontend/common/views/AGENTS.md`
translation ownership is normally the ViewModel's, but the task spec explicitly
mandates in-component `useAppTranslation` for these chips; they are
self-contained leaf components used inside grid cell renderers, where prop
drilling labels through `renderCell` would be noisier.

Colors use only theme palette tokens via the theme-callback `sx` pattern
(no hex, no string palette access):

- `PaidStatusChip({ paid })` — paid → `theme.palette.status.activeContainer`
  (green) + `theme.palette.status.onActiveContainer`; unpaid → MUI default chip
  (empty conditional branch, matching "green=Paid, default=Unpaid").
- `DisabledTeacherChip()` — grey `theme.palette.surfaceContainerHigh` +
  `theme.palette.onSurfaceVariant` (the same neutral pair the shared
  `StatusBadge` fallback uses), with `BlockOutlinedIcon` recolored to the
  on-surface-variant tone via the `& .MuiChip-icon` slot selector.

Accessibility (task 7.2): both chips carry `aria-label` with the full
localized label text so grid cells announce "Paid" / "Unpaid" / "Disabled"
to screen readers; both render `size="small"` for grid density.

No barrel `index.ts` was created for the folder (container task owns folder
assembly).
