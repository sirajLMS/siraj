# Outcome — Task 3.3: i18n namespace `dashboard.accounting.carryover`

## What was done

Created the `dashboard.accounting.carryover` locale namespace per implementation.md §7.1
(path corrected by plan-review R1: `types/dashboard/accounting/carryover.ts`, not
`namespaces/`). Both locale surfaces (eager `messages.ts` server tree + lazy
`*.namespace.ts` client loaders) are wired, per `shared/locale/AGENTS.md` "keep both
surfaces in sync".

Key groups implemented (all §7.1 groups + needed extras):

- `title`, `empty`, `loadError`
- `column.*` — teacher, studentsCount, studentsText, totalDuration ("Duration (h)"),
  payable, paid, fromDate ("From"), toDate ("To"), paymentDate
- `chip.*` — paid / unpaid / disabledTeacher
- `action.*` — addNew, edit, delete, bulkToExpense, bulkDelete, unpay, viewSessions,
  exportCsv (CSV toolbar action added beyond the table per §5.3 Export CSV button)
- `filters.*` — teacher(+placeholder), paidStatus + paid/unpaid/both, fromDate,
  toDate, includeDisabledTeachers, searchPlaceholder, clear
- `modal.bulkToExpense.*` — title, paymentDate, expenseDate, note, submit, cancel,
  and `summary(count, amount, currency)` typed interpolation with plural-aware EN/AR
- `modal.form.*` — titleAdd/titleEdit, teacher(+placeholder/lockedHint), fromDate,
  toDate, payable, currency, studentsCount, studentsText, note(+placeholder),
  submit, cancel
- `validation.*` — teacherRequired, dateRangeInvalid (fromDate <= toDate),
  payableNegative (>= 0), currencyRequired, noteTooLong (max 2000) — mirrors AC-4.1
- `error.*` — sessionNotAudited, sessionAlreadyLinked, alreadyPaid, cannotDeletePaid,
  fxRateMissing (strings verbatim from §7.1 table; service-layer siblings already
  live in the `errors` namespace via task 1.7)
- `success.*` — created, updated, deleted, unpaid (verbatim), plus pluralization
  functions `bulkCreated(count)`, `bulkDeleted(count)`, `bulkedToExpense(count)`
- `aggregate.*` — totalPayable, totalPaid, `paidCount(count)`, `unpaidCount(count)`
  (footer paid-vs-unpaid counts, §5.3)

EN and AR implementations are complete; AR pluralization follows the CLDR-shaped
branching pattern from `shared/AGENTS.md` (0/1/2/3–10/11+). Function-returning keys
use `if`/`return` (not nested ternaries) because `sonarjs/no-nested-conditional`
rejects nested ternaries.
