     their confirm dialogs — keeps the demo dataset stable across reruns; any
     cleanup failure is logged (testLogger), never masks the flow result.

## Plan-4 entry-point design decision (required by task)

The task's ideal journey starts on `/accounting/reports` with the audit-grid
"Carryover Balance" bulk action over 5 audited sessions × 2 teachers. **The
audit grid is not implemented** (Plan 4 pending: the session-audit E2E sibling
asserts only the report grid, and the bulk-carryover grid button does not
exist). Of the two sanctioned fallbacks — TODO-marked steps vs
service-seeded state — this spec uses **a third, stronger option**:

- **No TODOs**: no existing E2E spec carries TODO markers (`grep TODO
  test/ui/e2e` → zero hits); project convention treats specs as executable
  truth, and a TODO step would either be dead code or a guaranteed failure.
- **No service-level seeding**: `tests.instructions.md` bar E2E/GraphQL-layer
  tests from importing backend services; every existing E2E mutates state only
  through HTTP/GraphQL demo login and the UI itself.
- **Instead**: creation happens through the page's own **Add New form** (two
  records, two teachers) — a real operator path exercising AC-4.1 end-to-end,
  producing exactly the 2-carryover board state the downstream steps need
  ("navigate → see 2 rows → select both → bulk to expense"). The
  bulk-create-from-audited-sessions resolver path is already covered by the
  GraphQL mutation tests (2.4b), so no coverage is lost; only the audit-grid
  *click* entry point is uncovered, and that surface does not exist yet to click.

When the audit-grid bulk action ships, swapping the two form-driven creates
for the grid-driven flow is a one-helper change (`createBothCarryovers`).

Related known gap (documented, not worked around): the expense ledger
(Plan 6) has not landed — the to-expense service runs against the inline stub,
so "expense rows visible on `/accounting/expenses`" is **not asserted**; the
spec asserts the paid/payment-date effects on the carryover surface and CSV
instead. Unpay assertions exercise the stub's no-op revert path.
