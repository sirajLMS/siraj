# Outcome — Task 4.4: Carryover filter bar (`CarryoverFilterBar.tsx`)

## What was done

Created `frontend/common/views/dashboard/accounting/carryover/CarryoverFilterBar.tsx`
(props-free, ~290 lines) — a `"use client"` MUI v9 filter bar consuming
`useCarryoverFilterStore` directly (per the task's store-bridge allowance) and
translating in-component via `useAppTranslation(DashboardAccountingCarryover)`
(the in-component-translation precedent set by task 4.5's chips), covering all
mandated controls:

- **Search input** — `TextField` (small, `SearchOutlined` start adornment,
  `maxLength 200` per the payroll sibling constraint, `autoComplete="off"`,
  `aria-label` = `filters.searchPlaceholder`). Local text state pushes into the
  store only after a **300 ms debounce** (`useDebouncedSearchInput`); external
  store resets (Clear / ViewModel reset) re-sync the input through React's
  render-time state-adjustment pattern — the effect-based version was rejected
  by oxlint `react/set-state-in-effect` + `react/no-deriving-state-in-effects`
  and rewritten without effects.
- **Teacher autocomplete** — reuses the shared
  `TeacherAutocomplete` from `@/frontend/common/components/ui/input/userSelect`
  (backend `teachersQueryDocument`, permission-scoped). `useTeacherFilterSelection`
  bridges the store's id-only `teacherId` with the `PersonOption` shape; an
  external clear yields a null option at render time (no sync effect).
- **Paid-status radio** — `PaidStatus` RadioGroup (row) with `Paid` / `Unpaid` /
  `Both`, labels from a `Record<CarryoverPaidStatusFilter, string>` typed lookup
  (no switch/enum comparison), guarded change handler (`isPaidStatusFilter`),
  `aria-labelledby` bound to the `FormLabel`.
- **Date-range picker** — reuses `AppDateRangePicker` for from/to; `""` maps to
  `null` bounds exactly like the payroll sibling.
- **Disabled-teachers toggle** — `Switch` bound to `includeDisabledTeachers`
  (store default off), label-associated via `FormControlLabel`.
- **Clear button** — text `Button` with `ClearOutlined`, calls
  `clearFilters()` (which also drops bulk selection per store semantics), and is
  `disabled` while no filter deviates from the defaults.

Layout mirrors the prototype filter card (`carryover-list-default-desktop.png`;
**note**: the task-referenced `carryover-balance-dashboard.png` does not exist —
the list-default screenshot shows the same filter panel): a `Paper
variant="outlined"` panel with a top row (search / teacher / status) and a
bottom row (date range, then toggle + Clear pushed to the trailing edge via
`marginInlineStart: "auto"` for RTL safety). All colors/spacing come from the
theme (no hardcoded values); responsive stacking via `xs/md` breakpoints inside
`sx`.
