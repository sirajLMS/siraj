## Container contract

- `CarryoverViewProps = CarryoverViewModel & CarryoverDialogCallbacks & { actionsMenuLabel: string }` exported from the container; both tier views consume it (payroll `PayrollReportsViewProps` convention).
- Overlay state is a single discriminated union (`form` / `bulk-to-expense` / `delete` / `unpay` / `drawer`), so exactly one overlay is open at a time and row snapshots survive until close.
- Bulk dialogs resolve selected rows from the **current page** (`rows.filter(id ∈ selectedIds)`); selection is page-local by store design.
- `onDone` after every successful write (form excluded — its own eviction refetches) → `clearSelection()`, preventing stale ids in the next bulk payload.
- Row `onOpenDelete` ⇒ single → `DeleteCarryoverDialog`; toolbar Bulk Delete (`rows.length > 1`) ⇒ `BulkDeleteCarryoverDialog`.
- `onOpenDrawer` guards against a null row id.
- `actionsMenuLabel` comes from `DashboardAccountingPayments.columns.actions` in the container (tier views stay hook-free per ViewModel rules); the same payments-namespace precedent as the grid.
