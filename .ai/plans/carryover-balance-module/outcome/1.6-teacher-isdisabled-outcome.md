## What was implemented

`TeacherRepository.isDisabled(teacherId, tx?)` — the account-status snapshot helper
consumed by carryover creation (`isDisabledTeacher` column, E13/E14) — added to
`backend/db/repo/teachers/teacher.repository.ts`:

- Read-only method; non-transactional path uses `queryDb(tx)` per the Neon HTTP
  bare-read rule (repo AGENTS.md).
- `innerJoin(users, eq(teachers.userId, users.id))` + `eq(teachers.id, teacherId)` +
  `.limit(1)` — mirrors the existing `findActiveById` join pattern in the same file.
- Returns `parseAccountStatus(row?.status) === AccountStatus.DEACTIVATED`.
  `parseAccountStatus` normalizes the raw status column (typed `string` on the
  select row) to the `AccountStatus` enum, which satisfies the oxlint
  `no-unsafe-enum-comparison` rule; a missing teacher row parses to the default
  fallback (`ACTIVATED`), so the method returns `false` for unknown ids —
  documented in the JSDoc ("returns `false` when the teacher does not exist").
- No `deletedAt` filter: the spec (E13/E14, specs.md §data-model row
  `isDisabledTeacher`) defines the snapshot as the raw `users.status` value,
  independent of soft-delete bookkeeping.

## Carry-forward knowledge

- Consumers (the carryover service `bulkCreate`/manual `create` paths per
  implementation.md §3.2) should call
  `TeacherRepository.isDisabled(teacherId, tx)` **inside the write transaction**
  and persist the returned boolean to `carryover_balances.is_disabled_teacher`.
  It is a creation-time snapshot — there is deliberately no refresh path (E14:
  post-creation deactivation must NOT retroactively flip the flag; a future
  "refresh snapshot" action is explicitly out of scope).
- `isDisabled` returns `false` for a non-existent teacher id; callers that must
  distinguish "missing teacher" (their own NotFoundError path) stay responsible
  for the existence check (`findById`/`findActiveById`) as before.
- A deactivated-but-NOT-soft-deleted user returns `true`; a soft-deleted user
  returns whatever its `status` still is (no deletedAt filter — matches spec).
