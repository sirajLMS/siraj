## Deliverable

`frontend/common/views/dashboard/accounting/carryover/useCarryoverViewModel.ts` (new,
~350 LoC) — `useCarryoverViewModel()` molding the session-audit / payroll VM
composable pattern (sub-hooks assembled top-down, module-scope helpers):

- **Filter store composition** — `useCarryoverFilterSlice()` pulls every
  `useCarryoverFilterStore` field and action (incl. `selectedIds`,
  `toggleSelected`, `clearSelection`) into a `CarryoverFilterSlice`; the
  ViewModel spreads it so tier views consume one flat object.
- **Debounced search** — local `useDebouncedSearch(search)` (300 ms), identical
  to the sibling convention: the store holds raw text, the debounced value
  feeds the query and export, `hasActiveFilters` counts the raw typed value so
  "Clear filters" appears instantly.
- **GraphQL** — `useQuery(carryoverBalancesQueryDocument, { variables, fetchPolicy: "cache-and-network", skip: !canViewCarryover })`
  (never `useLazyQuery`). Variables: `{ filter, limit: pageSize, offset: page * pageSize }`;
  `buildCarryoverFilter()` returns `null` when no filter is active
  (`paidStatus: "Both"`, empty dates/search, disabled toggle off) and maps
  `"Both"` → `null` in the filter object (the resolver treats null = both).
- **Aggregates** — `toCarryoverAggregates()` normalizes
  `CarryoverBalancesQuery_carryoverBalances_aggregates`: nullable
  `totalPayable`/`totalPaid` pass through; `rowCountByPaid` (JSON scalar typed
  `unknown`) is narrowed with an `isRowCountByPaid` type guard to
  `{ paid: number; unpaid: number }`.
- **Pagination** — `page`/`pageSize` state with `onPageChange` /
  `onPageSizeChange` callbacks and `pageSizeOptions =
  CARRYOVER_PAGE_SIZE_OPTIONS` (from the store, for the list pager).
- **CSV export (E20)** — exported `buildCarryoverExportCsvUrl()` serializes
  onto `/api/carryover/export` with the route's exact param names
  (`teacherId`, `paidStatus`, `dateFrom`, `dateTo`, `search`,
  `includeDisabledTeachers`); `paidStatus` is omitted when `"Both"`
  (absent = both on the server) and `includeDisabledTeachers` is always sent so
  the export matches the on-screen grid exactly. `handleExportCsv()` fetches
  with `fetch` + blob + synthetic anchor (keeps `Content-Disposition` /
  `X-Export-Truncated` headers readable, server filename honored,
  `carryover-balances.csv` fallback), never rejects — resolves
  `{ truncated }` (`X-Export-Truncated: true` → `true`, spec E20) or `null` on
  failure/backend error (logged via `logger.error`). The consumer (grid/toolbar)
  owns the toast, matching `PayrollReportsDataGrid`.
- **Permissions** — `canViewCarryover` (`ACCOUNTING_CARRYOVER_VIEW`, also gates
  the query via `skip`) and `canManageCarryover` (`ACCOUNTING_CARRYOVER_MANAGE`)
  via `useUserStore(s => s.hasPermission)`.
- **Labels** — `useAppTranslation(DashboardAccountingCarryover)` →
  `labels: CarryoverLabels` grouped per Rule 7 (no `*Label` fields).
