## Section 1: Core Principles & Strict Rules

- [ ] **NO monolithic services.** Extend `ClassSessionService` and `SystemRulesService` only.

### Session state machine (aligned with DB trigger + Threat 3)

```
NOT_ACTIVATED
  │ session.activate_class (teacher, time window enforced)
  │ session.activate_override (admin, bypass window)
  ▼
ACTIVATED ── session.update_status.start ──► RUNNING
  │                                              │
  ├── session.update_status.absent ──────────────┼──► COMPLETED (outcome=ABSENT)
  └── session.update_status.leave ───────────────┘──► COMPLETED (outcome=LEAVE) + reschedule successor

session.reset (admin only) ──► NOT_ACTIVATED, outcome=PENDING, all fields cleared
```

**Threat 3 alignment:** `ACTIVATED → COMPLETED` is allowed **only** when `outcome IN ('ABSENT', 'LEAVE')`.  
`RUNNING → COMPLETED` remains required for `TAKEN` / stop paths.  
**DB trigger must be updated** (Task S1) — do not relax guards without matching trigger migration.

## Section 2: Security & Threat Remediation (mandatory)

All items from `.ai/done/service/1-sprint_1__db_repo_service_enhancments.md` apply. Story 2 **extends** them — never weakens them.

### Threat 1 — IDOR scoping (`runStateChange`)

**Current gap:** Repository checks teacher/parent relationship but **does not bypass for admin/staff** per sprint doc.

**Required fix (Task S0):** At top of `runStateChange`, before teacher/parent checks:

```ts
const isPrivilegedActor = await PermissionsService.hasAnyPermission(actorUserId, [
  AppPermission.SESSION_OVERRIDE_ACTIONS,
  AppPermission.SESSION_ACTIVATE_OVERRIDE,
  AppPermission.SESSION_RESET,
  AppPermission.DASHBOARD_VIEW_METRICS, // academy admin signal
]);
if (!isPrivilegedActor) {
  // existing teacher/parent IDOR checks
}
```

- Document multi-layer security in `SchedulingRepository` header: **RLS policies** + **DB trigger** + **repo assertions** + **service permission gates**.
- **RLS** already deployed: `backend/db/migration/class_instances_rls_policies.sql` — verify not regressed.
- Tests: mismatched teacher/parent throws `unauthorizedAction`; academy admin can reset any instance.

### Threat 2 — Timezone off-by-one (Story 2 touch points)

Story 2 does not add new date-filter queries, but **absent waiting period** compares server `now` against `scheduledStartAt` (UTC stored) — no local-date truncation.

- Use `instance.scheduledStartAt.getTime() + waitingMinutes * 60_000` in `SystemRulesService.assertAbsentWaitingPeriod`.
- Do **not** use `DATE(scheduled_start_at)` comparisons for waiting-period logic.

### Threat 3 — State machine bypass

**Layers (all three must agree):**

1. **DB trigger** `fn_enforce_class_instance_transition()` — update for Story 2 transitions (Task S1).
2. **Repo** `runStateChange` guards — update COMPLETED branch:
   ```ts
   } else if (state.executionState === "COMPLETED") {
     const allowedFromActivated =
       existing.executionState === "ACTIVATED" &&
       (state.outcome === "ABSENT" || state.outcome === "LEAVE");
     if (existing.executionState !== "RUNNING" && !allowedFromActivated) {
       throw localized invalidTransition;
     }
   }
   ```
3. **Service** `assertSessionActivated` — `executionState ∈ { ACTIVATED, RUNNING }` before any `update_status.*`.

**Reset transitions:** Allow `ACTIVATED | RUNNING | COMPLETED → NOT_ACTIVATED` in trigger + repo for `resetClassInstance` only.

### Threat 4 — Student quota

- `resetClassInstance` **must** call `adjustQuotaOnUpdate` when clearing `quotaDeducted` (restore `classesRemaining`).
- Leave reschedule successor creation **must** run `performRescheduleValidations` + quota check (existing `rescheduleClassInstance` path).
- Tests: reset restores quota; leave reschedule fails when `classesRemaining === 0` and quota would deduct.

### Threat 5 — Separation of duties (Story 2)

- `session.reset` gated **only** on `SESSION_RESET` — teachers never receive this permission in seeds.
- `session.activate_override` gated **only** on `SESSION_ACTIVATE_OVERRIDE` — separate from teacher `session.activate_class`.
- Service: `reset()` rejects if actor lacks `SESSION_RESET` even if they have `SESSION_UPDATE_STATUS_*`.

### Threat 6 — Payroll data integrity

- `payrollCredited` set `true` only inside `markClassAbsent` repo path — never cleared except by `resetClassInstance` (admin).
- Teachers cannot call `reset` to erase absent/payroll records (Threat 5).

### Threat 7 — Leave reschedule completeness

- **Prohibited:** Setting `isRescheduled=true` alone without creating successor instance.
- **Required:** `processClassLeave` in repo calls existing `rescheduleClassInstance` with computed next slot (same teacher/student, `scheduledStartAt` = next available from `recurring_schedules` or +7 days default from `system_settings` key `session_leave_reschedule_offset_days` default `7`).

### Task S1 — Database: State Trigger Migration for Story 2

**Target file:** `backend/db/migration/class_instances_state_transition_trigger.sql`

**Action plan:**

1. Extend `fn_enforce_class_instance_transition()`:
   ```sql
   -- Allow ACTIVATED → COMPLETED only for absent/leave outcomes
   IF OLD.execution_state = 'ACTIVATED' AND NEW.execution_state = 'COMPLETED' THEN
     IF NEW.outcome NOT IN ('ABSENT', 'LEAVE') THEN
       RAISE EXCEPTION 'Invalid transition: ACTIVATED can only complete to ABSENT or LEAVE.';
     END IF;
   END IF;

   -- Allow reset: any active state → NOT_ACTIVATED (admin reset path)
   IF NEW.execution_state = 'NOT_ACTIVATED' AND OLD.execution_state IN ('ACTIVATED', 'RUNNING', 'COMPLETED') THEN
     -- permitted (service layer enforces SESSION_RESET permission)
     NULL;
   END IF;
   ```

2. Apply via `bun db cleanGenerate` / migration push.

3. Extend `backend/db/test/logic/class_instances_security.test.ts`:
   - `ACTIVATED → COMPLETED` with `outcome=ABSENT` succeeds.
   - `ACTIVATED → COMPLETED` with `outcome=TAKEN` fails.
   - `COMPLETED → NOT_ACTIVATED` succeeds (reset).
