## 6. Schema & Relations (Confirmed from M1)

### Tables

| Table | Columns | Notes |
|---|---|---|
| `complaints` | id, parentId (FK→parents), studentId (FK→students, nullable), category (enum), submitterEmail, body, status (enum), createdAt, updatedAt, deletedAt | RLS enabled, soft-delete supported |
| `complaintResponses` | id, complaintId (FK→complaints cascade), responderUserId (FK→users, nullable), body, emailSent (boolean), createdAt | No soft-delete |
| `suggestions` | id, parentId (FK→parents), submitterName, body, emailSentAt (timestamp, nullable), createdAt | No soft-delete, no deletedAt |
| `complaintFiles` | id, fileId (FK→storageFiles cascade), complaintId (FK→complaints cascade), usageType, createdAt | Junction table in `storage.ts` |

### Drizzle Relations (Fully Defined)

- `complaints` → parent (one), student (one), responses (many complaintResponses)
- `complaintResponses` → complaint (one), responder (one user)
- `suggestions` → parent (one)
- `parents` → complaints (many), suggestions (many)
- `students` → complaints (many)

## 10. Backend Pattern Summary (for new file conventions)

- **Repositories**: Namespace pattern (`export namespace ComplaintRepository`), Drizzle ORM, `tx?: DBTransaction` parameter, `locale?: string` for i18n errors
- **Services**: Namespace pattern, permission checks via `PermissionsService.hasPermission()`, delegates data access to repositories, `locale?: string` propagation
- **Pothos**: `gqlSchemaBuilder.objectRef<T>()` pattern, resolvers delegate to services, `ctx.locale` propagation
- **Types**: `typeof table.$inferSelect` / `$inferInsert` pattern, exported from `backend/types/index.ts`
