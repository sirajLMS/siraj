## Decision Details

### D1: Schema — No Changes

All 3 tables (`complaints`, `complaintResponses`, `suggestions`) + junction table (`complaintFiles`) + enums (`ComplaintCategory`, `ComplaintStatus`) + Drizzle relations are fully defined and cover all story requirements. No DDL migration needed.

### D2: Permission Strategy

**Existing (reused for admin)**:
- `complaints.list` → Super Admin, Admin
- `complaints.delete` → Super Admin, Admin
- `complaints.respond` → Super Admin, Admin

**New (added)**:
- `support.submit_complaint` (`SUPPORT_SUBMIT_COMPLAINT`) → Parent
- `support.view_history` (`SUPPORT_VIEW_HISTORY`) → Parent
- `communication.submit_suggestion` (`COMMUNICATION_SUBMIT_SUGGESTION`) → Parent
- `system.dispatch_email` (`SYSTEM_DISPATCH_EMAIL`) → System Automated

### D3–D5: Frontend Migration

- 42 existing files: keep all UI views/components/utils as-is
- 4 containers: migrate from mock stores → real Zustand stores + `useQuery`
- 4 mock stores: move mock data to stories → delete files
- 4 stories: rewrite with `MockedProvider` + mock GraphQL responses
- 2 type files: extract from mock stores using generated GraphQL types
- 4 utils: update imports from mock stores → `.types` files

### D6: Repository Structure

Three separate repository files following the namespace pattern:
- `ComplaintRepository` — complaint CRUD + queue + metrics
- `ComplaintResponseRepository` — response CRUD
- `SuggestionRepository` — suggestion CRUD + metrics + mark reviewed

### D7–D9: Communication Service Architecture

```
CommunicationService (interface)
├── send(channel, event, payload): Promise<void>
├── OnAppChannel
│   └── Creates notificationDeliveries records
│   └── Uses NotificationEventType.COMPLAINT_RESPONSE / SUGGESTION_ACKNOWLEDGMENT
└── EmailChannel (STUB)
    └── Sets emailSent: true / emailSentAt: now()
    └── No actual email sending (deferred to follow-up story)
```

Services:
- `ComplaintService` — permission gating → `ComplaintRepository` + `ComplaintResponseRepository` + `CommunicationService`
- `SuggestionService` — permission gating → `SuggestionRepository` + `CommunicationService`

### D10–D11: i18n

- English: keep in monolithic `en.ts` (no split files)
- Arabic: use existing split files (`ar/dashboard/complaints/main.ts`, `ar/dashboard/suggestions/main.ts`)
- New keys: ~5 category labels + ~8 backend errors + ~2 notification titles
- Category labels: add `categoryLabels` field to existing `ComplaintsLabels` type
