## 3. Gaps — New i18n Keys Needed

### A. Complaint Category Labels (Missing)

The schema has `ComplaintCategory` enum values that need display labels:

| Enum Value | Suggested English | Suggested Arabic | Location |
|---|---|---|---|
| `ACADEMIC` | "Academic" | "أكاديمي" | New key in complaints types |
| `BEHAVIORAL` | "Behavioral" | "سلوكي" | New key |
| `TECHNICAL` | "Technical" | "تقني" | New key |
| `ADMINISTRATIVE` | "Administrative" | "إداري" | New key |
| `OTHER` | "Other" | "أخرى" | New key |

**Where to add**: New `categoryLabels` field in `ComplaintsParentLabels` and/or `ComplaintsAdminLabels` type.

### B. Complaint Status Labels for Admin (Partially Missing)

The parent has `statusLabels.{pending, resolved}` but the admin uses `tabs.{unanswered, answered}`. The enum values `UNANSWERED`/`ANSWERED` need consistent display labels:

| Enum Value | Existing Key | Status |
|---|---|---|
| `UNANSWERED` | `admin.tabs.unanswered` | Exists but only in tabs context |
| `ANSWERED` | `admin.tabs.answered` | Exists but only in tabs context |

**Recommendation**: Add `admin.statusLabels.{unanswered, answered}` to match the parent pattern.

### C. Backend Error Messages (Missing)

### E. English Split File for Suggestions (Missing)

The `shared/messages/en/dashboard/suggestions/` directory does NOT exist. If following the Arabic split pattern, it should be created. However, since the English split pattern is not yet wired (complaints split exists but isn't imported), this is a convention decision.

**User Decision**: Keep monolithic `en.ts`. Do NOT create split files for Story 14. Defer English split migration to a separate refactoring story.
