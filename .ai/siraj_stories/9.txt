Siraj LMS - Video Specifications (Part 10: 00:00 - 02:01)

1. Manual Invoice Creation

User Stories

As an Admin, I want the ability to manually generate an invoice for a parent so that I can bill them for custom requests or adjustments outside of the automated package renewal cycle.

Actions & Expected Outcomes

Action Taken: Admin navigates to the "Invoices" tab within a Parent's Profile and clicks the "+" (Add) button.

Expected Input: Mouse click event.

Expected Result: A manual invoice creation form mounts, displaying input fields for Fee and Issue date.

Action Taken: Admin inputs a specific fee amount, selects a date, and clicks "submit & send email" (or "submit").

Expected Input: Fee amount (e.g., 20), Issue date (e.g., 10/30/2024).

Expected Result: The system generates a new invoice record and optionally emails the parent. The Invoices table re-renders to include the new row with its Status strictly set to "Unpaid".

2. Invoice Payment Processing & Notification Resolution

User Stories

As an Admin, I want to click a quick-action button to mark an invoice as "Paid" so that the system accurately logs the payment date and updates the parent's financial standing.

As an Admin, I want the global "Unpaid Invoices" notification list to dynamically update and remove a parent's name the moment their outstanding invoice is marked as paid.

As an Admin, I want to be able to delete a mistakenly generated invoice so that the financial records remain accurate.

Actions & Expected Outcomes

Action Taken: Admin reviews an "Unpaid" invoice row and clicks the "Mark as Paid" action icon (green checkmark).

Expected Input: Mouse click event.

Expected Result: The system updates the invoice record in the database. The table row's Status updates to "Paid" (in green), the Paid Date column is populated with the current date, and the edit/pay action icons disappear.

Action Taken: Admin clicks the global "Notifications/Complaints" bell icon in the top header.

Expected Input: Mouse click event.

Expected Result: The system evaluates the Unpaid Invoices tray. Because the parent's invoice was just settled, their name is successfully removed from the dropdown list.

Action Taken: Admin clicks the "Delete" action icon (red trash can) on an invoice row.

Expected Input: Mouse click event.

Expected Result: A confirmation prompt appears. Upon confirming, the invoice is permanently removed from the parent's billing history table.

3. Quick Student Reassignment & Status Updates

User Stories

As an Admin, I want to quickly reassign a student to a different teacher directly from the Parent's profile view so that I don't have to navigate to a separate module.

As an Admin, I want to change a student's status (e.g., from Regular to On Leave or Suspended) so that I can manage their system access and scheduling permissions dynamically.

Actions & Expected Outcomes

Action Taken: Admin navigates to the "Parent's Students" data table and clicks the "Change" link located under the Teacher column for a specific student.

Expected Input: Mouse click event.

Expected Result: A modal or inline form appears displaying a dropdown list of all active Teachers.

Action Taken: Admin selects a new teacher (e.g., "Manar Badawy") from the dropdown and clicks "SUBMIT".

Expected Input: Teacher ID.

Expected Result: The system updates the student's assigned teacher in the database. The table re-renders to display the new teacher's name.

Action Taken: Admin clicks the current status text (e.g., "Regular") under the Status column for a specific student.

Expected Input: Mouse click event.

Expected Result: A dropdown mounts containing alternative status options (Regular, On Leave, Suspended).

Action Taken: Admin selects a new status and clicks "SUBMIT".

Expected Input: Status String.

Expected Result: The student's global state is updated, which subsequently affects their ability to attend classes or be billed.
