Siraj LMS - Video Specifications (Part 12: 00:00 - 02:00)

1. Global Students Directory & History Access

User Stories

As an Admin, I want to access a global "Students List" so that I can quickly monitor the statuses, assigned teachers, and demographic information of every student across the entire academy without needing to navigate through their parents' profiles.

As an Admin, I want to click a "History" icon on any student in the global list so that I can audit their past class attendance and view historical schedules month by month.

Actions & Expected Outcomes

Action Taken: Admin clicks "Students" from the main sidebar navigation menu.

Expected Input: Mouse click event.

Expected Result: The system routes to the Students Directory (/students.php). The page renders top-level metric cards summarizing all student statuses (Activated, Deactivated, Regular, On Leave, Suspended, On Trial). Below this, a data table lists every student alongside their Parent Name, Teacher Name, Country, Language, Gender, Date of Birth, Hours a Week, and current Status.

Action Taken: Admin clicks the "History" action icon (calendar/clock symbol) located in a specific student's row.

Expected Input: Student ID passed to the route.

Expected Result: The system navigates to the student's "Class History" view, rendering a monthly calendar grid.

Action Taken: Admin clicks the "View Class History of Other Months" button.

Expected Input: Mouse click event.

Expected Result: A filter form mounts allowing the admin to select a specific Year and Month from dropdowns. Upon clicking "Submit", the calendar grid re-fetches and displays the schedule data for that specific time period.

2. Managers (Admin Staff) Directory

User Stories

As a System Administrator, I want to access a "Managers" directory so that I can view and manage other staff members who hold administrative backend access.

As an Admin, I want to edit a manager's profile so that I can update their contact details, Skype ID, and system privileges.

Actions & Expected Outcomes

Action Taken: Admin clicks "Managers" from the main sidebar navigation menu.

Expected Input: Mouse click event.

Expected Result: The system routes to the Managers List page (/managers.php), rendering a data table of administrative users with columns for Image, Name, Email, Skype ID, Phone, Type (e.g., "Admin"), and Options.

Action Taken: Admin clicks the "Edit" action icon (pencil) for a specific manager profile.

Expected Input: Mouse click event passing the Manager ID.

Expected Result: The system mounts the "Edit Manager Profile" form containing modifiable fields for National ID, Phones, Skype, Gender, and Address. Submitting the form updates the manager's backend record.

3. Learning Resources Repository

User Stories

As an Admin, I want to upload learning resources (such as PDF books, syllabi, or worksheets) to a centralized system repository so that teachers have immediate access to official academy materials.

As a Teacher, I want the system to restrict these resources exclusively to staff, so that students cannot bypass the curriculum and access the backend files directly.

Actions & Expected Outcomes

Action Taken: Admin clicks "Resources" from the main sidebar navigation menu.

Expected Input: Mouse click event.

Expected Result: The system routes to the Learning Resources page (/resources.php).

Action Taken: Admin clicks the "+" (Add) button at the top right of the resources table.

Expected Input: Mouse click event.

Expected Result: An upload form mounts containing a "Doc Name" input field and a "Choose A Document" file picker.

Action Taken: Admin types a document name, selects a file (e.g., a PDF) from their local device, and clicks "UPLOAD".

Expected Input: Document Name (String), File object (e.g., .pdf).

Expected Result: The system uploads the document to the server storage, creates a database record, and adds the file to the resource table. A system rule applies to these files ensuring they are scoped exclusively for Teacher visibility on their respective portals.
