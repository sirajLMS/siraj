## Siraj LMS - Story 15: Communication Infrastructure & Suggestion Management

### 1. Overview

This story implements the deferred infrastructure from Story 14: real multi-channel communication delivery (Email via Resend, SMS via Twilio, Push via Firebase Cloud Messaging), complaint file attachments with configurable limits, and full admin suggestion management (review, respond, duplicate tracking).

---

### 2. Feature 1: Real Email Sending via Resend

**Current State:** Story 14 created an `EmailChannel` stub that sets `emailSent: true` / `emailSentAt: now()` without actually sending emails.

**Expected Outcome:**
- Install `resend` npm package
- Implement `EmailChannel` to send real emails via Resend API
- Email templates for: complaint response notification, suggestion acknowledgment
- `complaintResponses.emailSent` set to `true` only after successful delivery
- `suggestions.emailSentAt` set only after successful delivery
- Failed deliveries logged with `failureReason` in `notificationDeliveries`
- Env vars: `RESEND_API_KEY`, `RESEND_FROM_EMAIL`

---

### 3. Feature 2: SMS Notifications via Twilio

**Current State:** `NotificationChannel.SMS` enum exists but no implementation.

**Expected Outcome:**
- Install `twilio` npm package
- Implement `SmsChannel` in the communication service
- SMS templates for: complaint response notification (urgent complaints only)
- Env vars: `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM_NUMBER`
- Delivery tracking via `notificationDeliveries` with status lifecycle
- Rate limiting: max 3 SMS per parent per hour (configurable via system settings)

---

### 4. Feature 3: Push Notifications via Firebase Cloud Messaging

**Current State:** `userDeviceTokens` table exists with `platform` (IOS, ANDROID, WEB). `NotificationChannel.PUSH` enum exists. No FCM integration.

**Expected Outcome:**
- Install `firebase-admin` npm package
- Implement `PushChannel` in the communication service
- Push notifications for: complaint response, suggestion acknowledgment
- Uses existing `userDeviceTokens` table to resolve active tokens per user
- Delivery tracking via `notificationDeliveries` with `deviceTokenId` linkage
- Env vars: `FIREBASE_PROJECT_ID`, `FIREBASE_PRIVATE_KEY`, `FIREBASE_CLIENT_EMAIL`
- Token refresh: handle expired/invalid tokens by deactivating them

---

### 5. Feature 4: Complaint File Attachments

**Current State:** `complaintFiles` junction table exists (fileId, complaintId, usageType). `StorageRepository` already handles complaint file registration/unregistration. No frontend upload UI exists for complaints.

**Expected Outcome:**
- Frontend: File upload dropzone in complaint submission form (reuse `ResourceUploadDropzone` pattern)
- Backend: `ComplaintService.submitComplaint()` accepts file paths, registers via `StorageRepository.registerFileUsage()`
- File types: PDF, DOCX, DOC, TXT, MD, PNG, JPG, JPEG, GIF, WEBP
- Max file size: controlled via system settings key `complaint_max_file_size_mb` (default: 25MB)
- Max files per complaint: controlled via `complaint_max_files_per_complaint` (default: 5)
- File attachments visible in: parent complaint history, admin complaint queue detail view
- File deletion: when complaint is soft-deleted, associated files are unregistered

---

### 6. Feature 5: Admin Suggestion Management

**Current State:** `suggestions` table has no status column, no duplicate tracking, no admin response. Story 14 only created parent submission + admin listing.

**Schema Changes Required:**
- Add `status` column to `suggestions` table: enum `PENDING`, `REVIEWED`, `DUPLICATE`
- Add `duplicate_of_id` self-referencing FK (nullable) to `suggestions`
- Add `admin_response` text column (nullable) to `suggestions`
- Add `reviewed_by_user_id` FK to `users` (nullable)
- Add `reviewed_at` timestamp (nullable)
- Create `suggestion_status` PostgreSQL enum

**Admin Actions:**
1. **Mark Reviewed** — Sets status to `REVIEWED`, records reviewer + timestamp
2. **Respond** — Adds admin response text visible to the parent who submitted
3. **Mark as Duplicate** — Sets status to `DUPLICATE`, links to original suggestion via `duplicate_of_id`
   - Search existing suggestions to find the original (autocomplete/search UI)
   - Duplicate badge shown on suggestion card with link to original (GitHub-style)
   - Both the submitting parent and other admins can see the duplicate link
4. **Delete** — Soft-delete inappropriate suggestions (requires new `suggestions.delete` permission)

**New Permissions:**
| Permission Key | Enum Value | Group | Purpose |
|---|---|---|---|
| `suggestions.list` | `SUGGESTIONS_LIST` | Admin, Super Admin | View admin suggestion queue |
| `suggestions.review` | `SUGGESTIONS_REVIEW` | Admin, Super Admin | Mark reviewed, respond, mark duplicate |
| `suggestions.delete` | `SUGGESTIONS_DELETE` | Super Admin only | Delete inappropriate suggestions |

**Frontend Changes:**
- Suggestion card shows status badge (Pending/Reviewed/Duplicate)
- Duplicate badge links to original suggestion
- Admin action buttons: Mark Reviewed, Respond, Mark Duplicate, Delete
- Duplicate search modal: search existing suggestions, select original
- Parent view: see admin response + duplicate link on their suggestions
