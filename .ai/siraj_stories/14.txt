1. Parent Portal - Suggestions System (Email Integration)

User Stories

As a Parent, I want to navigate to a "Suggest" module and submit feedback so that I can communicate my ideas to the academy administration.

As an Admin, I want the system to automatically forward any parent suggestions directly to the academy's official support email inbox so that I can review them immediately without logging into the LMS.

Actions & Expected Outcomes

Action Taken: Parent logs in, clicks the "Suggest" link from the sidebar, fills in the "Your Full Name" and "Your Suggestion" text areas, and clicks "Submit".

Expected Input: Name string (e.g., "Omar Ayman"), Suggestion text string (e.g., "rqe").

Expected Result: The system records the feedback and displays an inline success message: "We Have Recieved Your Message" (typo preserved from video). Simultaneously, the system dispatches an automated email to the configured Admin Support address (Bung Academy Support) containing the Parent's Name and the Suggestion text.

2. Parent Portal - Complaint Submission & Tracking

User Stories

As a Parent, I want to submit a formal complaint specific to a particular student and teacher so that the administration can formally investigate my concerns.

As a Parent, I want to access a "Complaint Record" view so that I can read the administration's official response to my submitted complaints.

Actions & Expected Outcomes

Action Taken: Parent clicks "Complaints" -> "Regarding Teacher" from the sidebar.

Expected Input: Mouse click event.

Expected Result: A complaint form mounts with the following fields: Select Student (Dropdown), Your Email (Read-only/pre-filled), and Complaint (Text area).

Action Taken: Parent selects a specific student from the dropdown, types their issue into the Complaint box, and clicks "SUBMIT".

Expected Input: Student ID, Complaint string (e.g., "gagfs").

Expected Result: The complaint is saved to the database under an "Un-answered" status. The form clears and displays a success message: "We Will Answer Soon."

Action Taken: Parent clicks "Complaint Record" from the sidebar.

Expected Input: Mouse click event.

Expected Result: A view mounts displaying a historical log of their submitted complaints, showing the original complaint text alongside the "Answer" field populated by the Admin.

3. Admin Workflow - Managing & Answering Complaints

User Stories

As an Admin, I want to view a "Complaints" dashboard displaying metric counts of "Answered" and "Un-answered" tickets so that I can effectively manage my support queue.

As an Admin, I want to type a response to a parent's complaint and click an "Answer & send to email" button so that the issue is marked as resolved and the parent is instantly notified.

As an Admin, I want to delete a resolved or invalid complaint record so that I can maintain a clean support dashboard.

Actions & Expected Outcomes

Action Taken: Admin navigates to the "Complaints" view from the main sidebar.

Expected Input: Mouse click event.

Expected Result: The system renders the complaints dashboard with top metric cards ("Answered", "Un-answered"). Below, a feed displays pending complaints detailing the Parent Name, Date, Student Name, and the Complaint text.

Action Taken: Admin types a resolution message into the blank "Answer:" text field of a specific complaint card and clicks the "Answer & sned to email" button (typo preserved).

Expected Input: Answer text string (e.g., "enqrq").

Expected Result: The system updates the complaint record in the database. The status shifts from Un-answered to Answered, an email notification is dispatched to the parent, and the response becomes visible in the Parent's "Complaint Record" view.

Action Taken: Admin clicks the "Delete" action button (red trash can icon) on a complaint card.

Expected Input: Mouse click event.

Expected Result: A global confirmation prompt appears ("Are you sure that you want to delete this Complaint?"). Clicking "YES" permanently removes the record from the database, and the UI updates to show an empty state ("There is no complaints.") if the queue is clear.
