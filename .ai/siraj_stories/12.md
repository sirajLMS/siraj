## Siraj LMS - Permissions & Permission Groups (Part 13: 00:00 - 01:56)

### 1. Permission Groups (Roles)

The functionalities in this module introduce destructive actions for file management and expose highly sensitive aggregated payroll data. These are strictly mapped to administrative roles:

| Permission Group | Description | Assigned Permissions |
| --- | --- | --- |
| **Academy Admin** | Authority to provision and destroy academy files, and the ability to query, group, and audit academy-wide financial and operational reports. | Leverages existing `resource.upload`, introduces `resource.delete`, `report.generate_custom`, `report.view_financials` |
| **Teacher** | Restricted from destructive file operations and cross-staff financial reporting. | *None applicable* |
| **Student / Parent** | Excluded from internal documents and backend academy reporting. | *None applicable* |

---

### 2. Granular Permissions Breakdown

#### Group 1: Resource Lifecycle Management (`resource` - *Extended Application*)

Controls the complete lifecycle of internal curriculum files, extending the provisioning capabilities introduced in Part 12 to include destructive erasure.

* **Application of `resource.upload` (Execution)**
* **Description:** Grants the authority to finalize the provisioning of new files to the shared repository.
* **Expected Outcome:** Processes the inputted `Doc Name` and `File Object`, writes a new record to the database, uploads the file to the server, and re-renders the UI to display the new resource card.


* **`resource.delete`**
* **Description:** Grants the authority to destructively wipe a learning resource from the academy's repository.
* **Expected Outcome:** Exposes the "Delete" action icon (red trash can). Upon passing the mandatory confirmation prompt (`"Are you sure that you want to delete this resource?"`), the system permanently drops the file from server storage, removes the relational record from the database, and dynamically unmounts the card from the UI.



#### Group 2: Custom Reporting & Aggregation (`report`)

Controls access to the dynamic query engine used to calculate operational metrics and payroll estimates across specific temporal and demographic parameters.

* **`report.generate_custom`**
* **Description:** Grants access to the overarching Reports interface and the dynamic aggregation query engine.
* **Expected Outcome:** Authorizes the mounting of the query form. Allows the user to pass `From` date, `To` date, `Teacher ID`, and `Report Type` (e.g., "Group by Date") parameters to the backend. The system evaluates these parameters to fetch and render an aggregated data table of operational statuses (Taken, Absent, Leave, Pending).


* **`report.view_financials`**
* **Description:** Grants visibility into the calculated payroll and financial metrics within the generated reports.
* **Expected Outcome:** Authorizes the query engine to calculate and render the highly sensitive financial columns: total `Hours` worked, `Paid (EGP)`, and `Paid (USD)`, along with the bottom total summary row.

### 3. Traceability Mapping

> **Note on Security & Workflow Boundaries:**
> * **Separation of Operational and Financial Data:** By splitting the reporting permissions into `report.generate_custom` and `report.view_financials`, the system allows for future scalability. For instance, a lower-level scheduling manager might be granted `report.generate_custom` to evaluate teacher attendance (Absent vs. Taken counts), but explicitly denied `report.view_financials` to ensure they cannot see their colleagues' monetary compensation (Paid EGP/USD).
> * **Destructive File Management:** The `resource.delete` permission executes a hard deletion. Unlike simply hiding a file, this action permanently purges the file from the server to save storage space. The UI confirmation prompt acts as the required safety friction to prevent the accidental erasure of core curriculum materials.
> * **Dynamic Querying Power:** The `report.generate_custom` permission gives Admins immense visibility into academy operations. Grouping by "Date" allows an Admin to audit academy health on specific days, while grouping by "Teacher" directly transforms the data into an actionable payroll worksheet.
