Siraj LMS - Video Specifications (Part 4: 00:00 - 02:01)

1. Teacher Workflow - Requesting Leave / Reschedule

User Stories

As a Teacher, I want to click a "Leave" button on an upcoming or missed class so that I can notify the administration of my inability to attend and formally request a schedule change.

Actions & Expected Outcomes

Action Taken: Teacher logs in, navigates to their daily schedule, and clicks the "Leave" action button (logout/exit icon) on a specific class.

Expected Input: Mouse click event.

Expected Result: The system flags the class for administrative review. The status updates to indicate a leave request, and the class is added to the "Leave" metric count on the main Admin Dashboard to alert the administration. (Note: The video briefly shows a 404 error during this action, which is likely a bug in the existing system, but the intended result is the status update and admin notification).

2. Admin Workflow - Executing a Class Reschedule

User Stories

As an Admin, I want to view classes marked as "Leave" from the dashboard so that I can quickly process teacher absence requests.

As an Admin, I want to use a dedicated "Reschedule" form to assign a new date and time to a class so that the session is formally moved on the calendar without losing the original record's context.

Actions & Expected Outcomes

Action Taken: Admin clicks the "Leave" metric card on the Home Dashboard to filter the table, then clicks the "History/Details" button for the specific class.

Expected Input: Mouse click events.

Expected Result: The Admin is navigated to the Class Details page, which displays an action toolbar including a "Reschedule" button (calendar icon with a pencil/arrow).

Action Taken: Admin clicks the "Reschedule" button.

Expected Input: Mouse click event.

Expected Result: A "Reschedule a class" form mounts. The form displays a warning note about timezones and pre-populates the "Teacher Name" and "Student Name" fields (read-only).

Action Taken: Admin selects a new date from the date picker, inputs a new time, and clicks "SUBMIT".

Expected Input: Date (mm/dd/yyyy), Time (e.g., 04:00 AM).

Expected Result: The system updates the class record. The Class Status badge on the details page changes to "Re Scheduled", and the Remarks section automatically logs the original date and the new rescheduled date.

3. Admin Workflow - Verifying Future Scheduled Classes

User Stories

As an Admin, I want to filter the schedule by a future date and the "Re Scheduled" status so that I can verify the class was moved successfully and the teacher's future workload is accurate.

Actions & Expected Outcomes

Action Taken: Admin navigates back to the Home Dashboard, sets the "List of Classes on:" date picker to the newly assigned date (e.g., tomorrow's date), and clicks "SUBMIT".

Expected Input: Future Date string.

Expected Result: The system fetches and renders the schedule for the selected future date.

Action Taken: Admin clicks the "Re Scheduled" metric card in the top grid.

Expected Input: Mouse click event.

Expected Result: The table filters to isolate the recently moved class, allowing the Admin to confirm its presence at the new scheduled time.
