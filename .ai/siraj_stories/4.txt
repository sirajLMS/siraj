1. Schedule Verification - Viewing Rescheduled Classes

User Stories

As a Teacher or Admin, I want to filter my schedule by a future date so that I can verify that a successfully rescheduled class appears correctly on the new day.

As a user, I want the rescheduled class to prominently display a "Re Scheduled" badge so that I can easily differentiate it from regular classes.

Actions & Expected Outcomes

Action Taken: User navigates to the schedule table, selects a future date (e.g., tomorrow's date: 10/31/2024) using the date picker, and submits.

Expected Input: Future Date string.

Expected Result: The schedule table populates with the classes for that day. The newly rescheduled class from the previous workflow appears in the table with its Class Status badge rendering as "Re Scheduled" (in red text) instead of "Regular".

2. Academy Rules - Enforcing Leave/Reschedule Limits

User Stories

As a System Administrator, I want the system to enforce an academy rule that limits teachers to a maximum of two (2) "Leave" (reschedule) requests per designated period so that attendance policies are strictly maintained.

As a Teacher, I want the system to block my ability to request a leave if I have already exhausted my allowed quota so that I am aware I cannot miss any further classes without penalty.

Actions & Expected Outcomes

Action Taken: Teacher attempts to click the "Leave" action button on a class after having already successfully used the leave action twice.

Expected Input: Mouse click event.

Expected Result: The system checks the database for the teacher's historical leave count. Because the limit (2) has been reached, the system prevents the status from changing to "Leave". The action is blocked, and the teacher is prevented from making further self-service reschedule requests for that period. (Note: The video verbally describes this rule as a core system constraint).

3. Admin Workflow - Executing Subsequent Reschedules

User Stories

As an Admin, I want to be able to process a second "Leave" request using the Reschedule form so that the teacher's final allowed reschedule is logged in the system.

Actions & Expected Outcomes

Action Taken: Admin navigates to another class marked as "Leave", clicks the "History/Details" action, and then clicks the "Reschedule" button in the toolbar.

Expected Input: Mouse click events.

Expected Result: The Reschedule form mounts, allowing the admin to assign the final allowed schedule change for this teacher.

Action Taken: Admin inputs a new date and time, then clicks "SUBMIT".

Expected Input: Date (e.g., 01/01/2024), Time (e.g., 01:00 AM).

Expected Result: The system updates the class record to "Re Scheduled", logs the change in the remarks, and increments the teacher's consumed leave/reschedule count to its maximum limit of two.
