## Siraj LMS - Permissions & Permission Groups (Part 8: 00:00 - 02:02)

### 1. Permission Groups (Roles)

The functionalities in this module introduce destructive schedule management, sensitive profile editing, and global system operations. These are highly restricted to administrative roles:

| Permission Group | Description | Assigned Permissions |
| --- | --- | --- |
| **System Administrator** | Highest level of technical authority. Can execute global scripts that alter the entire database at once. | `system.bulk_update_dst` |
| **Admin** | Authority to destructively clear schedules, view parent data, and modify sensitive staff financial/profile records. | `schedule.delete_class`, `schedule.clear_weekly`, `staff.edit_profile`, `parent.view_directory` |
| **Teacher / Parent** | Excluded from these management and destructive capabilities. | *None applicable* |

---

### 2. Granular Permissions Breakdown

#### Group 1: Schedule Deletion & Erasure (`schedule.deletion`)

Controls destructive operations on the weekly calendar grids.

* **`schedule.delete_class`**
* **Description:** Grants the ability to target and delete a specific recurring class block from a teacher's schedule.
* **Expected Outcome:** Triggers a mandatory localized confirmation modal (`"Are you sure that you want to delete this class?"`). Upon confirming "YES", the system permanently drops the class from the database and visually removes it from the grid.


* **`schedule.clear_weekly`**
* **Description:** Grants the ability to perform a bulk erasure of a teacher's entire weekly schedule in a single action.
* **Expected Outcome:** Triggers a global confirmation modal (`"Are you sure that you want to delete the schedule?"`). Upon confirming "YES", the system drops all classes assigned to that specific Teacher ID for the week.



#### Group 2: Staff Profile Management (`staff`)

Controls access to sensitive personally identifiable information (PII) and financial records.

* **`staff.edit_profile`**
* **Description:** Grants access to the "Edit Teacher Profile" workflow.
* **Expected Outcome:** Authorizes read/write access to a comprehensive form categorized by: `Teacher Information` (National ID, Phone, Demographics), `Salary Details` (Amount, Currency, Bank Info), and `Official Details` (Zoom credentials, Timezone).



#### Group 3: Global System Operations (`system`)

Controls the execution of academy-wide scripts that manipulate thousands of records simultaneously.

* **`system.bulk_update_dst`**
* **Description:** Grants the authority to trigger the global Daylight Saving Time (DST) adjustment algorithm across the entire database.
* **Expected Outcome:**
* **Execution:** Calculates time shifts for all recurring classes based on associated user timezones.
* **Reporting:** Generates and displays a detailed conflict report categorizing all schedules into `Updated` (successful shifts), `Error` (shifts that caused overlapping class collisions requiring manual admin intervention), and `Checked / Empty` (no changes needed).





#### Group 4: Parent Management (`parent`)

Controls access to the global directory of parent accounts and their overarching financial/system statuses.

* **`parent.view_directory`**
* **Description:** Grants access to the overarching Parents Directory (`/parents.php`).
* **Expected Outcome:** Authorizes the rendering of aggregated parent status metric cards (Activated, Deactivated, Regular, On Leave, Suspended, On Trial) and populates the data table with user records, including visibility into outstanding `"Unpaid Invoices"`.

### 3. Traceability Mapping

> **Note on Security & Workflow Boundaries:**
> * **Destructive Actions & Safeguards:** The `schedule.delete_class` and `schedule.clear_weekly` permissions execute hard deletions (unlike marking a class "Absent" or "Leave"). Because this physically removes the record and alters future capacity, the UI enforces a mandatory confirmation step to prevent accidental data loss.
> * **Data Privacy (Salary & PII):** The `staff.edit_profile` permission is strictly isolated to Admins. It exposes highly sensitive data (National ID, Bank Info, Base Salary) that must never be visible to peers or accessible via standard directory views.
> * **Global Script Risk:** `system.bulk_update_dst` is the most powerful action in this module. Because it modifies the entire academy's database at once, it is typically reserved for a System Administrator. The required conflict report generation ensures that if the algorithm creates scheduling collisions (e.g., two classes now occupying the same time slot), the system catches the error rather than silently double-booking a teacher.
