## Siraj LMS - Permissions & Permission Groups (Part 6: 00:00 - 01:57)

### 1. Permission Groups (Roles)

The functionalities introduced in this module are exclusively assigned to administrative roles to protect sensitive financial data and prevent unauthorized auditing of staff availability:

| Permission Group | Description | Assigned Permissions |
| --- | --- | --- |
| **Academy Admin** | Global oversight of financial alerts, user billing profiles, and cross-academy staff availability. | `notification.view_alerts`, `billing.view_unpaid_invoices`, `user.view_profile`, `schedule.search_availability` |
| **Teacher / Student** | Excluded from these features to maintain data privacy regarding peer schedules and academy financials. | *None applicable* |

---

### 2. Granular Permissions Breakdown

#### Group 1: Notifications & Financial Alerts (`notification`, `billing`, `user`)

Controls access to system-wide alerts, outstanding payment tracking, and user account drill-downs.

* **`notification.view_alerts`**
* **Description:** Grants access to the global notifications UI component (bell icon) in the top header.
* **Expected Outcome:** Authorizes the mounting of the notification dropdown/modal containing system alerts, complaints, and aggregated system statuses.


* **`billing.view_unpaid_invoices`**
* **Description:** Allows the user to view the list of accounts with pending or overdue financial balances.
* **Expected Outcome:** Evaluates the billing database. If all accounts are settled, it renders the placeholder `"There is no invoices to be paid."` If balances are due, it renders a list of specific user names associated with the delayed payments.


* **`user.view_profile`**
* **Description:** Grants the ability to view a specific user's comprehensive account and billing details.
* **Expected Outcome:** Authorizes the routing from the unpaid invoices notification list directly to the targeted user's profile view, allowing the admin to manage or follow up on the outstanding invoice.



#### Group 2: Global Availability Search (`schedule`)

Controls access to the advanced querying engine used to find unassigned time slots across the entire teaching staff.

* **`schedule.search_availability`**
* **Description:** Grants access to the dedicated "Schedule Search" view (`/search-schedule.php`) and its cross-staff querying engine.
* **Expected Outcome:**
* **Form Access:** Renders the search form with temporal inputs (`From` time, `To` time) and demographic filters (`Gender`).
* **Query Execution:** Authorizes the system to query the entire database of teacher schedules based on the inputted parameters.
* **Visual Rendering:** Populates the UI with weekly visual calendar grids corresponding to each matching teacher. These grids isolate and display only the classes falling within the requested time block, visually highlighting the empty gaps (available slots) for easy identification.

### 3. Traceability Mapping

> **Note on Security & Workflow Boundaries:**
> * **Data Privacy (Financials):** The `billing.view_unpaid_invoices` permission acts as a strict boundary. Even if another user role somehow accesses the notification bell, the backend must prevent the unpaid invoices list from populating without this specific financial clearance.
> * **Data Privacy (Schedules):** The `schedule.search_availability` permission is strictly isolated to Admins. While a Teacher has the `teacher.view_dashboard` permission (from Part 2) to see their *own* schedule, they are explicitly blocked from executing global availability searches to view other teachers' workload capacities, ensuring operational privacy across the staff.
> * **Workflow Efficiency:** Routing an Admin directly from an alert (`billing.view_unpaid_invoices`) to the resolution point (`user.view_profile`) establishes a direct, permission-gated workflow that bypasses the need for manual user searching.
