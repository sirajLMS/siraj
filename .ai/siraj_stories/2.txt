Siraj LMS - Video Specifications (Part 3: 00:00 - 01:58)

1. Admin Override & Manual Class Activation

User Stories

As an Admin, I want to manually activate a scheduled class on behalf of a teacher so that I can bypass the time-window restrictions if the teacher encounters technical difficulties.

As a Teacher or Admin, I want the class row to reveal a set of session management controls (Start, Absent, Leave, Reset) immediately upon activation so that I can update the live status of the class.

Actions & Expected Outcomes

Action Taken: Admin navigates to the "Today Classes" dashboard, filters by a specific teacher (e.g., "Doaa Khaled"), and clicks the "Activate" button (red play icon) on an un-activated class.

Expected Input: Mouse click on the Activate icon.

Expected Result: The system overrides standard time-window checks for the Admin. The page reloads (or state updates), and the single "Activate" button is replaced by an action toolbar containing four specific icons: Start (Play), Absent (Person with X), Leave (Logout/Exit arrow), and Delete/Reset (Trash can).

2. Live Session Tracking (Start & Absent Actions)

User Stories

As a Teacher, I want to click a "Start" button the moment the student joins the virtual room so that the system logs the exact timestamp the lesson began.

As a Teacher, I want to click an "Absent" button if the student fails to show up after the mandated waiting period (e.g., half the class time) so that the class is recorded for attendance and payroll purposes without me teaching it.

Actions & Expected Outcomes

Action Taken: User clicks the "Start" action button (blue play icon) on an activated class.

Expected Input: Mouse click event.

Expected Result: The class status updates to indicate it is currently running. The system captures the current server timestamp and permanently logs it as the Start time in the Class Details database record.

Action Taken: User clicks the "Absent" action button (red person-with-X icon) on an activated class.

Expected Input: Mouse click event.

Expected Result: The system updates the class status to "Absent". Additionally, the system automatically populates the class's Description/Remarks field with a standard message: "I have been waiting for whole class time." The system flags this class to still be credited/paid to the teacher.

3. Session Correction & Rescheduling (Reset & Leave Actions)

User Stories

As an Admin, I want to use a "Delete/Reset" button on an actioned class so that I can revert the class to its original, untouched state if a teacher makes a mistake (e.g., accidentally marking a present student as absent).

As a Teacher or Admin, I want to click a "Leave" button if either party provides an excused cancellation so that the class is formally marked for future rescheduling.

Actions & Expected Outcomes

Action Taken: Admin clicks the "Delete" action button (red trash can icon) on a class that has already been marked as Absent, Started, or Leave.

Expected Input: Mouse click event.

Expected Result: The system clears any session-specific data (start times, absent remarks, leave statuses) for that record. The class state is fully reverted to its default "Regular" status, making it look as if the class hasn't happened yet.

Action Taken: User clicks the "Leave" action button (dark grey exit/logout icon).

Expected Input: Mouse click event.

Expected Result: The system updates the class status to "Leave". This triggers a workflow indicating an excused absence or formal cancellation, queuing the class to be rescheduled ("Re Scheduled") for another date.
