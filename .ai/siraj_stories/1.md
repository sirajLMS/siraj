## Siraj LMS - Permissions & Permission Groups (Part 2: 02:01 - End)

### 1. Permission Groups (Roles)

Building upon Part 1, the system maps the new functionalities to three specific permission groups:

| Permission Group | Description | Assigned Permissions |
| --- | --- | --- |
| **Admin** | High-level operations, global auditing across timezones, full history drilling, and session overrides. | `dashboard.search`, `schedule.view_timezones`, `history.view_calendar`, `history.view_details`, `session.override_actions` |
| **Teacher** | Access restricted to their own schedule, direct communication integrations, and time-restricted class control. | `teacher.view_dashboard`, `session.activate_class` |
| **System Automated** | Internal system rules that validate permissions against business constraints. | `system.enforce_time_window` |

---

### 2. Granular Permissions Breakdown

#### Group 1: Dashboard Search & Localization (`dashboard`, `schedule`)

Controls the search capabilities and timezone localization engines within administrative views.

* **`dashboard.search`**
* **Description:** Grants the ability to use the global search input on the class schedule table.
* **Expected Outcome:** Filters rows dynamically in real-time based on partial or full character matching against Teacher or Student name strings.


* **`schedule.view_timezones`**
* **Description:** Grants visibility into multi-timezone calculations within the schedule grid.
* **Expected Outcome:** Authorizes the UI to display localized time strings across three distinct vectors: Admin locale (`Your Time`), `Teacher Time`, and `Student Time`.



#### Group 2: Student History & Session Overrides (`history`, `session`)

Controls the deep-dive audit trail of student records and manual override controls.

* **`history.view_calendar`**
* **Description:** Allows the user to view and interact with a student's monthly "Class History" calendar grid.


* **`history.view_details`**
* **Description:** Grants permission to drill down into a specific session's metadata.
* **Expected Outcome:** Authorizes routing to `/history-details.php` and fetching of session strings (Student/Teacher names, Date, Duration, Status, Remarks, and Description).


* **`session.override_actions`**
* **Description:** Grants access to the administrative "Actions" control toolbar on the details page.
* **Expected Outcome:** Renders functional live-override components (`Activate/Play`, `Stop`, `User`, `Delete/Cancel`) along with the regulatory timezone disclaimer note.



#### Group 3: Teacher Portal Operations (`teacher`, `session`)

Controls access to personalized teaching dashboards and standard live-session triggers.

* **`teacher.view_dashboard`**
* **Description:** Grants access to the isolated Teacher home directory (`/teacher-home`).
* **Expected Outcome:** Automatically filters data payloads to only show classes assigned to the active Teacher ID, exposing rows containing the Zoom integration link and localized control elements.


* **`session.activate_class`**
* **Description:** Allows a user to issue a request to start/activate a scheduled class session.
* **Expected Outcome:** Submits an activation request to the system logic engine for structural time checks.



#### Group 4: Automated System Rules (`system`)

Back-end validation rules that guard permissions against context-based business logic constraints.

* **`system.enforce_time_window`**
* **Description:** System-level validation gate that cross-references any `session.activate_class` request against the server clock.
* **Expected Outcome:** Restricts execution to a narrow window (5 minutes prior to start through the end of the class duration). If failed, it revokes the activation sequence and forces an inline error message ("YOU MISSED THE CLASS TIME").



---

### 3. Traceability Mapping

> **Note on Security Boundary Changes:**
> * **Search & Timezones:** The global search bar (`dashboard.search`) and localized timezone processing (`schedule.view_timezones`) are isolated to administrative layouts, keeping standard user view states clean and performant.
> * **Administrative Overrides:** While a Teacher possesses the baseline capability to activate a class, the explicit authority to view past calendar details and manipulate session states retroactively via the toolbar requires elevated `session.override_actions` permission, preventing teachers from tampering with finalized class history records.
> * **Contextual Safety:** Even if a user possesses the `session.activate_class` permission, the request will be automatically rejected at the API layer if it fails the rule enforced by `system.enforce_time_window`.
