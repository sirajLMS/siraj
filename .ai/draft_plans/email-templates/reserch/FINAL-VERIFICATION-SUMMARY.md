## Cross-cutting findings

1. **Install set corrections** (covers claims 1, 11, 12): The plan over-specifies the install set. Apply one consistent correction:
    ```sh
    bun add react-email @react-email/editor@^1.1 @aws-sdk/client-ses postmark mailgun.js form-data nodemailer @types/nodemailer
    # optional -D, only if running the standalone preview server:
    bun add -D @react-email/ui
    ```
    Drop: `@react-email/components`, `@react-email/render`, `@react-email/ui` (from runtime + line 75), `@react-email/editor@^1.6` (use `@1.1` floor), `@tiptap/*` (bundled transitively).

2. **Typed-props registry is hand-rolled** (covers claims 2, 3, 7, 13): The plan's repeated claim that "props enforce type safety across all variants" while still allowing DB-stored `designJson` body overrides is **not mechanistically supported** by `@react-email/editor`. Typed props live in the code scaffold (`backend/services/communication/templates/components/*`); the visual editor edits an opaque TipTap `JSONContent` blob carrying no per-template type information. The discriminated-union registry (`EMAIL_TEMPLATES`) MUST be restructured per claim 7's fix (`EmailPropsByScope` map + mapped type + `defineEmailTemplate<P>` helper) — the plan's TS as written compiles but does not deliver the narrowing it advertises (TS #47109).

3. **i18n call shape wrong** (claim 10): `getServerTranslations` takes only `locale` (no namespace arg). Fix all plan references like `getServerTranslations(locale, "emails.errors")` → `getServerTranslations(locale).emailsTranslations.errors.*`. Add the new `emails.errors` sub-namespace to `EmailsLabels` + en + ar implementations — it does not exist today.

4. **Registry lifecycle** (claim 6): We must ship our own `createRegistry` (lift ~30 LOC from makerkit docs — `register` returns `this`, `get` returns `Promise<T>` and memoizes, throws `Unknown provider "<name>"` on miss). Move `EmailProviderName` into `backend/types` per the AGENTS.md type pattern. Make the throw-on-unregistered behavior change explicit (today's `EmailChannelFactory` falls back to resend — the new version throws). Preserve `resetEmailChannel()` cache-invalidation semantics. Drop the `senda` reference.

5. **Pothos convention drift** (claim 8): Add explicit subtask for registering the new `EmailScope` / `EmailTemplateStatus` / `EmailEditorPermission` enums in `backend/graphql/pothos/shared/enum.pothos.ts` (repo rule), and rename the mutation file path from `emailTemplate.mutations.ts` to `emailTemplate.mutation.ts` (singular, matching repo convention at `backend/graphql/mutation/**`).

6. **Drizzle array-of-enum is a first-time-use case** (claim 8): The repo has zero existing `.array()` columns. `pgEnum.array()` works (since drizzle-kit 0.24), but the safer, idiomatic-to-this-repo path is `attachmentRules: jsonb.$type<readonly EmailEditorPermission[]>()`. Also: the enum imports (`emailScopeEnum`, etc.) referenced in the plan's schema stub don't exist yet — must be created via `createPgEnumFromEnum` in `backend/db/schema/enums.ts` + backing TS enums in `@/backend/enum`.
