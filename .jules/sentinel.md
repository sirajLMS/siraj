## 2025-05-18 - Open Redirect Control Character Bypass
**Vulnerability:** The relative path safety check `isRelativeSafePath` in `frontend/common/lib/safeRedirect.ts` only checked for `startsWith("//")` and `startsWith("/\\")`. Certain browsers and URL parsers strip or normalize control characters (such as tab `\t`, newline `\n`, carriage return `\r`) or whitespace following a leading slash (e.g. `/\t/evil.com`), interpreting the string as protocol-relative (`//evil.com`) and redirecting to external malicious origins.
**Learning:** Checking for standard double-slash prefixes is insufficient for open-redirect defense when input paths are passed to browser redirection or URL resolution primitives that normalize whitespace and ASCII control characters.
**Prevention:** In redirect validation functions, reject any input containing ASCII control characters (`0x00-0x1F`, `0x7F`) or whitespace/control characters immediately following the leading slash (`/^[\/\\][\s\t\n\r]/`).
